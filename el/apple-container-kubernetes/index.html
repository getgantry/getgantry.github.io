Gantry/Kubernetes στο apple/container

Kubernetes στο Apple container

Το apple/container μπορεί να εκτελέσει ένα cluster Kubernetes του οποίου οι κόμβοι είναι κοντέινερ στο Mac σας. Το Gantry είναι ένα GUI γι' αυτό: δημιουργήστε ένα cluster, δείτε τους κόμβους του να ξεκινούν, εκτελέστε σε αυτό τις τοπικές σας εικόνες και περιηγηθείτε στα pod, στα αρχεία καταγραφής και στις υπηρεσίες του, χωρίς μεγάλες γραμμές εντολών container cluster.

Με λίγα λόγια. Σε host apple/container, η ενότητα Cluster του Gantry δημιουργεί και διαγράφει cluster Kubernetes με το container cluster (CLI 1.6.1 και 1.7) ή το container k8s (CLI 1.5.0 έως 1.6.0). Στο CLI 1.7.1 ορίζει το μέγεθος των worker χωριστά από το control plane και ενεργοποιεί την κοινή αποθήκη εικόνων. Η ενότητα Kubernetes περιηγείται στο cluster: pod, αρχεία καταγραφής, shell, προωθήσεις θυρών, κλιμάκωση και Εφαρμογή YAML.

Απαιτήσεις

  • Mac με Apple silicon, macOS 26 και το Gantry (brew install --cask getgantry/tap/gantry).
  • CLI container 1.5.0 ή νεότερο· προτείνεται η 1.7.1. Τα worker και το CNI Κανένα απαιτούν 1.6.0 ή νεότερη. Τα μεγέθη worker και η κοινή αποθήκη εικόνων απαιτούν 1.7.0 ή νεότερη. Χρησιμοποιήστε το υπογεγραμμένο πακέτο εγκατάστασης: η έκδοση Homebrew της 1.7.1 δεν έχει υπηρεσίες cluster.
  • kubectl για τον περιηγητή Kubernetes και το τερματικό. Το Gantry μπορεί να το εγκαταστήσει με Homebrew.

Δημιουργία cluster

  1. Επιλέξτε τον host apple/container σας και ανοίξτε τα Cluster στην πλαϊνή στήλη.
  2. Ξεκινήστε ένα νέο cluster και συμπληρώστε τις παρακάτω επιλογές.
  3. Δημιουργήστε το. Η λίστα εμφανίζει το νέο cluster με ζωντανή πρόοδο. Η Ακύρωση σταματά τη δημιουργία και διαγράφει τους κόμβους που έχουν ήδη δημιουργηθεί.
ΕπιλογήΣημαία CLIΣημειώσεις
Όνομα--nameΚαι όνομα του context στο kubeconfig
Worker--workersΑριθμός κόμβων worker. CLI 1.6.0+
CPU και μνήμη των worker--workers count=N,cpus=C,memory=MCLI 1.7+. Πριν από την 1.7, τα --cpus και --memory ορίζουν κάθε κόμβο
CPU--cpusControl plane (CLI 1.7+) ή κάθε κόμβος (πριν από την 1.7)
Μνήμη--memoryControl plane (CLI 1.7+) ή κάθε κόμβος (πριν από την 1.7), για παράδειγμα 4G
Χρήση τοπικών εικόνων--shared-image-storeCLI 1.7+. Οι κόμβοι εκτελούν εικόνες από την τοπική σας αποθήκη εικόνων
Εικόνα κόμβου--node-imageΚενό: κρατά την προεπιλογή του CLI
CNI--cniΠροεπιλογή (ενσωματωμένο kindnet), Κανένα (NONE, CLI 1.6.0+) ή διαδρομή προς προσαρμοσμένο manifest

Η ίδια εντολή στο CLI:

Shell
container cluster create --name dev --cpus 2 --memory 4G \
  --workers count=2,cpus=2,memory=4G --shared-image-store

Κόμβοι και λεπτομέρειες cluster

Η λίστα cluster έχει μία γραμμή για κάθε cluster. Η προβολή λεπτομερειών έχει Επισκόπηση (context του kubectl, διακομιστής API, έκδοση Kubernetes, αποθήκη εικόνων, worker και οι πόροι τους, δίκτυο κόμβων), πίνακα Κόμβοι και Επιθεώρηση για τα ακατέργαστα δεδομένα των κόμβων. Η γραμμή εργαλείων έχει Περιήγηση στους πόρους και το μενού «Περισσότερα» έχει Εγγραφή kubeconfig, Αντιγραφή εντολής context του kubectl και Διαγραφή.

Οι κόμβοι του cluster είναι κοντέινερ, αλλά τους διαχειρίζεται το container cluster. Το Gantry απενεργοποιεί την έναρξη, τη διακοπή, την επανεκκίνηση, την αφαίρεση και τη μετονομασία για έναν κόμβο και σας λέει γιατί, και τα «Έναρξη όλων» και «Διακοπή όλων» παραλείπουν τους κόμβους. Στο CLI 1.7 το CLI κρύβει επίσης τους κόμβους από το container list. Τα cluster που δημιουργήθηκαν με CLI 1.6 ή παλαιότερο δεν εμφανίζονται στη λίστα της 1.7· αφαιρέστε τα με container cluster delete --name <name>.

Περιήγηση στο cluster

Κάντε κλικ στην Περιήγηση στους πόρους σε ένα cluster σε εκτέλεση ή ανοίξτε το Kubernetes στην πλαϊνή στήλη. Η ενότητα δεν χρειάζεται host και εμφανίζει κάθε context του kubeconfig· τα context των cluster του apple/container εμφανίζονται πρώτα. Επιλέξτε έναν χώρο ονομάτων ή όλους τους χώρους ονομάτων και, στη συνέχεια, ένα είδος: pod, deployment, StatefulSet, DaemonSet, υπηρεσίες, Ingress, ConfigMap, μυστικά, κόμβους ή συμβάντα.

  • Pod: αρχεία καταγραφής με παρακολούθηση, tail και το προηγούμενο κοντέινερ· shell στο pod· προώθηση θύρας στο 127.0.0.1.
  • Φόρτοι εργασίας: κλιμάκωση deployment και StatefulSet· επανεκκίνηση rollout.
  • Μυστικά: οι τιμές είναι κρυφές στη λίστα και στο YAML μέχρι να κάνετε κλικ στην «Εμφάνιση».
  • Εφαρμογή YAML: επικολλήστε ένα manifest ή ανοίξτε ένα αρχείο· τα σφάλματα εμφανίζονται στο φύλλο.

Ο περιηγητής εκτελεί το kubectl. Αν το Gantry δεν το βρει, η ενότητα εμφανίζει το brew install kubectl με ένα κουμπί που το εκτελεί. Ένας εγγενής πελάτης Kubernetes που δεν χρειάζεται kubectl είναι υπό ανάπτυξη.

Σύνδεση του kubectl

Το CLI προσθέτει στο ~/.kube/config ένα context με το όνομα του cluster όταν το δημιουργεί. Χρησιμοποιήστε την Αντιγραφή εντολής context του kubectl στο Gantry ή πληκτρολογήστε τη:

Shell
kubectl --context dev get nodes

Για να κρατήσετε το cluster σε δικό του αρχείο, χρησιμοποιήστε την Εγγραφή kubeconfig. Το Gantry εκτελεί το container cluster write-config· η προεπιλεγμένη διαδρομή είναι ~/.kube/<name>.kubeconfig.

Χρήση τοπικών εικόνων στο cluster

Στο CLI 1.7, ενεργοποιήστε τη Χρήση τοπικών εικόνων όταν δημιουργείτε το cluster. Προσθέτει το --shared-image-store, ώστε οι κόμβοι να μπορούν να εκτελούν με το όνομά της οποιαδήποτε εικόνα δομείτε ή λαμβάνετε με το container, χωρίς μητρώο. Η ρύθμιση ορίζεται κατά τη δημιουργία και δεν αλλάζει. Αφού δομήσετε ξανά μια ετικέτα, χρησιμοποιήστε imagePullPolicy: Always ή νέα ετικέτα. Τα privileged pod μπορούν να διαβάσουν κάθε εικόνα της τοπικής σας αποθήκης, γι' αυτό κρατήστε τη ρύθμιση για τοπική ανάπτυξη.

Shell
container build -t myapp:dev .
kubectl --context dev create deployment myapp --image=myapp:dev

Στο CLI 1.5 και 1.6, κάντε δεξί κλικ στην εικόνα στις Εικόνες και επιλέξτε Φόρτωση στο cluster. Το Gantry εκτελεί το container cluster load-image, που αντιγράφει την εικόνα στο containerd κάθε κόμβου. Το CLI 1.7 αφαίρεσε αυτή την εντολή, οπότε εκεί το Gantry κρύβει την ενέργεια.

Shell
container cluster load-image --name dev myapp:dev

Όταν οι υπηρεσίες cluster δεν απαντούν

Αν μια εντολή cluster αποτύχει με cluster service unavailable, το Gantry ελέγχει πώς είναι εγκατεστημένο το CLI. Για μια έκδοση Homebrew χωρίς τα plugin cluster εμφανίζει μήνυμα ότι της λείπουν οι υπηρεσίες cluster και σύνδεσμο Λήψη προγράμματος εγκατάστασης… προς το υπογεγραμμένο πακέτο. Σε άλλες περιπτώσεις, το Gantry προσφέρει Επανεκκίνηση υπηρεσιών….

Επιλογή CNI

Η προεπιλογή είναι το ενσωματωμένο manifest του kindnet. Επιλέξτε Προσαρμοσμένο manifest για να εγκαταστήσετε το δικό σας CNI από αρχείο, για παράδειγμα Calico ή Cilium. Επιλέξτε Κανένα για να εγκαταστήσετε μόνοι σας ένα CNI αργότερα· μέχρι τότε οι κόμβοι μένουν NotReady.

Cluster από πράκτορες AI

Ο διακομιστής MCP του Gantry έχει list_clusters, create_cluster και delete_cluster, ώστε ένας πράκτορας όπως το Claude Code να μπορεί να φτιάξει ένα προσωρινό cluster για μια δοκιμή και να το αφαιρέσει μετά.

Προσθήκη του διακομιστή MCP του Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Περισσότερα για το apple/container

Για οδηγό βήμα προς βήμα από το τερματικό, διαβάστε Kubernetes σε Mac με το Apple container. Διαβάστε τον οδηγό apple/container για κάθε εντολή του container και τη λειτουργία της στο Gantry ή δείτε πώς συγκρίνεται το Gantry με τα Docker Desktop, OrbStack και Podman Desktop.

Ερωτήσεις και απαντήσεις

Υποστηρίζει το Apple container το Kubernetes;

Ναι. Το CLI container δημιουργεί cluster Kubernetes των οποίων οι κόμβοι τρέχουν ως κοντέινερ: container cluster στο CLI 1.6.1 και 1.7, container k8s στο CLI 1.5.0 έως 1.6.0. Το Gantry προσθέτει GUI σε αυτό.

Υποστηρίζει το Gantry το container cluster;

Ναι. Το Gantry εμφανίζει, δημιουργεί και διαγράφει cluster σε host apple/container, δείχνει τους κόμβους τους, γράφει το kubeconfig και ανοίγει το cluster στον περιηγητή Kubernetes. Στο CLI 1.7 ορίζει επίσης το μέγεθος των worker και ενεργοποιεί την κοινή αποθήκη εικόνων. Χρησιμοποιεί cluster ή k8s ανάλογα με την έκδοση του CLI σας.

Πώς χρησιμοποιώ το kubectl με ένα cluster του apple/container;

Όταν το CLI δημιουργεί ένα cluster, προσθέτει στο ~/.kube/config ένα context kubeconfig με το όνομα του cluster. Εκτελέστε kubectl --context <name> get nodes. Για ξεχωριστό αρχείο, χρησιμοποιήστε την Εγγραφή kubeconfig στο Gantry· η προεπιλεγμένη διαδρομή είναι ~/.kube/<name>.kubeconfig.

Πώς φορτώνω μια τοπική εικόνα στο cluster χωρίς μητρώο;

Στο CLI 1.7, δημιουργήστε το cluster με τη Χρήση τοπικών εικόνων (--shared-image-store). Τα pod εκτελούν τότε με το όνομά τους τις εικόνες που δομείτε ή λαμβάνετε με το container. Στο CLI 1.5 και 1.6, κάντε δεξί κλικ στην εικόνα στις «Εικόνες» και επιλέξτε Φόρτωση στο cluster· το Gantry εκτελεί το container cluster load-image. Το CLI 1.7 αφαίρεσε το load-image.

Μπορώ να δημιουργήσω cluster με πολλούς κόμβους;

Ναι. Ορίστε τον αριθμό των worker στο φύλλο δημιουργίας· τα worker απαιτούν CLI 1.6.0 ή νεότερο. Στο CLI 1.7 ορίζετε επίσης τις CPU και τη μνήμη των worker χωριστά από το control plane.

Μπορώ να χρησιμοποιήσω δικό μου CNI, όπως Calico ή Cilium;

Ναι. Επιλέξτε Προσαρμοσμένο manifest και διαλέξτε το αρχείο manifest ή επιλέξτε Κανένα και εφαρμόστε μόνοι σας ένα CNI αφού ξεκινήσει το cluster. Οι κόμβοι μένουν NotReady μέχρι να τρέξει ένα CNI. Το Κανένα απαιτεί CLI 1.6.0 ή νεότερο. Το προεπιλεγμένο CNI είναι το ενσωματωμένο manifest του kindnet.

Γιατί το Gantry λέει ότι οι υπηρεσίες cluster δεν είναι διαθέσιμες;

Οι υπηρεσίες του container δεν απάντησαν σε μια εντολή cluster. Αν το CLI σας είναι έκδοση Homebrew χωρίς τις υπηρεσίες cluster, το Gantry το αναφέρει και δίνει σύνδεσμο προς το υπογεγραμμένο πρόγραμμα εγκατάστασης στη σελίδα εκδόσεων του apple/container. Διαφορετικά, προσφέρει Επανεκκίνηση υπηρεσιών.

Χρειάζομαι το kubectl για να χρησιμοποιήσω το cluster στο Gantry;

Προς το παρόν, ναι: ο περιηγητής Kubernetes του Gantry εκτελεί το kubectl. Αν δεν είναι εγκατεστημένο, ο περιηγητής εμφανίζει την εντολή brew install kubectl και μπορεί να την εκτελέσει για εσάς. Ένας εγγενής πελάτης Kubernetes που καταργεί αυτό το βήμα είναι υπό ανάπτυξη.

Gantry/Analyser les images

Rechercher des vulnérabilités dans les images de conteneurs sur Mac

Trivy et Grype sont des scanners gratuits et open source qui comparent les paquets d'une image à des bases de vulnérabilités connues. Ils lisent directement les images Docker. L'outil container d'Apple n'a ni commande d'analyse ni socket Docker : il faut donc d'abord enregistrer l'image. Ce guide montre les deux méthodes, comment lire les résultats, comment écrire un SBOM et comment lancer l'analyse depuis Gantry.

En bref. Exécutez brew install trivy grype. Sur Docker, exécutez trivy image app:dev. Sur Apple container, enregistrez l'image avec container image save --platform linux/arm64 -o app.tar app:dev, décompressez-la avec tar -xf app.tar -C app-img et analysez le dossier : trivy image --input app-img ou grype oci-dir:app-img. Les deux outils refusent le fichier tar lui-même.

Installer un scanner

Installez un scanner ou les deux avec Homebrew. Chacun télécharge sa base de vulnérabilités lors de la première analyse, ce qui prend une minute.

Terminal
brew install trivy grype

Nous avons vérifié les commandes de ce guide avec Trivy 0.76.2, Grype 0.121.3 et container 1.7.1. Gantry nécessite Trivy 0.50.0 ou Grype 0.74.0 ou ultérieur.

Analyser une image Docker

Avec un moteur Docker (Docker Desktop, OrbStack ou Colima), les deux outils lisent une image locale par son nom via le socket Docker :

Terminal
trivy image app:dev
grype app:dev

Analyser une image Apple container

Enregistrez l'image dans une archive OCI et décompressez-la dans un dossier. Passez --platform : quand le stockage d'images ne contient que certaines plateformes d'une image, container image save échoue sans cette option.

Terminal
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Analysez ensuite le dossier. Trivy le lit avec --input, Grype avec le préfixe oci-dir: :

Terminal
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Attention
Ne passez pas le fichier .tar. L'archive de container image save commence par l'entrée ./ : Trivy signale « file manifest.json not found in tar », et Grype la rejette comme « potential path traversal attack ». Le dossier décompressé fonctionne avec les deux.

Lire les résultats

  • Gravité : Critique, Élevée, Moyenne, Faible ou Inconnue. Commencez par Critique et Élevée. --severity HIGH,CRITICAL limite la sortie de Trivy.
  • Version installée et version corrigée : s'il existe une version corrigée, mettez à jour l'image de base ou le paquet, puis reconstruisez. trivy --ignore-unfixed et grype --only-fixed masquent les résultats sans correctif.
  • « won't fix » : la distribution a décidé de ne pas corriger le paquet dans cette version. Utilisez une image de base plus récente, ou acceptez le risque.
  • Deux outils, deux bases : Trivy et Grype donnent souvent des chiffres différents. Aucun n'a tort ; ils utilisent des sources différentes.

Exporter un SBOM

Une nomenclature logicielle (SBOM) liste tous les paquets de l'image. Trivy écrit du CycloneDX et du SPDX ; Syft, l'outil compagnon de Grype, écrit aussi les deux.

Terminal
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Faire échouer un build en cas de résultats graves

Dans un script, laissez le scanner définir le code de sortie. Grype se termine avec un code non nul quand il existe un résultat de la gravité indiquée ou supérieure ; avec Trivy, utilisez --exit-code 1 --severity HIGH,CRITICAL.

Terminal
grype oci-dir:python-img --fail-on high
echo $?

Analyser depuis Gantry

Gantry 0.29.0 fait ces étapes pour vous. Choisissez Rechercher des vulnérabilités… dans le menu de l'image ou dans la barre d'outils du détail de l'image.

  • Gantry trouve Trivy ou Grype dans GANTRY_TRIVY ou GANTRY_GRYPE, dans le PATH, ou dans /opt/homebrew/bin et /usr/local/bin. Trivy est utilisé par défaut quand les deux sont installés. Sans scanner, la feuille affiche les commandes Homebrew.
  • Sur apple/container, Gantry enregistre l'image avec --platform, la décompresse et analyse le dossier. Sur Docker en local, il analyse une archive enregistrée. Sur Docker via SSH, il analyse la copie du tag dans le registre.
  • Les résultats sont regroupés par gravité, avec un symbole et un mot, pas seulement une couleur. Chaque ligne affiche l'identifiant avec un lien, le paquet, la version installée et la version corrigée. Un filtre retrouve un paquet ou un identifiant.
  • Exporter le SBOM écrit du CycloneDX (les deux outils) ou du SPDX (Trivy).
  • Arrêter ou la fermeture de la feuille arrête le scanner et supprime les fichiers temporaires.

Questions et réponses

Comment rechercher des vulnérabilités dans une image Apple container ?

Enregistrez-la avec container image save --platform linux/arm64 -o app.tar app:dev, décompressez-la avec tar -xf app.tar -C app-img, puis exécutez trivy image --input app-img ou grype oci-dir:app-img. Gantry fait ces étapes avec Rechercher des vulnérabilités….

Pourquoi Trivy ou Grype échoue-t-il sur l'archive de container image save ?

L'archive commence par l'entrée ./. Trivy n'y trouve ni manifest.json ni index.json, et Grype traite l'entrée comme une traversée de répertoire. Décompressez l'archive et analysez le dossier.

Trivy ou Grype : lequel utiliser ?

Les deux sont gratuits et open source. Trivy trouve aussi les secrets et les erreurs de configuration, et écrit du SPDX ; Grype est léger et centré sur les paquets. Ils utilisent des bases différentes : lancer les deux trouve davantage. Gantry utilise Trivy quand les deux sont installés.

Gantry installe-t-il les scanners ?

Non. Installez-les avec brew install trivy grype. Gantry cherche dans le PATH, /opt/homebrew/bin et /usr/local/bin, ou dans GANTRY_TRIVY et GANTRY_GRYPE.

Faut-il Docker Scout ou un compte Docker pour analyser des images ?

Non. Trivy et Grype fonctionnent sans compte, sur les images Docker comme sur les images Apple container.

Gantry/Kubernetes su apple/container

Kubernetes su Apple container

apple/container può eseguire un cluster Kubernetes i cui nodi sono container sul tuo Mac. Gantry ne è la GUI: crea un cluster, guarda i nodi avviarsi, collega kubectl e carica le tue immagini locali, senza lunghe righe di comando container cluster.

In breve. Su un host apple/container, la sezione Cluster di Gantry crea ed elimina cluster Kubernetes con container cluster (CLI 1.6.1) o container k8s (CLI dalla 1.5.0 alla 1.6.0). Supporta più worker, un CNI personalizzato, una vista dei nodi, kubeconfig e contesto kubectl, e Carica nel cluster per le immagini locali.

Requisiti

  • Un Mac con chip Apple, macOS 26 e Gantry (brew install --cask getgantry/tap/gantry).
  • La CLI container 1.5.0 o successiva; si consiglia la 1.6.1. I worker e il CNI Nessuno richiedono la 1.6.0 o successiva.
  • kubectl, se vuoi usare il cluster dal terminale.

Crea un cluster

  1. Seleziona il tuo host apple/container e apri Cluster nella barra laterale.
  2. Avvia la creazione di un nuovo cluster e compila le opzioni qui sotto.
  3. Crealo. L'elenco mostra il nuovo cluster con l'avanzamento in tempo reale. Annulla interrompe la creazione ed elimina i nodi già creati.
OpzioneFlag della CLINote
Nome--nameÈ anche il nome del contesto kubeconfig
Worker--workersNumero di nodi worker. CLI 1.6.0+
CPU--cpusPer nodo
Memoria--memoryPer nodo, per esempio 4G
Immagine dei nodi--node-imageSe vuoto, resta il valore predefinito della CLI
CNI--cniPredefinito (kindnet incluso), Nessuno (NONE, CLI 1.6.0+) o percorso di un manifest personalizzato

Lo stesso comando nella CLI:

Shell
container cluster create --name dev --workers 2 --cpus 2 --memory 4G

Nodi e dettagli del cluster

L'elenco dei cluster mostra ogni cluster con i suoi nodi: ruolo, stato e indirizzo. La vista di dettaglio ha una Panoramica (contesto kubectl, server API, worker, rete dei nodi), una tabella Nodi, Ispeziona per i dati grezzi dei nodi e le azioni Scrivi kubeconfig, Copia comando contesto kubectl ed Elimina.

Collega kubectl

Quando crea il cluster, la CLI aggiunge a ~/.kube/config un contesto con il nome del cluster. Usa Copia comando contesto kubectl in Gantry, oppure digitalo:

Shell
kubectl --context dev get nodes

Per tenere il cluster in un file a parte, usa Scrivi kubeconfig. Gantry esegue container cluster write-config; il percorso predefinito è ~/.kube/<name>.kubeconfig.

Carica immagini locali nel cluster

Crea o scarica un'immagine sull'host apple/container, poi fai clic destro su di essa in Immagini e scegli Carica nel cluster. Gantry esegue container cluster load-image, che copia l'immagine nel containerd di ogni nodo. Per lo sviluppo locale non serve un registro.

Shell
container cluster load-image --name dev myapp:dev

Scegli un CNI

Il predefinito è il manifest kindnet incluso. Scegli Manifest personalizzato per installare un tuo CNI da file, per esempio Calico o Cilium. Scegli Nessuno per installare tu un CNI in seguito; fino ad allora, i nodi restano NotReady.

Cluster gestiti dagli agenti AI

Il server MCP di Gantry offre list_clusters, create_cluster e delete_cluster, così un agente come Claude Code può creare un cluster temporaneo per un test e rimuoverlo dopo.

Aggiungi il server MCP di Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Domande e risposte

Apple container supporta Kubernetes?

Sì. La CLI container crea cluster Kubernetes i cui nodi girano come container: container cluster nella CLI 1.6.1, container k8s nelle CLI dalla 1.5.0 alla 1.6.0. Gantry aggiunge a tutto questo una GUI.

Gantry supporta container cluster?

Sì. Gantry elenca, crea ed elimina cluster sugli host apple/container, ne mostra i nodi, scrive il kubeconfig, copia il comando del contesto kubectl e carica immagini locali in un cluster. Usa cluster o k8s in base alla versione della tua CLI.

Come si usa kubectl con un cluster apple/container?

Quando la CLI crea un cluster, aggiunge a ~/.kube/config un contesto kubeconfig con il nome del cluster. Esegui kubectl --context <name> get nodes. Per tenere un file separato, usa Scrivi kubeconfig in Gantry; il percorso predefinito è ~/.kube/<name>.kubeconfig.

Come si carica un'immagine locale nel cluster senza registro?

In Gantry, fai clic destro sull'immagine in Immagini e scegli Carica nel cluster. Gantry esegue container cluster load-image, che copia l'immagine nel containerd di ogni nodo.

Si può creare un cluster con più nodi?

Sì. Imposta il numero di worker nel pannello di creazione. I worker richiedono la CLI 1.6.0 o successiva.

Posso usare un mio CNI, come Calico o Cilium?

Sì. Scegli Manifest personalizzato e seleziona il file del manifest, oppure scegli Nessuno e applica tu un CNI dopo l'avvio del cluster. I nodi restano NotReady finché non è attivo un CNI. Nessuno richiede la CLI 1.6.0 o successiva. Il CNI predefinito è il manifest kindnet incluso.

Gantry/Sa Docker Desktop-a

Prelazak sa Docker Desktop-a na Apple container

Apple-ov alat container pokreće iste OCI slike kao Docker, pa se većina vašeg rada prenosi uz nekoliko izmena u komandama. Ovaj vodič upoređuje Docker i container, prenosi slike i volumene i navodi nedostatke koje treba da znate pre prelaska.

Ukratko. Instalirajte potpisani paket container, zamenite docker sa container za run, build, logs, exec i images, kopirajte imenovane volumene preko tar datoteke i otvorite svoj docker-compose.yml u Gantry-ju, jer CLI nema compose. Dok isprobavate, Docker Desktop može da ostane instaliran.

Šta se menja

  • Jedna VM po kontejneru. Docker Desktop pokreće sve kontejnere u jednoj Linux VM. apple/container pokreće malu VM za svaki kontejner, pa svaki dobija sopstvenu IP adresu na vašem Mac-u.
  • Iste slike i registri. Slike su OCI slike; povlačite ih sa Docker Hub-a, GHCR-a i privatnih registara kao i pre.
  • Bez licencne naknade. apple/container je pod licencom Apache 2.0. Docker Desktop zahteva plaćeni plan u organizacijama sa 250 ili više zaposlenih ili sa 10 miliona dolara ili više prihoda.
  • Samo Apple silicon i macOS 26. Na Intel Mac računarima ostanite na Docker mehanizmu.

Većina zastavica za run je ista: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus i -m. Da biste pretvorili dugu komandu, nalepite je u Gantry: pogledajte Kreiranje kontejnera iz docker run komande.

    Prenos slika

Slike iz registra: ponovo ih povucite komandom container image pull. Lokalne slike koje postoje samo u Docker-u: sačuvajte ih u arhivu i učitajte je. container image load čita OCI arhive, a novije verzije Docker-a komandom docker save zapisuju OCI raspored. Ako učitavanje ne uspe, pošaljite sliku u registar i povucite je.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Prenos imenovanih volumena

Docker čuva podatke volumena unutar svoje VM. Kopirajte svaki volumen u tar datoteku pomoću kratkotrajnog kontejnera, a zatim ga raspakujte u novi apple/container volumen:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Imenovani volumen u apple/container-u je retka (sparse) ext4 slika diska, podrazumevano najviše 512 GB. Drugu veličinu podesite opcijom --opt size=20g. Montirane fascikle sa vašeg Mac-a rade kao u Docker-u: -v ~/project:/app.

    Compose datoteke

container CLI nema komandu compose. Umesto toga otvorite docker-compose.yml u Gantry-ju (iz Finder-a, preko Datoteka ▸ Otvori Compose datoteku… ili prevlačenjem). Gantry gradi servise sa build:, kreira mrežu projekta i imenovane volumene i pokreće servise redosledom iz depends_on. Servisi se međusobno dosežu po imenu servisa preko DNS alijasa mreže.

    Mreže i portovi
  • -p 8080:80 objavljuje port na localhost, kao u Docker-u.
  • Svaki kontejner ima i sopstvenu IP adresu. Kreirajte lokalni DNS domen komandom sudo container system dns create test i pokrećite kontejnere uz --dns-domain test: dobijaju imena kao što je web.test.
  • container network create pravi korisničke mreže; kontejneri na istoj mreži dosežu jedni druge.
  • Ne postoji režim --network host, none ni container:.
    Šta nedostaje
  • Nema Docker Engine API-ja. Alati koji komuniciraju sa /var/run/docker.sock, kao što su Testcontainers, Docker SDK-ovi ili Dev Containers, ne vide apple/container.
  • Nema smernica ponovnog pokretanja. --restart nije dostupan; kontejner se ne pokreće ponovo sam od sebe.
  • Nema Compose-a u CLI-ju. Gantry pokreće Compose datoteke: pogledajte Compose datoteke.
  • Nema proširenja za Docker Desktop.
  • Samo celi CPU-ovi: --cpus 0.5 ne radi.
  • Kubernetes radi drugačije: koristite container cluster, pogledajte Kubernetes na Mac-u.
    Zadržite oba tokom prelaska

Gantry upravlja apple/container-om i bilo kojim Docker mehanizmom (Docker Desktop, OrbStack, Colima ili Docker preko SSH-a) u jednoj bočnoj traci. Prenosite jedan po jedan projekat, a Docker zadržite za alate kojima je potreban njegov API. Kada vam više ne treba, možete da uklonite Docker Desktop.

Pitanja i odgovori

Može li Apple container da zameni Docker Desktop?

Za pokretanje, izgradnju i povlačenje kontejnera na Apple silicon-u, da. Nema Docker Engine API, smernice ponovnog pokretanja, proširenja ni komandu compose. Gantry dodaje Compose datoteke i GUI.

Da li Docker slike rade sa Apple container-om?

Da. apple/container koristi standardne OCI slike i povlači ih iz istih registara. arm64 slike rade nativno; amd64 slike rade preko Rosetta-e uz --arch amd64.

Da li docker compose radi sa Apple container-om?

Ne iz CLI-ja: ne postoji container compose. Gantry čita docker-compose.yml i umesto vas pokreće servise na apple/container-u.

Mogu li da koristim Docker Desktop i Apple container istovremeno?

Da. Ne dele slike ni volumene, ali mogu da rade jedan pored drugog. Gantry prikazuje oba u jednom prozoru.

Da li je Apple container besplatan za komercijalnu upotrebu?

Da. apple/container je otvorenog koda pod licencom Apache 2.0, a Gantry je pod licencom MIT. Oba su besplatna za preduzeća bilo koje veličine.

Gantry/Z docker run

Kontener z polecenia docker run

Większość plików README podaje wiersz docker run. Gantry odczytuje ten wiersz i wypełnia formularz Nowy kontener, dla hosta Docker lub dla narzędzia container od Apple. Ten przewodnik pokazuje, jak to zrobić i jak przekształcić polecenie ręcznie.

W skrócie. W Gantry otwórz Nowy kontener, wybierz Wklej polecenie…, wklej wiersz docker run i kliknij Wypełnij formularz. Gantry wymienia każdą flagę, której nie może użyć, wraz z powodem. W CLI większość flag jest taka sama: zamień docker run na container run i usuń --restart.

Wklejanie polecenia w Gantry

  1. Wybierz host: host Docker lub host apple/container.
  2. Otwórz Kontenery i kliknij Nowy kontener.
  3. Kliknij Wklej polecenie… i wklej wiersz. Końce wierszy z \, cudzysłowy, znak zachęty $ i sudo nie przeszkadzają.
  4. Przeczytaj podgląd: obraz, flagi, których Gantry nie może użyć, uwagi i ostrzeżenia dla tego hosta.
  5. Kliknij Wypełnij formularz, sprawdź wartości i utwórz kontener.

Gantry odczytuje docker run, docker container run, docker create, podman run i container run. Tekst po &&, ||, ; lub | jest pomijany, z uwagą.

Gantry zna około 80 innych flag Dockera: poprawnie pomija ich wartości i wymienia je jako nieużyte, więc nic nie ginie bez uwagi.

    Ostrzeżenia dla hostów apple/container

Niektóre opcje Dockera nie istnieją w apple/container. Gantry ostrzega o nich i pomija je w żądaniu utworzenia:

  • zasady ponownego uruchamiania (--restart);
  • ułamki procesora, takie jak --cpus 0.5;
  • tryby sieci host, none i container:;
  • porty bez portu hosta, takie jak -p 80.

Na hoście Docker Gantry ostrzega o opcjach apple/container: domenie DNS i opcjach jądra.

    Ręczne przekształcenie docker run na container run

W CLI większość flag pozostaje taka sama. Przykład z Redis:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

zmienia się w:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Najpierw utwórz nazwany wolumin poleceniem container volume create. Usuń --restart i zaokrąglij --cpus do liczby całkowitej. --platform działa jak w Dockerze.

    Kopiowanie kontenera jako polecenia

Działa to też w drugą stronę. Kliknij kontener prawym przyciskiem lub użyj menu Więcej i wybierz Kopiuj jako polecenie: Gantry zapisze wiersz docker run lub container run. Pomija wartości domyślne obrazu, takie jak jego środowisko i polecenie, więc wiersz pozostaje krótki. Działa to także dla zatrzymanych kontenerów.

    Zapisywanie jako przepis

W arkuszu Nowy kontener otwórz Przepisy i wybierz Zapisz jako przepis…. Następnym razem Wypełnij z przepisu da ten sam formularz na dowolnym hoście. Przepisy są w ~/Library/Application Support/Gantry/recipes.json, więc możesz zrobić ich kopię zapasową lub je udostępnić.

    Ograniczenia
  • Gantry zachowuje ścieżkę --env-file, ale nie odczytuje pliku, i nie odczytuje Twojej powłoki dla -e KEY bez wartości.
  • Montowania tmpfs i anonimowe woluminy z --mount są oznaczane jako nieobsługiwane.
  • Dwa porty dla tego samego portu kontenera (-p 8080:80 -p 8081:80) wypełniają formularz, ale formularz potem odrzuca duplikat.

Pytania i odpowiedzi

Jak przekształcić docker run na container run?

Zamień docker run na container run. -d, -p, -e, -v, --name, --rm, -it, -w i --entrypoint pozostają takie same. Usuń --restart i używaj całych procesorów. Możesz też wkleić wiersz w Gantry, a formularz wypełni się sam.

Czy Gantry może zaimportować polecenie docker run?

Tak. Wklej polecenie… w arkuszu Nowy kontener odczytuje docker run, docker create, podman run i container run i wypełnia formularz.

Co dzieje się z flagami, których Gantry nie obsługuje?

Są wymienione w podglądzie wraz z powodem i pozostają w formularzu w sekcji Z wklejonego polecenia, więc możesz je sprawdzić później.

Czy mogę zamienić działający kontener z powrotem na polecenie docker run?

Tak. Kopiuj jako polecenie w menu kontenera zapisuje wiersz docker run lub container run dla tego kontenera.

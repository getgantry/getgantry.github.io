Gantry/Kubernetes på Mac

Kjør Kubernetes på en Mac med Apple container

Apples verktøy container kan opprette en lokal Kubernetes-klynge med én kommando. Hver node er en lett virtuell maskin på Macen din. Denne guiden går fra en tom Mac til en deployment som kjører, først i terminalen og deretter i Gantry.

Kort fortalt. Installer den signerte container 1.7.1-pakken, kjør container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, bygg et image med container build og kjør det i klyngen etter navn. Gantry viser den samme klyngen i et vindu: noder, pods, logger, et skall og portvideresendinger.

Dette trenger du

  • En Mac med Apple-chip og macOS 26 eller nyere.
  • container-CLI 1.7.1 fra den signerte .pkg-filen på utgivelsessiden til apple/container. Homebrew-bygget av 1.7.1 har ikke klyngetjenestene, så container cluster feiler med cluster service unavailable.
  • Omtrent 6 GB ledig minne for eksempelet nedenfor: tre noder med 2 GB hver.
  • kubectl hvis du vil bruke klyngen fra terminalen (brew install kubectl).

Start tjenestene én gang etter at du har installert pakken:

Terminal
container system start

Opprett klyngen

Denne kommandoen lager en klynge med navnet dev med én kontrollplannode og to arbeidsnoder. Hver node får 2 CPU-er og 2 GB minne:

Terminal
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M angir størrelsen på en gruppe arbeidsnoder. Gjenta det for grupper med ulik størrelse. Uten --workers er én node både kontrollplan og arbeidsnode.
  • --cpus og --memory angir størrelsen på kontrollplanet. Standard er en firedel av CPU-ene og minnet på Macen din, minst 2 CPU-er og 2 GB.
  • --shared-image-store lar nodene bruke de lokale imagene dine (se nedenfor). Du kan ikke endre det senere: slett klyngen og opprett den på nytt.
  • --cni ./calico.yaml installerer din egen CNI i stedet for den medfølgende kindnet; --cni NONE installerer ingen.

CLI-en legger til en kontekst med navnet dev i ~/.kube/config. Sjekk nodene:

Terminal
container cluster list --nodes
kubectl --context dev get nodes

Kjør et lokalt image uten register

Med --shared-image-store kan nodene kjøre alle images i det lokale container-image-lageret ditt. Bygg et image og bruk det etter navn:

Terminal
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Merk
Når du har bygd den samme taggen på nytt, kjører du kubectl rollout restart med imagePullPolicy: Always, eller du bruker en ny tagg. Med IfNotPresent beholder en node kopien den allerede har. Alt som har root på en node, kan lese alle images i det lokale lageret ditt, også private images, så bruk det delte lageret bare til lokal utvikling.

På CLI 1.5 og 1.6 finnes det ikke noe delt lager. Bruk container cluster load-image der, eller Last inn i klynge i Gantry. CLI 1.7 fjernet load-image.

Åpne appen i en nettleser

Videresend en lokal port til deploymenten, og åpne deretter http://localhost:8080:

Terminal
kubectl --context dev port-forward deployment/hello 8080:80

Utforsk klyngen i Gantry

Gantry viser den samme klyngen uten kommandoer. Legg til apple/container-verten din, åpne Klynger og velg dev. Oversikten viser Kubernetes-versjonen, image-lageret, arbeidsnodene og CPU-ene og minnet deres. Klikk på Bla gjennom ressurser for å åpne delen Kubernetes i den konteksten.

  • Pods, deployments, StatefulSets, DaemonSets, services, ingresser, ConfigMaps, secrets, noder og hendelser, for ett navnerom eller alle.
  • Pod-logger med følging og hale, et skall i poden, og portvideresendinger med en liste der du kan stoppe dem.
  • Skalering, omstart av utrulling, sletting og Bruk YAML fra et innlimt manifest eller en fil.
  • Secret-verdier forblir maskert til du klikker på Vis.

Kubernetes-utforskeren kjører kubectl. Mangler det, viser Gantry brew install kubectl og kan kjøre kommandoen for deg. En nativ klient som ikke trenger kubectl, er under utvikling.

Du kan også opprette klyngen i Gantry: Klynger ▸ Ny klynge har trinnvelgere for kontrollplanet og arbeidsnodene og en Bruk lokale images-bryter. Mer på siden Kubernetes på apple/container.

Stopp og slett klyngen

Terminal
container cluster delete --name dev

Stopper kontrollplannoden, for eksempel etter container system stop, sletter du klyngen og oppretter den på nytt. Lag en midlertidig klynge med --rm for å fjerne nodene når de stopper.

Vanlige problemer

  • cluster service unavailable: CLI-en er Homebrew-bygget, eller tjenestene kjører ikke. Installer den signerte pakken, eller start tjenestene på nytt med container system stop og container system start. Gantry gir det samme rådet under Klynger.
  • En gammel klynge mangler i listen: CLI 1.7 viser ikke klynger som er opprettet med 1.6 eller eldre. Fjern en slik klynge med container cluster delete --name <name>.
  • Nodene forblir NotReady: du brukte --cni NONE. Bruk et CNI-manifest.
  • Du kan ikke stoppe en nodecontainer: dette er med vilje. container stop og delete avviser klyngenoder; bruk container cluster delete.

Slik står dette seg mot Docker Desktop og OrbStack

Docker Desktop har innebygd Kubernetes med kubeadm (én node) eller kind (flere noder), og OrbStack har en innebygd klynge med én node. container cluster kjører kubeadm på kindest/node-images, hver node i sin egen VM, med klynger med flere noder og delt image-lager. Se hele sammenligningen.

Spørsmål og svar

Kan jeg kjøre Kubernetes på en Mac uten Docker?

Ja. Apples container-CLI oppretter Kubernetes-klynger selv med container cluster create. Hver node kjører som en lett VM, og du trenger verken Docker, Docker Desktop, kind eller minikube.

Hvor mange noder kan en container cluster ha?

Ett kontrollplan og så mange arbeidsnoder som Macen din har CPU-er og minne til. Angi dem med --workers; på CLI 1.7 kan hver gruppe arbeidsnoder ha egne CPU-er og eget minne.

Hvordan bruker jeg et lokalt bygd image i klyngen?

Opprett klyngen med --shared-image-store (CLI 1.7), bygg imaget med container build -t name:tag . og bruk name:tag i pod-spesifikasjonen. Du trenger ikke noe register.

Hvilken Kubernetes-versjon bruker container cluster?

CLI 1.7.1 bruker node-imaget kindest/node:v1.35.5 som standard. Velg en annen versjon med --node-image, for eksempel docker.io/kindest/node:v1.34.11. Gantry viser versjonen i klyngeoversikten.

Finnes det et GUI for container cluster?

Ja. Gantry oppretter og sletter klynger, viser nodene og lar deg bla gjennom pods, deployments, services, logger og secrets i Kubernetes-delen. Det er gratis og har åpen kildekode.

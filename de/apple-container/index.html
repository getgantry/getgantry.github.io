Gantry/apple/container-Leitfaden

Apple container auf dem Mac: der komplette Leitfaden und die GUI

apple/container führt Linux-Container auf deinem Mac aus, jeden in einer eigenen leichtgewichtigen virtuellen Maschine. Es kommt als Befehlszeilentool. Gantry ist eine native macOS-GUI dafür. Dieser Leitfaden erklärt das Tool und seine Einrichtung und zeigt, welche Gantry-Funktion welchen container-Befehl abdeckt.

Kurz gesagt. Gantry ist eine kostenlose, quelloffene (MIT) macOS-App, die Apples container-Tool und Docker in einem Fenster verwaltet. Sie unterstützt die container-CLI 1.0 bis 1.7.1 (empfohlen) und zeigt nur die Funktionen, die deine CLI-Version unterstützt. Installiere sie mit brew install --cask getgantry/tap/gantry.

Was ist apple/container?

apple/container ist ein Open-Source-Tool von Apple, geschrieben in Swift, das Linux-Container auf dem Mac erstellt und ausführt. Docker Desktop führt alle Container in einer gemeinsamen Linux-VM aus; apple/container startet jeden Container in einer eigenen leichtgewichtigen virtuellen Maschine auf Basis von Apples Virtualization-Framework. Es nutzt standardmäßige OCI-Images und pullt und pusht daher bei denselben Registrys wie Docker.

  • Hardware: ein Mac mit Apple Silicon.
  • macOS: Apple unterstützt es unter macOS 26.
  • Oberfläche: nur die container-CLI. Es gibt keine Desktop-App und keinen compose-Befehl.
  • Netzwerk: Jeder Container bekommt eine eigene IP-Adresse auf deinem Mac, und lokale DNS-Domains geben Containern Namen wie web.test.

Warum eine GUI für apple/container?

Die CLI ist vollständig, aber im Alltag braucht man viele Befehle: container list, logs, stats, exec und für den Rest system, builder, registry, machine und cluster. Gantry bündelt sie in einem Fenster mit Live-Updates, sodass du den Zustand siehst, statt ihn abzufragen. Dazu kommt, was die CLI nicht hat: Compose-Dateien, Ausfall-Mitteilungen, eine Flottenansicht mit deinen Docker-Hosts und ein MCP-Server für KI-Agenten.

apple/container mit Gantry einrichten

  1. Installiere Gantry: brew install --cask getgantry/tap/gantry, und entferne dann das Quarantäne-Flag (siehe Installation).
  2. Installiere die container-CLI aus dem signierten .pkg auf der Release-Seite von apple/container. Fehlt sie oder ist sie älter als 1.0, zeigt Gantry ein Einrichtungsdialog mit den Schritten.
  3. Wähle in Gantry Host hinzufügen… und füge einen Apple Container-Host hinzu. Beim Verbinden werden die container-Dienste gestartet, falls sie gestoppt sind.
  4. Ist kein Standardkernel installiert, zeigt die Host-Übersicht ein Banner. Klicke darauf, um den empfohlenen Kernel zu installieren.
Achtung
Verwende das signierte Installationspaket, nicht den Homebrew-Build. Dem Homebrew-Build fehlen das Maschinen-Backend und in 1.7.1 die Cluster-Dienste, daher laufen container machine und container cluster damit nicht.

Was Gantry auf apple/container ergänzt

Kubernetes-Cluster

Erstelle Kubernetes-Cluster mit container cluster, lege die Größe der Worker fest, lass Pods deine lokalen Images verwenden, wähle das CNI und sieh jeden Node. Durchsuche den Cluster danach im Kubernetes-Browser von Gantry. Siehe Kubernetes auf apple/container und die Schritt-für-Schritt-Anleitung Kubernetes auf dem Mac ausführen.

Container-Maschinen und VS Code

Maschinen sind dauerhafte Linux-Umgebungen aus container machine. Gantry erstellt, startet, stoppt und löscht sie, legt die Standardmaschine fest, ändert CPUs und Arbeitsspeicher und öffnet eine Shell. Ab CLI 1.1 kann eine Maschine mit verschachtelter Virtualisierung (Apple Silicon M3 oder neuer) und einem eigenen Kernel starten. In VS Code öffnen verbindet sich über Remote-SSH mit einer laufenden Maschine; im Image der Maschine muss sshd laufen.

Docker Compose auf apple/container

Öffne eine docker-compose.yml aus dem Finder (Öffnen mit ▸ Gantry oder Schnellaktionen ▸ Compose Up in apple/container), über Ablage ▸ Compose-Datei öffnen… oder indem du sie auf das Fenster ziehst. Gantry baut build:-Dienste, erstellt das Projektnetzwerk und benannte Volumes und startet jeden Dienst in der Reihenfolge von depends_on mit den Standard-Labels com.docker.compose.*. Ist eine Standard-DNS-Domain gesetzt, erreichen sich die Dienste über Netzwerk-Aliasse per Dienstname.

Netzwerk-DNS-Aliasse und lokale Domains

Gantry übergibt Netzwerk-Aliasse an container als --network <name>,alias=…. Ohne Standard-DNS-Domain funktionieren nur vollqualifizierte Namen, und ein Subtree-Alias (mit führendem Punkt, etwa .gateway) funktioniert nur als exakter Alias. Mit einer Standard-Domain funktionieren auch Kurznamen. Gantry erstellt und löscht lokale DNS-Domains, legt die Standard-Domain fest und gibt neuen Containern einen Hostnamen nach dem Muster name.domain. Siehe Lokale DNS-Namen.

System: Dienste, Builder, Registrys, Kernel, Logs, Eigenschaften

Jeder apple/container-Host hat einen Bereich System. Er funktioniert auch, wenn der Host getrennt ist, sodass du gestoppte Dienste von dort aus starten kannst.

  • Status und Version: Client- und Serverversion, mit Warnung, wenn sie sich unterscheiden; Dienste starten, stoppen und neu starten; Host-Infos und Pfade.
  • Image-Builder: Status, Image, CPUs, Arbeitsspeicher und IP; Starten mit Optionen für CPU, Arbeitsspeicher und DNS; Stoppen; Löschen. Eine Karte meldet, wenn das Builder-Image veraltet ist, und erstellt den Builder neu.
  • Registry-Anmeldungen: auflisten, anmelden und abmelden. Das Passwort geht nur über stdin (--password-stdin) an die CLI, und Gantry speichert keine Kopie.
  • Kernel: den empfohlenen Kernel, eine Kernel-Datei oder ein tar-Archiv installieren, mit gestreamtem Fortschritt.
  • Dienst-Logs: live oder einmalig, über 5 Minuten bis 1 Tag, gefiltert nach Level, Dienst und Text.
  • Systemeigenschaften: Änderungen gehen in ~/.config/container/config.toml, mit einer Markierung für ausstehende Neustarts und der Taste Dienste neu starten. In CLI 1.7 haben Nameserver, Suchdomains und Optionen unter [container.dns] einen Listeneditor.

Commit, Festplatte trimmen und Dateien

Als Image committen nutzt container commit (CLI 1.6). Festplatte trimmen nutzt container clean (CLI 1.4) und erscheint auch als Zeile in „Speicherplatz freigeben“. Der Tab „Dateien“ lädt Dateien herunter und lässt dich sie mit container copy in den Finder ziehen (der Container muss gestartet sein); außerdem lädt er Dateien und Ordner hoch.

Labels, die = enthalten

container create lehnt einen Label-Wert ab, der = enthält, auch mit CLI 1.6.1. Gantry codiert solche Werte beim Erstellen des Containers und decodiert sie beim Zurücklesen – die Labels, die du setzt, sind die Labels, die du siehst.

MCP-Server und Kurzbefehle

Der mitgelieferte Server gantry-mcp gibt KI-Agenten auf apple/container-Hosts denselben Zugriff: Container, Images, Volumes, Netzwerke, Compose, Maschinen (list_machines, create_machine und mehr), Cluster (list_clusters, create_cluster, delete_cluster) und die apple_*-Systemtools für Dienste, Builder, Registrys (ohne Login-Tool), Eigenschaften, Logs und Kernel-Installation. App Intents ergänzen Aktionen für Kurzbefehle und Siri. Siehe KI-Agenten & MCP.

Gantry-MCP-Server hinzufügen
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container neben Docker

Gantry verwaltet apple/container-Hosts, den lokalen Docker-Daemon (Docker Desktop, OrbStack, Colima) und entfernte Docker-Hosts über SSH in einer Seitenleiste und einem Flotten-Dashboard. Du musst dich nicht für eine Runtime entscheiden. Einen Vergleich Funktion für Funktion findest du unter Gantry vs. Docker Desktop, OrbStack und Podman Desktop. Für den Umstieg lies Von Docker Desktop zu Apple container wechseln.

Fragen und Antworten

Was ist die beste GUI für Apple container?

Gantry ist eine kostenlose, quelloffene native macOS-GUI für apple/container. Sie bildet die container-CLI in einer Desktop-App ab: Container, Logs, Statistiken und Exec, dazu Kubernetes-Cluster, Maschinen, den Image-Builder, Registry-Anmeldungen, Kernel, Dienst-Logs und Systemeigenschaften. Die Tabelle auf dieser Seite listet jeden Befehl und die Gantry-Funktion, die ihn nutzt.

Hat Apple container eine GUI?

Apple liefert container nur als Befehlszeilentool aus. Gantry ist eine separate Open-Source-App, die ihm eine GUI gibt, direkt neben deinen Docker-Hosts.

Kann ich docker compose mit Apple container nutzen?

apple/container hat keinen compose-Befehl. Gantry liest eine docker-compose.yml, baut build:-Dienste, erstellt das Netzwerk und benannte Volumes und startet die Dienste in der Reihenfolge von depends_on. Dienstnamen werden über Netzwerk-DNS-Aliasse aufgelöst.

Wie öffne ich eine Container-Maschine in VS Code?

Starte die Maschine in Gantry und klicke auf In VS Code öffnen. Gantry öffnet sie über Remote-SSH, wie in Apples Beispiel container-machine-vscode. Im Image der Maschine muss sshd laufen.

Läuft Apple container auf Intel-Macs?

Nein. apple/container erfordert einen Mac mit Apple Silicon. Gantry läuft auch auf Intel-Macs, verwaltet dort aber nur Docker-Hosts.

Welche Version der container-CLI sollte ich installieren?

Gantry braucht 1.0 oder neuer und empfiehlt 1.7.1. Installiere es mit dem signierten Installationspaket von der Release-Seite von apple/container. Dem Homebrew-Build fehlen das Maschinen-Backend und in 1.7.1 die Cluster-Dienste, daher funktionieren container machine und container cluster damit nicht.

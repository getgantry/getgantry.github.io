Gantry/Vindo do Docker Desktop

Mudar do Docker Desktop para o Apple container

A ferramenta container da Apple executa as mesmas imagens OCI que o Docker, por isso a maior parte do seu trabalho passa com poucas alterações aos comandos. Este guia faz a correspondência entre o Docker e o container, muda imagens e volumes, e lista as limitações que deve conhecer antes de mudar.

Em resumo. Instale o pacote assinado do container, substitua docker por container para run, build, logs, exec e imagens, copie os volumes com nome através de um ficheiro tar e abra o seu docker-compose.yml no Gantry, porque a CLI não tem compose. Pode manter o Docker Desktop instalado enquanto experimenta.

O que muda

  • Uma VM por contentor. O Docker Desktop executa todos os contentores numa única VM Linux. O apple/container inicia uma pequena VM para cada contentor, por isso cada um recebe o seu próprio endereço IP no Mac.
  • As mesmas imagens e registos. As imagens são imagens OCI; descarrega-as do Docker Hub, do GHCR e de registos privados como antes.
  • Sem custos de licença. O apple/container é Apache 2.0. O Docker Desktop requer um plano pago em organizações com 250 ou mais trabalhadores ou com 10 milhões de USD ou mais de receita.
  • Apenas Apple silicon e macOS 26. Nos Mac com Intel, continue com um motor Docker.

A maioria das flags de run é igual: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus e -m. Para converter um comando longo, cole-o no Gantry: consulte Criar um contentor a partir de um comando docker run.

    Trazer as imagens

Imagens de um registo: descarregue-as novamente com container image pull. Imagens locais que só existem no Docker: guarde-as num arquivo e carregue-o. container image load lê arquivos OCI, e as versões recentes do Docker escrevem um layout OCI com docker save. Se o carregamento falhar, envie a imagem para um registo e descarregue-a.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Mudar os volumes com nome

O Docker guarda os dados dos volumes dentro da sua VM. Copie cada volume para um ficheiro tar com um contentor de curta duração e depois extraia-o para um novo volume do apple/container:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Um volume com nome no apple/container é uma imagem de disco ext4 esparsa, com um máximo de 512 GB por predefinição. Defina outro tamanho com --opt size=20g. As montagens de associação de pastas do Mac funcionam como no Docker: -v ~/project:/app.

    Ficheiros Compose

A CLI container não tem um comando compose. Em vez disso, abra o docker-compose.yml no Gantry (Finder, Ficheiro ▸ Abrir ficheiro Compose… ou arrastar e largar). O Gantry compila os serviços com build:, cria a rede do projeto e os volumes com nome, e inicia os serviços pela ordem de depends_on. Os serviços comunicam entre si pelo nome do serviço através de aliases DNS de rede.

    Redes e portas
  • -p 8080:80 publica uma porta em localhost, como no Docker.
  • Cada contentor tem também o seu próprio endereço IP. Crie um domínio DNS local com sudo container system dns create test e execute os contentores com --dns-domain test: recebem nomes como web.test.
  • container network create cria redes de utilizador; os contentores na mesma rede comunicam entre si.
  • Não existem os modos --network host, none nem container:.
    O que falta
  • Sem API do Docker Engine. As ferramentas que comunicam com /var/run/docker.sock, como Testcontainers, os SDK do Docker ou Dev Containers, não veem o apple/container.
  • Sem políticas de reinício. --restart não está disponível; um contentor não volta a arrancar sozinho.
  • Sem Compose na CLI. O Gantry executa ficheiros Compose: consulte Ficheiros Compose.
  • Sem extensões do Docker Desktop.
  • Apenas CPU inteiras: --cpus 0.5 não funciona.
  • O Kubernetes é diferente: utilize container cluster; consulte Executar Kubernetes num Mac.
    Manter os dois durante a mudança

O Gantry gere o apple/container e qualquer motor Docker (Docker Desktop, OrbStack, Colima ou Docker por SSH) numa única barra lateral. Mude um projeto de cada vez e mantenha o Docker para as ferramentas que precisam da sua API. Quando já não precisar dele, pode remover o Docker Desktop.

Perguntas e respostas

O Apple container pode substituir o Docker Desktop?

Para executar, compilar e descarregar contentores em Apple silicon, sim. Não tem a API do Docker Engine, políticas de reinício, extensões nem um comando compose. O Gantry acrescenta ficheiros Compose e uma GUI.

As imagens Docker funcionam com o Apple container?

Sim. O apple/container utiliza imagens OCI padrão e descarrega-as dos mesmos registos. As imagens arm64 são executadas nativamente; as imagens amd64 são executadas através do Rosetta com --arch amd64.

O docker compose funciona com o Apple container?

Não a partir da CLI: não existe container compose. O Gantry lê o docker-compose.yml e executa os serviços no apple/container por si.

Posso usar o Docker Desktop e o Apple container ao mesmo tempo?

Sim. Não partilham imagens nem volumes, mas podem ser executados lado a lado. O Gantry mostra os dois numa janela.

O Apple container é gratuito para uso comercial?

Sim. O apple/container é de código aberto com a licença Apache 2.0, e o Gantry tem licença MIT. Ambos são gratuitos para empresas de qualquer dimensão.

Gantry/Disc extern

Păstrați containerele și volumele pe un disc extern

Imaginile, containerele și volumele umplu repede un disc intern mic. Cu instrumentul container de la Apple puteți păstra aceste date pe un SSD extern: puneți acolo dosare individuale cu montări bind sau mutați întreaga rădăcină de date. Acest ghid arată ambele variante și cum deconectați discul fără daune.

Pe scurt. Formatați discul ca APFS. Pentru un singur proiect, montați un dosar prin bind: -v /Volumes/Fast/pg:/data. Pentru tot, opriți serviciile, copiați ~/Library/Application Support/com.apple.container pe disc cu cp -Rp și porniți serviciile de fiecare dată cu container system start --app-root /Volumes/Fast/container.

Unde sunt datele acum

apple/container păstrează toate datele într-un singur dosar, rădăcina aplicației (app root). Implicit, acesta este ~/Library/Application Support/com.apple.container, cu dosare pentru containere, conținutul imaginilor, snapshoturi, volume, kerneluri și rețele. Verificați calea și spațiul ocupat:

Terminal
container system status | grep appRoot
container system df

Alegeți și formatați discul

  • Folosiți un SSD pe USB-C sau Thunderbolt. Un hard disk clasic funcționează, dar containerele pornesc mai încet.
  • Formatați-l ca APFS (merge și Mac OS Extended). Nu folosiți exFAT, FAT sau NTFS: volumele sunt imagini de disc rare (sparse), iar aceste sisteme de fișiere nu au fișiere sparse și nici permisiuni Unix.
  • Nu folosiți un disc de rețea pentru rădăcina aplicației.
  • Dați discului un nume scurt, fără spații, de exemplu Fast. Calea este atunci /Volumes/Fast.

Varianta 1: datele proiectului pe disc, cu montări bind

O montare bind partajează un dosar de pe Mac cu containerul, iar dosarul poate fi pe orice disc. Este calea simplă de a ține datele mari, precum o bază de date sau fișiere de model, în afara discului intern:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Discul trebuie să fie conectat înainte de pornirea containerului. Imaginile și containerul însuși rămân pe discul intern.

Varianta 2: mutați toate datele apple/container pe disc

Astfel se mută imaginile, containerele, snapshoturile și volumele. Opriți mai întâi serviciile, ca niciun fișier să nu se modifice în timpul copierii:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Folosiți cp -Rp. În testul nostru pe macOS 27 (din APFS în APFS prin USB), a păstrat imaginile volumelor sparse și a păstrat atributele extinse. ditto a scris fiecare imagine sparse la dimensiunea completă, ceea ce poate umple discul. Păstrați dosarul vechi până când verificați că containerele, imaginile și volumele apar în liste.

Atenție
CLI-ul nu reține --app-root. Fiecare container system start fără această opțiune folosește din nou dosarul intern. Folosiți flagul de fiecare dată, de exemplu într-un alias de shell, și verificați paths.appRoot în container system status.

Gantry 0.27.0 pornește serviciile fără --app-root când se conectează la o gazdă ale cărei servicii sunt oprite. Porniți mai întâi serviciile din terminal, cu flagul; Gantry folosește apoi serviciile care rulează. Suportul Gantry pentru o rădăcină de date mutată este în dezvoltare.

Arhivați imagini pe disc

Pentru a elibera spațiu fără să pierdeți o imagine, salvați-o pe discul extern și ștergeți-o. Încărcați-o din nou când aveți nevoie de ea:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Deconectați discul în siguranță

  1. Opriți containerele care folosesc discul: container stop <name>.
  2. Dacă rădăcina aplicației este pe disc, opriți serviciile: container system stop.
  3. Scoateți discul în Finder, apoi deconectați-l.

Dacă discul dispare în timp ce containerele rulează de pe el, acestea eșuează, iar scrierile în curs se pot pierde. După ce reconectați discul, porniți serviciile cu --app-root, apoi porniți containerele.

Discuri externe în Gantry

Gantry rulează deja montări bind de pe orice disc: în Container nou, adăugați un volum, alegeți un dosar de pe discul extern și o cale în container. Suportul Gantry pentru mutarea rădăcinii de date, volume pe un disc extern și un avertisment când discul nu este conectat este în dezvoltare.

Docker Desktop își mută imaginea de disc din Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack a adăugat o setare pentru locația datelor în versiunea 0.13.0. Vedeți comparația.

Întrebări și răspunsuri

Pot păstra imaginile Apple container pe un disc extern?

Da. Porniți serviciile cu container system start --app-root /Volumes/Disk/container. Toate imaginile, containerele, snapshoturile și volumele se află apoi în acel dosar.

Ce sistem de fișiere trebuie să aibă discul extern?

APFS. Volumele sunt imagini de disc sparse, iar containerele au nevoie de permisiuni Unix, pe care exFAT, FAT și NTFS nu le au.

Cum copiez datele containerelor fără să umplu discul?

Folosiți cp -Rp, care a păstrat mici imaginile sparse ale volumelor în testul nostru. ditto a copiat fiecare imagine sparse la dimensiunea completă.

Ce se întâmplă dacă deconectez discul în timp ce containerele rulează?

Containerele care folosesc discul eșuează, iar datele încă nescrise se pot pierde. Înainte să scoateți discul, opriți containerele și, dacă rădăcina aplicației este pe disc, serviciile.

Reține CLI-ul container noua locație?

Nu. Transmiteți --app-root la fiecare container system start. container system status afișează rădăcina folosită ca paths.appRoot.

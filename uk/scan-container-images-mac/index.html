Gantry/Перевірка образів

Перевірка образів контейнерів на вразливості на Mac

Trivy і Grype — безплатні сканери з відкритим кодом, які порівнюють пакети в образі з базами відомих вразливостей. Образи Docker вони читають безпосередньо. Інструмент container від Apple не має команди перевірки та сокета Docker, тому образ спершу треба зберегти. Посібник показує обидва способи, а також як читати результати, як записати SBOM і як перевіряти образи з Gantry.

Коротко. Виконайте brew install trivy grype. На Docker виконайте trivy image app:dev. На Apple container збережіть образ командою container image save --platform linux/arm64 -o app.tar app:dev, розпакуйте його командою tar -xf app.tar -C app-img і перевірте папку: trivy image --input app-img або grype oci-dir:app-img. Сам tar-файл обидва інструменти не приймають.

Інсталяція сканера

Інсталюйте один сканер або обидва через Homebrew. Під час першої перевірки кожен із них завантажує свою базу вразливостей, це триває близько хвилини.

Термінал
brew install trivy grype

Ми перевірили команди з цього посібника з Trivy 0.76.2, Grype 0.121.3 і container 1.7.1. Gantry потребує Trivy 0.50.0 або Grype 0.74.0 чи новіших.

Перевірка образу Docker

З рушієм Docker (Docker Desktop, OrbStack або Colima) обидва інструменти читають локальний образ за назвою через сокет Docker:

Термінал
trivy image app:dev
grype app:dev

Перевірка образу Apple container

Збережіть образ в OCI-архів і розпакуйте його в папку. Укажіть --platform: якщо у сховищі образів є лише частина платформ образу, container image save без цього прапорця завершується з помилкою.

Термінал
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Потім перевірте папку. Trivy читає її з прапорцем --input, Grype — із префіксом oci-dir::

Термінал
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Увага
Не передавайте файл .tar. Архів container image save починається із запису ./: Trivy повідомляє «file manifest.json not found in tar», а Grype відхиляє його як «potential path traversal attack». Розпакована папка працює з обома.

Читання результатів

  • Рівень серйозності: Critical, High, Medium, Low або Unknown. Почніть із Critical і High. --severity HIGH,CRITICAL обмежує вивід Trivy.
  • Інстальована й виправлена версія: якщо виправлена версія є, оновіть базовий образ або пакет і зберіть знову. trivy --ignore-unfixed і grype --only-fixed приховують знахідки без виправлення.
  • «won't fix»: дистрибутив вирішив не виправляти пакет у цьому випуску. Використайте новіший базовий образ або прийміть ризик.
  • Два інструменти, дві бази: Trivy і Grype часто показують різну кількість знахідок. Жоден не помиляється: у них різні джерела.

Експорт SBOM

Перелік компонентів ПЗ (SBOM) містить усі пакети образу. Trivy записує CycloneDX і SPDX; Syft, супутній інструмент Grype, теж записує обидва формати.

Термінал
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Зупинка збірки за серйозних знахідок

У скрипті нехай код виходу задає сканер. Grype завершується з ненульовим кодом, якщо є знахідка заданого рівня серйозності або вищого; із Trivy використовуйте --exit-code 1 --severity HIGH,CRITICAL.

Термінал
grype oci-dir:python-img --fail-on high
echo $?

Перевірка з Gantry

Gantry 0.29.0 виконує ці кроки за вас. Виберіть Перевірити на вразливості… у меню образу або на панелі інструментів подробиць образу.

  • Gantry шукає Trivy або Grype в GANTRY_TRIVY чи GANTRY_GRYPE, у PATH або в /opt/homebrew/bin і /usr/local/bin. Якщо інстальовано обидва, типово використовується Trivy. Якщо сканера немає, вікно показує команди Homebrew.
  • На apple/container Gantry зберігає образ із --platform, розпаковує його й перевіряє папку. На локальному Docker він перевіряє збережений архів. На Docker через SSH він перевіряє копію тегу в реєстрі.
  • Результати згруповано за рівнем серйозності, із символом і словом, а не лише кольором. У кожному рядку — ID із посиланням, пакет, інстальована версія та версія з виправленням. Фільтр знаходить пакет або ID.
  • Експортувати SBOM записує CycloneDX (обидва інструменти) або SPDX (Trivy).
  • Кнопка Зупинити або закриття вікна зупиняє сканер і видаляє тимчасові файли.

Запитання й відповіді

Як перевірити образ Apple container на вразливості?

Збережіть його командою container image save --platform linux/arm64 -o app.tar app:dev, розпакуйте командою tar -xf app.tar -C app-img, потім виконайте trivy image --input app-img або grype oci-dir:app-img. У Gantry ці кроки виконує Перевірити на вразливості….

Чому Trivy або Grype не приймає архів із container image save?

Архів починається із запису ./. Trivy не знаходить у ньому manifest.json або index.json, а Grype вважає цей запис обходом шляху (path traversal). Розпакуйте архів і перевірте папку.

Trivy чи Grype: що вибрати?

Обидва безплатні та з відкритим кодом. Trivy також знаходить секрети й помилки конфігурації та записує SPDX; Grype невеликий і зосереджений на пакетах. Бази в них різні, тож разом вони знаходять більше. Якщо інстальовано обидва, Gantry використовує Trivy.

Чи інсталює Gantry сканери?

Ні. Інсталюйте їх командою brew install trivy grype. Gantry шукає їх у PATH, /opt/homebrew/bin і /usr/local/bin або в GANTRY_TRIVY і GANTRY_GRYPE.

Чи потрібен Docker Scout або обліковий запис Docker, щоб перевіряти образи?

Ні. Trivy і Grype працюють без облікового запису — і з образами Docker, і з образами Apple container.

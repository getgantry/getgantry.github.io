Funzioni

Ogni area di Gantry, nell'ordine della barra laterale dell'app. La colonna a sinistra mostra i comandi che l'area sostituisce.

Scarica per macOS Gantry

Container

Crea, esegui, apri e modifica i container su ogni host.

  • container run
  • docker exec -it
  • docker cp
  • docker port
Incolla un docker run
Incolla un comando docker run, podman run o container run e Gantry compila il modulo Nuovo container, con l'elenco dei flag che non può usare. Copia qualsiasi container come comando, o salvalo come ricetta. Come funziona
Terminale exec integrato
Emulazione di terminale completa in qualsiasi container in esecuzione, locale o remoto, con temi a colori (Sistema, Solarized, Dracula, Nord).
File browser con drag & drop
Sfoglia il file system di un container, sposta file dentro e fuori e trascina intere cartelle direttamente dal Finder, sugli host Docker come su apple/container.
Apri nel browser & inoltra
Un clic apre una porta pubblicata. Le porte SSH vengono inoltrate in automatico su localhost; se la porta è occupata, Gantry ne sceglie una libera che puoi modificare.
Condividi su Internet
Un clic espone una porta pubblicata tramite un Cloudflare Tunnel. Gantry installa cloudflared per te, poi ti dà un tunnel rapido (senza account, un URL *.trycloudflare.com) o un tunnel con nome sul tuo dominio: perfetto per un'anteprima di sviluppo, un webhook o per far raggiungere a un agente AI un container sul tuo Mac.
Segreti del portachiavi nell'ambiente
Conserva password e token nel portachiavi di macOS (Impostazioni → Segreti) e usali come variabili d'ambiente in “Nuovo container” ed “Esecuzione rapida”. Il modulo mostra keychain:NAME, mai il valore, e Gantry legge il valore solo quando crea il container. L'esportazione in Compose, le ricette e “Copia come comando” scrivono il nome, non il valore.
Agisci su più elementi insieme
Seleziona più container, immagini, volumi o reti e avviali, arrestali, riavviali o rimuovili in un solo passaggio, con l'avanzamento e un resoconto per ogni elemento.
Statistiche in tempo reale
CPU, memoria, rete & I/O del disco in grafici in tempo reale, con campionamento ogni secondo.
Container su un disco esterno
Sposta tutti i dati di apple/container su un disco esterno, tieni i volumi su un disco a tua scelta e ricevi un avviso chiaro quando quel disco non è collegato. Leggi la guida

Immagini e build

Scarica, crea, scansiona e rimuovi immagini.

  • docker build
  • docker pull
  • trivy image
  • docker system prune
Crea & scarica immagini
Trascina un Dockerfile sulla finestra per creare l'immagine con il log in tempo reale, oppure scaricala per riferimento con l'avanzamento di ogni layer. Aggiungi tag, ripulisci e leggi la cronologia dei layer. Un badge segnala le immagini create per un'architettura di CPU diversa da quella dell'host.
Cronologia delle build
Ogni host ha una sezione Build: le build con i loro passaggi, i riscontri nella cache e il log. Gantry conserva le build che avvia, con i nomi degli argomenti di build ma non i loro valori. Sugli host Docker legge anche docker buildx history (buildx 0.23.0 o successivo). apple/container non conserva una cronologia delle build, quindi lì vedi le build avviate da Gantry.
Scansiona le immagini con Trivy o Grype
Scegli Cerca vulnerabilità… su un'immagine. Gantry esegue il Trivy (0.50.0 o successivo) o il Grype (0.74.0 o successivo) che hai installato, per esempio con Homebrew, e raggruppa i risultati da Critico a Sconosciuto. Esporta SBOM scrive CycloneDX, oppure SPDX con Trivy. Funziona su apple/container, Docker locale e Docker via SSH; in quest'ultimo caso Gantry scansiona la copia nel registro di un'immagine con tag.
Registri privati
I pull usano il docker login che hai già fatto: Gantry risolve le credenziali da ~/.docker/config.json, dagli helper e dal portachiavi, sia alla creazione sia in Esecuzione rapida e in Compose.
Recupera spazio
Un pannello mostra cosa occupa spazio (immagini orfane, container arrestati, volumi inutilizzati, cache di build) con le dimensioni, e ripulisce ogni voce o tutto insieme. Su apple/container esegue anche Compatta disco.

Compose

Esegui un docker-compose.yml su Docker o su apple/container, e creane uno dai container in esecuzione.

  • docker compose up -d
  • docker compose down
  • docker compose logs -f
Compose su ogni host
I container sono raggruppati per progetto Compose. Avvia un file Compose su qualsiasi host (Docker locale, SSH o apple/container) con un editor YAML integrato; l'esecuzione si adatta a ogni motore.
Esporta come Compose
Scegli Esporta come Compose… su uno o più container per ottenere un docker-compose.yml con porte, montaggi, reti, criterio di riavvio, controllo di integrità, limiti e altro. I valori che sembrano segreti diventano ${NAME}, a meno che tu non li includa. Sugli host apple/container, Gantry avvisa dei flag che Compose non può esprimere. Come funziona

Kubernetes

Esplora ogni contesto kubeconfig, oppure crea un cluster con apple/container.

  • kubectl get pods -A
  • kubectl logs -f
  • kubectl port-forward
  • container cluster
Browser Kubernetes
Esplora pod, deployment, stateful set, daemon set, servizi, ingress, config map, secret, nodi ed eventi di qualsiasi contesto kubeconfig. Segui i log dei pod, apri una shell, inoltra una porta, scala, riavvia un rollout e applica YAML. Gantry comunica direttamente con l'API di Kubernetes, quindi un cluster creato con container cluster create si può esplorare subito, senza installare altro: niente kubectl.
Cluster Kubernetes
Crea un cluster Kubernetes con container cluster: dimensiona separatamente il control plane e i worker, scegli il CNI e vedi i nodi, la versione di Kubernetes e il contesto kubeconfig. I nodi del cluster sono protetti contro arresti ed eliminazioni accidentali. Scopri di più

Host e flotta

Questo Mac, gli host Docker via SSH e apple/container in un'unica dashboard.

  • docker -H ssh://user@host
  • docker context use
  • docker stats
Un'unica dashboard per ogni host
Daemon locale, flotta SSH e apple/container in un'unica schermata: sparkline di CPU e memoria in tempo reale, ripartizione dei container per stato e problemi di integrità che portano dritti al colpevole.
Host remoti via SSH
Tunnel identici a docker -H ssh:// tramite dial-stdio: bastion ProxyJump, autenticazione con più chiavi, riconnessione automatica. Niente da installare sul server, segreti nel portachiavi. Importazione con un clic da ~/.ssh/config e docker context ls.
Uso delle risorse per tutti gli host
Un'unica tabella ordinabile dei container in esecuzione su ogni host connesso: host, nome, immagine, CPU, memoria, I/O di rete, I/O del disco e tempo di attività. Filtra per nome, immagine o host, oppure mostra un solo host. Fai doppio clic su una riga per aprire il container. La tabella usa i campioni che Gantry raccoglie già ogni 5 secondi, quindi non apre nuovi flussi di statistiche. Aprila dalla barra laterale, con ⌘K o con gantry://open/usage.

Log ed errori

Leggi, cerca ed esporta i log. Trova la causa quando un container va in errore.

  • docker logs -f
  • container logs
  • docker events
Log in tempo reale
Scorrimento automatico in tempo reale, ricerca ⌘F regex o letterale, filtro per livello (Error→Trace), colori ANSI, buffer da 50.000 righe e log dello stack uniti per un intero progetto Compose.
Esporta i log
Esporta log… (⇧⌘E) salva le righe che vedi, con il filtro per livello, la ricerca e l'intervallo di tempo, in un file .log o .txt. Copia righe visibili le copia. Sugli host Docker puoi aggiungere data e ora e mostrare solo un periodo che va dagli ultimi 5 minuti fino all'ultimo giorno.
Notifiche di errore
Una notifica nativa quando un container va in crash, esaurisce la memoria o diventa non integro su qualsiasi host. Fai clic per andare dritto al container; gli arresti che avvii tu non generano notifiche.
“Spiega errore” con Apple Intelligence
Scegli Spiega errore… su un container andato in crash o su un'operazione non riuscita. Gantry invia i log recenti e i dettagli, senza i valori delle variabili d'ambiente e senza il testo che somiglia a un segreto, al modello sul dispositivo, e mostra la causa probabile, le evidenze e i passi successivi. I log lunghi possono andare a Private Cloud Compute (macOS 27). Il pannello mostra esattamente cosa è stato inviato.
Screenshot in “Spiega errore”
Trascina, incolla o aggiungi fino a 3 immagini in “Spiega errore”, per esempio uno screenshot di una pagina di errore. Le immagini restano su questo Mac: le legge solo il modello sul dispositivo (macOS 27), mai Private Cloud Compute.

macOS

La barra dei menu, le notifiche, Spotlight, Comandi Rapidi e la tastiera.

  • ⌘K
  • ⌥⌘P
  • ⇧⌘E
Parte di macOS
Notifiche con Riavvia, Mostra log e Copia come prompt. Spotlight trova container, progetti Compose e host. Azioni per Siri e Comandi Rapidi, un widget sullo stato della flotta, controlli nel Centro di Controllo per i servizi apple/container o per un container preferito, e link gantry:// per gli script.
Avanzamento nella barra dei menu
Il pannello della barra dei menu mostra ogni download, build e operazione Compose in corso con una barra di avanzamento, i layer o i servizi completati, i byte, il tempo e un pulsante Annulla. L'icona nella barra dei menu indica quante operazioni sono in corso. Ogni progetto Compose ha Scarica le immagini e Compose Down; Compose Down mantiene volumi e immagini.
Palette dei comandi
Premi ⌘K e digita. Un'unica ricerca copre container, progetti Compose, immagini, volumi, reti, macchine, cluster e host, con azioni come Avvia, Mostra log e Apri shell.
Touch ID per le azioni distruttive
Se lo attivi, Gantry chiede Touch ID (o la password di login) prima di rimuovere un container o eliminare un host. I segreti sono già nel portachiavi.
Temi del terminale
Vesti la shell integrata con Sistema, Solarized Dark, Dracula o Nord: una palette completa per primo piano, sfondo e 16 colori ANSI, applicata in tempo reale.

La GUI nativa per macOS per Apple container

Lo strumento container di Apple esegue container Linux come VM leggere sui chip Apple, ma è distribuito solo come strumento a riga di comando. Gantry è la sua app desktop: Gantry sta a container come Docker Desktop sta a Docker. Supporta ogni CLI container dalla 1.0 alla 1.7.1 consigliata, e attiva ogni funzione solo se la CLI installata la supporta.

  • container system start
  • container machine
  • container builder start
  • container registry login
Container, log, statistiche ed exec
Crea, avvia, arresta, forza l'arresto e ripulisci; log in tempo reale, statistiche, terminale exec, top ed esportazione tar, nella stessa interfaccia dei tuoi host Docker.
Cluster Kubernetes
Crea un cluster Kubernetes con container cluster: dimensiona separatamente il control plane e i worker, scegli il CNI e vedi i nodi, la versione di Kubernetes e il contesto kubeconfig. I nodi del cluster sono protetti contro arresti ed eliminazioni accidentali. Scopri di più
Immagini locali nel cluster
Con la CLI 1.7, attiva Usa immagini locali (--shared-image-store) e i pod eseguono le immagini che crei o scarichi, senza registro. Con le CLI 1.5 e 1.6, fai clic destro su un'immagine e scegli Carica nel cluster.
Indicazioni chiare quando l'installazione è guasta
Se i servizi del cluster non rispondono, Gantry ti dice perché. Una build Homebrew senza i servizi del cluster riceve un link al programma di installazione firmato; in tutti gli altri casi compare il pulsante Riavvia servizi.
Macchine container in VS Code
Crea, avvia e arresta ambienti Linux container machine, imposta CPU e memoria, apri una shell o apri la macchina in VS Code tramite Remote-SSH.
Virtualizzazione annidata e kernel personalizzati
Avvia una macchina con la virtualizzazione annidata (M3 o successivo) o con un tuo kernel. Avvia i container da un kernel personalizzato con argomenti di avvio aggiuntivi.
Compose per Apple container
apple/container non ha compose. Gantry esegue il tuo docker-compose.yml: crea le immagini, la rete e i volumi, e avvia i servizi nell'ordine di depends_on. I nomi dei servizi vengono risolti tramite alias DNS di rete.
Alias DNS di rete
Alias dei container, alias di sottoalbero come .gateway e nomi brevi quando è impostato un dominio DNS predefinito. Ogni container riceve un IP instradabile e un hostname name.domain.
Gestisci il builder di immagini
Vedi stato, immagine, CPU, memoria e IP del builder. Avvialo con opzioni per CPU, memoria e DNS, arrestalo o eliminalo. Quando l'immagine del builder è obsoleta, Gantry propone di ricrearlo.
Accessi ai registri
Elenca, aggiungi e rimuovi gli accessi container registry. La password arriva alla CLI solo tramite stdin, e Gantry non ne conserva copia.
Installazione del kernel
Installa il kernel consigliato, un file del kernel o un archivio tar, con l'avanzamento in tempo reale. Gantry ti avvisa quando non è installato alcun kernel predefinito.
Servizi e log dei servizi
Avvia, arresta e riavvia i servizi di container, confronta le versioni di client e server e segui in tempo reale i log dei servizi, filtrati per livello, servizio e testo.
Editor delle proprietà di sistema
Modifica le proprietà di sistema di container in config.toml. Gantry segnala le modifiche che richiedono un riavvio e riavvia i servizi al posto tuo. Con la CLI 1.7 modifica anche i valori predefiniti di [container.dns]: server dei nomi, domini di ricerca e opzioni.
Salva come immagine e Compatta disco
Salva un container come immagine (container commit) e recupera spazio su disco con Compatta disco (container clean), disponibile anche nel pannello Recupera spazio.
File browser: caricamento e download
Sfoglia i file di un container, scaricali o trascinali nel Finder (container copy), e trascina dentro file o intere cartelle.
Esecuzione rapida e Finder
Scegli un'immagine, condividi una cartella, mappa le porte e scegli un dominio, poi avvia. Fai clic destro su un file Compose nel Finder e aprilo con Gantry.
Etichette che contengono =
La CLI container rifiuta i valori delle etichette con =. Gantry li codifica alla creazione e li decodifica in lettura, così un valore come a=b resta intatto.
Una flotta, due runtime
Gli host apple/container stanno accanto ai tuoi host Docker locali e SSH in un'unica dashboard, con le stesse sparkline, lo stesso stato di integrità e le stesse notifiche di guasto.
Strumenti MCP per gli agenti
Il server MCP incluso dà agli agenti la stessa portata: container, macchine, cluster e strumenti di sistema apple_* per servizi, builder, registri, proprietà, log e kernel.

Architettura

Gantry comunica con l'API di Docker Engine e con la CLI container di Apple. Non esegue alcun servizio proprio.

100% SwiftUI nativo
SwiftUI nativo, non Electron. L'app usa i controlli, il font e le finestre di macOS.
Swift 6
Codice moderno e sicuro per la concorrenza, sulla toolchain più recente.
Accesso diretto all'API Engine
Docker tramite il socket Unix, senza bisogno della CLI di Docker. apple/container tramite la sua CLI container.
Aggiornamenti automatici
Un appcast Sparkle firmato EdDSA ti tiene aggiornato senza disturbarti.

Domande

Qual è la migliore GUI per Apple container?

Gantry è una GUI nativa per macOS, gratuita e open source, pensata per lo strumento container di Apple (apple/container). Copre il ciclo di vita dei container, i log, le statistiche e un terminale exec, oltre alle parti della CLI che le altre GUI non raggiungono: cluster Kubernetes (container cluster), macchine container, builder di immagini, accessi ai registri, kernel, log dei servizi e proprietà di sistema. Supporta le CLI dalla 1.0 alla 1.7.1 e attiva ogni funzione solo se la tua CLI la supporta. Leggi la guida ad apple/container.

Cos'è Apple container (apple/container)?

apple/container è lo strumento open source di Apple per eseguire container Linux su un Mac. Ogni container gira nella propria macchina virtuale leggera, basata sul framework Virtualization di Apple. Richiede un Mac con chip Apple ed è distribuito come strumento a riga di comando chiamato container, senza app desktop. Gantry è quell'app desktop.

Gantry supporta container cluster e Kubernetes?

Sì. Su un host apple/container, Gantry crea ed elimina cluster Kubernetes con container cluster (CLI 1.6.1 e 1.7; le CLI dalla 1.5.0 alla 1.6.0 usano container k8s). Scegli il nome, i worker, le CPU e la memoria del control plane e dei worker (1.7), l'immagine dei nodi, il CNI e se i nodi usano le tue immagini locali (1.7). Gantry mostra i nodi, scrive il kubeconfig e apre il cluster nel suo browser Kubernetes. Vedi Kubernetes su apple/container.

Si può usare docker compose con Apple container?

Sì. apple/container non ha un comando compose, quindi è Gantry a orchestrare tramite la CLI container: crea le immagini dei servizi build:, crea la rete del progetto e i volumi con nome, e avvia ogni servizio nell'ordine di depends_on con le etichette Compose standard. I nomi dei servizi vengono risolti tramite alias DNS di rete. Apri un docker-compose.yml dal Finder, dal menu File o trascinandolo sulla finestra.

Come si apre una macchina container in VS Code?

Avvia la macchina in Gantry e fai clic su Apri in VS Code. Gantry apre la macchina in VS Code tramite Remote-SSH, come nell'esempio container-machine-vscode di Apple. L'immagine della macchina deve eseguire sshd, e devi avere installato VS Code con l'estensione Remote-SSH.

Quali versioni di apple/container supporta Gantry?

Gantry richiede la CLI container 1.0 o successiva e consiglia la 1.7.1. Legge la versione installata e mostra solo le funzioni che quella versione supporta, per esempio le dimensioni dei worker e l'archivio immagini condiviso (1.7), il commit (1.6) e Compatta disco (1.4). Se la CLI manca o è vecchia, Gantry offre una configurazione guidata.

Gantry può esplorare un cluster Kubernetes?

Sì. La sezione Kubernetes elenca pod, deployment, stateful set, daemon set, servizi, ingress, config map, secret, nodi ed eventi per ogni contesto kubeconfig, e offre log dei pod, una shell nel pod, inoltri di porta, scalabilità, riavvio del rollout, eliminazione e Applica YAML. Gantry comunica direttamente con l'API di Kubernetes, quindi kubectl non serve. Vedi Kubernetes su Mac.

Cosa invia “Spiega errore” ad Apple Intelligence?

I log recenti e i dettagli del container, senza i valori delle variabili d'ambiente e senza il testo che somiglia a un segreto. Le richieste brevi vengono elaborate dal modello sul dispositivo. Se attivi l'impostazione per i log lunghi (macOS 27), i log lunghi vanno a Private Cloud Compute. Il pannello mostra cosa è stato inviato. Un comando suggerito si apre in Terminale, ma non viene eseguito finché non premi A capo. Senza Apple Intelligence, Gantry offre un prompt da copiare in un altro assistente IA.

Posso incollare un comando docker run in Gantry?

Sì. Nel pannello Nuovo container, scegli Incolla comando…. Gantry legge docker run, docker create, podman run e container run, compila il modulo ed elenca ogni flag che non può usare, con il motivo. Vedi Creare un container da un comando docker run.

Gantry può gestire builder, registri e kernel di apple/container?

Sì. La sezione Sistema di un host apple/container avvia, arresta ed elimina il builder di immagini con opzioni per CPU, memoria e DNS; elenca, aggiunge e rimuove gli accessi ai registri (la password arriva alla CLI solo tramite stdin); installa il kernel consigliato, un file del kernel o un archivio tar; trasmette i log dei servizi in tempo reale; e modifica le proprietà di sistema in config.toml.

Gantry è un'alternativa a Docker Desktop, OrbStack o Podman Desktop?

Per la GUI, sì. Gantry è un'app nativa e gratuita per macOS per gestire container, immagini, volumi, reti, log e statistiche. È un client, non un motore: usa il daemon Docker che hai già (Docker Desktop, OrbStack, Colima) o lo strumento container di Apple, e aggiunge una vista multi-host, host SSH e un server MCP. Vedi il confronto.

Gantry è gratis?

Sì. Gantry è gratuito e open source con licenza MIT. Nessun abbonamento, nessun account e nessun limite al numero di host o di container.

Cosa serve per usare Gantry?

macOS 26 o successivo su chip Apple o Intel, più un daemon Docker (Docker Desktop, OrbStack, Colima o simili) oppure lo strumento container di Apple. apple/container richiede a sua volta un chip Apple, quindi su un Mac Intel Gantry gestisce solo host Docker.

Gantry funziona con OrbStack, Colima e Docker Desktop?

Sì. Gantry comunica direttamente con l'API di Docker Engine tramite il socket Unix, quindi funziona con qualsiasi daemon che la espone, compresi OrbStack, Colima e Docker Desktop.

Gantry può gestire host Docker remoti?

Sì. Gantry si connette ai daemon remoti via SSH, come docker -H ssh://, con bastion ProxyJump, autenticazione con più chiavi e riconnessione automatica. Sul server non serve installare nulla, e i segreti restano nel portachiavi di macOS.

Gantry mi avvisa quando un container si guasta?

Sì. Gantry invia una notifica nativa di macOS quando un container va in crash, esaurisce la memoria o non supera il controllo di integrità, su qualsiasi host: locale, SSH o apple/container. Fai clic sulla notifica per andare al container. Arresti e riavvii che avvii da Gantry non generano notifiche, e puoi disattivare la funzione nelle Impostazioni.

Gantry può scaricare immagini da registri privati?

Sì. Sugli host Docker, Gantry legge le credenziali dal tuo ~/.docker/config.json (lo stesso docker login che hai già fatto), comprese autenticazione inline, credential helper e portachiavi di macOS. Sugli host apple/container gestisce gli accessi container registry.

Gantry può esporre un container locale su Internet?

Sì. Con un clic su una porta pubblicata la condividi tramite Cloudflare Tunnel. Se serve, Gantry installa cloudflared, poi avvia un tunnel rapido (senza account Cloudflare, con un URL temporaneo trycloudflare.com) o un tunnel con nome sul tuo hostname. L'URL pubblico appare sotto la porta, con i comandi per aprirlo, copiarlo e fermarlo.

Gantry è un'app Electron?

No. Gantry è un'app nativa scritta con SwiftUI e Swift 6. L'interfaccia è disponibile in 28 lingue: inglese, cinese semplificato e 26 lingue europee, ad esempio il serbo in alfabeto cirillico e latino. Segue la lingua di sistema di macOS.

Come si installa Gantry?

Esegui brew install --cask getgantry/tap/gantry, oppure scarica l'ultima release da GitHub e trascina Gantry.app in Applicazioni.

Gli agenti AI possono controllare Gantry?

Sì. Gantry include un server MCP e gli App Intents di macOS, quindi Claude, Comandi Rapidi, Siri e gli script arrivano dove arriva la GUI, su ogni host, compresi gli host SSH: container, immagini, volumi, reti, Compose, macchine apple/container, cluster Kubernetes, strumenti di sistema apple_* (servizi, builder, registri, proprietà, log, kernel) e condivisione delle porte. Su macOS 26 e successivi, Spiega errore… chiede anche ad Apple Intelligence perché un container non è riuscito. Aggiungi il server MCP con claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp.

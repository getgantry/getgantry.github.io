Gantry/Kubernetes na apple/container

Kubernetes na Apple container

apple/container umí spustit cluster Kubernetes, jehož uzly jsou kontejnery na vašem Macu. Gantry je pro něj GUI: vytvořte cluster, sledujte, jak se uzly spouštějí, spouštějte v něm své místní image a procházejte jeho pody, logy a služby, bez dlouhých příkazů container cluster.

Ve zkratce. Na hostiteli apple/container vytváří a maže sekce Clustery v Gantry clustery Kubernetes pomocí container cluster (CLI 1.6.1 a 1.7) nebo container k8s (CLI 1.5.0 až 1.6.0). V CLI 1.7.1 nastavuje velikost pracovních uzlů odděleně od řídicí roviny a zapíná sdílené úložiště imagů. Sekce Kubernetes cluster prochází: pody, logy, shell, přesměrování portů, škálování a Použít YAML.

Požadavky

  • Mac s Apple silicon, macOS 26 a Gantry (brew install --cask getgantry/tap/gantry).
  • CLI container 1.5.0 nebo novější; doporučená je 1.7.1. Pracovní uzly a CNI Žádný vyžadují 1.6.0 nebo novější. Velikosti pracovních uzlů a sdílené úložiště imagů vyžadují 1.7.0 nebo novější. Použijte podepsaný instalační balíček: build 1.7.1 z Homebrew nemá služby clusteru.
  • kubectl pro prohlížeč Kubernetes a terminál. Gantry ho umí nainstalovat přes Homebrew.

Vytvoření clusteru

  1. Vyberte hostitele apple/container a v postranním panelu otevřete Clustery.
  2. Založte nový cluster a vyplňte možnosti níže.
  3. Vytvořte ho. Seznam zobrazí nový cluster s průběhem v reálném čase. Zrušit vytváření zastaví a smaže uzly, které už vznikly.
MožnostPříznak CLIPoznámky
Název--nameZároveň název kontextu v kubeconfig
Pracovní uzly--workersPočet pracovních uzlů. CLI 1.6.0+
CPU a paměť pracovních uzlů--workers count=N,cpus=C,memory=MCLI 1.7+. Před 1.7 nastavují --cpus a --memory každý uzel
CPU--cpusŘídicí rovina (CLI 1.7+) nebo každý uzel (před 1.7)
Paměť--memoryŘídicí rovina (CLI 1.7+) nebo každý uzel (před 1.7), například 4G
Používat místní image--shared-image-storeCLI 1.7+. Uzly spouštějí image z vašeho místního úložiště imagů
Image uzlu--node-imagePrázdné pole ponechá výchozí hodnotu CLI
CNI--cniVýchozí (vestavěný kindnet), Žádný (NONE, CLI 1.6.0+) nebo cesta k vlastnímu manifestu

Stejný příkaz v CLI:

Shell
container cluster create --name dev --cpus 2 --memory 4G \
  --workers count=2,cpus=2,memory=4G --shared-image-store

Uzly a podrobnosti clusteru

Seznam clusterů má pro každý cluster jeden řádek. Podrobné zobrazení obsahuje Přehled (kontext kubectl, server API, verze Kubernetes, úložiště imagů, pracovní uzly a jejich prostředky, síť uzlů), tabulku Uzly a Inspekce se surovými daty uzlů. Na panelu nástrojů je Procházet zdroje a v nabídce Další Zapsat kubeconfig, Kopírovat příkaz kubectl pro kontext a Smazat.

Uzly clusteru jsou kontejnery, ale patří container cluster. Gantry u uzlu zakáže spuštění, zastavení, restart, odstranění a přejmenování a vysvětlí proč; Spustit vše a Zastavit vše uzly přeskočí. V CLI 1.7 skrývá uzly v container list i samotné CLI. Clustery vytvořené v CLI 1.6 nebo starším se v seznamu 1.7 nezobrazí; odstraňte je příkazem container cluster delete --name <name>.

Procházení clusteru

U běžícího clusteru klikněte na Procházet zdroje nebo otevřete Kubernetes v postranním panelu. Sekce nepotřebuje hostitele a vypisuje všechny kontexty kubeconfig; kontexty clusterů apple/container jsou na začátku. Vyberte jmenný prostor nebo všechny jmenné prostory a pak druh: pody, deploymenty, StatefulSety, DaemonSety, služby, ingressy, ConfigMapy, secrety, uzly nebo události.

  • Pody: logy se sledováním, koncem a předchozím kontejnerem; shell v podu; přesměrování portu na 127.0.0.1.
  • Workloady: škálování deploymentů a StatefulSetů; restart nasazení.
  • Secrety: hodnoty jsou v seznamu i v YAML skryté, dokud nekliknete na Zobrazit.
  • Použít YAML: vložte manifest nebo otevřete soubor; chyby se zobrazí v listu.

Prohlížeč spouští kubectl. Pokud ho Gantry nenajde, sekce zobrazí brew install kubectl s tlačítkem, které příkaz spustí. Nativní klient Kubernetes, který kubectl nepotřebuje, je ve vývoji.

Připojení kubectl

Při vytváření clusteru přidá CLI do ~/.kube/config kontext pojmenovaný podle clusteru. Použijte v Gantry Kopírovat příkaz kubectl pro kontext, nebo ho napište ručně:

Shell
kubectl --context dev get nodes

Chcete-li mít cluster v samostatném souboru, použijte Zapsat kubeconfig. Gantry spustí container cluster write-config; výchozí cesta je ~/.kube/<name>.kubeconfig.

Místní image v clusteru

V CLI 1.7 zapněte při vytváření clusteru Používat místní image. Volba přidá --shared-image-store, takže uzly mohou podle názvu spustit jakýkoli image, který sestavíte nebo stáhnete pomocí container, bez registru. Nastavení je dané při vytvoření. Po novém sestavení tagu použijte imagePullPolicy: Always nebo nový tag. Privilegované pody mohou číst všechny image ve vašem místním úložišti, proto tuto volbu používejte jen pro místní vývoj.

Shell
container build -t myapp:dev .
kubectl --context dev create deployment myapp --image=myapp:dev

V CLI 1.5 a 1.6 klikněte na image v sekci Image pravým tlačítkem a zvolte Načíst do clusteru. Gantry spustí container cluster load-image, který zkopíruje image do containerd každého uzlu. CLI 1.7 tento příkaz odstranilo, proto tam Gantry akci skrývá.

Shell
container cluster load-image --name dev myapp:dev

Když služby clusteru neodpovídají

Pokud příkaz clusteru selže s chybou cluster service unavailable, Gantry zkontroluje, jak je CLI nainstalované. Build z Homebrew bez pluginů clusteru dostane zprávu, že mu chybí služby clusteru, a odkaz Stáhnout instalátor… na podepsaný balíček. V ostatních případech Gantry nabídne Restartovat služby….

Volba CNI

Výchozí je vestavěný manifest kindnet. Zvolte Vlastní manifest a nainstalujte vlastní CNI ze souboru, například Calico nebo Cilium. Zvolte Žádný, pokud chcete CNI nainstalovat sami později; do té doby zůstanou uzly ve stavu NotReady.

Clustery z AI agentů

Server MCP Gantry nabízí list_clusters, create_cluster a delete_cluster, takže agent jako Claude Code si může vytvořit dočasný cluster pro test a potom ho odstranit.

Přidání serveru MCP Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Více o apple/container

Podrobný postup z terminálu najdete v průvodci Kubernetes na Macu s Apple container. Přečtěte si průvodce apple/container s každým příkazem container a jeho funkcí v Gantry, nebo se podívejte, jak si Gantry stojí ve srovnání s Docker Desktop, OrbStack a Podman Desktop.

Otázky a odpovědi

Podporuje Apple container Kubernetes?

Ano. CLI container vytváří clustery Kubernetes, jejichž uzly běží jako kontejnery: container cluster v CLI 1.6.1 a 1.7, container k8s v CLI 1.5.0 až 1.6.0. Gantry k tomu přidává GUI.

Podporuje Gantry container cluster?

Ano. Gantry vypisuje, vytváří a maže clustery na hostitelích apple/container, zobrazuje jejich uzly, zapisuje kubeconfig a otevírá cluster ve svém prohlížeči Kubernetes. V CLI 1.7 také nastaví velikost pracovních uzlů a zapne sdílené úložiště imagů. Podle verze CLI používá cluster nebo k8s.

Jak používat kubectl s clusterem apple/container?

Když CLI vytvoří cluster, přidá do ~/.kube/config kontext kubeconfig pojmenovaný podle clusteru. Spusťte kubectl --context <name> get nodes. Chcete-li mít samostatný soubor, použijte v Gantry Zapsat kubeconfig; výchozí cesta je ~/.kube/<name>.kubeconfig.

Jak dostat místní image do clusteru bez registru?

V CLI 1.7 vytvořte cluster s volbou Používat místní image (--shared-image-store). Pody pak spouštějí podle názvu image, které sestavíte nebo stáhnete pomocí container. V CLI 1.5 a 1.6 klikněte na image v sekci Image pravým tlačítkem a zvolte Načíst do clusteru; Gantry spustí container cluster load-image. CLI 1.7 příkaz load-image odstranilo.

Jde vytvořit cluster s více uzly?

Ano. Počet pracovních uzlů nastavte v listu pro vytvoření; pracovní uzly vyžadují CLI 1.6.0 nebo novější. V CLI 1.7 nastavíte také CPU a paměť pracovních uzlů odděleně od řídicí roviny.

Můžu použít vlastní CNI, například Calico nebo Cilium?

Ano. Zvolte Vlastní manifest a vyberte soubor manifestu, nebo zvolte Žádný a CNI nasaďte sami po spuštění clusteru. Dokud CNI neběží, uzly zůstávají ve stavu NotReady. Žádný vyžaduje CLI 1.6.0 nebo novější. Výchozí CNI je vestavěný manifest kindnet.

Proč Gantry hlásí, že služby clusteru nejsou dostupné?

Služby container neodpověděly na příkaz clusteru. Pokud je vaše CLI build z Homebrew bez služeb clusteru, Gantry to oznámí a odkáže na podepsaný instalátor na stránce vydání apple/container. Jinak nabídne Restartovat služby.

Potřebuji kubectl pro práci s clusterem v Gantry?

Zatím ano: prohlížeč Kubernetes v Gantry spouští kubectl. Pokud není nainstalovaný, prohlížeč zobrazí příkaz brew install kubectl a může ho spustit za vás. Nativní klient Kubernetes, který tento krok odstraní, je ve vývoji.

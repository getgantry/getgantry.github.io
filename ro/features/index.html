Funcții

Fiecare zonă Gantry, în ordinea din bara laterală a aplicației. Coloana din stânga arată comenzile pe care le înlocuiește zona.

Descarcă pentru macOS Gantry

Containere

Creați, rulați, deschideți și modificați containere pe fiecare gazdă.

  • container run
  • docker exec -it
  • docker cp
  • docker port
Lipiți un docker run
Lipiți o comandă docker run, podman run sau container run, iar Gantry completează formularul Container nou, cu o listă a flagurilor pe care nu le poate folosi. Copiați orice container înapoi ca comandă sau salvați-l ca rețetă. Cum funcționează
Terminal exec integrat
Emulare completă de terminal în orice container care rulează, local sau la distanță — cu teme de culori (Sistem, Solarized, Dracula, Nord).
Browser de fișiere cu tragere și plasare
Răsfoiți sistemul de fișiere al unui container, mutați fișiere înăuntru și în afară și plasați dosare întregi direct din Finder — atât pe gazde Docker, cât și pe gazde apple/container.
Deschidere în browser și redirecționare
Un clic deschide un port publicat. Porturile SSH sunt tunelate automat către localhost — iar dacă portul e ocupat, Gantry alege unul liber, pe care îl puteți modifica.
Partajare pe internet
Un clic expune un port publicat printr-un Cloudflare Tunnel. Gantry instalează cloudflared pentru dvs., apoi vă oferă un tunel rapid (fără cont, cu un URL *.trycloudflare.com) sau un tunel cu nume pe propriul domeniu — perfect pentru o previzualizare de dezvoltare, un webhook sau pentru ca un agent AI să ajungă la un container de pe Mac.
Secrete din portchei în mediu
Păstrați parolele și tokenurile în portcheiul macOS (Configurări → Secrete) și folosiți-le ca variabile de mediu în Container nou și Rulare rapidă. Formularul afișează keychain:NAME, niciodată valoarea, iar Gantry citește valoarea doar când creează containerul. Exportul Compose, rețetele și Copiază ca comandă scriu numele, nu valoarea.
Acțiuni pe mai multe elemente deodată
Selectați mai multe containere, imagini, volume sau rețele și porniți-le, opriți-le, reporniți-le sau eliminați-le dintr-un singur pas, cu progres și un raport pentru fiecare element.
Statistici în timp real
CPU, memorie, rețea și I/O pe disc în grafice în timp real, cu eșantionare la fiecare secundă.
Containere pe un disc extern
Mutați toate datele apple/container pe un disc extern, păstrați volumele pe un disc ales de dvs. și primiți un avertisment clar când acel disc nu este conectat. Citiți ghidul

Imagini și builduri

Descărcați, construiți, scanați și eliminați imagini.

  • docker build
  • docker pull
  • trivy image
  • docker system prune
Construiți și descărcați imagini
Trageți un Dockerfile în fereastră pentru build cu jurnal în timp real sau descărcați după referință, cu progres pe fiecare strat. Adăugați taguri, curățați și citiți istoricul straturilor. O insignă marchează imaginile construite pentru altă arhitectură de CPU decât cea a gazdei.
Istoricul build-urilor
Fiecare gazdă are o secțiune Build-uri: build-urile cu pașii lor, accesările din cache și jurnalul. Gantry păstrează build-urile pe care le pornește, cu numele argumentelor de build, dar fără valorile lor. Pe gazdele Docker citește și docker buildx history (buildx 0.23.0 sau mai nou). apple/container nu păstrează un istoric al build-urilor, așa că acolo vedeți build-urile pornite de Gantry.
Scanați imaginile cu Trivy sau Grype
Alegeți Scanează vulnerabilitățile… pe o imagine. Gantry rulează Trivy (0.50.0 sau mai nou) sau Grype (0.74.0 sau mai nou), pe care l-ați instalat, de exemplu cu Homebrew, și grupează rezultatele de la critice la necunoscute. Exportă SBOM scrie CycloneDX sau, cu Trivy, SPDX. Funcționează pe apple/container, pe Docker local și pe Docker prin SSH, unde Gantry scanează copia din registru a unei imagini cu tag.
Registre private
Descărcările folosesc docker login-ul pe care l-ați făcut deja — Gantry preia datele de autentificare din ~/.docker/config.json, din helpers și din portchei, la creare, în Rulare rapidă și în Compose.
Recuperați spațiu
Un panou arată ce ocupă spațiu — imagini orfane, containere oprite, volume nefolosite, cache de build — cu dimensiunile lor și curăță fiecare categorie sau pe toate. Pe apple/container rulează și Compactează discul.

Compose

Rulați un docker-compose.yml pe Docker sau pe apple/container și creați unul din containerele care rulează.

  • docker compose up -d
  • docker compose down
  • docker compose logs -f
Compose pe fiecare gazdă
Containerele sunt grupate după proiectul Compose. Porniți un fișier Compose pe orice gazdă — Docker local, SSH sau apple/container — cu un editor YAML integrat; executorul se adaptează fiecărui motor.
Exportă ca Compose
Alegeți Exportă ca Compose… pe unul sau mai multe containere pentru a obține un docker-compose.yml cu porturi, montări, rețele, politica de repornire, verificarea de sănătate, limite și altele. Valorile care seamănă cu secrete devin ${NAME}, dacă nu le includeți. Pe gazdele apple/container, Gantry avertizează despre flagurile pe care Compose nu le poate exprima. Cum funcționează

Kubernetes

Răsfoiți fiecare context kubeconfig sau creați un cluster cu apple/container.

  • kubectl get pods -A
  • kubectl logs -f
  • kubectl port-forward
  • container cluster
Browser Kubernetes
Răsfoiți pod-uri, deployment-uri, StatefulSet-uri, DaemonSet-uri, servicii, Ingress-uri, ConfigMap-uri, secrete, noduri și evenimente din orice context kubeconfig. Urmăriți jurnalele pod-urilor, deschideți un shell, redirecționați un port, scalați, reporniți un rollout și aplicați YAML. Gantry comunică direct cu API-ul Kubernetes, așa că un cluster creat cu container cluster create poate fi răsfoit fără să instalați nimic altceva: fără kubectl.
Clustere Kubernetes
Creați un cluster Kubernetes cu container cluster: dimensionați separat planul de control și workerii, alegeți CNI-ul și vedeți nodurile, versiunea Kubernetes și contextul kubeconfig. Nodurile clusterului sunt protejate împotriva opririi și ștergerii accidentale. Aflați mai multe
  • Kubernetes pe apple/container
  • Kubernetes pe Mac

Gazde și flotă

Acest Mac, gazdele Docker prin SSH și apple/container pe un singur panou de bord.

  • docker -H ssh://user@host
  • docker context use
  • docker stats
Un singur panou pentru toate gazdele
Daemon local, flotă SSH și apple/container pe un singur ecran: minigrafice CPU și memorie în timp real, containere defalcate pe stări și probleme de sănătate care duc direct la cauză.
Gazde la distanță prin SSH
Tunele exact ca docker -H ssh:// prin dial-stdio — bastioane ProxyJump, autentificare cu mai multe chei, reconectare automată. Nimic de instalat pe server, secretele în portchei. Import cu un clic din ~/.ssh/config și docker context ls.
Utilizarea resurselor pentru toate gazdele
Un singur tabel sortabil cu containerele care rulează pe fiecare gazdă conectată: gazdă, nume, imagine, CPU, memorie, I/O de rețea, I/O pe disc și timp de funcționare. Filtrați după nume, imagine sau gazdă ori afișați o singură gazdă. Faceți dublu clic pe un rând pentru a deschide containerul. Tabelul folosește mostrele pe care Gantry le preia deja la fiecare 5 secunde, deci nu deschide fluxuri noi de statistici. Deschideți-l din bara laterală, cu ⌘K sau cu gantry://open/usage.

Jurnale și eșecuri

Citiți, căutați și exportați jurnalele. Aflați cauza când un container eșuează.

  • docker logs -f
  • container logs
  • docker events
Jurnale în timp real
Urmărire în timp real, căutare ⌘F cu regex sau text literal, filtru pe nivel (Error→Trace), culori ANSI, un buffer de 50.000 de linii — și jurnalele stivei combinate pentru un întreg proiect Compose.
Exportul jurnalelor
Exportă jurnalele… (⇧⌘E) salvează liniile pe care le vedeți, cu filtrul pe nivel, căutarea și intervalul de timp, ca fișier .log sau .txt. Copiază liniile vizibile le copiază. Pe gazdele Docker puteți adăuga marcaje de timp și puteți afișa doar ultima perioadă, de la 5 minute până la o zi.
Notificări de eșec
O notificare nativă când un container se închide neașteptat, rămâne fără memorie sau devine nesănătos pe orice gazdă. Faceți clic pe ea pentru a ajunge direct la container — opririle declanșate de dvs. nu generează notificări.
„Explică eșecul” cu Apple Intelligence
Alegeți Explică eșecul… pe un container care s-a închis neașteptat sau pe o operațiune eșuată. Gantry trimite jurnalele recente și detaliile, fără valorile variabilelor de mediu și fără textul care seamănă cu un secret, la modelul de pe dispozitiv și afișează cauza probabilă, dovezile și pașii următori. Jurnalele lungi pot ajunge la Private Cloud Compute (macOS 27). Panoul arată exact ce s-a trimis.
Capturi de ecran în „Explică eșecul”
Trageți, lipiți sau adăugați până la 3 imagini în „Explică eșecul”, de exemplu o captură de ecran a unei pagini de eroare. Imaginile rămân pe acest Mac: doar modelul de pe dispozitiv le citește (macOS 27), niciodată Private Cloud Compute.

macOS

Bara de meniu, notificările, Spotlight, Scurtături și tastatura.

  • ⌘K
  • ⌥⌘P
  • ⇧⌘E
Parte din macOS
Notificări cu Repornește, Vezi jurnalele și Copiază ca prompt. Spotlight găsește containere, proiecte Compose și gazde. Acțiuni pentru Siri și Scurtături, un widget cu starea flotei, comenzi în Centrul de control pentru serviciile apple/container sau pentru un container preferat și linkuri gantry:// pentru scripturi.
Progresul în bara de meniu
Panoul din bara de meniu afișează fiecare descărcare, build și operațiune Compose în curs, cu o bară de progres, straturile sau serviciile terminate, octeții, timpul și un buton Anulează. Pictograma din bara de meniu arată câte operațiuni rulează. Fiecare proiect Compose are Descarcă imaginile și Compose Down; Compose Down păstrează volumele și imaginile.
Paletă de comenzi
Apăsați ⌘K și tastați. O singură căutare acoperă containere, proiecte Compose, imagini, volume, rețele, mașini, clustere și gazde, cu acțiuni precum Pornește, Afișează jurnalele și Deschide shell.
Touch ID pentru acțiuni distructive
Dacă activați opțiunea, Gantry cere Touch ID — sau parola de autentificare — înainte de a elimina un container sau de a șterge o gazdă. Secretele stau deja în portchei.
Teme pentru terminal
Îmbrăcați shellul integrat în Sistem, Solarized Dark, Dracula sau Nord — o paletă completă pentru prim-plan, fundal și 16 culori ANSI, aplicată pe loc.

GUI-ul nativ macOS pentru Apple container

Instrumentul container de la Apple rulează containere Linux ca mașini virtuale ușoare pe Apple silicon, dar vine doar ca instrument de linie de comandă. Gantry este aplicația desktop pentru el: ce este Docker Desktop pentru Docker este Gantry pentru container. Acceptă fiecare CLI container de la 1.0 până la versiunea recomandată 1.7.1 și activează fiecare funcție doar când CLI-ul instalat o acceptă.

  • container system start
  • container machine
  • container builder start
  • container registry login
Containere, jurnale, statistici și exec
Creați, porniți, opriți, forțați oprirea și curățați; jurnale în timp real, statistici, un terminal exec, top și export tar, în aceeași interfață ca gazdele Docker.
Clustere Kubernetes
Creați un cluster Kubernetes cu container cluster: dimensionați separat planul de control și workerii, alegeți CNI-ul și vedeți nodurile, versiunea Kubernetes și contextul kubeconfig. Nodurile clusterului sunt protejate împotriva opririi și ștergerii accidentale. Aflați mai multe
Imagini locale în cluster
Pe CLI 1.7, activați Folosește imaginile locale (--shared-image-store), iar pod-urile rulează imaginile pe care le construiți sau le descărcați, fără registru. Pe CLI 1.5 și 1.6, faceți clic dreapta pe o imagine și alegeți Încarcă în cluster.
Indicații clare când instalarea are probleme
Dacă serviciile clusterului nu răspund, Gantry vă spune de ce. O versiune Homebrew fără serviciile clusterului primește un link către programul de instalare semnat; în orice alt caz apare butonul Repornește serviciile.
Mașini container în VS Code
Creați, porniți și opriți medii Linux container machine, setați CPU-urile și memoria, deschideți un shell sau deschideți mașina în VS Code prin Remote-SSH.
Virtualizare imbricată și kerneluri personalizate
Porniți o mașină cu virtualizare imbricată (M3 sau mai nou) sau cu propriul kernel. Porniți containere dintr-un kernel personalizat, cu argumente de boot suplimentare.
Compose pentru Apple container
apple/container nu are compose. Gantry rulează fișierul dvs. docker-compose.yml: construiește, creează rețeaua și volumele și pornește serviciile în ordinea din depends_on. Numele serviciilor se rezolvă prin aliasuri DNS de rețea.
Aliasuri DNS de rețea
Aliasuri de container, aliasuri de subarbore precum .gateway și nume scurte când este setat un domeniu DNS implicit. Fiecare container primește un IP rutabil și un hostname name.domain.
Gestionarea builderului de imagini
Vedeți starea builderului, imaginea, CPU-urile, memoria și IP-ul. Porniți-l cu opțiuni de CPU, memorie și DNS, opriți-l sau ștergeți-l. Când imaginea builderului este învechită, Gantry se oferă să o recreeze.
Autentificări la registre
Listați, adăugați și eliminați autentificări container registry. Parola ajunge la CLI doar prin stdin, iar Gantry nu păstrează nicio copie.
Instalarea kernelului
Instalați kernelul recomandat, un fișier kernel sau o arhivă tar, cu progresul în timp real. Gantry vă avertizează când nu este instalat niciun kernel implicit.
Servicii și jurnalele serviciilor
Porniți, opriți și reporniți serviciile container, comparați versiunile clientului și serverului și urmăriți în timp real jurnalele serviciilor, filtrate după nivel, serviciu și text.
Editor de proprietăți de sistem
Editați proprietățile de sistem container din config.toml. Gantry marchează modificările care necesită o repornire și repornește serviciile în locul dvs. Pe CLI 1.7, editează și valorile implicite [container.dns]: servere de nume, domenii de căutare și opțiuni.
Salvare ca imagine și Compactează discul
Salvați un container ca imagine (container commit) și recuperați spațiu pe disc cu Compactează discul (container clean), disponibil și în panoul Recuperează spațiu.
Browser de fișiere: încărcare și descărcare
Răsfoiți fișierele unui container, descărcați-le sau trageți-le în Finder (container copy) și plasați înăuntru fișiere sau dosare întregi.
Rulare rapidă și Finder
Alegeți o imagine, partajați un dosar, mapați porturi, alegeți un domeniu și rulați. Faceți clic dreapta pe un fișier Compose în Finder și deschideți-l cu Gantry.
Etichete care conțin =
CLI-ul container respinge valorile de etichetă care conțin =. Gantry le codifică la creare și le decodifică la citire, așa că o valoare precum a=b rămâne intactă.
O flotă, două runtime-uri
Gazdele apple/container stau lângă gazdele Docker locale și SSH pe același panou, cu aceleași minigrafice, aceeași stare de sănătate și aceleași notificări de eroare.

Întrebări

Care este cel mai bun GUI pentru Apple container?

Gantry este un GUI nativ macOS, gratuit și open source, creat pentru instrumentul container de la Apple (apple/container). Acoperă ciclul de viață al containerelor, jurnalele, statisticile și un terminal exec, plus părțile CLI-ului la care alte GUI-uri nu ajung: clustere Kubernetes (container cluster), mașini container, builderul de imagini, autentificările la registre, kerneluri, jurnalele serviciilor și proprietățile de sistem. Acceptă CLI 1.0–1.7.1 și activează fiecare funcție doar când CLI-ul dvs. o acceptă. Vedeți ghidul apple/container.

Ce este Apple container (apple/container)?

apple/container este instrumentul open source de la Apple pentru rularea containerelor Linux pe Mac. Fiecare container rulează în propria mașină virtuală ușoară, construită pe framework-ul Virtualization de la Apple. Necesită un Mac cu Apple silicon și vine ca instrument de linie de comandă numit container, fără aplicație desktop. Gantry adaugă această aplicație desktop.

Gantry acceptă container cluster și Kubernetes?

Da. Pe o gazdă apple/container, Gantry creează și șterge clustere Kubernetes cu container cluster (CLI 1.6.1 și 1.7; CLI 1.5.0–1.6.0 folosesc container k8s). Alegeți numele, workerii, CPU-urile și memoria planului de control și ale workerilor (1.7), imaginea nodurilor, CNI-ul și dacă nodurile folosesc imaginile dvs. locale (1.7). Gantry afișează nodurile, salvează kubeconfig și deschide clusterul în browserul său Kubernetes. Vedeți Kubernetes pe apple/container.

Pot folosi docker compose cu Apple container?

Da. apple/container nu are comanda compose, așa că Gantry face orchestrarea prin CLI-ul container: construiește serviciile cu build:, creează rețeaua proiectului și volumele cu nume și pornește fiecare serviciu în ordinea din depends_on, cu etichetele Compose standard. Numele serviciilor se rezolvă prin aliasuri DNS de rețea. Deschideți un docker-compose.yml din Finder, din meniul Fișier sau trăgându-l în fereastră.

Cum deschid o mașină container în VS Code?

Porniți mașina în Gantry și faceți clic pe Deschide în VS Code. Gantry deschide mașina în VS Code prin Remote-SSH, ca în exemplul container-machine-vscode de la Apple. Imaginea mașinii trebuie să ruleze sshd, iar VS Code cu extensia Remote-SSH trebuie să fie instalat.

Ce versiuni apple/container acceptă Gantry?

Gantry necesită CLI-ul container 1.0 sau o versiune ulterioară și recomandă 1.7.1. Citește versiunea instalată și afișează doar funcțiile acceptate de acea versiune, de exemplu dimensiunile workerilor și depozitul de imagini partajat (1.7), Salvează ca imagine (1.6) și Compactează discul (1.4). Dacă CLI-ul lipsește sau este vechi, Gantry oferă o configurare ghidată.

Poate Gantry răsfoi un cluster Kubernetes?

Da. Secțiunea Kubernetes listează pod-uri, deployment-uri, StatefulSet-uri, DaemonSet-uri, servicii, Ingress-uri, ConfigMap-uri, secrete, noduri și evenimente pentru fiecare context kubeconfig și oferă jurnale de pod, un shell în pod, redirecționări de porturi, scalare, repornire de rollout, ștergere și Aplică YAML. Gantry comunică direct cu API-ul Kubernetes, deci nu aveți nevoie de kubectl. Vedeți Rulați Kubernetes pe Mac.

Ce trimite „Explică eșecul” către Apple Intelligence?

Jurnalele recente și detaliile containerului, fără valorile variabilelor de mediu și fără textul care seamănă cu un secret. Cererile mici rulează pe modelul de pe dispozitiv. Cu opțiunea pentru jurnale lungi activată (macOS 27), jurnalele lungi ajung la Private Cloud Compute. Panoul arată ce s-a trimis. O comandă sugerată se deschide în Terminal, dar nu rulează până nu apăsați Retur. Fără Apple Intelligence, Gantry oferă un prompt pe care îl puteți copia într-un alt asistent AI.

Pot lipi o comandă docker run în Gantry?

Da. În foaia Container nou, alegeți Lipește comanda…. Gantry citește docker run, docker create, podman run și container run, completează formularul și listează fiecare flag pe care nu îl poate folosi, cu motivul. Vedeți Creați un container dintr-o comandă docker run.

Poate Gantry gestiona builderul, registrele și kernelul apple/container?

Da. Secțiunea Sistem a unei gazde apple/container pornește, oprește și șterge builderul de imagini, cu opțiuni de CPU, memorie și DNS; listează, adaugă și elimină autentificări la registre (parola ajunge la CLI doar prin stdin); instalează kernelul recomandat, un fișier kernel sau o arhivă tar; transmite în timp real jurnalele serviciilor; și editează proprietățile de sistem din config.toml.

Este Gantry o alternativă la Docker Desktop, OrbStack sau Podman Desktop?

Ca GUI, da. Gantry este o aplicație nativă macOS gratuită pentru gestionarea containerelor, imaginilor, volumelor, rețelelor, jurnalelor și statisticilor. Este un client, nu un motor: folosește daemonul Docker pe care îl rulați deja (Docker Desktop, OrbStack, Colima) sau instrumentul container de la Apple și adaugă o vizualizare pentru mai multe gazde, gazde SSH și un server MCP. Consultați comparația.

Gantry este gratuit?

Da. Gantry este gratuit și open source, sub licența MIT. Fără abonament, fără cont și fără limită de gazde sau de containere.

De ce am nevoie ca să rulez Gantry?

macOS 26 sau o versiune ulterioară pe Apple silicon sau Intel, plus un daemon Docker (Docker Desktop, OrbStack, Colima sau similar) ori instrumentul container de la Apple. apple/container în sine necesită Apple silicon, așa că pe un Mac cu Intel Gantry gestionează doar gazde Docker.

Gantry funcționează cu OrbStack, Colima și Docker Desktop?

Da. Gantry comunică direct cu API-ul Docker Engine prin socketul Unix, deci funcționează cu orice daemon care îl expune, inclusiv OrbStack, Colima și Docker Desktop.

Poate Gantry gestiona gazde Docker la distanță?

Da. Gantry se conectează la daemonuri la distanță prin SSH, la fel ca docker -H ssh://, cu bastioane ProxyJump, autentificare cu mai multe chei și reconectare automată. Nu trebuie instalat nimic pe server, iar secretele stau în portcheiul macOS.

Mă anunță Gantry când un container cade?

Da. Gantry trimite o notificare nativă macOS când un container se închide neașteptat, rămâne fără memorie sau nu trece verificarea de sănătate pe orice gazdă: locală, SSH sau apple/container. Faceți clic pe ea pentru a ajunge la container. Opririle și repornirile pe care le lansați din Gantry nu generează notificări, iar funcția se poate dezactiva din Configurări.

Poate Gantry descărca imagini din registre private?

Da. Pe gazdele Docker, Gantry citește datele de autentificare din ~/.docker/config.json (același docker login pe care l-ați rulat deja), inclusiv autentificarea inline, credential helpers și portcheiul macOS. Pe gazdele apple/container, gestionează autentificările container registry.

Poate Gantry expune un container local pe internet?

Da. Un clic pe un port publicat îl partajează printr-un Cloudflare Tunnel. Gantry instalează cloudflared dacă este nevoie, apoi pornește un tunel rapid (fără cont Cloudflare, cu un URL temporar trycloudflare.com) sau un tunel cu nume pe propriul dvs. hostname. URL-ul public apare sub port, cu butoane pentru deschidere, copiere și oprire.

Este Gantry o aplicație Electron?

Nu. Gantry este o aplicație nativă construită cu SwiftUI și Swift 6. Interfața este disponibilă în 28 de limbi: engleză, chineză simplificată și 26 de limbi europene, de exemplu sârbă cu alfabet chirilic și latin. Urmează limba sistemului macOS.

Cum instalez Gantry?

Rulați brew install --cask getgantry/tap/gantry sau descărcați cea mai recentă versiune de pe GitHub și trageți Gantry.app în Aplicații.

Pot agenții AI să controleze Gantry?

Da. Gantry include un server MCP și App Intents macOS, astfel încât Claude, Scurtături, Siri și scripturile au aceleași posibilități ca GUI-ul pe fiecare gazdă, inclusiv pe gazdele SSH: containere, imagini, volume, rețele, Compose, mașini apple/container, clustere Kubernetes, instrumentele de sistem apple_* (servicii, builder, registre, proprietăți, jurnale, kernel) și partajarea porturilor. Pe macOS 26 și versiunile ulterioare, Explică eșecul… întreabă și Apple Intelligence de ce a eșuat un container. Adăugați serverul MCP cu claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp.

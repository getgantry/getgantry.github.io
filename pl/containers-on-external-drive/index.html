Gantry/Dysk zewnętrzny

Kontenery i woluminy na dysku zewnętrznym

Obrazy, kontenery i woluminy szybko zapełniają mały dysk wewnętrzny. Z narzędziem container od Apple możesz trzymać te dane na zewnętrznym dysku SSD: umieścić tam pojedyncze foldery przez montowania katalogów albo przenieść cały katalog danych. Ten przewodnik pokazuje oba sposoby i to, jak odłączyć dysk bez szkód.

W skrócie. Sformatuj dysk jako APFS. Dla jednego projektu zamontuj folder: -v /Volumes/Fast/pg:/data. Dla wszystkiego zatrzymaj usługi, skopiuj ~/Library/Application Support/com.apple.container na dysk poleceniem cp -Rp i za każdym razem uruchamiaj usługi poleceniem container system start --app-root /Volumes/Fast/container.

Gdzie są teraz dane

apple/container trzyma wszystkie dane w jednym folderze, katalogu głównym aplikacji (app root). Domyślnie to ~/Library/Application Support/com.apple.container, z folderami na kontenery, zawartość obrazów, migawki, woluminy, jądra i sieci. Sprawdź ścieżkę i zajęte miejsce:

Terminal
container system status | grep appRoot
container system df

Wybór i formatowanie dysku

  • Użyj dysku SSD na USB-C lub Thunderbolt. Dysk talerzowy też działa, ale kontenery uruchamiają się wolniej.
  • Sformatuj go jako APFS (Mac OS Extended też działa). Nie używaj exFAT, FAT ani NTFS: woluminy to rzadkie obrazy dysku, a te systemy plików nie mają plików rzadkich ani uprawnień uniksowych.
  • Nie używaj dysku sieciowego jako katalogu głównego aplikacji.
  • Nadaj dyskowi krótką nazwę bez spacji, na przykład Fast. Ścieżka to wtedy /Volumes/Fast.
    Sposób 1: dane projektu na dysku przez montowania katalogów

Montowanie katalogu udostępnia kontenerowi folder z Twojego Maca, a ten folder może być na dowolnym dysku. To prosty sposób, żeby trzymać duże dane, takie jak baza danych czy pliki modeli, poza dyskiem wewnętrznym:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Dysk musi być podłączony, zanim kontener się uruchomi. Obrazy i sam kontener zostają na dysku wewnętrznym.

    Sposób 2: wszystkie dane apple/container na dysku

Ten sposób przenosi obrazy, kontenery, migawki i woluminy. Najpierw zatrzymaj usługi, żeby żaden plik nie zmienił się podczas kopiowania:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Użyj cp -Rp. W naszym teście na macOS 27 (z APFS na APFS przez USB) zachował rzadkie obrazy woluminów i rozszerzone atrybuty. ditto zapisał każdy rzadki obraz w pełnym rozmiarze, co może zapełnić dysk. Zachowaj stary folder, dopóki nie sprawdzisz, że Twoje kontenery, obrazy i woluminy są na liście.

Uwaga
CLI nie zapamiętuje --app-root. Każde container system start bez tej flagi znowu używa folderu wewnętrznego. Podawaj flagę za każdym razem, na przykład w aliasie powłoki, i sprawdzaj paths.appRoot w container system status.

Gantry 0.27.0 uruchamia usługi bez --app-root, gdy łączy się z hostem, którego usługi są zatrzymane. Najpierw uruchom usługi z tą flagą w terminalu; Gantry użyje wtedy działających usług.

    Archiwizacja obrazów na dysku

Aby zwolnić miejsce bez utraty obrazu, zapisz go na dysku zewnętrznym i usuń. Gdy będzie potrzebny, wczytaj go ponownie:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Bezpieczne odłączanie dysku
  1. Zatrzymaj kontenery, które używają dysku: container stop <name>.
  2. Jeśli katalog główny aplikacji jest na dysku, zatrzymaj usługi: container system stop.
  3. Wysuń dysk w Finderze, a potem go odłącz.

Jeśli dysk zniknie, gdy działają z niego kontenery, ulegną one awarii, a trwające zapisy mogą przepaść. Po ponownym podłączeniu dysku uruchom usługi z --app-root, a potem kontenery.

    Dyski zewnętrzne w Gantry

Gantry już teraz obsługuje montowania katalogów z dowolnego dysku: w Nowy kontener dodaj wolumin, wybierz folder na dysku zewnętrznym i ścieżkę w kontenerze.

    Docker Desktop i OrbStack

Docker Desktop przenosi swój obraz dysku w Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack dodał ustawienie lokalizacji danych w wersji 0.13.0. Zobacz porównanie.

Pytania i odpowiedzi

Czy mogę trzymać obrazy Apple container na dysku zewnętrznym?

Tak. Uruchom usługi poleceniem container system start --app-root /Volumes/Disk/container. Wszystkie obrazy, kontenery, migawki i woluminy będą wtedy w tym folderze.

Jakiego systemu plików użyć na dysku zewnętrznym?

APFS. Woluminy to rzadkie obrazy dysku, a kontenery potrzebują uprawnień uniksowych, których exFAT, FAT i NTFS nie mają.

Jak skopiować dane kontenerów, nie zapełniając dysku?

Użyj cp -Rp, który w naszym teście zachował małe rzadkie obrazy woluminów. ditto skopiował każdy rzadki obraz w pełnym rozmiarze.

Co się stanie, jeśli odłączę dysk, gdy działają kontenery?

Kontenery, które używają dysku, ulegną awarii, a dane jeszcze niezapisane mogą przepaść. Przed wysunięciem dysku zatrzymaj kontenery, a jeśli katalog główny aplikacji jest na dysku, także usługi.

Czy CLI container zapamiętuje nową lokalizację?

Nie. Podawaj --app-root przy każdym container system start. container system status pokazuje używany katalog jako paths.appRoot.

Gantry/Scanarea imaginilor

Scanați imaginile de containere pentru vulnerabilități pe Mac

Trivy și Grype sunt scanere gratuite și open source care compară pachetele dintr-o imagine cu baze de date de vulnerabilități cunoscute. Ele citesc direct imaginile Docker. Instrumentul container de la Apple nu are o comandă de scanare și nici un socket Docker, așa că salvați mai întâi imaginea. Acest ghid arată ambele variante, cum citiți rezultatele, cum scrieți un SBOM și cum scanați din Gantry.

Pe scurt. Rulați brew install trivy grype. Pe Docker, rulați trivy image app:dev. Pe Apple container, salvați imaginea cu container image save --platform linux/arm64 -o app.tar app:dev, dezarhivați-o cu tar -xf app.tar -C app-img și scanați dosarul: trivy image --input app-img sau grype oci-dir:app-img. Ambele instrumente refuză fișierul tar propriu-zis.

Instalați un scaner

Instalați unul sau ambele scanere cu Homebrew. Fiecare își descarcă baza de date de vulnerabilități la prima scanare, ceea ce durează aproximativ un minut.

Terminal
brew install trivy grype

Am verificat comenzile din acest ghid cu Trivy 0.76.2, Grype 0.121.3 și container 1.7.1. Gantry are nevoie de Trivy 0.50.0 sau Grype 0.74.0 ori mai nou.

Scanați o imagine Docker

Cu un motor Docker (Docker Desktop, OrbStack sau Colima), ambele instrumente citesc o imagine locală după nume, prin socketul Docker:

Terminal
trivy image app:dev
grype app:dev

Scanați o imagine Apple container

Salvați imaginea într-o arhivă OCI și dezarhivați-o într-un dosar. Transmiteți --platform: când depozitul de imagini are doar unele platforme ale unei imagini, container image save eșuează fără această opțiune.

Terminal
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Apoi scanați dosarul. Trivy îl citește cu --input, Grype cu prefixul oci-dir::

Terminal
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Atenție
Nu transmiteți fișierul .tar. Arhiva produsă de container image save începe cu intrarea ./: Trivy raportează „file manifest.json not found in tar”, iar Grype o respinge ca „potential path traversal attack”. Dosarul dezarhivat funcționează cu ambele.

Citiți rezultatele

  • Severitate: Critical, High, Medium, Low sau Unknown. Începeți cu Critical și High. --severity HIGH,CRITICAL limitează ieșirea Trivy.
  • Versiunea instalată și versiunea cu remediere: dacă există o versiune cu remediere, actualizați imaginea de bază sau pachetul și construiți din nou. trivy --ignore-unfixed și grype --only-fixed ascund rezultatele fără remediere.
  • „won't fix”: distribuția a decis să nu remedieze pachetul în această versiune. Folosiți o imagine de bază mai nouă sau acceptați riscul.
  • Două instrumente, două baze de date: Trivy și Grype raportează adesea numere diferite. Niciunul nu greșește; folosesc surse diferite.

Exportați un SBOM

O listă a componentelor software (SBOM) enumeră fiecare pachet din imagine. Trivy scrie CycloneDX și SPDX; Syft, instrumentul însoțitor al lui Grype, le scrie și el pe amândouă.

Terminal
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Opriți un build la rezultate grave

Într-un script, lăsați scanerul să seteze codul de ieșire. Grype iese cu un cod diferit de zero când există un rezultat cu severitatea dată sau mai mare; cu Trivy, folosiți --exit-code 1 --severity HIGH,CRITICAL.

Terminal
grype oci-dir:python-img --fail-on high
echo $?

Scanați din Gantry

Gantry 0.29.0 face acești pași în locul dvs. Alegeți Scanează vulnerabilitățile… din meniul imaginii sau din bara de instrumente a detaliilor imaginii.

  • Gantry găsește Trivy sau Grype în GANTRY_TRIVY sau GANTRY_GRYPE, în PATH ori în /opt/homebrew/bin și /usr/local/bin. Trivy este implicit când ambele sunt instalate. Fără scaner, foaia afișează comenzile Homebrew.
  • Pe apple/container, Gantry salvează imaginea cu --platform, o dezarhivează și scanează dosarul. Pe Docker local, scanează o arhivă salvată. Pe Docker prin SSH, scanează copia din registru a tagului.
  • Rezultatele sunt grupate după severitate, cu un simbol și un cuvânt, nu doar cu o culoare. Fiecare rând are ID-ul cu link, pachetul, versiunea instalată și versiunea cu remediere. Un filtru găsește un pachet sau un ID.
  • Exportă SBOM scrie CycloneDX (ambele instrumente) sau SPDX (Trivy).
  • Oprește sau închiderea foii oprește scanerul și șterge fișierele temporare.

Întrebări și răspunsuri

Cum scanez o imagine Apple container pentru vulnerabilități?

Salvați-o cu container image save --platform linux/arm64 -o app.tar app:dev, dezarhivați-o cu tar -xf app.tar -C app-img, apoi rulați trivy image --input app-img sau grype oci-dir:app-img. Gantry face acești pași cu Scanează vulnerabilitățile….

De ce eșuează Trivy sau Grype pe arhiva produsă de container image save?

Arhiva începe cu intrarea ./. Trivy nu găsește în ea manifest.json sau index.json, iar Grype tratează intrarea ca path traversal. Dezarhivați arhiva și scanați dosarul.

Trivy sau Grype: pe care să îl folosesc?

Ambele sunt gratuite și open source. Trivy găsește și secrete și configurări greșite și scrie SPDX; Grype este mic și axat pe pachete. Folosesc baze de date diferite, așa că rularea ambelor găsește mai mult. Gantry folosește Trivy când ambele sunt instalate.

Instalează Gantry scanerele?

Nu. Instalați-le cu brew install trivy grype. Gantry le caută în PATH, /opt/homebrew/bin și /usr/local/bin sau în GANTRY_TRIVY și GANTRY_GRYPE.

Am nevoie de Docker Scout sau de un cont Docker pentru a scana imagini?

Nu. Trivy și Grype funcționează fără cont, pe imaginile Docker și pe imaginile Apple container.

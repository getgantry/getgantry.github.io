Gantry/Kubernetes на Mac-у

Kubernetes на Mac-у уз Apple container

Apple-ов алат container може једном командом да креира локални Kubernetes кластер. Сваки чвор је лака виртуелна машина на вашем Mac-у. Овај водич води од празног Mac-а до покренутог deployment-а, прво у терминалу, а затим у Gantry-ју.

Укратко. Инсталирајте потписани пакет container 1.7.1, покрените container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, изградите слику командом container build и покрените је у кластеру по имену. Gantry приказује исти кластер у прозору: чворове, подове, логове, љуску и прослеђене портове.

Шта вам је потребно

  • Mac са Apple silicon-ом и macOS-ом 26 или новијим.
  • container CLI 1.7.1 из потписаног .pkg пакета са странице издања apple/container-а. Homebrew верзија 1.7.1 не садржи сервисе кластера, па container cluster не успева са поруком cluster service unavailable.
  • Око 6 GB слободне меморије за пример испод: три чвора са по 2 GB.
  • kubectl ако желите да кластер користите из терминала (brew install kubectl).

Покрените сервисе једном, након инсталације пакета:

Терминал
container system start

Креирање кластера

Ова команда прави кластер под именом dev са једним чвором контролне равни и два радна чвора. Сваки чвор добија 2 CPU-а и 2 GB меморије:

Терминал
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M одређује величину групе радних чворова. Поновите је за групе различитих величина. Без --workers један чвор је и контролна раван и радни чвор.
  • --cpus и --memory одређују величину контролне равни. Подразумевано је четвртина CPU-ова и меморије вашег Mac-а, најмање 2 CPU-а и 2 GB.
  • --shared-image-store дозвољава чворовима да користе ваше локалне слике (погледајте испод). Касније не можете да га промените: обришите кластер и креирајте га поново.
  • --cni ./calico.yaml инсталира ваш CNI уместо приложеног kindnet-а; --cni NONE не инсталира ниједан.

CLI додаје контекст под именом dev у ~/.kube/config. Проверите чворове:

Терминал
container cluster list --nodes
kubectl --context dev get nodes

Покретање локалне слике без регистра

Уз --shared-image-store чворови могу да покрену било коју слику из вашег локалног container складишта слика. Изградите слику и користите је по имену:

Терминал
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Напомена
Када поново изградите исту ознаку, покрените kubectl rollout restart уз imagePullPolicy: Always или користите нову ознаку. Уз IfNotPresent чвор задржава копију коју већ има. Све што има root приступ на чвору може да чита сваку слику у вашем локалном складишту, укључујући приватне слике, па заједничко складиште користите само за локални развој.

На CLI-ју 1.5 и 1.6 нема заједничког складишта. Тамо користите container cluster load-image или Учитај у кластер у Gantry-ју. CLI 1.7 је уклонио load-image.

Отварање апликације у прегледачу

Проследите локални порт ка deployment-у, а затим отворите http://localhost:8080:

Терминал
kubectl --context dev port-forward deployment/hello 8080:80

Преглед кластера у Gantry-ју

Gantry приказује исти кластер без команди. Додајте свој apple/container хост, отворите Кластери и изаберите dev. Преглед приказује верзију Kubernetes-а, складиште слика, радне чворове и њихов CPU и меморију. Кликните Прегледај ресурсе да бисте отворили одељак Kubernetes на том контексту.

  • Подови, deployment-и, stateful set-ови, daemon set-ови, сервиси, ingress-и, config map-е, тајне, чворови и догађаји, за један простор имена или за све.
  • Логови пода уз праћење и последње редове, љуска у поду и прослеђивање портова са листом из које можете да их зауставите.
  • Скалирање, rollout restart, брисање и Примени YAML из налепљеног манифеста или датотеке.
  • Вредности тајни остају скривене док не кликнете Откриј.

Kubernetes прегледач покреће kubectl. Ако недостаје, Gantry приказује brew install kubectl и може да га покрене уместо вас. Нативни клијент коме није потребан kubectl је у развоју.

Кластер можете да креирате и у Gantry-ју: Кластери ▸ Нови кластер има бројаче за контролну раван и радне чворове и прекидач Користи локалне слике. Више на страници Kubernetes на apple/container-у.

Заустављање и брисање кластера

Терминал
container cluster delete --name dev

Ако се чвор контролне равни заустави, на пример након container system stop, обришите кластер и креирајте га поново. Привремени кластер креирајте уз --rm, да би се његови чворови уклонили када се зауставе.

Чести проблеми

  • cluster service unavailable: CLI је Homebrew верзија или сервиси нису покренути. Инсталирајте потписани пакет или поново покрените сервисе командама container system stop и container system start. Gantry исти савет приказује у одељку Кластери.
  • Стари кластер недостаје на листи: CLI 1.7 не приказује кластере креиране у 1.6 или старијем. Уклоните такав кластер командом container cluster delete --name <name>.
  • Чворови остају NotReady: користили сте --cni NONE. Примените CNI манифест.
  • Не можете да зауставите контејнер чвора: то је намерно. container stop и delete одбијају чворове кластера; користите container cluster delete.

Поређење са Docker Desktop-ом и OrbStack-ом

Docker Desktop има уграђени Kubernetes са kubeadm-ом (један чвор) или kind-ом (више чворова), а OrbStack има уграђени кластер са једним чвором. container cluster покреће kubeadm на сликама kindest/node, сваки чвор у сопственој VM, са кластерима од више чворова и заједничким складиштем слика. Погледајте потпуно поређење.

Сродна упутства

  • Прелазак са Docker Desktop-а на Apple container: команде, Compose, волумени и недостаци
  • Контејнери и волумени на спољном диску на Mac-у
  • Контејнер из docker run команде на Mac-у (docker run у container run)
  • Apple container GUI за Mac: комплетан водич за apple/container
  • Kubernetes на Apple container-у: GUI за container cluster и Kubernetes прегледач

Питања и одговори

Могу ли да покрећем Kubernetes на Mac-у без Docker-а?

Да. Apple-ов container CLI сам креира Kubernetes кластере командом container cluster create. Сваки чвор ради као лака VM, а нису вам потребни Docker, Docker Desktop, kind ни minikube.

Колико чворова може да има container cluster?

Једну контролну раван и онолико радних чворова колико ваш Mac има CPU-ова и меморије. Подесите их опцијом --workers; на CLI-ју 1.7 свака група радних чворова може да има сопствени CPU и меморију.

Како да користим локално изграђену слику у кластеру?

Креирајте кластер уз --shared-image-store (CLI 1.7), изградите слику командом container build -t name:tag . и користите name:tag у спецификацији пода. Регистар није потребан.

Коју верзију Kubernetes-а користи container cluster?

CLI 1.7.1 подразумевано користи слику чвора kindest/node:v1.35.5. Другу верзију изаберите опцијом --node-image, на пример docker.io/kindest/node:v1.34.11. Gantry приказује верзију у прегледу кластера.

Да ли постоји GUI за container cluster?

Да. Gantry креира и брише кластере, приказује чворове и у свом одељку Kubernetes прегледа подове, deployment-е, сервисе, логове и тајне. Бесплатан је и отвореног кода.

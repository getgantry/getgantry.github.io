Kubernetes на Mac с Apple container

Инструментът container на Apple може да създаде локален клъстер на Kubernetes с една команда. Всеки възел е лека виртуална машина на вашия Mac. Това ръководство води от празен Mac до работещ deployment, първо в терминала, а след това в Gantry.

Накратко. Инсталирайте подписания пакет container 1.7.1, изпълнете container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, изградете образ с container build и го стартирайте в клъстера по име. Gantry показва същия клъстер в прозорец: възли, подове, логове, обвивка и пренасочени портове.

Какво ви трябва

  • Mac с Apple silicon и macOS 26 или по-нова.
  • CLI container 1.7.1 от подписания .pkg на страницата с версии на apple/container. Компилацията на 1.7.1 от Homebrew не включва услугите на клъстера, така че container cluster завършва с cluster service unavailable.
  • Около 6 GB свободна памет за примера по-долу: три възела по 2 GB.
  • kubectl, ако искате да използвате клъстера от терминала (brew install kubectl).

Стартирайте услугите веднъж, след като инсталирате пакета:

Терминал
container system start

Създаване на клъстера

Тази команда създава клъстер с име dev с един управляващ възел и два работни възела. Всеки възел получава 2 CPU и 2 GB памет:

Терминал
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M задава размера на група работни възли. Повторете го за групи с различни размери. Без --workers един възел е и управляващ, и работен.
  • --cpus и --memory задават размера на управляващия възел. По подразбиране това е една четвърт от CPU и паметта на вашия Mac, най-малко 2 CPU и 2 GB.
  • --shared-image-store позволява на възлите да използват локалните ви образи (вижте по-долу). Не можете да го промените по-късно: изтрийте клъстера и го създайте отново.
  • --cni ./calico.yaml инсталира ваш CNI вместо вградения kindnet; --cni NONE не инсталира никакъв.

CLI добавя контекст с име dev в ~/.kube/config. Проверете възлите:

Терминал
container cluster list --nodes
kubectl --context dev get nodes

Стартиране на локален образ без регистър

С --shared-image-store възлите могат да стартират всеки образ от локалния ви склад за образи на container. Изградете образ и го използвайте по име:

Терминал
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Бележка
След като изградите отново същия таг, изпълнете kubectl rollout restart с imagePullPolicy: Always или използвайте нов таг. С IfNotPresent възелът запазва копието, което вече има. Всичко с root достъп до възел може да чете всеки образ в локалния ви склад, включително частни образи, затова използвайте общия склад само за локална разработка.

В CLI 1.5 и 1.6 няма общ склад. Там използвайте container cluster load-image или Зареди в клъстер в Gantry. CLI 1.7 премахна load-image.

Отваряне на приложението в браузър

Пренасочете локален порт към deployment, след това отворете http://localhost:8080:

Терминал
kubectl --context dev port-forward deployment/hello 8080:80

Разглеждане на клъстера в Gantry

Gantry показва същия клъстер без команди. Добавете своя хост с apple/container, отворете Клъстери и изберете dev. Обзорът показва версията на Kubernetes, склада за образи, работните възли и техните CPU и памет. Щракнете Разгледай ресурсите, за да отворите раздела Kubernetes в този контекст.

  • Подове, deployments, stateful sets, daemon sets, услуги, ingresses, config maps, тайни, възли и събития, за едно пространство от имена или за всички.
  • Логове на подовете със следене и последни редове, обвивка в пода и пренасочване на портове със списък, от който можете да ги спирате.
  • Мащабиране, rollout restart, изтриване и Приложи YAML от поставен манифест или файл.
  • Стойностите на тайните остават скрити, докато не щракнете „Покажи“.

Браузърът за Kubernetes изпълнява kubectl. Ако липсва, Gantry показва brew install kubectl и може да го изпълни вместо вас. В процес на разработка е нативен клиент, който не изисква kubectl.

Можете да създадете клъстера и в Gantry: Клъстери ▸ Нов клъстер има броячи за управляващия възел и работните възли и превключвател Използвай локални образи. Повече на страницата Kubernetes в apple/container.

Спиране и изтриване на клъстера

Терминал
container cluster delete --name dev

Ако управляващият възел спре, например след container system stop, изтрийте клъстера и го създайте отново. Създайте временен клъстер с --rm, за да се премахват възлите му, когато спрат.

Чести проблеми

  • cluster service unavailable: CLI е компилацията от Homebrew или услугите не работят. Инсталирайте подписания пакет или рестартирайте услугите с container system stop и container system start. Gantry показва същия съвет в „Клъстери“.
  • Стар клъстер липсва в списъка: CLI 1.7 не показва клъстери, създадени с 1.6 или по-стара версия. Премахнете такъв клъстер с container cluster delete --name <name>.
  • Възлите остават NotReady: използвали сте --cni NONE. Приложете манифест на CNI.
  • Не можете да спрете контейнер на възел: това е нарочно. container stop и delete отказват за възли на клъстер; използвайте container cluster delete.

Сравнение с Docker Desktop и OrbStack

Docker Desktop има вграден Kubernetes с kubeadm (един възел) или kind (няколко възела), а OrbStack има вграден клъстер с един възел. container cluster изпълнява kubeadm върху образи kindest/node, всеки възел в собствена виртуална машина, с клъстери с няколко възела и общ склад за образи. Вижте пълното сравнение.

Свързани ръководства

  • Преминаване от Docker Desktop към Apple container: команди, Compose, томове и пропуски
  • Контейнери и томове на външен диск на Mac
  • Създаване на контейнер от команда docker run на Mac (docker run към container run)
  • GUI за Apple container на Mac: пълно ръководство за apple/container
  • Kubernetes в Apple container: GUI за container cluster и браузър за Kubernetes

Въпроси и отговори

Мога ли да стартирам Kubernetes на Mac без Docker?

Да. CLI container на Apple сам създава клъстери на Kubernetes с container cluster create. Всеки възел работи като лека виртуална машина и не ви трябват Docker, Docker Desktop, kind или minikube.

Колко възела може да има един container cluster?

Един управляващ възел и толкова работни възли, колкото позволяват CPU и паметта на вашия Mac. Задайте ги с --workers; в CLI 1.7 всяка група работни възли може да има собствени CPU и памет.

Как да използвам локално изграден образ в клъстера?

Създайте клъстера с --shared-image-store (CLI 1.7), изградете образа с container build -t name:tag . и използвайте name:tag в спецификацията на пода. Не е нужен регистър.

Коя версия на Kubernetes използва container cluster?

CLI 1.7.1 използва по подразбиране образа на възел kindest/node:v1.35.5. Изберете друга версия с --node-image, например docker.io/kindest/node:v1.34.11. Gantry показва версията в обзора на клъстера.

Има ли GUI за container cluster?

Да. Gantry създава и изтрива клъстери, показва възлите и разглежда подове, deployments, услуги, логове и тайни в своя раздел Kubernetes. Безплатен е и е с отворен код.

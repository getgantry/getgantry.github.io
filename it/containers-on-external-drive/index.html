Gantry/Disco esterno

Container e volumi su un disco esterno

Immagini, container e volumi riempiono in fretta un disco interno piccolo. Con lo strumento container di Apple puoi tenere questi dati su un SSD esterno: metti lì singole cartelle con i bind mount, oppure sposta l'intera radice dei dati. Questa guida mostra entrambi i modi, e come scollegare il disco senza danni.

In breve. Formatta il disco in APFS. Per un solo progetto, monta una cartella con un bind mount: -v /Volumes/Fast/pg:/data. Per tutto, arresta i servizi, copia ~/Library/Application Support/com.apple.container sul disco con cp -Rp e avvia ogni volta i servizi con container system start --app-root /Volumes/Fast/container.

Dove sono i dati adesso

apple/container tiene tutti i suoi dati in un'unica cartella, la radice dell'app (app root). Per impostazione predefinita è ~/Library/Application Support/com.apple.container, con cartelle per container, contenuti delle immagini, snapshot, volumi, kernel e reti. Controlla il percorso e lo spazio occupato:

Terminale
container system status | grep appRoot
container system df

Scegli e formatta il disco

  • Usa un SSD USB-C o Thunderbolt. Un disco meccanico funziona, ma i container si avviano più lentamente.
  • Formattalo in APFS (va bene anche Mac OS esteso). Non usare exFAT, FAT o NTFS: i volumi sono immagini disco sparse, e questi file system non hanno né file sparsi né permessi Unix.
  • Non usare un disco di rete per la radice dell'app.
  • Dai al disco un nome breve e senza spazi, per esempio Fast. Il percorso sarà /Volumes/Fast.

Opzione 1: dati del progetto sul disco con i bind mount

Un bind mount condivide una cartella del Mac con il container, e la cartella può trovarsi su qualsiasi disco. È il modo più semplice per tenere dati voluminosi, come un database o i file di un modello, fuori dal disco interno:

Terminale
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Il disco deve essere collegato prima che il container si avvii. Le immagini e il container stesso restano sul disco interno.

Opzione 2: sposta tutti i dati di apple/container sul disco

Così sposti immagini, container, snapshot e volumi. Prima arresta i servizi, così nessun file cambia durante la copia:

Terminale
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Usa cp -Rp. Nel nostro test su macOS 27 (da APFS ad APFS via USB), ha mantenuto sparse le immagini dei volumi e ha conservato gli attributi estesi. ditto ha scritto ogni immagine sparsa a piena dimensione, cosa che può riempire il disco. Tieni la vecchia cartella finché non hai verificato che container, immagini e volumi siano elencati.

Attenzione
La CLI non ricorda --app-root. Ogni container system start senza il flag usa di nuovo la cartella interna. Usa il flag ogni volta, per esempio in un alias della shell, e controlla paths.appRoot in container system status.

Gantry 0.27.0 avvia i servizi senza --app-root quando si connette a un host con i servizi arrestati. Avvia prima i servizi dal terminale con il flag; Gantry userà poi i servizi in esecuzione. Il supporto di Gantry per una radice dei dati spostata è in sviluppo.

Archivia le immagini sul disco

Per liberare spazio senza perdere un'immagine, salvala sul disco esterno ed eliminala. Caricala di nuovo quando ti serve:

Terminale
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Scollega il disco in sicurezza

  1. Arresta i container che usano il disco: container stop <name>.
  2. Se la radice dell'app è sul disco, arresta i servizi: container system stop.
  3. Espelli il disco nel Finder, poi scollegalo.

Se il disco scompare mentre ci sono container in esecuzione da lì, questi non funzionano più, e le scritture in corso possono andare perse. Dopo aver ricollegato il disco, avvia i servizi con --app-root, poi avvia i container.

Dischi esterni in Gantry

Gantry esegue già oggi bind mount da qualsiasi disco: in Nuovo container, aggiungi un volume, scegli una cartella sul disco esterno e un percorso nel container. Il supporto di Gantry per lo spostamento della radice dei dati, i volumi su un disco esterno e un avviso quando il disco non è collegato è in sviluppo.

Docker Desktop e OrbStack

Docker Desktop sposta la sua immagine disco in Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack ha aggiunto un'impostazione per la posizione dei dati nella versione 0.13.0. Vedi il confronto.

Domande e risposte

Posso tenere le immagini di Apple container su un disco esterno?

Sì. Avvia i servizi con container system start --app-root /Volumes/Disk/container. Tutte le immagini, i container, gli snapshot e i volumi si troveranno in quella cartella.

Quale file system deve usare il disco esterno?

APFS. I volumi sono immagini disco sparse e i container hanno bisogno dei permessi Unix, che exFAT, FAT e NTFS non hanno.

Come copio i dati dei container senza riempire il disco?

Usa cp -Rp, che nel nostro test ha mantenuto piccole le immagini sparse dei volumi. ditto ha copiato ogni immagine sparsa a piena dimensione.

Cosa succede se scollego il disco mentre i container sono in esecuzione?

I container che usano il disco non funzionano più, e i dati non ancora scritti possono andare persi. Prima di espellere il disco, arresta i container e, se la radice dell'app è sul disco, i servizi.

La CLI container ricorda la nuova posizione?

No. Passa --app-root a ogni container system start. container system status mostra la radice in uso come paths.appRoot.

Gantry/Z docker run

Kontajner z príkazu docker run

Väčšina súborov README uvádza riadok docker run. Gantry tento riadok prečíta a vyplní formulár Nový kontajner, pre hostiteľa Docker alebo pre nástroj container od Apple. Tento návod ukazuje ako a aj ako príkaz previesť ručne.

V skratke. V Gantry otvorte Nový kontajner, zvoľte Vložiť príkaz…, vložte riadok docker run a kliknite na Vyplniť formulár. Gantry vypíše každý príznak, ktorý nemôže použiť, aj s dôvodom. V CLI je väčšina príznakov rovnaká: nahraďte docker run za container run a odstráňte --restart.

Vloženie príkazu v Gantry

  1. Vyberte hostiteľa: hostiteľa Docker alebo hostiteľa apple/container.
  2. Otvorte Kontajnery a kliknite na Nový kontajner.
  3. Kliknite na Vložiť príkaz… a vložte riadok. Konce riadkov s \, úvodzovky, výzva $ aj sudo nevadia.
  4. Prezrite si náhľad: obraz, príznaky, ktoré Gantry nemôže použiť, poznámky a upozornenia pre tohto hostiteľa.
  5. Kliknite na Vyplniť formulár, skontrolujte hodnoty a vytvorte kontajner.

Gantry číta docker run, docker container run, docker create, podman run a container run. Text za &&, ||, ; alebo | sa ignoruje, s poznámkou.

Gantry pozná asi 80 ďalších príznakov Dockeru: správne preskočí ich hodnoty a vypíše ich ako nepoužité, takže sa nič nestratí bez poznámky.

Upozornenia pre hostiteľov apple/container

Niektoré možnosti Dockeru v apple/container neexistujú. Gantry na ne upozorní a vynechá ich z požiadavky na vytvorenie:

  • politiky reštartu (--restart);
  • zlomky CPU, napríklad --cpus 0.5;
  • sieťové režimy host, none a container:;
  • porty bez portu hostiteľa, napríklad -p 80.

Na hostiteľovi Docker Gantry upozorní na možnosti apple/container: doménu DNS a možnosti jadra.

Ručný prevod docker run na container run

V CLI zostáva väčšina príznakov rovnaká. Príklad s Redis:

Terminál
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

sa zmení na:

Terminál
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Najprv vytvorte pomenovaný zväzok príkazom container volume create. Odstráňte --restart a zaokrúhlite --cpus na celé číslo. --platform funguje ako v Dockeri.

Kopírovanie kontajnera ako príkazu

Funguje to aj opačne. Kliknite na kontajner pravým tlačidlom alebo použite menu Viac a zvoľte Kopírovať ako príkaz: Gantry vytvorí riadok docker run alebo container run. Vynechá predvolené hodnoty obrazu, napríklad jeho prostredie a príkaz, takže riadok zostane krátky. Funguje to aj pri zastavených kontajneroch.

Uloženie ako recept

V hárku Nový kontajner otvorte Recepty a zvoľte Uložiť ako recept…. Nabudúce vám Vyplniť z receptu dá ten istý formulár na ľubovoľnom hostiteľovi. Recepty sú v ~/Library/Application Support/Gantry/recipes.json, takže ich môžete zálohovať alebo zdieľať.

Obmedzenia

  • Gantry zachová cestu --env-file, ale súbor nečíta, a pri -e KEY bez hodnoty nečíta váš shell.
  • Pripojenia tmpfs a anonymné zväzky z --mount sa vypíšu ako nepodporované.
  • Dva porty pre ten istý port kontajnera (-p 8080:80 -p 8081:80) formulár vyplnia, ale formulár potom duplikát odmietne.

Otázky a odpovede

Ako previesť docker run na container run?

Nahraďte docker run za container run. -d, -p, -e, -v, --name, --rm, -it, -w a --entrypoint zostávajú rovnaké. Odstráňte --restart a používajte celé CPU. Alebo riadok vložte do Gantry a nechajte ju vyplniť formulár.

Dokáže Gantry importovať príkaz docker run?

Áno. Vložiť príkaz… v hárku Nový kontajner prečíta docker run, docker create, podman run a container run a vyplní formulár.

Čo sa stane s príznakmi, ktoré Gantry nepodporuje?

Vypíšu sa v náhľade aj s dôvodom a zostanú vo formulári v sekcii Z vloženého príkazu, takže ich môžete skontrolovať neskôr.

Môžem bežiaci kontajner previesť späť na príkaz docker run?

Áno. Kopírovať ako príkaz v menu kontajnera vytvorí pre tento kontajner riadok docker run alebo container run.

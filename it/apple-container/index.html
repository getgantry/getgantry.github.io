Gantry/Guida ad apple/container

Apple container su Mac: la guida completa e la GUI

apple/container esegue container Linux sul tuo Mac, ognuno nella propria macchina virtuale leggera. È distribuito come strumento a riga di comando. Gantry è una GUI nativa per macOS che lo gestisce. Questa guida spiega lo strumento, come configurarlo e quale funzione di Gantry copre ogni comando container.

In breve. Gantry è un'app per macOS gratuita e open source (MIT) che gestisce lo strumento container di Apple e Docker da un'unica finestra. Supporta le CLI container dalla 1.0 alla 1.7.1 (consigliata) e mostra solo le funzioni che la tua versione della CLI supporta. Installala con brew install --cask getgantry/tap/gantry.

Cos'è apple/container?

apple/container è uno strumento open source di Apple, scritto in Swift, che crea ed esegue container Linux su un Mac. Docker Desktop esegue tutti i container in un'unica VM Linux condivisa; apple/container esegue ogni container nella propria macchina virtuale leggera, basata sul framework Virtualization di Apple. Usa immagini OCI standard, quindi scarica dagli stessi registri di Docker e carica su di essi.

  • Hardware: un Mac con chip Apple.
  • macOS: Apple lo supporta su macOS 26.
  • Interfaccia: solo la CLI container. Non c'è un'app desktop né un comando compose.
  • Rete: ogni container riceve un proprio indirizzo IP sul tuo Mac, e i domini DNS locali danno ai container nomi come web.test.

Perché usare una GUI per apple/container?

La CLI è completa, ma il lavoro quotidiano richiede molti comandi: container list, logs, stats, exec, poi system, builder, registry, machine e cluster per il resto. Gantry li riunisce in un'unica finestra con aggiornamenti in tempo reale, così vedi lo stato invece di doverlo interrogare. Aggiunge anche ciò che la CLI non ha: file Compose, notifiche di guasto, una vista della flotta con i tuoi host Docker e un server MCP per gli agenti AI.

Configurare apple/container con Gantry

  1. Installa Gantry: brew install --cask getgantry/tap/gantry, poi rimuovi l'attributo di quarantena (vedi Installazione).
  2. Installa la CLI container dal .pkg firmato nella pagina delle release di apple/container. Se manca o è precedente alla 1.0, Gantry mostra un pannello di configurazione con i passaggi.
  3. In Gantry, scegli Aggiungi host… e aggiungi un host Apple Container. La connessione avvia i servizi di container se sono arrestati.
  4. Se non è installato alcun kernel predefinito, la panoramica dell'host mostra un banner. Fai clic per installare il kernel consigliato.
Attenzione
Usa il pacchetto di installazione firmato, non la build Homebrew. La build Homebrew non include il backend delle macchine e, nella 1.7.1, i servizi del cluster, quindi container machine e container cluster non possono funzionare.

Cosa aggiunge Gantry ad apple/container

Cluster Kubernetes

Crea cluster Kubernetes con container cluster, dimensiona i worker, lascia che i pod usino le tue immagini locali, scegli il CNI e vedi ogni nodo. Poi esplora il cluster nel browser Kubernetes di Gantry. Vedi Kubernetes su apple/container e la guida passo passo Kubernetes su Mac.

Macchine container e VS Code

Le macchine sono ambienti Linux di lunga durata creati con container machine. Gantry le crea, le avvia, le arresta e le elimina, imposta la macchina predefinita, modifica CPU e memoria e apre una shell. Con la CLI 1.1 o successiva, una macchina può avviarsi con la virtualizzazione annidata (chip Apple M3 o successivo) e un kernel personalizzato. Apri in VS Code si connette a una macchina in esecuzione tramite Remote-SSH; l'immagine della macchina deve eseguire sshd.

Docker Compose su apple/container

Apri un docker-compose.yml dal Finder (Apri con ▸ Gantry o Azioni rapide ▸ Compose Up in apple/container), da File ▸ Apri file Compose… o trascinandolo sulla finestra. Gantry crea le immagini dei servizi build:, crea la rete del progetto e i volumi con nome, e avvia ogni servizio nell'ordine di depends_on con le etichette standard com.docker.compose.*. Con un dominio DNS predefinito impostato, i servizi si raggiungono tra loro per nome tramite gli alias di rete.

Alias DNS di rete e domini locali

Gantry passa gli alias di rete a container come --network <name>,alias=…. Senza un dominio DNS predefinito passano solo i nomi completi, e un alias di sottoalbero (con un punto iniziale, come .gateway) passa solo come alias esatto. Con un dominio predefinito funzionano anche i nomi brevi. Gantry crea ed elimina domini DNS locali, imposta il dominio predefinito e assegna ai nuovi container un hostname name.domain. Vedi Nomi DNS locali.

Sistema: servizi, builder, registri, kernel, log, proprietà

Ogni host apple/container ha una sezione Sistema. Funziona anche quando l'host è disconnesso, quindi puoi avviare da lì i servizi arrestati.

  • Stato e versione: versioni di client e server, con un avviso se sono diverse; avvio, arresto e riavvio dei servizi; dati e percorsi dell'host.
  • Builder di immagini: stato, immagine, CPU, memoria e IP; avvio con opzioni per CPU, memoria e DNS; arresto; eliminazione. Una scheda ti avvisa quando l'immagine del builder è obsoleta e lo ricrea.
  • Accessi ai registri: elenco, accesso e disconnessione. La password arriva alla CLI solo tramite stdin (--password-stdin), e Gantry non ne conserva copia.
  • Kernel: installa il kernel consigliato, un file del kernel o un archivio tar, con l'avanzamento in tempo reale.
  • Log dei servizi: in tempo reale o una tantum, su un intervallo da 5 minuti a 1 giorno, filtrati per livello, servizio e testo.
  • Proprietà di sistema: le modifiche vanno in ~/.config/container/config.toml, con un indicatore di riavvio in sospeso e un pulsante Riavvia servizi. Con la CLI 1.7, i server dei nomi, i domini di ricerca e le opzioni di [container.dns] hanno un editor a elenco.

Salva come immagine, Compatta disco e file

Salva come immagine usa container commit (CLI 1.6). Compatta disco usa container clean (CLI 1.4) e compare anche come riga in Recupera spazio. La scheda File scarica i file e ti permette di trascinarli nel Finder con container copy (il container deve essere avviato), e carica file e cartelle.

Etichette che contengono =

container create rifiuta un valore di etichetta che contiene =, anche con la CLI 1.6.1. Gantry codifica questi valori quando crea il container e li decodifica quando lo rilegge, così le etichette che imposti sono quelle che vedi.

Server MCP e Comandi Rapidi

Il server gantry-mcp incluso dà agli agenti AI la stessa portata sugli host apple/container: container, immagini, volumi, reti, Compose, macchine (list_machines, create_machine e altri), cluster (list_clusters, create_cluster, delete_cluster) e strumenti di sistema apple_* per servizi, builder, registri (senza strumento di accesso), proprietà, log e installazione del kernel. Le App Intents aggiungono azioni per Comandi Rapidi e Siri. Vedi Agenti AI & MCP.

Aggiungi il server MCP di Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container accanto a Docker

Gantry gestisce gli host apple/container, il daemon Docker locale (Docker Desktop, OrbStack, Colima) e gli host Docker remoti via SSH in un'unica barra laterale e un'unica dashboard della flotta. Non devi scegliere un solo runtime. Per un confronto funzione per funzione, vedi Gantry a confronto con Docker Desktop, OrbStack e Podman Desktop. Per spostare il tuo lavoro, leggi Passare da Docker Desktop ad Apple container.

Domande e risposte

Qual è la migliore GUI per Apple container?

Gantry è una GUI nativa per macOS, gratuita e open source, pensata per apple/container. Porta la CLI container in un'app desktop: container, log, statistiche ed exec, più cluster Kubernetes, macchine, builder di immagini, accessi ai registri, kernel, log dei servizi e proprietà di sistema. La tabella in questa pagina elenca ogni comando e la funzione di Gantry che lo usa.

Apple container ha un'interfaccia grafica?

Apple distribuisce container solo come strumento a riga di comando. Gantry è un'app open source separata che gli dà una GUI, accanto ai tuoi host Docker.

Si può usare docker compose con Apple container?

apple/container non ha un comando compose. Gantry legge un docker-compose.yml, crea le immagini dei servizi build:, crea la rete e i volumi con nome e avvia i servizi nell'ordine di depends_on. I nomi dei servizi vengono risolti tramite alias DNS di rete.

Come si apre una macchina container in VS Code?

Avvia la macchina in Gantry e fai clic su Apri in VS Code. Gantry la apre tramite Remote-SSH, come nell'esempio container-machine-vscode di Apple. L'immagine della macchina deve eseguire sshd.

Apple container funziona sui Mac Intel?

No. apple/container richiede un Mac con chip Apple. Gantry funziona anche sui Mac Intel, ma lì gestisce solo host Docker.

Quale versione della CLI container conviene installare?

Gantry richiede la 1.0 o successiva e consiglia la 1.7.1. Installala con il pacchetto di installazione firmato dalla pagina delle release di apple/container. La build Homebrew non include il backend delle macchine né, nella 1.7.1, i servizi del cluster, quindi container machine e container cluster non funzionano con essa.

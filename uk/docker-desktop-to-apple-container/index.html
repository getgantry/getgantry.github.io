Перехід із Docker Desktop на Apple container

Інструмент container від Apple запускає ті самі образи OCI, що й Docker, тож більшість роботи переноситься з невеликими змінами команд. Цей посібник зіставляє Docker і container, переносить образи й томи та перелічує обмеження, про які варто знати до переходу.

Коротко. Інсталюйте підписаний пакет container, замініть docker на container для run, build, logs, exec і images, скопіюйте іменовані томи через tar-файл і відкрийте docker-compose.yml у Gantry, бо в CLI немає compose. Поки ви пробуєте, Docker Desktop можна не видаляти.

Що змінюється

  • Одна ВМ на контейнер. Docker Desktop запускає всі контейнери в одній ВМ Linux. apple/container запускає невелику ВМ для кожного контейнера, тож кожен має власну IP-адресу на вашому Mac.
  • Ті самі образи й реєстри. Образи — це образи OCI; ви отримуєте їх із Docker Hub, GHCR і приватних реєстрів, як і раніше.
  • Без плати за ліцензію. apple/container поширюється за ліцензією Apache 2.0. Docker Desktop потребує платного плану в організаціях, де 250 або більше працівників чи дохід $10 млн або більше.
  • Лише Apple silicon і macOS 26. На Mac з Intel залишайтеся на рушії Docker.

Перенесення образів

Образи з реєстру отримайте знову командою container image pull. Локальні образи, які є лише в Docker, збережіть в архів і завантажте його. container image load читає архіви OCI, а нові версії Docker записують через docker save макет OCI. Якщо завантаження не вдалося, надішліть образ у реєстр і отримайте його звідти.

Термінал
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Перенесення іменованих томів

Docker зберігає дані томів усередині своєї ВМ. Скопіюйте кожен том у tar-файл за допомогою тимчасового контейнера, потім розпакуйте його в новий том apple/container:

Термінал
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Іменований том в apple/container — це розріджений образ диска ext4, типово не більше ніж 512 ГБ. Інший розмір задайте через --opt size=20g. Bind-монтування папок вашого Mac працює так само, як у Docker: -v ~/project:/app.

Файли Compose

У CLI container немає команди compose. Натомість відкрийте docker-compose.yml у Gantry (із Finder, через Файл ▸ Відкрити файл Compose… або перетягуванням). Gantry збирає служби з build:, створює мережу проєкту й іменовані томи та запускає служби в порядку depends_on. Служби звертаються одна до одної за назвою служби через мережеві DNS-псевдоніми.

Мережі й порти

  • -p 8080:80 публікує порт на localhost, як у Docker.
  • Кожен контейнер має й власну IP-адресу. Створіть локальний DNS-домен командою sudo container system dns create test і запускайте контейнери з --dns-domain test: вони отримають назви на кшталт web.test.
  • container network create створює мережі користувача; контейнери в одній мережі бачать один одного.
  • Режимів --network host, none і container: немає.

Чого немає

  • Немає Docker Engine API. Інструменти, які звертаються до /var/run/docker.sock, наприклад Testcontainers, Docker SDK або Dev Containers, не бачать apple/container.
  • Немає політик перезапуску. --restart недоступний; контейнер сам не запускається знову.
  • Немає Compose в CLI. Файли Compose запускає Gantry: див. Файли Compose.
  • Немає розширень Docker Desktop.
  • Лише цілі CPU: --cpus 0.5 не працює.
  • Kubernetes влаштовано інакше: використовуйте container cluster, див. Kubernetes на Mac.

Залиште обидва на час переходу

Gantry керує apple/container і будь-яким рушієм Docker (Docker Desktop, OrbStack, Colima або Docker через SSH) на одній боковій панелі. Переносьте по одному проєкту й залиште Docker для інструментів, яким потрібен його API. Коли Docker Desktop стане непотрібним, його можна видалити.

Запитання й відповіді

Чи може Apple container замінити Docker Desktop?

Для запуску, збирання й отримання контейнерів на Apple silicon — так. У ньому немає Docker Engine API, політик перезапуску, розширень і команди compose. Gantry додає файли Compose і GUI.

Чи працюють образи Docker з Apple container?

Так. apple/container використовує стандартні образи OCI й отримує їх із тих самих реєстрів. Образи arm64 працюють нативно, образи amd64 — через Rosetta з --arch amd64.

Чи працює docker compose з Apple container?

Не з CLI: команди container compose немає. Gantry читає docker-compose.yml і сам запускає служби на apple/container.

Чи можна одночасно використовувати Docker Desktop і Apple container?

Так. У них немає спільних образів і томів, але працювати поруч вони можуть. Gantry показує обидва в одному вікні.

Чи безплатний Apple container для комерційного використання?

Так. apple/container — відкритий код за ліцензією Apache 2.0, а Gantry поширюється за ліцензією MIT. Обидва безплатні для компаній будь-якого розміру.

Gantry/От Docker Desktop

Преминаване от Docker Desktop към Apple container

Инструментът container на Apple стартира същите OCI образи като Docker, така че по-голямата част от работата ви се пренася с няколко промени в командите. Това ръководство съпоставя Docker с container, пренася образи и томове и изброява пропуските, които трябва да знаете преди преминаването.

Накратко. Инсталирайте подписания пакет container, заменете docker с container за run, build, logs, exec и images, копирайте именуваните томове чрез tar файл и отворете своя docker-compose.yml в Gantry, защото CLI няма compose. Докато пробвате, можете да оставите Docker Desktop инсталиран.

Какво се променя

  • Една виртуална машина на контейнер. Docker Desktop стартира всички контейнери в една Linux виртуална машина. apple/container стартира малка виртуална машина за всеки контейнер, така че всеки получава собствен IP адрес на вашия Mac.
  • Същите образи и регистри. Образите са OCI образи; изтегляте от Docker Hub, GHCR и частни регистри както досега.
  • Без лицензна такса. apple/container е с лиценз Apache 2.0. Docker Desktop изисква платен план в организации с 250 или повече служители или с $10 млн. или повече приходи.
  • Само Apple silicon и macOS 26. На Mac с Intel останете със среда на Docker.

Пренасяне на образите

Образи от регистър: изтеглете ги отново с container image pull. Локални образи, които съществуват само в Docker: запишете ги в архив и го заредете. container image load чете OCI архиви, а новите версии на Docker записват OCI структура с docker save. Ако зареждането не успее, качете образа в регистър и го изтеглете.

Терминал
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Пренасяне на именувани томове

Docker държи данните на томовете във своята виртуална машина. Копирайте всеки том в tar файл с краткотраен контейнер, след това го разархивирайте в нов том на apple/container:

Терминал
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Именуваният том в apple/container е разреден (sparse) ext4 дисков образ, по подразбиране най-много 512 GB. Задайте друг размер с --opt size=20g. Bind монтиранията на папки от вашия Mac работят както в Docker: -v ~/project:/app.

Файлове Compose

CLI container няма команда compose. Вместо това отворете docker-compose.yml в Gantry (от Finder, с Файл ▸ Отвори файл Compose… или с плъзгане и пускане). Gantry изгражда услугите с build:, създава мрежата и именуваните томове на проекта и стартира услугите в реда от depends_on. Услугите се достигат една друга по име чрез DNS псевдоними в мрежата.

Мрежи и портове

  • -p 8080:80 публикува порт на localhost, както в Docker.
  • Всеки контейнер има и собствен IP адрес. Създайте локален DNS домейн с sudo container system dns create test и стартирайте контейнерите с --dns-domain test: те получават имена като web.test.
  • container network create създава потребителски мрежи; контейнерите в една и съща мрежа се достигат един друг.
  • Няма режими --network host, none или container:.

Какво липсва

  • Няма Docker Engine API. Инструментите, които говорят с /var/run/docker.sock, като Testcontainers, Docker SDK или Dev Containers, не виждат apple/container.
  • Няма политики за рестартиране. --restart не е наличен; контейнерът не се стартира отново сам.
  • Няма Compose в CLI. Gantry изпълнява файлове Compose: вижте Файлове Compose.
  • Няма разширения на Docker Desktop.
  • Само цели CPU: --cpus 0.5 не работи.
  • Kubernetes е различен: използвайте container cluster, вижте Kubernetes на Mac.

Дръжте и двете, докато преминавате

Gantry управлява apple/container и всяка среда на Docker (Docker Desktop, OrbStack, Colima или Docker през SSH) в една странична лента. Пренасяйте проектите един по един и запазете Docker за инструментите, които се нуждаят от неговия API. Когато вече не ви трябва, можете да премахнете Docker Desktop.

Въпроси и отговори

Може ли Apple container да замени Docker Desktop?

За стартиране, изграждане и изтегляне на контейнери на Apple silicon – да. Няма Docker Engine API, политики за рестартиране, разширения или команда compose. Gantry добавя файлове Compose и GUI.

Работят ли образите на Docker с Apple container?

Да. apple/container използва стандартни OCI образи и изтегля от същите регистри. Образите за arm64 работят нативно; образите за amd64 работят чрез Rosetta с --arch amd64.

Работи ли docker compose с Apple container?

Не от CLI: няма container compose. Gantry чете docker-compose.yml и стартира услугите в apple/container вместо вас.

Мога ли да използвам Docker Desktop и Apple container едновременно?

Да. Те не споделят образи и томове, но могат да работят едновременно. Gantry показва и двете в един прозорец.

Безплатен ли е Apple container за търговска употреба?

Да. apple/container е с отворен код под лиценз Apache 2.0, а Gantry е с лиценз MIT. И двата са безплатни за компании от всякакъв размер.

Gantry/Kubernetes Macis

Kubernetes Macis Apple containeriga

Apple'i container-tööriist loob kohaliku Kubernetese klastri ühe käsuga. Iga sõlm on teie Macis kerge virtuaalmasin. See juhend viib teid tühjast Macist töötava Deploymendini, kõigepealt terminalis ja seejärel Gantrys.

Lühidalt. Installige allkirjastatud container 1.7.1 pakett, käivitage container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, koostage tõmmis käsuga container build ja käitage seda klastris nime järgi. Gantry näitab sama klastrit aknas: sõlmed, podid, logid, shell ja pordisuunamised.

Mida on vaja

  • Apple'i kiibiga Mac, macOS 26 või uuem.
  • container CLI 1.7.1 allkirjastatud .pkg-failist apple/containeri väljalasete lehel. Versiooni 1.7.1 Homebrew-versioonis pole klastriteenuseid, seega container cluster nurjub veaga cluster service unavailable.
  • Allpool oleva näite jaoks umbes 6 GB vaba mälu: kolm sõlme, igaühel 2 GB.
  • kubectl, kui soovite klastrit kasutada terminalist (brew install kubectl).

Pärast paketi installimist käivitage teenused üks kord:

Terminal
container system start

Klastri loomine

See käsk loob klastri nimega dev, millel on üks juhttasandi sõlm ja kaks töösõlme. Iga sõlm saab 2 CPU-d ja 2 GB mälu:

Terminal
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M määrab töösõlmede rühma suuruse. Eri suurusega rühmade jaoks korrake seda. Ilma liputa --workers on üks sõlm korraga juhttasand ja töösõlm.
  • --cpus ja --memory määravad juhttasandi suuruse. Vaikimisi on see veerand teie Maci CPU-dest ja mälust, vähemalt 2 CPU-d ja 2 GB.
  • --shared-image-store laseb sõlmedel kasutada teie kohalikke tõmmiseid (vaadake allpool). Seda ei saa hiljem muuta: kustutage klaster ja looge see uuesti.
  • --cni ./calico.yaml installib kaasasoleva kindneti asemel teie oma CNI; --cni NONE ei installi ühtegi.

CLI lisab faili ~/.kube/config konteksti nimega dev. Kontrollige sõlmi:

Terminal
container cluster list --nodes
kubectl --context dev get nodes

Kohaliku tõmmise käitamine ilma registrita

Lipuga --shared-image-store saavad sõlmed käitada mis tahes tõmmist teie kohalikust container tõmmisehoidlast. Koostage tõmmis ja kasutage seda nime järgi:

Terminal
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Märkus
Kui koostate sama sildi uuesti, käivitage kubectl rollout restart koos imagePullPolicy: Always-iga või kasutage uut silti. Väärtusega IfNotPresent jätab sõlm alles koopia, mis tal juba on. Kõik, millel on sõlmes root-õigused, saab lugeda kõiki teie kohaliku hoidla tõmmiseid, ka privaatseid, seega kasutage jagatud hoidlat ainult kohalikuks arenduseks.

CLI 1.5-s ja 1.6-s jagatud hoidlat pole. Kasutage seal käsku container cluster load-image või Gantrys toimingut Laadi klastrisse. CLI 1.7 eemaldas käsu load-image.

Rakenduse avamine brauseris

Suunake kohalik port Deploymendile, seejärel avage http://localhost:8080:

Terminal
kubectl --context dev port-forward deployment/hello 8080:80

Klastri sirvimine Gantrys

Gantry näitab sama klastrit ilma käskudeta. Lisage oma apple/containeri host, avage Klastrid ja valige dev. Ülevaade näitab Kubernetese versiooni, tõmmisehoidlat, töösõlmi ning nende CPU-sid ja mälu. Klõpsake Sirvi ressursse, et avada selle konteksti jaoks jaotis Kubernetes.

  • Podid, Deploymentid, StatefulSetid, DaemonSetid, teenused, Ingressid, ConfigMapid, saladused, sõlmed ja sündmused, ühes nimeruumis või kõigis.
  • Podi logid jälgimise ja viimaste ridadega, shell podis ning pordisuunamised loendiga, kust saate neid peatada.
  • Skaleerimine, juurutuse taaskäivitamine, kustutamine ja Rakenda YAML kleebitud manifestist või failist.
  • Saladuste väärtused jäävad varjatuks, kuni klõpsate Näita.

Kubernetese brauser käivitab kubectl-i. Kui see puudub, näitab Gantry käsku brew install kubectl ja saab selle teie eest käivitada. Arenduses on natiivne klient, mis ei vaja kubectl-i.

Klastri saate luua ka Gantrys: lehel Klastrid ▸ Uus klaster on juhttasandi ja töösõlmede sammurid ning lüliti Kasuta kohalikke tõmmiseid. Lisateavet leiate lehelt Kubernetes apple/containeris.

Klastri peatamine ja kustutamine

Terminal
container cluster delete --name dev

Kui juhttasandi sõlm peatub, näiteks pärast käsku container system stop, kustutage klaster ja looge see uuesti. Ajutise klastri loomiseks kasutage lippu --rm, mis eemaldab sõlmed, kui need peatuvad.

Levinud probleemid

  • cluster service unavailable: CLI on Homebrew-versioon või teenused ei tööta. Installige allkirjastatud pakett või taaskäivitage teenused käskudega container system stop ja container system start. Gantry annab jaotises Klastrid sama nõuande.
  • Vana klaster puudub loendist: CLI 1.7 ei loetle klastreid, mis on loodud versiooniga 1.6 või varasemaga. Eemaldage see käsuga container cluster delete --name <name>.
  • Sõlmed jäävad olekusse NotReady: kasutasite lippu --cni NONE. Rakendage CNI manifest.
  • Sõlme konteinerit ei saa peatada: see on tahtlik. container stop ja delete keelduvad klastri sõlmedega töötamast; kasutage käsku container cluster delete.

Võrdlus Docker Desktopi ja OrbStackiga

Docker Desktopil on sisseehitatud Kubernetes kubeadmiga (üks sõlm) või kindiga (mitu sõlme) ja OrbStackil on sisseehitatud ühe sõlmega klaster. container cluster käitab kubeadmi kindest/node tõmmistel, iga sõlm oma virtuaalmasinas, mitme sõlmega klastrite ja jagatud tõmmisehoidlaga. Vaadake täielikku võrdlust.

Seotud juhendid

  • Docker Desktopilt Apple containerile: käsud, Compose, köited ja puudujäägid
  • Konteinerid ja köited Maci välisel kettal
  • Konteineri loomine docker run käsust Macis (docker run → container run)
  • Apple containeri GUI Macile: täielik apple/containeri juhend
  • Kubernetes Apple containeris: GUI container clusterile ja Kubernetese brauser

Küsimused ja vastused

Kas Kubernetest saab Macis käitada ilma Dockerita?

Jah. Apple'i container CLI loob Kubernetese klastrid ise käsuga container cluster create. Iga sõlm töötab kerge virtuaalmasinana ning teil pole vaja Dockerit, Docker Desktopi, kindi ega minikube'i.

Mitu sõlme saab container clusteril olla?

Üks juhttasand ja nii palju töösõlmi, kui teie Maci CPU-dest ja mälust jätkub. Määrake need lipuga --workers; CLI 1.7-s saab igal töösõlmede rühmal olla oma CPU-d ja mälu.

Kuidas kasutada klastris kohalikult koostatud tõmmist?

Looge klaster lipuga --shared-image-store (CLI 1.7), koostage tõmmis käsuga container build -t name:tag . ja kasutage podi spetsifikatsioonis nime name:tag. Registrit pole vaja.

Millist Kubernetese versiooni container cluster kasutab?

CLI 1.7.1 kasutab vaikimisi sõlme tõmmist kindest/node:v1.35.5. Teise versiooni valimiseks kasutage lippu --node-image, näiteks docker.io/kindest/node:v1.34.11. Gantry näitab versiooni klastri ülevaates.

Kas container clusteril on GUI?

Jah. Gantry loob ja kustutab klastreid, näitab sõlmi ning sirvib oma Kubernetese jaotises podisid, Deploymente, teenuseid, logisid ja saladusi. See on tasuta ja avatud lähtekoodiga.

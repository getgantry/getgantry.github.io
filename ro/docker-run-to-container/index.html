Gantry/Din docker run

Creați un container dintr-o comandă docker run

Majoritatea fișierelor README dau o linie docker run. Gantry citește acea linie și completează formularul Container nou, pentru o gazdă Docker sau pentru instrumentul container de la Apple. Acest ghid arată cum și cum convertiți comanda manual.

Pe scurt. În Gantry, deschideți Container nou, alegeți Lipește comanda…, lipiți linia docker run și faceți clic pe Completează formularul. Gantry listează fiecare flag pe care nu îl poate folosi, cu motivul. Pentru CLI, majoritatea flagurilor sunt aceleași: înlocuiți docker run cu container run și eliminați --restart.

Lipiți comanda în Gantry

  1. Selectați o gazdă: o gazdă Docker sau o gazdă apple/container.
  2. Deschideți Containere și faceți clic pe Container nou.
  3. Faceți clic pe Lipește comanda… și lipiți linia. Sfârșiturile de linie cu \, ghilimelele, un prompt $ și sudo nu sunt o problemă.
  4. Citiți previzualizarea: imaginea, flagurile pe care Gantry nu le poate folosi, notele și avertismentele pentru această gazdă.
  5. Faceți clic pe Completează formularul, verificați valorile și creați containerul.

Gantry citește docker run, docker container run, docker create, podman run și container run. Textul de după &&, ||, ; sau | este ignorat, cu o notă.

Ce flaguri completează formularul

FlagCâmp din formularNote
imagine, --name, comandăImagine, Nume, Comandă
-p, --publishPorturiIP de gazdă, IPv6, udp, intervale de până la 100 de porturi
-e, --envMediu-e KEY singur dă o valoare goală și o notă
--env-fileFișier envCalea se păstrează; fișierul nu este citit
-v, --mountVolumeMontări bind și volume cu nume, ro sau rw
--networkRețeaUn meniu cu rețelele gazdei
--restartPolitică de repornireDoar gazde Docker
--cpus, -mCPU-uri, MemorieVerificate direct în formular
--entrypoint, -w, -uPunct de intrare, Director de lucru, Utilizator
-l, --labelEtichete

Încă aproximativ 80 de flaguri Docker sunt cunoscute: Gantry le omite corect valorile și le listează ca nefolosite, astfel încât nimic nu se pierde fără o notă.

Avertismente pentru gazdele apple/container

Unele opțiuni Docker nu există în apple/container. Gantry vă avertizează și le lasă în afara cererii de creare:

  • politicile de repornire (--restart);
  • fracțiuni de CPU, precum --cpus 0.5;
  • modurile de rețea host, none și container:;
  • porturi fără port pe gazdă, precum -p 80.

Pe o gazdă Docker, Gantry avertizează despre opțiunile apple/container: domeniul DNS și opțiunile de kernel.

Convertiți manual docker run în container run

Pentru CLI, majoritatea flagurilor rămân aceleași. Un exemplu cu Redis:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

devine:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Creați mai întâi volumul cu nume cu container volume create. Eliminați --restart și rotunjiți --cpus la un număr întreg. --platform funcționează ca în Docker.

Copiați un container ca comandă

Funcționează și invers. Faceți clic dreapta pe un container sau folosiți meniul Mai mult și alegeți Copiază ca comandă: Gantry scrie o linie docker run sau container run. Omite valorile implicite ale imaginii, precum mediul și comanda, ca linia să rămână scurtă. Funcționează și pentru containerele oprite.

Salvați-l ca rețetă

În foaia Container nou, deschideți Rețete și alegeți Salvează ca rețetă…. Data viitoare, Completează din rețetă oferă același formular pe orice gazdă. Rețetele se află în ~/Library/Application Support/Gantry/recipes.json, deci le puteți salva ca backup sau le puteți partaja.

Limitări

  • Gantry păstrează calea din --env-file, dar nu citește fișierul și nu citește shellul dvs. pentru -e KEY fără valoare.
  • Montările tmpfs și volumele anonime din --mount sunt listate ca neacceptate.
  • Două porturi pentru același port de container (-p 8080:80 -p 8081:80) completează formularul, dar formularul refuză apoi duplicatul.

Întrebări și răspunsuri

Cum convertesc docker run în container run?

Înlocuiți docker run cu container run. -d, -p, -e, -v, --name, --rm, -it, -w și --entrypoint rămân aceleași. Eliminați --restart și folosiți CPU-uri întregi. Sau lipiți linia în Gantry și lăsați-l să completeze formularul.

Poate Gantry importa o comandă docker run?

Da. Lipește comanda… din foaia Container nou citește docker run, docker create, podman run și container run și completează formularul.

Ce se întâmplă cu flagurile pe care Gantry nu le acceptă?

Sunt listate în previzualizare, cu motivul, și rămân în formular în secțiunea Din comanda lipită, ca să le puteți verifica ulterior.

Pot transforma un container care rulează înapoi într-o comandă docker run?

Da. Copiază ca comandă din meniul containerului scrie o linie docker run sau container run pentru acel container.

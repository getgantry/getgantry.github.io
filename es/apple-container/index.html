Gantry/Guía de apple/container

Apple container en Mac: guía completa y GUI

apple/container ejecuta contenedores Linux en tu Mac, cada uno en su propia máquina virtual ligera. Se distribuye como herramienta de línea de comandos. Gantry es una GUI nativa de macOS para ella. Esta guía explica la herramienta, cómo configurarla y qué función de Gantry cubre cada comando de container.

En resumen. Gantry es una app de macOS gratuita y de código abierto (MIT) que gestiona la herramienta container de Apple y Docker desde una sola ventana. Es compatible con la CLI container 1.0 a 1.6.1 (recomendada) y muestra solo las funciones que admite tu versión de la CLI. Instálala con brew install --cask getgantry/tap/gantry.

¿Qué es apple/container?

apple/container es una herramienta de código abierto de Apple, escrita en Swift, que crea y ejecuta contenedores Linux en un Mac. Docker Desktop ejecuta todos los contenedores en una única VM Linux compartida; apple/container ejecuta cada contenedor en su propia máquina virtual ligera, basada en el framework Virtualization de Apple. Usa imágenes OCI estándar, así que descarga de los mismos registros que Docker y sube a ellos.

  • Hardware: un Mac con chip de Apple.
  • macOS: Apple lo admite en macOS 26.
  • Interfaz: solo la CLI container. No hay app de escritorio ni comando compose.
  • Red: cada contenedor obtiene su propia dirección IP en tu Mac, y los dominios DNS locales dan a los contenedores nombres como web.test.

¿Por qué usar una GUI para apple/container?

La CLI es completa, pero el trabajo diario exige muchos comandos: container list, logs, stats, exec, y luego system, builder, registry, machine y cluster para el resto. Gantry los reúne en una ventana con actualizaciones en directo, así que ves el estado en lugar de tener que consultarlo una y otra vez. Además, añade lo que la CLI no tiene: archivos Compose, notificaciones de fallos, una vista de flota con tus hosts Docker y un servidor MCP para agentes de IA.

Configurar apple/container con Gantry

  1. Instala Gantry: brew install --cask getgantry/tap/gantry, y luego quita el atributo de cuarentena (consulta Instalación).
  2. Instala la CLI container desde el .pkg firmado de la página de versiones de apple/container. Si falta o es anterior a la 1.0, Gantry muestra una hoja de configuración con los pasos.
  3. En Gantry, elige Añadir host… y añade un host Apple Container. Al conectarse, se inician los servicios de container si están detenidos.
  4. Si no hay ningún kernel predeterminado instalado, el resumen del host muestra un aviso. Haz clic en él para instalar el kernel recomendado.
Atención
Usa el paquete instalador firmado, no la versión de Homebrew. La versión de Homebrew no incluye el backend de máquinas, así que container machine no puede funcionar.

Lo que Gantry añade en apple/container

Clústeres de Kubernetes

Crea con container cluster clústeres de Kubernetes con varios workers, elige la CNI, consulta cada nodo, escribe el kubeconfig y carga imágenes locales en el clúster. Consulta Kubernetes en apple/container.

Máquinas de container y VS Code

Las máquinas son entornos Linux de larga duración creados con container machine. Gantry las crea, inicia, detiene y elimina, define la máquina predeterminada, edita las CPU y la memoria, y abre un shell. Con la CLI 1.1 o posterior, una máquina puede arrancar con virtualización anidada (chip de Apple M3 o posterior) y un kernel personalizado. Abrir en VS Code se conecta a una máquina en ejecución por Remote-SSH; la imagen de la máquina debe ejecutar sshd.

Docker Compose en apple/container

Abre un docker-compose.yml desde el Finder (Abrir con ▸ Gantry o Acciones rápidas ▸ Compose Up en apple/container), desde Archivo ▸ Abrir archivo Compose… o soltándolo en la ventana. Gantry compila los servicios con build:, crea la red del proyecto y los volúmenes con nombre, e inicia cada servicio en el orden de depends_on con las etiquetas estándar com.docker.compose.*. Con un dominio DNS predeterminado, los servicios se comunican entre sí por nombre de servicio mediante alias de red.

Alias DNS de red y dominios locales

Gantry pasa los alias de red a container como --network <name>,alias=…. Sin un dominio DNS predeterminado, solo se aceptan nombres completos (FQDN), y un alias de subárbol (con un punto inicial, como .gateway) solo se acepta tal cual. Con un dominio predeterminado, también funcionan los nombres cortos. Gantry crea y elimina dominios DNS locales, define el dominio predeterminado y da a los contenedores nuevos un nombre de host name.domain. Consulta Nombres DNS locales.

Sistema: servicios, builder, registros, kernel, logs, propiedades

Cada host apple/container tiene una sección Sistema. Funciona aunque el host esté desconectado, así que desde ahí puedes iniciar los servicios detenidos.

  • Estado y versión: versiones del cliente y del servidor, con un aviso cuando no coinciden; inicio, detención y reinicio de los servicios; datos y rutas del host.
  • Builder de imágenes: estado, imagen, CPU, memoria e IP; inicio con opciones de CPU, memoria y DNS; detención; eliminación.
  • Sesiones en registros: listar, iniciar sesión y cerrar sesión. La contraseña llega a la CLI solo por stdin (--password-stdin), y Gantry no guarda ninguna copia.
  • Kernel: instala el kernel recomendado, un archivo de kernel o un archivo tar, con el progreso en directo.
  • Logs de servicios: en directo o de una sola vez, de 5 minutos a 1 día, filtrados por nivel, servicio y texto.
  • Propiedades del sistema: los cambios se guardan en ~/.config/container/config.toml, con un indicador de reinicio pendiente y un botón Reiniciar servicios.

Guardar como imagen, Compactar disco y archivos

Guardar como imagen usa container commit (CLI 1.6). Compactar disco usa container clean (CLI 1.4) y también aparece como fila en Recuperar espacio. La pestaña Archivos descarga archivos y te permite arrastrarlos al Finder con container copy (el contenedor debe estar iniciado), y sube archivos y carpetas.

Etiquetas que contienen =

container create rechaza un valor de etiqueta que contenga =, también en la CLI 1.6.1. Gantry codifica esos valores al crear el contenedor y los decodifica al leerlo de nuevo, así que las etiquetas que defines son las que ves.

Servidor MCP y Atajos

El servidor gantry-mcp incluido da a los agentes de IA el mismo alcance en los hosts apple/container: contenedores, imágenes, volúmenes, redes, Compose, máquinas (list_machines, create_machine y más), clústeres (list_clusters, create_cluster, delete_cluster) y herramientas de sistema apple_* para servicios, builder, registros (sin herramienta de inicio de sesión), propiedades, logs e instalación de kernels. Los App Intents añaden acciones de Atajos y Siri. Consulta Agentes de IA y MCP.

Añadir el servidor MCP de Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container junto a Docker

Gantry gestiona hosts apple/container, el daemon de Docker local (Docker Desktop, OrbStack, Colima) y hosts Docker remotos por SSH en una sola barra lateral y un solo panel de flota. No tienes que elegir un único runtime. Para comparar las herramientas función por función, consulta Gantry frente a Docker Desktop, OrbStack y Podman Desktop.

Preguntas y respuestas

¿Cuál es la mejor GUI para Apple container?

Gantry es una GUI nativa de macOS, gratuita y de código abierto, creada para apple/container. Lleva la CLI container a una app de escritorio: contenedores, logs, estadísticas y exec, además de clústeres de Kubernetes, máquinas, el builder de imágenes, sesiones en registros, kernels, logs de servicios y propiedades del sistema. La tabla de esta página recoge cada comando y la función de Gantry que lo usa.

¿Apple container tiene interfaz gráfica?

Apple distribuye container solo como herramienta de línea de comandos. Gantry es una app de código abierto independiente que le da una GUI, junto a tus hosts Docker.

¿Se puede usar docker compose con Apple container?

apple/container no tiene comando compose. Gantry lee un docker-compose.yml, compila los servicios con build:, crea la red y los volúmenes con nombre, e inicia los servicios en el orden de depends_on. Los nombres de servicio se resuelven mediante alias DNS de red.

¿Cómo abro una máquina de container en VS Code?

Inicia la máquina en Gantry y haz clic en Abrir en VS Code. Gantry la abre por Remote-SSH, como en el ejemplo container-machine-vscode de Apple. La imagen de la máquina debe ejecutar sshd.

¿Apple container funciona en Macs con Intel?

No. apple/container requiere un Mac con chip de Apple. Gantry también funciona en Macs con Intel, pero ahí solo gestiona hosts Docker.

¿Qué versión de la CLI container debo instalar?

Gantry necesita la 1.0 o posterior y está probado con la 1.6.1. Instálala con el paquete instalador firmado de la página de versiones de apple/container. La versión de Homebrew no incluye el backend de máquinas, así que container machine no funciona con ella.

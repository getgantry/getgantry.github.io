Gantry/Da Docker Desktop

Passare da Docker Desktop ad Apple container

Lo strumento container di Apple esegue le stesse immagini OCI di Docker, quindi gran parte del tuo lavoro si sposta cambiando pochi comandi. Questa guida mette in corrispondenza Docker e container, sposta immagini e volumi ed elenca i limiti da conoscere prima di passare.

In breve. Installa il pacchetto firmato di container, sostituisci docker con container per run, build, logs, exec e immagini, copia i volumi con nome tramite un file tar e apri il tuo docker-compose.yml in Gantry, perché la CLI non ha compose. Puoi tenere installato Docker Desktop mentre provi.

Cosa cambia

  • Una VM per container. Docker Desktop esegue tutti i container in un'unica VM Linux. apple/container avvia una piccola VM per ogni container, quindi ognuno ha il proprio indirizzo IP sul tuo Mac.
  • Stesse immagini e stessi registri. Le immagini sono immagini OCI; le scarichi da Docker Hub, GHCR e registri privati come prima.
  • Nessun costo di licenza. apple/container è Apache 2.0. Docker Desktop richiede un piano a pagamento nelle organizzazioni con 250 o più dipendenti o con un fatturato di 10 milioni di dollari o più.
  • Solo chip Apple e macOS 26. Sui Mac Intel, resta su un motore Docker.

Porta con te le immagini

Immagini da un registro: scaricale di nuovo con container image pull. Immagini locali che esistono solo in Docker: salvale in un archivio e caricalo. container image load legge archivi OCI, e le versioni recenti di Docker scrivono un layout OCI con docker save. Se il caricamento non riesce, carica l'immagine su un registro e scaricala da lì.

Terminale
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Sposta i volumi con nome

Docker tiene i dati dei volumi dentro la sua VM. Copia ogni volume in un file tar con un container temporaneo, poi estrailo in un nuovo volume apple/container:

Terminale
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

In apple/container un volume con nome è un'immagine disco ext4 sparsa, di 512 GB al massimo per impostazione predefinita. Imposta un'altra dimensione con --opt size=20g. I bind mount delle cartelle del Mac funzionano come in Docker: -v ~/project:/app.

File Compose

La CLI container non ha un comando compose. Apri invece il docker-compose.yml in Gantry (dal Finder, con File ▸ Apri file Compose… o trascinandolo). Gantry crea le immagini dei servizi build:, crea la rete e i volumi con nome del progetto e avvia i servizi nell'ordine di depends_on. I servizi si raggiungono per nome tramite gli alias DNS della rete.

Reti e porte

  • -p 8080:80 pubblica una porta su localhost, come in Docker.
  • Ogni container ha anche il proprio indirizzo IP. Crea un dominio DNS locale con sudo container system dns create test ed esegui i container con --dns-domain test: ricevono nomi come web.test.
  • container network create crea reti utente; i container sulla stessa rete si raggiungono tra loro.
  • Non esistono le modalità --network host, none o container:.

Cosa manca

  • Nessuna API Docker Engine. Gli strumenti che parlano con /var/run/docker.sock, come Testcontainers, gli SDK Docker o Dev Containers, non vedono apple/container.
  • Nessun criterio di riavvio. --restart non è disponibile; un container non si riavvia da solo.
  • Nessun Compose nella CLI. Gantry esegue i file Compose: vedi File Compose.
  • Nessuna estensione di Docker Desktop.
  • Solo CPU intere: --cpus 0.5 non funziona.
  • Kubernetes funziona diversamente: usa container cluster, vedi Kubernetes su Mac.

Tienili entrambi durante il passaggio

Gantry gestisce apple/container e qualsiasi motore Docker (Docker Desktop, OrbStack, Colima o Docker via SSH) in un'unica barra laterale. Sposta un progetto alla volta e tieni Docker per gli strumenti che hanno bisogno della sua API. Quando non ti serve più, puoi rimuovere Docker Desktop.

Domande e risposte

Apple container può sostituire Docker Desktop?

Per eseguire, creare e scaricare container sui chip Apple, sì. Non ha l'API Docker Engine, i criteri di riavvio, le estensioni né un comando compose. Gantry aggiunge i file Compose e una GUI.

Le immagini Docker funzionano con Apple container?

Sì. apple/container usa immagini OCI standard e scarica dagli stessi registri. Le immagini arm64 girano in modo nativo; le immagini amd64 girano tramite Rosetta con --arch amd64.

docker compose funziona con Apple container?

Non dalla CLI: non esiste container compose. Gantry legge il docker-compose.yml ed esegue i servizi su apple/container al posto tuo.

Posso usare Docker Desktop e Apple container contemporaneamente?

Sì. Non condividono immagini né volumi, ma possono funzionare fianco a fianco. Gantry li mostra entrambi in un'unica finestra.

Apple container è gratuito per uso commerciale?

Sì. apple/container è open source con licenza Apache 2.0, e Gantry ha licenza MIT. Entrambi sono gratuiti per aziende di qualsiasi dimensione.

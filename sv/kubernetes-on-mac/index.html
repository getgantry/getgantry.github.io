Gantry/Kubernetes på Mac

Kör Kubernetes på en Mac med Apple container

Apples container-verktyg kan skapa ett lokalt Kubernetes-kluster med ett enda kommando. Varje nod är en lätt virtuell maskin på din Mac. Den här guiden går från en tom Mac till en deployment som körs, först i terminalen och sedan i Gantry.

Kort sagt. Installera det signerade paketet för container 1.7.1, kör container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, bygg en image med container build och kör den i klustret via namn. Gantry visar samma kluster i ett fönster: noder, poddar, loggar, ett skal och portvidarebefordringar.

Det här behöver du

  • En Mac med Apple-chip och macOS 26 eller senare.
  • container-CLI 1.7.1 från den signerade .pkg-filen på versionssidan för apple/container. Homebrew-bygget av 1.7.1 saknar klustertjänsterna, så container cluster misslyckas med cluster service unavailable.
  • Cirka 6 GB ledigt minne för exemplet nedan: tre noder med 2 GB vardera.
  • kubectl om du vill använda klustret från terminalen (brew install kubectl).

Starta tjänsterna en gång när du har installerat paketet:

Terminal
container system start

Skapa klustret

Det här kommandot skapar ett kluster med namnet dev med en kontrollplansnod och två workers. Varje nod får 2 CPU:er och 2 GB minne:

Terminal
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M anger storleken för en grupp workers. Upprepa det för grupper av olika storlek. Utan --workers är en enda nod både kontrollplan och worker.
  • --cpus och --memory anger storleken för kontrollplanet. Standard är en fjärdedel av din Macs CPU:er och minne, minst 2 CPU:er och 2 GB.
  • --shared-image-store låter noderna använda dina lokala images (se nedan). Du kan inte ändra det senare: radera klustret och skapa det igen.
  • --cni ./calico.yaml installerar din egen CNI i stället för den medföljande kindnet; --cni NONE installerar ingen.

CLI:et lägger till en kontext med namnet dev i ~/.kube/config. Kontrollera noderna:

Terminal
container cluster list --nodes
kubectl --context dev get nodes

Kör en lokal image utan register

Med --shared-image-store kan noderna köra vilken image som helst i ditt lokala image-lager för container. Bygg en image och använd den via namn:

Terminal
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Anmärkning
När du har byggt om samma tagg kör du kubectl rollout restart med imagePullPolicy: Always, eller använder en ny tagg. Med IfNotPresent behåller en nod den kopia den redan har. Allt med root på en nod kan läsa varje image i ditt lokala lager, även privata images, så använd det delade lagret bara för lokal utveckling.

På CLI 1.5 och 1.6 finns inget delat lager. Använd container cluster load-image där, eller Läs in i kluster i Gantry. CLI 1.7 tog bort load-image.

Öppna appen i en webbläsare

Vidarebefordra en lokal port till din deployment och öppna sedan http://localhost:8080:

Terminal
kubectl --context dev port-forward deployment/hello 8080:80

Bläddra i klustret i Gantry

Gantry visar samma kluster utan kommandon. Lägg till din apple/container-värd, öppna Kluster och markera dev. Översikten visar Kubernetes-versionen, image-lagret, dina workers och deras CPU:er och minne. Klicka på Bläddra bland resurser för att öppna avsnittet Kubernetes med den kontexten.

  • Poddar, deployments, stateful sets, daemon sets, services, ingresses, config maps, secrets, noder och händelser, för en namnrymd eller alla.
  • Poddloggar med följ och tail, ett skal i podden och portvidarebefordringar med en lista där du kan stoppa dem.
  • Skalning, omstart av utrullning, radering och Verkställ YAML från ett inklistrat manifest eller en fil.
  • Värden i secrets förblir maskerade tills du klickar på Visa.

Kubernetes-utforskaren kör kubectl. Om det saknas visar Gantry brew install kubectl och kan köra det åt dig. En inbyggd klient som inte behöver kubectl är under utveckling.

Du kan också skapa klustret i Gantry: Kluster ▸ Nytt kluster har stegreglage för kontrollplanet och dina workers och en växel för Använd lokala images. Mer på sidan Kubernetes på apple/container.

Stoppa och radera klustret

Terminal
container cluster delete --name dev

Om kontrollplansnoden stoppas, till exempel efter container system stop, raderar du klustret och skapar det igen. Skapa ett tillfälligt kluster med --rm så tas noderna bort när de stoppas.

Vanliga problem

  • cluster service unavailable: CLI:et är Homebrew-bygget, eller tjänsterna körs inte. Installera det signerade paketet, eller starta om tjänsterna med container system stop och container system start. Gantry visar samma råd i Kluster.
  • Ett gammalt kluster saknas i listan: CLI 1.7 listar inte kluster som skapats med 1.6 eller tidigare. Ta bort ett sådant med container cluster delete --name <name>.
  • Noderna förblir NotReady: du använde --cni NONE. Verkställ ett CNI-manifest.
  • Du kan inte stoppa en nodcontainer: det är avsiktligt. container stop och delete vägrar för klusternoder; använd container cluster delete.

Så här står det sig mot Docker Desktop och OrbStack

Docker Desktop har inbyggd Kubernetes med kubeadm (en nod) eller kind (flera noder), och OrbStack har ett inbyggt kluster med en nod. container cluster kör kubeadm på kindest/node-images, varje nod i en egen VM, med kluster med flera noder och det delade image-lagret. Se den fullständiga jämförelsen.

Frågor och svar

Kan jag köra Kubernetes på en Mac utan Docker?

Ja. Apples container-CLI skapar Kubernetes-kluster själv med container cluster create. Varje nod körs som en lätt VM, och du behöver inte Docker, Docker Desktop, kind eller minikube.

Hur många noder kan ett container cluster ha?

Ett kontrollplan och så många workers som din Mac har CPU:er och minne till. Ange dem med --workers; på CLI 1.7 kan varje grupp workers ha egna CPU:er och eget minne.

Hur använder jag en lokalt byggd image i klustret?

Skapa klustret med --shared-image-store (CLI 1.7), bygg imagen med container build -t name:tag . och använd name:tag i poddens specifikation. Inget register behövs.

Vilken Kubernetes-version använder container cluster?

CLI 1.7.1 använder nodimagen kindest/node:v1.35.5 som standard. Välj en annan version med --node-image, till exempel docker.io/kindest/node:v1.34.11. Gantry visar versionen i klusteröversikten.

Finns det ett GUI för container cluster?

Ja. Gantry skapar och raderar kluster, visar noderna och bläddrar bland poddar, deployments, services, loggar och secrets i sitt avsnitt Kubernetes. Det är gratis och har öppen källkod.

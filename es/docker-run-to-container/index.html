Gantry/Desde docker run

Crear un contenedor a partir de un comando docker run

La mayoría de los README traen una línea docker run. Gantry lee esa línea y rellena el formulario Nuevo contenedor, para un host Docker o para la herramienta container de Apple. Esta guía muestra cómo hacerlo y cómo convertir el comando a mano.

En resumen. En Gantry, abre Nuevo contenedor, elige Pegar comando…, pega la línea docker run y haz clic en Rellenar formulario. Gantry lista cada parámetro que no puede usar, con el motivo. En la CLI, la mayoría de los parámetros son iguales: cambia docker run por container run y quita --restart.

Pegar el comando en Gantry

  1. Selecciona un host: un host Docker o un host apple/container.
  2. Abre Contenedores y haz clic en Nuevo contenedor.
  3. Haz clic en Pegar comando… y pega la línea. Los finales de línea con \, las comillas, un prompt $ y sudo no son un problema.
  4. Revisa la vista previa: la imagen, los parámetros que Gantry no puede usar, las notas y los avisos para este host.
  5. Haz clic en Rellenar formulario, comprueba los valores y crea el contenedor.

Gantry lee docker run, docker container run, docker create, podman run y container run. El texto que sigue a &&, ||, ; o | se ignora, con una nota.

Gantry conoce unos 80 parámetros de Docker más: omite sus valores correctamente y los lista como no usados, así que nada se pierde sin una nota.

Avisos para hosts apple/container

Algunas opciones de Docker no existen en apple/container. Gantry avisa de ellas y las deja fuera de la solicitud de creación:

  • políticas de reinicio (--restart);
  • fracciones de CPU, como --cpus 0.5;
  • los modos de red host, none y container:;
  • puertos sin puerto del host, como -p 80.

En un host Docker, Gantry avisa de las opciones de apple/container: el dominio DNS y las opciones del kernel.

Convertir docker run en container run a mano

En la CLI, la mayoría de los parámetros no cambian. Un ejemplo con Redis:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

pasa a ser:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Crea antes el volumen con nombre con container volume create. Quita --restart y redondea --cpus a un número entero. --platform funciona como en Docker.

Copiar un contenedor como comando

También funciona al revés. Haz clic derecho en un contenedor, o usa el menú Más, y elige Copiar como comando: Gantry escribe una línea docker run o container run. Omite los valores predeterminados de la imagen, como su entorno y su comando, para que la línea sea corta. Esto también funciona con contenedores detenidos.

Guardarlo como receta

En la hoja Nuevo contenedor, abre Recetas y elige Guardar como receta…. La próxima vez, Rellenar desde receta te da el mismo formulario en cualquier host. Las recetas están en ~/Library/Application Support/Gantry/recipes.json, así que puedes hacer copia de seguridad de ellas o compartirlas.

Limitaciones

  • Gantry conserva la ruta de --env-file, pero no lee el archivo, y no lee tu shell para -e KEY sin valor.
  • Los montajes tmpfs y los volúmenes anónimos de --mount aparecen como no admitidos.
  • Dos puertos para el mismo puerto del contenedor (-p 8080:80 -p 8081:80) rellenan el formulario, pero después el formulario rechaza el duplicado.

Preguntas y respuestas

¿Cómo convierto docker run en container run?

Cambia docker run por container run. -d, -p, -e, -v, --name, --rm, -it, -w y --entrypoint no cambian. Quita --restart y usa CPU enteras. O pega la línea en Gantry y deja que rellene el formulario.

¿Gantry puede importar un comando docker run?

Sí. Pegar comando…, en la hoja Nuevo contenedor, lee docker run, docker create, podman run y container run y rellena el formulario.

¿Qué pasa con los parámetros que Gantry no admite?

Aparecen en la vista previa con el motivo y se quedan en el formulario, en la sección Del comando pegado, para que puedas revisarlos más tarde.

¿Puedo convertir un contenedor en ejecución de nuevo en un comando docker run?

Sí. Copiar como comando, en el menú del contenedor, escribe una línea docker run o container run para ese contenedor.

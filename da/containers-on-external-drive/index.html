Gantry/Eksternt drev

Gem containere og volumes på et eksternt drev

Images, containere og volumes fylder hurtigt en lille intern disk. Med Apples container-værktøj kan du gemme de data på en ekstern SSD: læg enkelte mapper der med bind-mounts, eller flyt hele datarodden. Denne guide viser begge dele, og hvordan du fjerner disken uden skader.

Kort fortalt. Formatér disken som APFS. Til ét projekt bind-mounter du en mappe: -v /Volumes/Fast/pg:/data. Til det hele stopper du tjenesterne, kopierer ~/Library/Application Support/com.apple.container til disken med cp -Rp og starter tjenesterne med container system start --app-root /Volumes/Fast/container hver gang.

Hvor dataene ligger nu

apple/container gemmer alle sine data i én mappe, app-roden. Som standard er det ~/Library/Application Support/com.apple.container, med mapper til containere, image-indhold, snapshots, volumes, kerner og netværk. Tjek stien og den brugte plads:

Terminal
container system status | grep appRoot
container system df

Vælg og formatér disken

  • Brug en SSD på USB-C eller Thunderbolt. En harddisk med roterende plader virker, men containere starter langsommere.
  • Formatér den som APFS (Mac OS udvidet virker også). Brug ikke exFAT, FAT eller NTFS: volumes er sparse diskimages, og de filsystemer har hverken sparse filer eller Unix-tilladelser.
  • Brug ikke en netværksdisk til app-roden.
  • Giv disken et kort navn uden mellemrum, for eksempel Fast. Stien er så /Volumes/Fast.

Mulighed 1: gem projektdata på disken med bind-mounts

Et bind-mount deler en mappe på din Mac med containeren, og mappen kan ligge på enhver disk. Det er den nemme måde at holde store data, som en database eller modelfiler, væk fra den interne disk:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Disken skal være tilsluttet, før containeren starter. Images og selve containeren bliver på den interne disk.

Mulighed 2: flyt alle apple/container-data til disken

Det flytter images, containere, snapshots og volumes. Stop først tjenesterne, så ingen filer ændres under kopieringen:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Brug cp -Rp. I vores test på macOS 27 (APFS til APFS over USB) forblev volume-imagesene sparse, og de udvidede attributter blev bevaret. ditto skrev hvert sparse image i fuld størrelse, hvilket kan fylde disken. Behold den gamle mappe, indtil du har tjekket, at dine containere, images og volumes vises.

Bemærk
CLI'en husker ikke --app-root. Hver container system start uden flaget bruger igen den interne mappe. Brug flaget hver gang, for eksempel i et shell-alias, og tjek paths.appRoot i container system status.

Gantry 0.27.0 starter tjenesterne uden --app-root, når den forbinder til en vært, hvis tjenester er stoppet. Start først tjenesterne fra terminalen med flaget; så bruger Gantry de kørende tjenester. Understøttelse i Gantry af en flyttet datarod er under udvikling.

Arkivér images på disken

Vil du frigøre plads uden at miste et image, så gem det på den eksterne disk, og slet det. Indlæs det igen, når du har brug for det:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Fjern disken sikkert

  1. Stop de containere, der bruger disken: container stop <name>.
  2. Ligger app-roden på disken, så stop tjenesterne: container system stop.
  3. Skub disken ud i Finder, og tag den derefter ud.

Forsvinder disken, mens containere kører fra den, fejler de, og skrivninger, der er i gang, kan gå tabt. Når du har tilsluttet disken igen, så start tjenesterne med --app-root, og start derefter containerne.

Eksterne drev i Gantry

Gantry kører i dag bind-mounts fra enhver disk: i Ny container tilføjer du et volume og vælger en mappe på den eksterne disk og en sti i containeren. Understøttelse i Gantry af flytning af datarodden, volumes på en ekstern disk og en advarsel, når disken ikke er tilsluttet, er under udvikling.

Docker Desktop og OrbStack

Docker Desktop flytter sit diskimage under Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack fik en indstilling for dataplacering i version 0.13.0. Se sammenligningen.

Spørgsmål og svar

Kan jeg gemme images fra Apple container på et eksternt drev?

Ja. Start tjenesterne med container system start --app-root /Volumes/Disk/container. Alle images, containere, snapshots og volumes ligger derefter i den mappe.

Hvilket filsystem skal det eksterne drev bruge?

APFS. Volumes er sparse diskimages, og containere kræver Unix-tilladelser, som exFAT, FAT og NTFS ikke har.

Hvordan kopierer jeg containerdataene uden at fylde disken?

Brug cp -Rp, som holdt de sparse volume-images små i vores test. ditto kopierede hvert sparse image i fuld størrelse.

Hvad sker der, hvis jeg tager drevet ud, mens containere kører?

De containere, der bruger disken, fejler, og data, der endnu ikke er skrevet, kan gå tabt. Stop containerne og, hvis app-roden ligger på disken, tjenesterne, før du skubber den ud.

Husker container-CLI'en den nye placering?

Nej. Angiv --app-root ved hver container system start. container system status viser den rod, der bruges, som paths.appRoot.

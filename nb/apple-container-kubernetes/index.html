Gantry/Kubernetes på apple/container

Kubernetes på Apple container

apple/container kan kjøre en Kubernetes-klynge der nodene er containere på Macen din. Gantry er et GUI for det: opprett en klynge, se nodene starte, kjør de lokale imagene dine i den, og bla gjennom pods, logger og services, uten lange container cluster-kommandolinjer.

Kort fortalt. På en apple/container-vert oppretter og sletter delen Klynger i Gantry Kubernetes-klynger med container cluster (CLI 1.6.1 og 1.7) eller container k8s (CLI 1.5.0 til 1.6.0). På CLI 1.7.1 angir den størrelsen på arbeidsnodene separat fra kontrollplanet og slår på det delte image-lageret. Delen Kubernetes utforsker klyngen: pods, logger, skall, portvideresending, skalering og Bruk YAML.

Krav

  • En Mac med Apple-chip, macOS 26 og Gantry (brew install --cask getgantry/tap/gantry).
  • container-CLI 1.5.0 eller nyere; 1.7.1 anbefales. Arbeidsnoder og CNI-en Ingen krever 1.6.0 eller nyere. Størrelser på arbeidsnoder og delt image-lager krever 1.7.0 eller nyere. Bruk den signerte installeringspakken: Homebrew-bygget av 1.7.1 har ingen klyngetjenester.
  • kubectl for Kubernetes-utforskeren og terminalen. Gantry kan installere det med Homebrew.

Opprett en klynge

  1. Velg apple/container-verten din og åpne Klynger i sidepanelet.
  2. Start en ny klynge og fyll ut valgene nedenfor.
  3. Opprett den. Listen viser den nye klyngen med fremdrift live. Avbryt stopper opprettingen og sletter nodene som allerede er laget.
ValgCLI-flaggMerknader
Navn--nameOgså navnet på kubeconfig-konteksten
Arbeidsnoder--workersAntall arbeidsnoder. CLI 1.6.0+
CPU-er og minne for arbeidsnoder--workers count=N,cpus=C,memory=MCLI 1.7+. Før 1.7 gjelder --cpus og --memory for alle noder
CPU-er--cpusKontrollplanet (CLI 1.7+), eller alle noder (før 1.7)
Minne--memoryKontrollplanet (CLI 1.7+), eller alle noder (før 1.7), for eksempel 4G
Bruk lokale images--shared-image-storeCLI 1.7+. Nodene kjører images fra det lokale image-lageret ditt
Node-image--node-imageTomt beholder standarden til CLI-en
CNI--cniStandard (medfølgende kindnet), Ingen (NONE, CLI 1.6.0+) eller sti til et egendefinert manifest

Den samme kommandoen i CLI-en:

Skall
container cluster create --name dev --cpus 2 --memory 4G \
  --workers count=2,cpus=2,memory=4G --shared-image-store

Noder og klyngedetaljer

Klyngelisten viser én rad per klynge. Detaljvisningen har Oversikt (kubectl-kontekst, API-server, Kubernetes-versjon, image-lager, arbeidsnoder og ressursene deres, nodenettverk), en Noder-tabell og Inspiser for rådataene til nodene. Verktøylinjen har Bla gjennom ressurser, og Mer-menyen har Skriv kubeconfig, Kopier kubectl-kontekstkommando og Slett.

Klyngenoder er containere, men det er container cluster som eier dem. Gantry slår av start, stopp, omstart, fjerning og nytt navn for en node og forteller deg hvorfor, og Start alle og Stopp alle hopper over noder. På CLI 1.7 skjuler CLI-en også noder fra container list. Klynger opprettet med CLI 1.6 eller eldre vises ikke i 1.7-listen; fjern dem med container cluster delete --name <name>.

Utforsk klyngen

Klikk på Bla gjennom ressurser på en klynge som kjører, eller åpne Kubernetes i sidepanelet. Delen trenger ingen vert, og den viser alle kubeconfig-kontekster; kontekstene til apple/container-klynger kommer først. Velg et navnerom eller alle navnerom, og deretter en art: pods, deployments, StatefulSets, DaemonSets, services, ingresser, ConfigMaps, secrets, noder eller hendelser.

  • Pods: logger med følging, hale og forrige container; et skall i poden; portvideresending til 127.0.0.1.
  • Arbeidslaster: skaler deployments og StatefulSets; start en utrulling på nytt.
  • Secrets: verdiene er maskert i listen og i YAML-en til du klikker på Vis.
  • Bruk YAML: lim inn et manifest eller åpne en fil; feil vises i arket.

Utforskeren kjører kubectl. Finner ikke Gantry det, viser delen brew install kubectl med en knapp som kjører kommandoen.

Koble til kubectl

CLI-en legger til en kontekst med navnet på klyngen i ~/.kube/config når den oppretter klyngen. Bruk Kopier kubectl-kontekstkommando i Gantry, eller skriv den selv:

Skall
kubectl --context dev get nodes

Vil du ha klyngen i en egen fil, bruker du Skriv kubeconfig. Gantry kjører container cluster write-config; standardstien er ~/.kube/<name>.kubeconfig.

Bruk lokale images i klyngen

På CLI 1.7 slår du på Bruk lokale images når du oppretter klyngen. Det legger til --shared-image-store, så nodene kan kjøre alle images du bygger eller henter med container, etter navn, uten register. Innstillingen låses ved opprettelse. Når du har bygd en tagg på nytt, bruker du imagePullPolicy: Always eller en ny tagg. Privilegerte pods kan lese alle images i det lokale lageret ditt, så bruk dette bare til lokal utvikling.

Skall
container build -t myapp:dev .
kubectl --context dev create deployment myapp --image=myapp:dev

På CLI 1.5 og 1.6 høyreklikker du på imaget under Images og velger Last inn i klynge. Gantry kjører container cluster load-image, som kopierer imaget inn i containerd på hver node. CLI 1.7 fjernet denne kommandoen, så Gantry skjuler handlingen der.

Skall
container cluster load-image --name dev myapp:dev

Når klyngetjenestene ikke svarer

Feiler en klyngekommando med cluster service unavailable, sjekker Gantry hvordan CLI-en er installert. Et Homebrew-bygg uten klyngeprogramtilleggene får meldingen om at bygget mangler klyngetjenestene, og en Last ned installeringsprogram…-lenke til den signerte pakken. I andre tilfeller tilbyr Gantry Start tjenestene på nytt….

Velg en CNI

Standard er det medfølgende kindnet-manifestet. Velg Egendefinert manifest for å installere din egen CNI, for eksempel Calico eller Cilium, fra en fil. Velg Ingen for å installere en CNI selv senere; inntil da forblir nodene NotReady.

Kjør Kubernetes på en Mac med Apple container

Apples verktøy container kan opprette en lokal Kubernetes-klynge med én kommando. Hver node er en lett virtuell maskin på Macen din. Denne guiden går fra en tom Mac til en deployment som kjører, først i terminalen og deretter i Gantry.

Dette trenger du

  • En Mac med Apple-chip og macOS 26 eller nyere.
  • container-CLI 1.7.1 fra den signerte .pkg-filen på utgivelsessiden til apple/container. Homebrew-bygget av 1.7.1 har ikke klyngetjenestene, så container cluster feiler med cluster service unavailable.
  • Omtrent 6 GB ledig minne for eksempelet nedenfor: tre noder med 2 GB hver.
  • kubectl hvis du vil bruke klyngen fra terminalen (brew install kubectl).

Start tjenestene én gang etter at du har installert pakken:

Terminal
container system start
    Opprett klyngen

Denne kommandoen lager en klynge med navnet dev med én kontrollplannode og to arbeidsnoder. Hver node får 2 CPU-er og 2 GB minne:

Terminal
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M angir størrelsen på en gruppe arbeidsnoder. Gjenta det for grupper med ulik størrelse. Uten --workers er én node både kontrollplan og arbeidsnode.
  • --cpus og --memory angir størrelsen på kontrollplanet. Standard er en firedel av CPU-ene og minnet på Macen din, minst 2 CPU-er og 2 GB.
  • --shared-image-store lar nodene bruke de lokale imagene dine (se nedenfor). Du kan ikke endre det senere: slett klyngen og opprett den på nytt.
  • --cni ./calico.yaml installerer din egen CNI i stedet for den medfølgende kindnet; --cni NONE installerer ingen.

CLI-en legger til en kontekst med navnet dev i ~/.kube/config. Sjekk nodene:

Terminal
container cluster list --nodes
kubectl --context dev get nodes
    Kjør et lokalt image uten register

Med --shared-image-store kan nodene kjøre alle images i det lokale container-image-lageret ditt. Bygg et image og bruk det etter navn:

Terminal
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Merk
Når du har bygd den samme taggen på nytt, kjører du kubectl rollout restart med imagePullPolicy: Always, eller du bruker en ny tagg. Med IfNotPresent beholder en node kopien den allerede har. Alt som har root på en node, kan lese alle images i det lokale lageret ditt, også private images, så bruk det delte lageret bare til lokal utvikling.

På CLI 1.5 og 1.6 finnes det ikke noe delt lager. Bruk container cluster load-image der, eller Last inn i klynge i Gantry. CLI 1.7 fjernet load-image.

    Åpne appen i en nettleser

Videresend en lokal port til deploymenten, og åpne deretter http://localhost:8080:

Terminal
kubectl --context dev port-forward deployment/hello 8080:80
    Stopp og slett klyngen
Terminal
container cluster delete --name dev

Stopper kontrollplannoden, for eksempel etter container system stop, sletter du klyngen og oppretter den på nytt. Lag en midlertidig klynge med --rm for å fjerne nodene når de stopper.

    Vanlige problemer
  • cluster service unavailable: CLI-en er Homebrew-bygget, eller tjenestene kjører ikke. Installer den signerte pakken, eller start tjenestene på nytt med container system stop og container system start. Gantry gir det samme rådet under Klynger.
  • En gammel klynge mangler i listen: CLI 1.7 viser ikke klynger som er opprettet med 1.6 eller eldre. Fjern en slik klynge med container cluster delete --name <name>.
  • Nodene forblir NotReady: du brukte --cni NONE. Bruk et CNI-manifest.
  • Du kan ikke stoppe en nodecontainer: dette er med vilje. container stop og delete avviser klyngenoder; bruk container cluster delete.
    Slik står dette seg mot Docker Desktop og OrbStack

Docker Desktop har innebygd Kubernetes med kubeadm (én node) eller kind (flere noder), og OrbStack har en innebygd klynge med én node. container cluster kjører kubeadm på kindest/node-images, hver node i sin egen VM, med klynger med flere noder og delt image-lager. Se hele sammenligningen.

Klynger fra AI-agenter

MCP-serveren til Gantry har list_clusters, create_cluster og delete_cluster, så en agent som Claude Code kan lage en midlertidig klynge for en test og fjerne den etterpå.

Legg til MCP-serveren til Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Spørsmål og svar

Støtter Apple container Kubernetes?

Ja. container-CLI-en oppretter Kubernetes-klynger der nodene kjører som containere: container cluster i CLI 1.6.1 og 1.7, container k8s i CLI 1.5.0 til 1.6.0. Gantry gir dette et GUI.

Støtter Gantry container cluster?

Ja. Gantry viser, oppretter og sletter klynger på apple/container-verter, viser nodene deres, skriver kubeconfig og åpner klyngen i Kubernetes-utforskeren. På CLI 1.7 angir den også størrelsen på arbeidsnodene og slår på det delte image-lageret. Den bruker cluster eller k8s etter hvilken CLI-versjon du har.

Hvordan bruker jeg kubectl med en apple/container-klynge?

Når CLI-en oppretter en klynge, legger den til en kubeconfig-kontekst med navnet på klyngen i ~/.kube/config. Kjør kubectl --context <name> get nodes. Vil du ha en egen fil, bruker du Skriv kubeconfig i Gantry; standardstien er ~/.kube/<name>.kubeconfig.

Hvordan får jeg et lokalt image inn i klyngen uten et register?

På CLI 1.7 oppretter du klyngen med Bruk lokale images (--shared-image-store). Pods kjører da imagene du bygger eller henter med container, etter navn. På CLI 1.5 og 1.6 høyreklikker du på imaget under Images og velger Last inn i klynge; Gantry kjører container cluster load-image. CLI 1.7 fjernet load-image.

Kan jeg opprette en klynge med flere noder?

Ja. Angi antall arbeidsnoder i opprettingsarket; arbeidsnoder krever CLI 1.6.0 eller nyere. På CLI 1.7 angir du også CPU-er og minne for arbeidsnodene separat fra kontrollplanet.

Kan jeg bruke min egen CNI, som Calico eller Cilium?

Ja. Velg Egendefinert manifest og velg manifestfilen, eller velg Ingen og installer en CNI selv etter at klyngen har startet. Nodene forblir NotReady til en CNI kjører. Ingen krever CLI 1.6.0 eller nyere. Standard-CNI-en er det medfølgende kindnet-manifestet.

Hvorfor sier Gantry at klyngetjenestene ikke er tilgjengelige?

container-tjenestene svarte ikke på en klyngekommando. Er CLI-en din et Homebrew-bygg uten klyngetjenestene, sier Gantry fra og lenker til det signerte installeringsprogrammet på utgivelsessiden til apple/container. Ellers tilbyr den Start tjenestene på nytt.

Trenger jeg kubectl for å bruke klyngen i Gantry?

Foreløpig ja: Kubernetes-utforskeren i Gantry kjører kubectl. Er det ikke installert, viser utforskeren kommandoen brew install kubectl og kan kjøre den for deg.

Kan jeg kjøre Kubernetes på en Mac uten Docker?

Ja. Apples container-CLI oppretter Kubernetes-klynger selv med container cluster create. Hver node kjører som en lett VM, og du trenger verken Docker, Docker Desktop, kind eller minikube.

Hvor mange noder kan en container cluster ha?

Ett kontrollplan og så mange arbeidsnoder som Macen din har CPU-er og minne til. Angi dem med --workers; på CLI 1.7 kan hver gruppe arbeidsnoder ha egne CPU-er og eget minne.

Hvilken Kubernetes-versjon bruker container cluster?

CLI 1.7.1 bruker node-imaget kindest/node:v1.35.5 som standard. Velg en annen versjon med --node-image, for eksempel docker.io/kindest/node:v1.34.11. Gantry viser versjonen i klyngeoversikten.

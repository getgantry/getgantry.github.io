Z Docker Desktop na Apple container

Nástroj container od Apple spúšťa tie isté obrazy OCI ako Docker, takže väčšinu práce prenesiete s niekoľkými zmenami v príkazoch. Tento návod prevádza Docker na container, prenáša obrazy a zväzky a uvádza medzery, o ktorých by ste mali vedieť pred prechodom.

V skratke. Nainštalujte podpísaný balík container, pri run, build, logs, exec a obrazoch nahraďte docker za container, pomenované zväzky skopírujte cez súbor tar a docker-compose.yml otvorte v Gantry, pretože CLI nemá compose. Počas skúšania môžete mať Docker Desktop naďalej nainštalovaný.

Čo sa mení

  • Jeden virtuálny stroj na kontajner. Docker Desktop spúšťa všetky kontajnery v jednom linuxovom virtuálnom stroji. apple/container spúšťa malý virtuálny stroj pre každý kontajner, takže každý dostane na vašom Macu vlastnú IP adresu.
  • Rovnaké obrazy a registre. Obrazy sú obrazy OCI; sťahujete ich z Docker Hub, GHCR a súkromných registrov ako doteraz.
  • Žiadny licenčný poplatok. apple/container je pod licenciou Apache 2.0. Docker Desktop vyžaduje platený plán v organizáciách s 250 a viac zamestnancami alebo s obratom 10 mil. USD a viac.
  • Len Apple silicon a macOS 26. Na Macoch s procesorom Intel zostaňte pri engine Docker.

Väčšina príznakov run je rovnaká: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus a -m. Dlhý príkaz prevediete tak, že ho vložíte do Gantry: pozrite si Kontajner z príkazu docker run.

    Prenos obrazov

Obrazy z registra: stiahnite ich znova príkazom container image pull. Lokálne obrazy, ktoré existujú len v Dockeri: uložte ich do archívu a ten načítajte. container image load číta archívy OCI a novšie verzie Dockeru zapisujú príkazom docker save layout OCI. Ak načítanie zlyhá, odošlite obraz do registra a stiahnite ho.

Terminál
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Presun pomenovaných zväzkov

Docker drží dáta zväzkov vo svojom virtuálnom stroji. Každý zväzok skopírujte do súboru tar pomocou krátko bežiaceho kontajnera a potom ho rozbaľte do nového zväzku apple/container:

Terminál
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Pomenovaný zväzok v apple/container je riedky (sparse) obraz disku ext4, predvolene najviac 512 GB. Inú veľkosť nastavíte pomocou --opt size=20g. Bind mounty priečinkov z vášho Macu fungujú ako v Dockeri: -v ~/project:/app.

    Súbory Compose

CLI container nemá príkaz compose. Namiesto toho otvorte docker-compose.yml v Gantry (Finder, Súbor ▸ Otvoriť súbor Compose… alebo presunutím). Gantry zostaví služby s build:, vytvorí sieť projektu a pomenované zväzky a spustí služby v poradí podľa depends_on. Služby sa navzájom nájdu podľa názvu služby vďaka aliasom DNS v sieti.

    Siete a porty
  • -p 8080:80 publikuje port na localhost, rovnako ako v Dockeri.
  • Každý kontajner má aj vlastnú IP adresu. Vytvorte lokálnu doménu DNS príkazom sudo container system dns create test a spúšťajte kontajnery s --dns-domain test: dostanú názvy ako web.test.
  • container network create vytvára používateľské siete; kontajnery v tej istej sieti sa navzájom vidia.
  • Režim --network host, none ani container: neexistuje.
    Čo chýba
  • Žiadne Docker Engine API. Nástroje, ktoré komunikujú s /var/run/docker.sock, napríklad Testcontainers, Docker SDK alebo Dev Containers, apple/container nevidia.
  • Žiadne politiky reštartu. --restart nie je k dispozícii; kontajner sa sám znova nespustí.
  • Žiadny Compose v CLI. Súbory Compose spúšťa Gantry: pozrite si Súbory Compose.
  • Žiadne rozšírenia Docker Desktop.
  • Len celé CPU: --cpus 0.5 nefunguje.
  • Kubernetes funguje inak: použite container cluster, pozrite si Kubernetes na Macu.
    Počas prechodu majte oboje

Gantry spravuje apple/container aj ľubovoľný engine Docker (Docker Desktop, OrbStack, Colima alebo Docker cez SSH) v jednom bočnom paneli. Prenášajte jeden projekt po druhom a Docker si nechajte pre nástroje, ktoré potrebujú jeho API. Keď ho už nebudete potrebovať, môžete Docker Desktop odinštalovať.

Otázky a odpovede

Môže Apple container nahradiť Docker Desktop?

Na spúšťanie, zostavovanie a sťahovanie kontajnerov na Apple silicon áno. Nemá Docker Engine API, politiky reštartu, rozšírenia ani príkaz compose. Gantry pridáva súbory Compose a GUI.

Fungujú obrazy Dockeru s Apple container?

Áno. apple/container používa štandardné obrazy OCI a sťahuje z tých istých registrov. Obrazy arm64 bežia natívne; obrazy amd64 bežia cez Rosetta s --arch amd64.

Funguje docker compose s Apple container?

Z CLI nie: container compose neexistuje. Gantry prečíta docker-compose.yml a spustí služby na apple/container za vás.

Môžem používať Docker Desktop a Apple container súčasne?

Áno. Nezdieľajú obrazy ani zväzky, ale môžu bežať vedľa seba. Gantry ukazuje oba v jednom okne.

Je Apple container zadarmo na komerčné použitie?

Áno. apple/container je open source pod licenciou Apache 2.0 a Gantry je pod licenciou MIT. Oboje je zadarmo pre firmy ľubovoľnej veľkosti.

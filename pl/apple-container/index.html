Gantry/Przewodnik po apple/container

Apple container na Macu: pełny przewodnik i GUI

apple/container uruchamia linuksowe kontenery na Macu, każdy we własnej lekkiej maszynie wirtualnej. Jest dostępne jako narzędzie wiersza poleceń. Gantry to dla niego natywne GUI na macOS. Ten przewodnik wyjaśnia, czym jest to narzędzie, jak je skonfigurować i która funkcja Gantry obsługuje każde polecenie container.

W skrócie. Gantry to darmowa aplikacja open source (MIT) na macOS, która zarządza narzędziem container od Apple i Dockerem z jednego okna. Obsługuje CLI container od 1.0 do 1.6.1 (zalecana wersja) i pokazuje tylko funkcje obsługiwane przez Twoją wersję CLI. Zainstaluj ją poleceniem brew install --cask getgantry/tap/gantry.

Czym jest apple/container?

apple/container to narzędzie open source od Apple, napisane w Swift, które tworzy i uruchamia linuksowe kontenery na Macu. Docker Desktop uruchamia wszystkie kontenery we wspólnej linuksowej maszynie wirtualnej; apple/container uruchamia każdy kontener we własnej lekkiej maszynie wirtualnej, opartej na frameworku Virtualization od Apple. Korzysta ze standardowych obrazów OCI, więc pobiera z tych samych rejestrów co Docker i wypycha do nich.

  • Sprzęt: Mac z Apple silicon.
  • macOS: Apple obsługuje je na macOS 26.
  • Interfejs: tylko CLI container. Nie ma aplikacji desktopowej ani polecenia compose.
  • Sieć: każdy kontener dostaje własny adres IP na Macu, a lokalne domeny DNS nadają kontenerom nazwy, takie jak web.test.

Po co GUI dla apple/container?

CLI jest kompletne, ale codzienna praca to mnóstwo poleceń: container list, logs, stats, exec, a do reszty system, builder, registry, machine i cluster. Gantry zbiera je w jednym oknie z aktualizacjami na żywo, więc widzisz stan, zamiast go odpytywać. Dodaje też to, czego CLI nie ma: pliki Compose, powiadomienia o awariach, widok floty z hostami Docker i serwer MCP dla agentów AI.

Konfiguracja apple/container z Gantry

  1. Zainstaluj Gantry: brew install --cask getgantry/tap/gantry, a potem usuń flagę kwarantanny (zobacz Instalacja).
  2. Zainstaluj CLI container z podpisanego pakietu .pkg ze strony wydań apple/container. Jeśli go brakuje lub jest starsze niż 1.0, Gantry wyświetli arkusz z instrukcją instalacji.
  3. W Gantry wybierz Dodaj host… i dodaj host Apple Container. Połączenie uruchamia usługi container, jeśli są zatrzymane.
  4. Jeśli nie ma zainstalowanego domyślnego jądra, przegląd hosta pokazuje baner. Kliknij go, aby zainstalować zalecane jądro.
Uwaga
Użyj podpisanego pakietu instalacyjnego, a nie wersji z Homebrew. Wersja z Homebrew nie zawiera backendu maszyn, więc container machine nie zadziała.

Co Gantry dodaje do apple/container

Klastry Kubernetes

Twórz klastry Kubernetes z wieloma węzłami roboczymi poleceniem container cluster, wybieraj CNI, przeglądaj każdy węzeł, zapisuj kubeconfig i wczytuj lokalne obrazy do klastra. Zobacz Kubernetes na apple/container.

Maszyny container i VS Code

Maszyny to trwałe linuksowe środowiska tworzone przez container machine. Gantry je tworzy, uruchamia, zatrzymuje i usuwa, ustawia maszynę domyślną, zmienia procesory i pamięć oraz otwiera powłokę. Od CLI 1.1 maszyna może się uruchamiać z wirtualizacją zagnieżdżoną (Apple silicon M3 lub nowszy) i własnym jądrem. Otwórz w VS Code łączy się z uruchomioną maszyną przez Remote-SSH; obraz maszyny musi uruchamiać sshd.

Docker Compose na apple/container

Otwórz docker-compose.yml z Findera (Otwórz za pomocą ▸ Gantry lub Szybkie czynności ▸ Compose Up w apple/container), z menu Plik ▸ Otwórz plik Compose… albo upuszczając go na okno. Gantry buduje usługi z build:, tworzy sieć projektu i nazwane woluminy, a następnie uruchamia usługi w kolejności depends_on ze standardowymi etykietami com.docker.compose.*. Gdy ustawiona jest domyślna domena DNS, usługi docierają do siebie po nazwie usługi przez aliasy sieci.

Aliasy DNS sieci i lokalne domeny

Gantry przekazuje aliasy sieci do container jako --network <name>,alias=…. Bez domyślnej domeny DNS przechodzą tylko w pełni kwalifikowane nazwy, a alias poddrzewa (z kropką na początku, np. .gateway) przechodzi tylko jako dokładny alias. Z domyślną domeną działają też krótkie nazwy. Gantry tworzy i usuwa lokalne domeny DNS, ustawia domenę domyślną i nadaje nowym kontenerom nazwę hosta name.domain. Zobacz Lokalne nazwy DNS.

System: usługi, builder, rejestry, jądro, logi, właściwości

Każdy host apple/container ma sekcję System. Działa ona także wtedy, gdy host jest rozłączony, więc możesz z niej uruchomić zatrzymane usługi.

  • Status i wersja: wersje klienta i serwera z ostrzeżeniem, gdy się różnią; uruchamianie, zatrzymywanie i ponowne uruchamianie usług; informacje o hoście i ścieżki.
  • Builder obrazów: stan, obraz, procesory, pamięć i IP; uruchamianie z opcjami CPU, pamięci i DNS; zatrzymywanie; usuwanie.
  • Logowania do rejestrów: lista, logowanie i wylogowanie. Hasło trafia do CLI wyłącznie przez stdin (--password-stdin), a Gantry nie przechowuje jego kopii.
  • Jądro: instalacja zalecanego jądra, pliku jądra lub archiwum tar z postępem na żywo.
  • Logi usług: na żywo lub jednorazowo, z okresu od 5 minut do 1 dnia, z filtrem poziomu, usługi i tekstu.
  • Właściwości systemowe: zmiany trafiają do ~/.config/container/config.toml, z oznaczeniem oczekującego restartu i przyciskiem Uruchom ponownie usługi.

Zapis jako obraz, Przytnij dysk i pliki

Zapisz jako obraz korzysta z container commit (CLI 1.6). Przytnij dysk korzysta z container clean (CLI 1.4) i pojawia się też jako wiersz w panelu Odzyskaj miejsce. Karta Pliki zapisuje pliki na Macu i pozwala przeciągać je do Findera za pomocą container copy (kontener musi być uruchomiony), a także wysyła pliki i foldery.

Etykiety ze znakiem =

container create odrzuca wartość etykiety zawierającą =, także w CLI 1.6.1. Gantry koduje takie wartości przy tworzeniu kontenera i dekoduje je przy odczycie, więc widzisz dokładnie te etykiety, które ustawiasz.

Serwer MCP i Skróty

Wbudowany serwer gantry-mcp daje agentom AI te same możliwości na hostach apple/container: kontenery, obrazy, woluminy, sieci, Compose, maszyny (list_machines, create_machine i inne), klastry (list_clusters, create_cluster, delete_cluster) oraz narzędzia systemowe apple_* dla usług, buildera, rejestrów (bez narzędzia do logowania), właściwości, logów i instalacji jądra. App Intents dodają akcje dla Skrótów i Siri. Zobacz Agenci AI i MCP.

Dodaj serwer MCP Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container obok Dockera

Gantry zarządza hostami apple/container, lokalnym demonem Dockera (Docker Desktop, OrbStack, Colima) i zdalnymi hostami Docker przez SSH na jednym pasku bocznym i jednym pulpicie floty. Nie musisz wybierać jednego środowiska. Porównanie narzędzi funkcja po funkcji znajdziesz na stronie Gantry kontra Docker Desktop, OrbStack i Podman Desktop.

Pytania i odpowiedzi

Jakie GUI wybrać dla Apple container?

Gantry to darmowe natywne GUI open source na macOS, stworzone dla apple/container. Przenosi CLI container do aplikacji desktopowej: kontenery, logi, statystyki i exec, a do tego klastry Kubernetes, maszyny, builder obrazów, logowania do rejestrów, jądra, logi usług i właściwości systemowe. Tabela na tej stronie zestawia każde polecenie z funkcją Gantry, która z niego korzysta.

Czy Apple container ma GUI?

Apple udostępnia container wyłącznie jako narzędzie wiersza poleceń. Gantry to osobna aplikacja open source, która daje mu GUI, obok hostów Docker.

Czy można używać docker compose z Apple container?

apple/container nie ma polecenia compose. Gantry odczytuje docker-compose.yml, buduje usługi z build:, tworzy sieć i nazwane woluminy, a następnie uruchamia usługi w kolejności depends_on. Nazwy usług są rozwiązywane przez aliasy DNS sieci.

Jak otworzyć maszynę container w VS Code?

Uruchom maszynę w Gantry i kliknij Otwórz w VS Code. Gantry otworzy ją przez Remote-SSH, tak jak w przykładzie container-machine-vscode od Apple. Obraz maszyny musi uruchamiać sshd.

Czy Apple container działa na Macach z Intelem?

Nie. apple/container wymaga Maca z Apple silicon. Gantry działa także na Macach z Intelem, ale tam zarządza tylko hostami Docker.

Którą wersję CLI container zainstalować?

Gantry wymaga wersji 1.0 lub nowszej i jest testowany z 1.6.1. Zainstaluj ją z podpisanego pakietu instalacyjnego ze strony wydań apple/container. Wersja z Homebrew nie zawiera backendu maszyn, więc container machine z nią nie działa.

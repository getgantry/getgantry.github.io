Gantry/Desde Docker Desktop

Pasar de Docker Desktop a Apple container

La herramienta container de Apple ejecuta las mismas imágenes OCI que Docker, así que la mayor parte de tu trabajo se traslada con unos pocos cambios de comandos. Esta guía relaciona Docker con container, traslada imágenes y volúmenes, y enumera las carencias que conviene conocer antes del cambio.

En resumen. Instala el paquete firmado de container, cambia docker por container para run, build, logs, exec e imágenes, copia los volúmenes con nombre mediante un archivo tar y abre tu docker-compose.yml en Gantry, porque la CLI no tiene compose. Puedes mantener Docker Desktop instalado mientras lo pruebas.

Qué cambia

  • Una VM por contenedor. Docker Desktop ejecuta todos los contenedores en una sola VM Linux. apple/container arranca una VM pequeña para cada contenedor, así que cada uno tiene su propia dirección IP en tu Mac.
  • Las mismas imágenes y registros. Las imágenes son imágenes OCI; descargas de Docker Hub, GHCR y registros privados como antes.
  • Sin coste de licencia. apple/container es Apache 2.0. Docker Desktop requiere un plan de pago en organizaciones con 250 empleados o más, o con 10 millones de USD de ingresos o más.
  • Solo chip de Apple y macOS 26. En los Mac con Intel, sigue con un motor Docker.

Traer tus imágenes

Imágenes de un registro: vuelve a descargarlas con container image pull. Imágenes locales que solo existen en Docker: guárdalas en un archivo y cárgalo. container image load lee archivos OCI, y las versiones recientes de Docker escriben un layout OCI con docker save. Si la carga falla, sube la imagen a un registro y descárgala.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Trasladar los volúmenes con nombre

Docker guarda los datos de los volúmenes dentro de su VM. Copia cada volumen a un archivo tar con un contenedor de corta duración y después descomprímelo en un volumen nuevo de apple/container:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Un volumen con nombre en apple/container es una imagen de disco ext4 dispersa, de 512 GB como máximo de forma predeterminada. Define otro tamaño con --opt size=20g. Los montajes enlazados de carpetas de tu Mac funcionan como en Docker: -v ~/project:/app.

Archivos Compose

La CLI container no tiene un comando compose. En su lugar, abre el docker-compose.yml en Gantry (desde el Finder, con Archivo ▸ Abrir archivo Compose… o arrastrándolo). Gantry compila los servicios build:, crea la red y los volúmenes con nombre del proyecto e inicia los servicios en el orden de depends_on. Los servicios se encuentran entre sí por el nombre de servicio mediante alias DNS de red.

Redes y puertos

  • -p 8080:80 publica un puerto en localhost, como en Docker.
  • Además, cada contenedor tiene su propia dirección IP. Crea un dominio DNS local con sudo container system dns create test y ejecuta los contenedores con --dns-domain test: reciben nombres como web.test.
  • container network create crea redes de usuario; los contenedores de la misma red se ven entre sí.
  • No hay modo --network host, none ni container:.

Qué falta

  • Sin API de Docker Engine. Las herramientas que se comunican con /var/run/docker.sock, como Testcontainers, los SDK de Docker o Dev Containers, no ven apple/container.
  • Sin políticas de reinicio. --restart no está disponible; un contenedor no vuelve a arrancar por sí solo.
  • Sin Compose en la CLI. Gantry ejecuta archivos Compose: consulta Archivos Compose.
  • Sin extensiones de Docker Desktop.
  • Solo CPU enteras: --cpus 0.5 no funciona.
  • Kubernetes funciona de otra forma: usa container cluster; consulta Ejecutar Kubernetes en un Mac.

Mantener ambos durante el cambio

Gantry gestiona apple/container y cualquier motor Docker (Docker Desktop, OrbStack, Colima o Docker por SSH) en una sola barra lateral. Traslada un proyecto cada vez y mantén Docker para las herramientas que necesitan su API. Cuando ya no lo necesites, puedes desinstalar Docker Desktop.

Preguntas y respuestas

¿Puede Apple container sustituir a Docker Desktop?

Para ejecutar, compilar y descargar contenedores en chips de Apple, sí. No tiene la API de Docker Engine, políticas de reinicio, extensiones ni un comando compose. Gantry añade los archivos Compose y una GUI.

¿Las imágenes de Docker funcionan con Apple container?

Sí. apple/container usa imágenes OCI estándar y descarga de los mismos registros. Las imágenes arm64 se ejecutan de forma nativa; las amd64, mediante Rosetta con --arch amd64.

¿docker compose funciona con Apple container?

No desde la CLI: no existe container compose. Gantry lee el docker-compose.yml y ejecuta los servicios en apple/container por ti.

¿Puedo usar Docker Desktop y Apple container a la vez?

Sí. No comparten imágenes ni volúmenes, pero pueden funcionar en paralelo. Gantry muestra los dos en una sola ventana.

¿Apple container es gratuito para uso comercial?

Sí. apple/container es de código abierto con licencia Apache 2.0, y Gantry tiene licencia MIT. Los dos son gratuitos para empresas de cualquier tamaño.

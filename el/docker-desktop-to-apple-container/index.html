Μετάβαση από το Docker Desktop στο Apple container

Το εργαλείο container της Apple εκτελεί τις ίδιες εικόνες OCI με το Docker, οπότε το μεγαλύτερο μέρος της δουλειάς σας μεταφέρεται με λίγες αλλαγές στις εντολές. Αυτός ο οδηγός αντιστοιχίζει το Docker στο container, μεταφέρει εικόνες και τόμους και παραθέτει τα κενά που πρέπει να γνωρίζετε πριν αλλάξετε.

Με λίγα λόγια. Εγκαταστήστε το υπογεγραμμένο πακέτο container, αντικαταστήστε το docker με container για run, build, logs, exec και εικόνες, αντιγράψτε τους ονομασμένους τόμους με ένα αρχείο tar και ανοίξτε το docker-compose.yml στο Gantry, γιατί το CLI δεν έχει compose. Μπορείτε να κρατήσετε το Docker Desktop εγκατεστημένο όσο δοκιμάζετε.

Τι αλλάζει

  • Μία VM ανά κοντέινερ. Το Docker Desktop εκτελεί όλα τα κοντέινερ σε μία VM Linux. Το apple/container ξεκινά μια μικρή VM για κάθε κοντέινερ, οπότε το καθένα έχει δική του διεύθυνση IP στο Mac σας.
  • Ίδιες εικόνες και μητρώα. Οι εικόνες είναι εικόνες OCI· κάνετε λήψη από Docker Hub, GHCR και ιδιωτικά μητρώα όπως πριν.
  • Χωρίς τέλος άδειας. Το apple/container είναι Apache 2.0. Το Docker Desktop απαιτεί πρόγραμμα επί πληρωμή σε οργανισμούς με 250 ή περισσότερους υπαλλήλους ή έσοδα $10 εκατ. και άνω.
  • Μόνο Apple silicon και macOS 26. Σε Mac με Intel, μείνετε σε μηχανή Docker.

Μεταφορά των εικόνων σας

Εικόνες από μητρώο: κάντε ξανά λήψη με container image pull. Τοπικές εικόνες που υπάρχουν μόνο στο Docker: αποθηκεύστε τες σε αρχείο αρχειοθέτησης και φορτώστε το. Το container image load διαβάζει αρχεία OCI, και οι πρόσφατες εκδόσεις του Docker γράφουν διάταξη OCI με docker save. Αν η φόρτωση αποτύχει, στείλτε την εικόνα σε ένα μητρώο και κάντε λήψη από εκεί.

Τερματικό
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Μεταφορά ονομασμένων τόμων

Το Docker κρατά τα δεδομένα των τόμων μέσα στη VM του. Αντιγράψτε κάθε τόμο σε ένα αρχείο tar με ένα βραχύβιο κοντέινερ και, στη συνέχεια, αποσυμπιέστε το σε νέο τόμο του apple/container:

Τερματικό
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Ένας ονομασμένος τόμος στο apple/container είναι μια αραιή εικόνα δίσκου ext4, έως 512 GB από προεπιλογή. Ορίστε άλλο μέγεθος με --opt size=20g. Τα bind mount φακέλων του Mac σας λειτουργούν όπως στο Docker: -v ~/project:/app.

Αρχεία Compose

Το CLI container δεν έχει εντολή compose. Ανοίξτε αντί γι' αυτό το docker-compose.yml στο Gantry (Finder, Αρχείο ▸ Άνοιγμα αρχείου Compose… ή μεταφορά και απόθεση). Το Gantry δομεί τις υπηρεσίες build:, δημιουργεί το δίκτυο του έργου και τους ονομασμένους τόμους και ξεκινά τις υπηρεσίες με τη σειρά του depends_on. Οι υπηρεσίες επικοινωνούν μεταξύ τους με το όνομα υπηρεσίας μέσω ψευδωνύμων DNS του δικτύου.

Δίκτυα και θύρες

  • Το -p 8080:80 δημοσιεύει μια θύρα στο localhost, όπως στο Docker.
  • Κάθε κοντέινερ έχει επίσης δική του διεύθυνση IP. Δημιουργήστε έναν τοπικό τομέα DNS με sudo container system dns create test και εκτελέστε κοντέινερ με --dns-domain test: παίρνουν ονόματα όπως web.test.
  • Το container network create δημιουργεί δίκτυα χρήστη· τα κοντέινερ στο ίδιο δίκτυο επικοινωνούν μεταξύ τους.
  • Δεν υπάρχει λειτουργία --network host, none ή container:.

Τι λείπει

  • Δεν υπάρχει API του Docker Engine. Τα εργαλεία που μιλούν με το /var/run/docker.sock, όπως τα Testcontainers, τα SDK του Docker ή τα Dev Containers, δεν βλέπουν το apple/container.
  • Δεν υπάρχουν πολιτικές επανεκκίνησης. Το --restart δεν είναι διαθέσιμο· ένα κοντέινερ δεν ξεκινά ξανά μόνο του.
  • Δεν υπάρχει Compose στο CLI. Το Gantry εκτελεί αρχεία Compose: δείτε Αρχεία Compose.
  • Δεν υπάρχουν επεκτάσεις του Docker Desktop.
  • Μόνο ακέραιες CPU: το --cpus 0.5 δεν λειτουργεί.
  • Το Kubernetes διαφέρει: χρησιμοποιήστε container cluster, δείτε Kubernetes σε Mac.

Κρατήστε και τα δύο κατά τη μετάβαση

Το Gantry διαχειρίζεται το apple/container και οποιαδήποτε μηχανή Docker (Docker Desktop, OrbStack, Colima ή Docker μέσω SSH) σε μία πλαϊνή στήλη. Μεταφέρετε ένα έργο τη φορά και κρατήστε το Docker για τα εργαλεία που χρειάζονται το API του. Όταν δεν το χρειάζεστε πια, μπορείτε να αφαιρέσετε το Docker Desktop.

Ερωτήσεις και απαντήσεις

Μπορεί το Apple container να αντικαταστήσει το Docker Desktop;

Για εκτέλεση, δόμηση και λήψη κοντέινερ σε Apple silicon, ναι. Δεν έχει το API του Docker Engine, πολιτικές επανεκκίνησης, επεκτάσεις ή εντολή compose. Το Gantry προσθέτει αρχεία Compose και GUI.

Λειτουργούν οι εικόνες Docker με το Apple container;

Ναι. Το apple/container χρησιμοποιεί τυπικές εικόνες OCI και κάνει λήψη από τα ίδια μητρώα. Οι εικόνες arm64 εκτελούνται εγγενώς· οι εικόνες amd64 εκτελούνται μέσω Rosetta με --arch amd64.

Λειτουργεί το docker compose με το Apple container;

Όχι από το CLI: δεν υπάρχει container compose. Το Gantry διαβάζει το docker-compose.yml και εκτελεί τις υπηρεσίες στο apple/container για εσάς.

Μπορώ να χρησιμοποιώ το Docker Desktop και το Apple container ταυτόχρονα;

Ναι. Δεν μοιράζονται εικόνες ή τόμους, αλλά μπορούν να εκτελούνται παράλληλα. Το Gantry εμφανίζει και τα δύο σε ένα παράθυρο.

Είναι το Apple container δωρεάν για εμπορική χρήση;

Ναι. Το apple/container είναι ανοιχτού κώδικα με άδεια Apache 2.0 και το Gantry έχει άδεια MIT. Και τα δύο είναι δωρεάν για εταιρείες κάθε μεγέθους.

Gantry/От docker run

Създаване на контейнер от команда docker run

Повечето README файлове дават ред docker run. Gantry чете този ред и попълва формуляра „Нов контейнер“ за хост на Docker или за инструмента container на Apple. Това ръководство показва как, както и как да преобразувате командата ръчно.

Накратко. В Gantry отворете Нов контейнер, изберете Постави команда…, поставете реда docker run и щракнете Попълни формуляра. Gantry изброява всеки флаг, който не може да използва, с причината. За CLI повечето флагове са същите: заменете docker run с container run и премахнете --restart.

Поставяне на командата в Gantry

  1. Изберете хост: хост на Docker или хост с apple/container.
  2. Отворете Контейнери и щракнете Нов контейнер.
  3. Щракнете Постави команда… и поставете реда. Краища на редове с \, кавички, подкана $ и sudo не са проблем.
  4. Прочетете прегледа: образа, флаговете, които Gantry не може да използва, бележките и предупрежденията за този хост.
  5. Щракнете Попълни формуляра, проверете стойностите и създайте контейнера.

Gantry чете docker run, docker container run, docker create, podman run и container run. Текстът след &&, ||, ; или | се пренебрегва, с бележка.

Известни са още около 80 флага на Docker: Gantry пропуска стойностите им правилно и ги изброява като неизползвани, така че нищо не се губи без бележка.

    Предупреждения за хостове с apple/container

Някои опции на Docker не съществуват в apple/container. Gantry предупреждава за тях и ги изпуска от заявката за създаване:

  • политики за рестартиране (--restart);
  • дробни CPU като --cpus 0.5;
  • мрежовите режими host, none и container:;
  • портове без порт на хоста, като -p 80.

На хост на Docker Gantry предупреждава за опциите на apple/container: DNS домейна и опциите на ядрото.

    Ръчно преобразуване на docker run в container run

За CLI повечето флагове остават същите. Пример с Redis:

Терминал
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

става:

Терминал
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Първо създайте именувания том с container volume create. Премахнете --restart и закръглете --cpus до цяло число. --platform работи както в Docker.

    Копиране на контейнер като команда

Работи и в обратната посока. Щракнете с десния бутон върху контейнер или използвайте менюто „Още“ и изберете Копирай като команда: Gantry записва ред docker run или container run. Пропуска стойностите по подразбиране на образа, като средата и командата му, така че редът остава кратък. Работи и за спрени контейнери.

    Запазване като рецепта

В листа „Нов контейнер“ отворете Рецепти и изберете Запази като рецепта…. Следващия път Попълни от рецепта дава същия формуляр на всеки хост. Рецептите са в ~/Library/Application Support/Gantry/recipes.json, така че можете да ги архивирате или споделите.

    Ограничения
  • Gantry запазва пътя от --env-file, но не чете файла и не чете вашата обвивка за -e KEY без стойност.
  • tmpfs монтиранията и анонимните томове от --mount се изброяват като неподдържани.
  • Два порта за един и същ порт на контейнера (-p 8080:80 -p 8081:80) попълват формуляра, но след това формулярът отказва дубликата.

Въпроси и отговори

Как да преобразувам docker run в container run?

Заменете docker run с container run. -d, -p, -e, -v, --name, --rm, -it, -w и --entrypoint остават същите. Премахнете --restart и използвайте цели CPU. Или поставете реда в Gantry и го оставете да попълни формуляра.

Може ли Gantry да импортира команда docker run?

Да. Постави команда… в листа „Нов контейнер“ чете docker run, docker create, podman run и container run и попълва формуляра.

Какво става с флаговете, които Gantry не поддържа?

Те се изброяват в прегледа с причината и остават във формуляра в раздела „От поставената команда“, така че можете да ги проверите по-късно.

Мога ли да превърна работещ контейнер обратно в команда docker run?

Да. Копирай като команда в менюто на контейнера записва ред docker run или container run за този контейнер.

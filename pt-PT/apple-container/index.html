Gantry/Guia do apple/container

Apple container no Mac: o guia completo e a GUI

O apple/container executa contentores Linux no seu Mac, cada um na sua própria máquina virtual leve. É distribuído como ferramenta de linha de comandos. O Gantry é uma GUI nativa do macOS para ele. Este guia explica a ferramenta, como a configurar e que funcionalidade do Gantry cobre cada comando container.

Em resumo. O Gantry é uma app gratuita e de código aberto (MIT) para macOS que gere a ferramenta container da Apple e o Docker numa só janela. Suporta a CLI container 1.0 a 1.6.1 (recomendada) e mostra apenas as funcionalidades que a sua versão da CLI suporta. Instale-o com brew install --cask getgantry/tap/gantry.

O que é o apple/container?

O apple/container é uma ferramenta de código aberto da Apple, escrita em Swift, que cria e executa contentores Linux num Mac. O Docker Desktop executa todos os contentores numa única VM Linux partilhada; o apple/container executa cada contentor na sua própria máquina virtual leve, baseada na framework Virtualization da Apple. Utiliza imagens OCI padrão, por isso descarrega dos mesmos registos que o Docker e envia para eles.

  • Hardware: um Mac com Apple silicon.
  • macOS: a Apple suporta-o no macOS 26.
  • Interface: apenas a CLI container. Não há app de secretária nem comando compose.
  • Rede: cada contentor recebe o seu próprio endereço IP no Mac, e os domínios DNS locais dão aos contentores nomes como web.test.

Porquê usar uma GUI para o apple/container?

A CLI é completa, mas o trabalho diário exige muitos comandos: container list, logs, stats, exec, e depois system, builder, registry, machine e cluster para o resto. O Gantry reúne-os numa janela com atualizações em direto, por isso vê o estado em vez de ter de o consultar repetidamente. Acrescenta também o que a CLI não tem: ficheiros Compose, notificações de falhas, uma vista de frota com os seus hosts Docker e um servidor MCP para agentes de IA.

Configurar o apple/container com o Gantry

  1. Instale o Gantry: brew install --cask getgantry/tap/gantry e depois remova o atributo de quarentena (consulte Instalação).
  2. Instale a CLI container a partir do .pkg assinado na página de versões do apple/container. Se não estiver instalada ou for anterior à 1.0, o Gantry mostra uma folha de configuração com os passos.
  3. No Gantry, escolha Adicionar host… e adicione um host Apple Container. Ao ligar, os serviços container são iniciados se estiverem parados.
  4. Se não houver nenhum kernel predefinido instalado, a vista geral do host mostra um aviso. Clique nele para instalar o kernel recomendado.
Atenção
Utilize o pacote de instalação assinado, não a versão do Homebrew. A versão do Homebrew não inclui o backend de máquinas, por isso o container machine não consegue funcionar.

O que o Gantry acrescenta ao apple/container

Clusters Kubernetes

Crie com container cluster clusters Kubernetes com vários workers, escolha a CNI, veja cada nó, escreva o kubeconfig e carregue imagens locais no cluster. Consulte Kubernetes no apple/container.

Máquinas do container e VS Code

As máquinas são ambientes Linux de longa duração criados com container machine. O Gantry cria-as, inicia-as, para-as e elimina-as, define a máquina predefinida, edita as CPU e a memória, e abre uma shell. Na CLI 1.1 ou posterior, uma máquina pode arrancar com virtualização aninhada (Apple silicon M3 ou posterior) e um kernel personalizado. Abrir no VS Code liga-se a uma máquina em execução por Remote-SSH; a imagem da máquina tem de executar o sshd.

Docker Compose no apple/container

Abra um docker-compose.yml a partir do Finder (Abrir com ▸ Gantry ou Ações rápidas ▸ Compose Up no apple/container), a partir de Ficheiro ▸ Abrir ficheiro Compose… ou largando-o na janela. O Gantry compila os serviços com build:, cria a rede do projeto e os volumes com nome, e inicia cada serviço pela ordem de depends_on com as etiquetas padrão com.docker.compose.*. Com um domínio DNS predefinido, os serviços comunicam entre si pelo nome do serviço através de aliases de rede.

Aliases DNS de rede e domínios locais

O Gantry passa os aliases de rede ao container como --network <name>,alias=…. Sem um domínio DNS predefinido, só passam nomes totalmente qualificados, e um alias de subárvore (com um ponto inicial, como .gateway) só passa como o seu alias exato. Com um domínio predefinido, os nomes curtos também funcionam. O Gantry cria e elimina domínios DNS locais, define o domínio predefinido e dá aos novos contentores um nome de host name.domain. Consulte Nomes DNS locais.

Sistema: serviços, builder, registos, kernel, logs, propriedades

Cada host apple/container tem uma secção Sistema. Funciona com o host desligado, por isso pode iniciar a partir daí os serviços parados.

  • Estado e versão: versões do cliente e do servidor, com um aviso quando diferem; iniciar, parar e reiniciar os serviços; dados e caminhos do host.
  • Builder de imagens: estado, imagem, CPU, memória e IP; iniciar com opções de CPU, memória e DNS; parar; eliminar.
  • Sessões em registos: listar, iniciar sessão e terminar sessão. A palavra-passe chega à CLI apenas por stdin (--password-stdin), e o Gantry não guarda nenhuma cópia.
  • Kernel: instalar o kernel recomendado, um ficheiro de kernel ou um arquivo tar, com o progresso em direto.
  • Logs dos serviços: em direto ou pontuais, de 5 minutos a 1 dia, filtrados por nível, serviço e texto.
  • Propriedades de sistema: as alterações são guardadas em ~/.config/container/config.toml, com um indicador de reinício pendente e um botão Reiniciar serviços.

Guardar como imagem, Compactar disco e ficheiros

Guardar como imagem usa container commit (CLI 1.6). Compactar disco usa container clean (CLI 1.4) e aparece também como linha em Recuperar espaço. O separador Ficheiros transfere ficheiros e permite arrastá-los para o Finder com container copy (o contentor tem de estar iniciado), e envia ficheiros e pastas.

Etiquetas que contêm =

O container create rejeita um valor de etiqueta que contenha =, também na CLI 1.6.1. O Gantry codifica esses valores ao criar o contentor e descodifica-os ao lê-lo, por isso as etiquetas que define são as etiquetas que vê.

Servidor MCP e Atalhos

O servidor gantry-mcp incluído dá aos agentes de IA o mesmo alcance nos hosts apple/container: contentores, imagens, volumes, redes, Compose, máquinas (list_machines, create_machine e outras), clusters (list_clusters, create_cluster, delete_cluster) e ferramentas de sistema apple_* para serviços, builder, registos (sem ferramenta de início de sessão), propriedades, logs e instalação de kernels. As App Intents acrescentam ações dos Atalhos e da Siri. Consulte Agentes de IA e MCP.

Adicionar o servidor MCP do Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

O apple/container ao lado do Docker

O Gantry gere hosts apple/container, o daemon Docker local (Docker Desktop, OrbStack, Colima) e hosts Docker remotos por SSH numa só barra lateral e num só painel de frota. Não tem de escolher um único runtime. Para comparar as ferramentas funcionalidade a funcionalidade, consulte Gantry vs Docker Desktop, OrbStack e Podman Desktop.

Perguntas e respostas

Qual é a melhor GUI para o Apple container?

O Gantry é uma GUI nativa do macOS, gratuita e de código aberto, criada para o apple/container. Transpõe a CLI container para uma app de secretária: contentores, logs, estatísticas e exec, e ainda clusters Kubernetes, máquinas, o builder de imagens, sessões em registos, kernels, logs dos serviços e propriedades de sistema. A tabela desta página lista cada comando e a funcionalidade do Gantry que o utiliza.

O Apple container tem interface gráfica?

A Apple distribui o container apenas como ferramenta de linha de comandos. O Gantry é uma app de código aberto independente que lhe dá uma GUI, ao lado dos seus hosts Docker.

É possível usar o docker compose com o Apple container?

O apple/container não tem um comando compose. O Gantry lê um docker-compose.yml, compila os serviços com build:, cria a rede e os volumes com nome, e inicia os serviços pela ordem de depends_on. Os nomes dos serviços são resolvidos através de aliases DNS de rede.

Como abrir uma máquina do container no VS Code?

Inicie a máquina no Gantry e clique em Abrir no VS Code. O Gantry abre-a por Remote-SSH, como no exemplo container-machine-vscode da Apple. A imagem da máquina tem de executar o sshd.

O Apple container funciona em Macs Intel?

Não. O apple/container requer um Mac com Apple silicon. O Gantry também funciona em Macs Intel, mas aí gere apenas hosts Docker.

Que versão da CLI container devo instalar?

O Gantry requer a 1.0 ou posterior e é testado com a 1.6.1. Instale-a com o pacote de instalação assinado da página de versões do apple/container. A versão do Homebrew não inclui o backend de máquinas, por isso o container machine não funciona com ela.

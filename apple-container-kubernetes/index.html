Gantry/Kubernetes on apple/container

Kubernetes on Apple container

apple/container can run a Kubernetes cluster whose nodes are containers on your Mac. Gantry is a GUI for it: create a cluster, watch its nodes come up, connect kubectl and load your local images, without long container cluster command lines.

In short. On an apple/container host, the Gantry Clusters section creates and deletes Kubernetes clusters with container cluster (CLI 1.6.1) or container k8s (CLI 1.5.0 to 1.6.0). It supports multiple workers, a custom CNI, a nodes view, kubeconfig and kubectl context, and Load into Cluster for local images.

Requirements

  • A Mac with Apple silicon, macOS 26, and Gantry (brew install --cask getgantry/tap/gantry).
  • The container CLI 1.5.0 or later; 1.6.1 is recommended. Workers and the None CNI need 1.6.0 or later.
  • kubectl, if you want to use the cluster from the terminal.

Create a cluster

  1. Select your apple/container host and open Clusters in the sidebar.
  2. Start a new cluster and fill in the options below.
  3. Create it. The list shows the new cluster with streamed progress. Cancel stops the creation and deletes the nodes that were already made.
OptionCLI flagNotes
Name--nameAlso the kubeconfig context name
Workers--workersNumber of worker nodes. CLI 1.6.0+
CPUs--cpusPer node
Memory--memoryPer node, for example 4G
Node image--node-imageEmpty keeps the CLI default
CNI--cniDefault (bundled kindnet), None (NONE, CLI 1.6.0+) or a custom manifest path

The same command on the CLI:

Shell
container cluster create --name dev --workers 2 --cpus 2 --memory 4G

Nodes and cluster details

The cluster list shows each cluster with its nodes: role, state and address. The detail view has an Overview (kubectl context, API server, workers, node network), a Nodes table, Inspect for the raw node data, and the actions Write Kubeconfig, Copy kubectl Context Command and Delete.

Connect kubectl

The CLI adds a context named after the cluster to ~/.kube/config when it creates the cluster. Use Copy kubectl Context Command in Gantry, or type it:

Shell
kubectl --context dev get nodes

To keep the cluster in its own file, use Write Kubeconfig. Gantry runs container cluster write-config; the default path is ~/.kube/<name>.kubeconfig.

Load local images into the cluster

Build or pull an image on the apple/container host, then right-click it in Images and choose Load into Cluster. Gantry runs container cluster load-image, which copies the image into the containerd of each node. You do not need a registry for local development.

Shell
container cluster load-image --name dev myapp:dev

Choose a CNI

The default is the bundled kindnet manifest. Choose Custom manifest to install your own CNI, for example Calico or Cilium, from a file. Choose None to install a CNI yourself later; until then, the nodes stay NotReady.

Clusters from AI agents

The Gantry MCP server has list_clusters, create_cluster and delete_cluster, so an agent such as Claude Code can make a temporary cluster for a test and remove it after.

Add the Gantry MCP server
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Questions and answers

Does Apple container support Kubernetes?

Yes. The container CLI creates Kubernetes clusters whose nodes run as containers: container cluster in CLI 1.6.1, container k8s in CLI 1.5.0 to 1.6.0. Gantry gives this a GUI.

Does Gantry support container cluster?

Yes. Gantry lists, creates and deletes clusters on apple/container hosts, shows their nodes, writes the kubeconfig, copies the kubectl context command and loads local images into a cluster. It uses cluster or k8s to match your CLI version.

How do I use kubectl with an apple/container cluster?

When the CLI creates a cluster, it adds a kubeconfig context named after the cluster to ~/.kube/config. Run kubectl --context <name> get nodes. To keep a separate file, use Write Kubeconfig in Gantry; the default path is ~/.kube/<name>.kubeconfig.

How do I get a local image into the cluster without a registry?

In Gantry, right-click the image in Images and choose Load into Cluster. Gantry runs container cluster load-image, which copies the image into the containerd of each node.

Can I create a multi-node cluster?

Yes. Set the number of workers in the create sheet. Workers need CLI 1.6.0 or later.

Can I use my own CNI such as Calico or Cilium?

Yes. Choose Custom manifest and select the manifest file, or choose None and apply a CNI yourself after the cluster starts. Nodes stay NotReady until a CNI runs. None needs CLI 1.6.0 or later. The default CNI is the bundled kindnet manifest.

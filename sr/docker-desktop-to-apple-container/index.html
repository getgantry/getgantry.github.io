Прелазак са Docker Desktop-а на Apple container

Apple-ов алат container покреће исте OCI слике као Docker, па се већина вашег рада преноси уз неколико измена у командама. Овај водич упоређује Docker и container, преноси слике и волумене и наводи недостатке које треба да знате пре преласка.

Укратко. Инсталирајте потписани пакет container, замените docker са container за run, build, logs, exec и images, копирајте именоване волумене преко tar датотеке и отворите свој docker-compose.yml у Gantry-ју, јер CLI нема compose. Док испробавате, Docker Desktop може да остане инсталиран.

Шта се мења

  • Једна VM по контејнеру. Docker Desktop покреће све контејнере у једној Linux VM. apple/container покреће малу VM за сваки контејнер, па сваки добија сопствену IP адресу на вашем Mac-у.
  • Исте слике и регистри. Слике су OCI слике; повлачите их са Docker Hub-а, GHCR-а и приватних регистара као и пре.
  • Без лиценцне накнаде. apple/container је под лиценцом Apache 2.0. Docker Desktop захтева плаћени план у организацијама са 250 или више запослених или са 10 милиона долара или више прихода.
  • Само Apple silicon и macOS 26. На Intel Mac рачунарима останите на Docker механизму.

Већина заставица за run је иста: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus и -m. Да бисте претворили дугу команду, налепите је у Gantry: погледајте Креирање контејнера из docker run команде.

    Пренос слика

Слике из регистра: поново их повуците командом container image pull. Локалне слике које постоје само у Docker-у: сачувајте их у архиву и учитајте је. container image load чита OCI архиве, а новије верзије Docker-а командом docker save записују OCI распоред. Ако учитавање не успе, пошаљите слику у регистар и повуците је.

Терминал
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Пренос именованих волумена

Docker чува податке волумена унутар своје VM. Копирајте сваки волумен у tar датотеку помоћу краткотрајног контејнера, а затим га распакујте у нови apple/container волумен:

Терминал
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Именовани волумен у apple/container-у је ретка (sparse) ext4 слика диска, подразумевано највише 512 GB. Другу величину подесите опцијом --opt size=20g. Монтиране фасцикле са вашег Mac-а раде као у Docker-у: -v ~/project:/app.

    Compose датотеке

container CLI нема команду compose. Уместо тога отворите docker-compose.yml у Gantry-ју (из Finder-а, преко Датотека ▸ Отвори Compose датотеку… или превлачењем). Gantry гради сервисе са build:, креира мрежу пројекта и именоване волумене и покреће сервисе редоследом из depends_on. Сервиси се међусобно досежу по имену сервиса преко DNS алијаса мреже.

    Мреже и портови
  • -p 8080:80 објављује порт на localhost, као у Docker-у.
  • Сваки контејнер има и сопствену IP адресу. Креирајте локални DNS домен командом sudo container system dns create test и покрећите контејнере уз --dns-domain test: добијају имена као што је web.test.
  • container network create прави корисничке мреже; контејнери на истој мрежи досежу једни друге.
  • Не постоји режим --network host, none ни container:.
    Шта недостаје
  • Нема Docker Engine API-ја. Алати који комуницирају са /var/run/docker.sock, као што су Testcontainers, Docker SDK-ови или Dev Containers, не виде apple/container.
  • Нема смерница поновног покретања. --restart није доступан; контејнер се не покреће поново сам од себе.
  • Нема Compose-а у CLI-ју. Gantry покреће Compose датотеке: погледајте Compose датотеке.
  • Нема проширења за Docker Desktop.
  • Само цели CPU-ови: --cpus 0.5 не ради.
  • Kubernetes ради другачије: користите container cluster, погледајте Kubernetes на Mac-у.
    Задржите оба током преласка

Gantry управља apple/container-ом и било којим Docker механизмом (Docker Desktop, OrbStack, Colima или Docker преко SSH-а) у једној бочној траци. Преносите један по један пројекат, а Docker задржите за алате којима је потребан његов API. Када вам више не треба, можете да уклоните Docker Desktop.

Сродна упутства

  • Контејнери и волумени на спољном диску на Mac-у
  • Контејнер из docker run команде на Mac-у (docker run у container run)
  • Apple container GUI за Mac: комплетан водич за apple/container
  • Kubernetes на Apple container-у: GUI за container cluster и Kubernetes прегледач
  • Gantry, Docker Desktop, OrbStack и Podman Desktop на Mac-у: поређење (2026)

Питања и одговори

Може ли Apple container да замени Docker Desktop?

За покретање, изградњу и повлачење контејнера на Apple silicon-у, да. Нема Docker Engine API, смернице поновног покретања, проширења ни команду compose. Gantry додаје Compose датотеке и GUI.

Да ли Docker слике раде са Apple container-ом?

Да. apple/container користи стандардне OCI слике и повлачи их из истих регистара. arm64 слике раде нативно; amd64 слике раде преко Rosetta-е уз --arch amd64.

Да ли docker compose ради са Apple container-ом?

Не из CLI-ја: не постоји container compose. Gantry чита docker-compose.yml и уместо вас покреће сервисе на apple/container-у.

Могу ли да користим Docker Desktop и Apple container истовремено?

Да. Не деле слике ни волумене, али могу да раде један поред другог. Gantry приказује оба у једном прозору.

Да ли је Apple container бесплатан за комерцијалну употребу?

Да. apple/container је отвореног кода под лиценцом Apache 2.0, а Gantry је под лиценцом MIT. Оба су бесплатна за предузећа било које величине.

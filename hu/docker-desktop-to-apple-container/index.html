Gantry/Docker Desktopról

Átállás a Docker Desktopról az Apple containerre

Az Apple container eszköze ugyanazokat az OCI-image-eket futtatja, mint a Docker, így a munkája nagy része néhány parancs módosításával átvihető. Ez az útmutató megfelelteti a Dockert a container eszköznek, átviszi az image-eket és a köteteket, és felsorolja azokat a hiányosságokat, amelyekről a váltás előtt tudnia kell.

Röviden. Telepítse az aláírt container csomagot, a run, build, logs, exec és images parancsoknál cserélje a docker szót container-re, a nevesített köteteket másolja át egy tar-fájllal, a docker-compose.yml fájlt pedig nyissa meg a Gantryben, mert a CLI-ben nincs compose. A kipróbálás idejére a Docker Desktop telepítve maradhat.

Mi változik

  • Konténerenként egy VM. A Docker Desktop minden konténert egyetlen Linux VM-ben futtat. Az apple/container minden konténerhez külön kis VM-et indít, így mindegyik saját IP-címet kap a Macen.
  • Ugyanazok az image-ek és registryk. Az image-ek OCI-image-ek; ugyanúgy letölthet a Docker Hubról, a GHCR-ről és privát registrykből, mint eddig.
  • Nincs licencdíj. Az apple/container Apache 2.0 licencű. A Docker Desktophoz fizetős előfizetés kell a 250 vagy több alkalmazottat foglalkoztató, illetve legalább 10 millió dollár árbevételű szervezetekben.
  • Csak Apple chipen és macOS 26-on. Intel-alapú Macen maradjon egy Docker-motornál.

A run legtöbb kapcsolója ugyanaz: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus és -m. Egy hosszú parancs átalakításához illessze be a Gantrybe: lásd Konténer létrehozása docker run parancsból.

Az image-ek átvitele

Registryből származó image-ek: töltse le őket újra a container image pull paranccsal. Csak a Dockerben létező helyi image-ek: mentse őket archívumba, és töltse be. A container image load OCI-archívumokat olvas, a Docker újabb verziói pedig OCI-elrendezést írnak a docker save paranccsal. Ha a betöltés sikertelen, töltse fel az image-et egy registrybe, és onnan töltse le.

Terminál
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Nevesített kötetek átvitele

A Docker a kötetek adatait a saját VM-jében tárolja. Másolja ki minden kötetét egy tar-fájlba egy rövid életű konténerrel, majd csomagolja ki egy új apple/container-kötetbe:

Terminál
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Az apple/containerben a nevesített kötet egy ritka (sparse) ext4-lemezkép, alapértelmezés szerint legfeljebb 512 GB. Más méretet a --opt size=20g kapcsolóval adhat meg. A Mac mappáinak bind mountjai ugyanúgy működnek, mint a Dockerben: -v ~/project:/app.

Compose-fájlok

A container CLI-ben nincs compose parancs. Ehelyett nyissa meg a docker-compose.yml fájlt a Gantryben (a Finderből, a Fájl ▸ Compose-fájl megnyitása… menüponttal vagy húzással). A Gantry buildeli a build: szolgáltatásokat, létrehozza a projekt hálózatát és nevesített köteteit, majd depends_on sorrendben elindítja a szolgáltatásokat. A szolgáltatások szolgáltatásnév alapján érik el egymást, hálózati DNS-aliasokon keresztül.

Hálózatok és portok

  • A -p 8080:80 a localhost címen tesz közzé egy portot, ahogy a Dockerben.
  • Minden konténernek saját IP-címe is van. Hozzon létre egy helyi DNS-tartományt a sudo container system dns create test paranccsal, és futtassa a konténereket a --dns-domain test kapcsolóval: ilyen neveket kapnak, mint web.test.
  • A container network create felhasználói hálózatokat hoz létre; az azonos hálózaton lévő konténerek elérik egymást.
  • Nincs --network host, none vagy container: mód.

Ami hiányzik

  • Nincs Docker Engine API. A /var/run/docker.sock socketen kommunikáló eszközök, például a Testcontainers, a Docker SDK-k vagy a Dev Containers, nem látják az apple/containert.
  • Nincsenek újraindítási szabályok. A --restart nem érhető el; a konténer magától nem indul újra.
  • Nincs Compose a CLI-ben. A Gantry futtatja a Compose-fájlokat: lásd Compose-fájlok.
  • Nincsenek Docker Desktop-bővítmények.
  • Csak egész CPU-k: a --cpus 0.5 nem működik.
  • A Kubernetes másképp működik: használja a container cluster parancsot, lásd Kubernetes futtatása Macen.

Mindkettő megtartása a váltás alatt

A Gantry egyetlen oldalsávban kezeli az apple/containert és bármely Docker-motort (Docker Desktop, OrbStack, Colima vagy Docker SSH-n keresztül). Egyszerre egy projektet vigyen át, és tartsa meg a Dockert azokhoz az eszközökhöz, amelyeknek az API-ja kell. Ha már nincs rá szüksége, eltávolíthatja a Docker Desktopot.

Kapcsolódó útmutatók

  • Kubernetes futtatása Macen az Apple containerrel: lépésről lépésre
  • Konténerek és kötetek tárolása külső meghajtón Macen
  • Konténer létrehozása docker run parancsból Macen (docker run → container run)
  • Apple container GUI Macre: a teljes apple/container-útmutató
  • Kubernetes az Apple containeren: GUI a container clusterhez és Kubernetes-böngésző

Kérdések és válaszok

Kiválthatja az Apple container a Docker Desktopot?

Konténerek futtatására, buildelésére és letöltésére Apple chipen igen. Nincs benne Docker Engine API, újraindítási szabály, bővítmény és compose parancs. A Gantry Compose-fájl-támogatást és GUI-t ad hozzá.

Működnek a Docker-image-ek az Apple containerrel?

Igen. Az apple/container szabványos OCI-image-eket használ, és ugyanazokból a registrykből tölt le. Az arm64-image-ek natívan futnak; az amd64-image-ek a Rosettán keresztül, a --arch amd64 kapcsolóval.

Működik a docker compose az Apple containerrel?

A CLI-ből nem: nincs container compose. A Gantry beolvassa a docker-compose.yml fájlt, és Ön helyett futtatja a szolgáltatásokat az apple/containeren.

Használhatom egyszerre a Docker Desktopot és az Apple containert?

Igen. Nem osztoznak az image-eken és a köteteken, de futhatnak egymás mellett. A Gantry mindkettőt egy ablakban mutatja.

Ingyenes az Apple container kereskedelmi használatra?

Igen. Az apple/container nyílt forráskódú, Apache 2.0 licenccel, a Gantry pedig MIT licencű. Mindkettő ingyenes bármilyen méretű cég számára.

A GUI nativa do macOS para o Apple container
e o Docker: toda a sua frota num só painel.

O Gantry é uma app para Mac, gratuita e de código aberto, para a ferramenta container da Apple e para o Docker, localmente e por SSH. Execute contentores, clusters Kubernetes, máquinas e projetos Compose no apple/container a partir de uma janela, ao lado dos seus hosts Docker. Uma alternativa ao Docker Desktop e ao OrbStack gratuita para o Mac. Sem Electron. Sem subscrição. Sem limites.

Descarregar para macOS
$ brew install --cask getgantry/tap/gantry

Novidades da 0.27.0

Kubernetes, Apple Intelligence e o resto do macOS

O Gantry 0.27.0 acrescenta um explorador Kubernetes, explica contentores com falhas com o Apple Intelligence e funciona com o Spotlight, a Siri, os widgets e o Centro de controlo. Suporta o apple/container 1.7.1 e tem um novo design que segue as Human Interface Guidelines da Apple.

Explorador Kubernetes

Explore pods, Deployments, StatefulSets, DaemonSets, serviços, Ingress, ConfigMaps, segredos, nós e eventos de qualquer contexto do kubeconfig. Acompanhe os logs dos pods, abra uma shell, reencaminhe uma porta, escale, reinicie um rollout e aplique YAML. O próprio Gantry comunica com a API do Kubernetes, por isso um cluster criado com container cluster create fica pronto a explorar sem instalar mais nada: sem kubectl.

“Explicar falha” com o Apple Intelligence

Escolha Explicar falha… num contentor que falhou ou numa operação sem êxito. O Gantry envia os logs recentes e os detalhes, sem os valores do ambiente e sem texto que pareça um segredo, para o modelo do dispositivo, e mostra a causa provável, as evidências e os passos seguintes. Os logs longos podem ir para o Private Cloud Compute (macOS 27). O painel mostra exatamente o que foi enviado.

Parte do macOS

Notificações com Reiniciar, Ver logs e Copiar como prompt. O Spotlight encontra contentores, projetos Compose e hosts. Ações da Siri e dos Atalhos, um widget do estado da frota, controlos no Centro de controlo para os serviços do apple/container ou para um contentor favorito, e ligações gantry:// para scripts.

Paleta de comandos

Prima ⌘K e escreva. Uma única pesquisa abrange contentores, projetos Compose, imagens, volumes, redes, máquinas, clusters e hosts, com ações como Iniciar, Mostrar logs e Abrir shell.

Atuar sobre vários de uma vez

Selecione vários contentores, imagens, volumes ou redes e inicie-os, pare-os, reinicie-os ou remova-os num só passo, com o progresso e um relatório para cada item.

Terminal exec integrado

Emulação de terminal completa em qualquer contentor em execução, local ou remoto, com temas de cores (Sistema, Solarized, Dracula, Nord).

Hosts remotos por SSH

Túneis exatamente como docker -H ssh:// através de dial-stdio: bastiões ProxyJump, autenticação com várias chaves, religação automática. Nada a instalar no servidor, segredos no porta-chaves. Importação com um clique a partir de ~/.ssh/config e docker context ls.

Explorador de ficheiros com arrastar e largar

Explore o sistema de ficheiros de um contentor, mova ficheiros para dentro e para fora, e largue pastas inteiras diretamente do Finder, tanto em hosts Docker como apple/container.

Abrir no navegador e reencaminhar

Um clique abre uma porta publicada. As portas SSH são encaminhadas automaticamente por túnel para localhost e, se a porta estiver ocupada, o Gantry escolhe uma livre que pode editar.

Partilhar na Internet

Um clique expõe uma porta publicada através de um Cloudflare Tunnel. O Gantry instala o cloudflared por si e depois disponibiliza um túnel rápido (sem conta, com um URL *.trycloudflare.com) ou um túnel com nome no seu próprio domínio: ideal para uma pré-visualização de desenvolvimento, um webhook ou para um agente de IA chegar a um contentor no seu Mac.

Compose em qualquer host

Os contentores são agrupados pelo projeto Compose. Execute um ficheiro Compose em qualquer host (Docker local, SSH ou apple/container) com um editor YAML integrado; o executor adapta-se a cada motor.

Registos privados, automaticamente

Os descarregamentos usam o docker login que já fez: o Gantry obtém as credenciais de ~/.docker/config.json, dos helpers e do porta-chaves, ao criar, na Execução rápida e no Compose.

Compilar e descarregar imagens

Largue um Dockerfile na janela para compilar com log em direto, ou descarregue por referência com o progresso de cada camada. Adicione tags, limpe e consulte o histórico de camadas. Um indicador assinala as imagens compiladas para uma arquitetura de CPU diferente da do host.

Recuperar espaço

Um painel mostra o que está a ocupar espaço (imagens órfãs, contentores parados, volumes não utilizados, cache de compilação) com os respetivos tamanhos, e limpa cada item ou todos. No apple/container, também executa Compactar disco.

Touch ID em ações destrutivas

Se ativar esta opção, o Gantry pede o Touch ID (ou a palavra-passe de início de sessão) antes de remover um contentor ou eliminar um host. Os segredos já ficam no porta-chaves.

Temas do terminal

Vista a shell integrada com Sistema, Solarized Dark, Dracula ou Nord: uma paleta completa de primeiro plano, fundo e 16 cores ANSI, aplicada em direto.

GUI para o apple/container

A GUI nativa do macOS para o Apple container

A ferramenta container da Apple executa contentores Linux como VM leves em Apple silicon, mas só é distribuída como ferramenta de linha de comandos. O Gantry é a app de secretária para ela: o que o Docker Desktop é para o Docker, o Gantry é para o container. Suporta todas as CLI container desde a 1.0 até à 1.7.1 recomendada, e só ativa cada funcionalidade quando a CLI instalada a suporta.

Contentores, logs, estatísticas e exec

Crie, inicie, pare, termine à força e limpe; logs em direto, estatísticas, um terminal exec, top e exportação para tar, na mesma interface dos seus hosts Docker.

Clusters Kubernetes

Crie um cluster Kubernetes com container cluster: defina separadamente o tamanho do plano de controlo e dos workers, escolha a CNI e veja os nós, a versão do Kubernetes e o contexto do kubeconfig. Os nós do cluster estão protegidos contra paragens e eliminações acidentais. Saber mais

Imagens locais no cluster

Na CLI 1.7, ative Utilizar imagens locais (--shared-image-store) e os pods executam as imagens que compilar ou descarregar, sem registo. Nas CLI 1.5 e 1.6, clique com o botão direito numa imagem e escolha Carregar no cluster.

Indicações claras quando a instalação está danificada

Se os serviços do cluster não responderem, o Gantry diz-lhe porquê. Uma compilação do Homebrew sem os serviços do cluster recebe uma ligação para o instalador assinado; nos outros casos aparece um botão Reiniciar serviços.

Máquinas do container no VS Code

Crie, inicie e pare ambientes Linux com container machine, defina CPU e memória, abra uma shell ou abra a máquina no VS Code por Remote-SSH.

Virtualização aninhada e kernels personalizados

Arranque uma máquina com virtualização aninhada (M3 ou posterior) ou com o seu próprio kernel. Arranque contentores a partir de um kernel personalizado com argumentos de arranque adicionais.

Compose para o Apple container

O apple/container não tem compose. O Gantry executa o seu docker-compose.yml: compila, cria a rede e os volumes, e inicia os serviços pela ordem de depends_on. Os nomes dos serviços são resolvidos através de aliases DNS de rede.

Aliases DNS de rede

Aliases de contentor, aliases de subárvore como .gateway e nomes curtos quando há um domínio DNS predefinido. Cada contentor recebe um IP encaminhável e um nome de host name.domain.

Gerir o builder de imagens

Veja o estado do builder, a imagem, as CPU, a memória e o IP. Inicie-o com opções de CPU, memória e DNS, pare-o ou elimine-o. Quando a imagem do builder está desatualizada, o Gantry propõe recriá-la.

Sessões em registos

Liste, adicione e remova sessões do container registry. A palavra-passe chega à CLI apenas por stdin, e o Gantry não guarda nenhuma cópia.

Instalação do kernel

Instale o kernel recomendado, um ficheiro de kernel ou um arquivo tar, com o progresso em direto. O Gantry avisa quando não há nenhum kernel predefinido instalado.

Serviços e logs dos serviços

Inicie, pare e reinicie os serviços do container, compare as versões do cliente e do servidor, e acompanhe em direto os logs dos serviços filtrados por nível, serviço e texto.

Editor de propriedades de sistema

Edite as propriedades de sistema do container em config.toml. O Gantry assinala as alterações que requerem um reinício e reinicia os serviços por si. Na CLI 1.7, também edita as predefinições de [container.dns]: servidores de nomes, domínios de pesquisa e opções.

Guardar como imagem e Compactar disco

Guarde um contentor como imagem (container commit) e recupere espaço em disco com Compactar disco (container clean), também disponível no painel Recuperar espaço.

Explorador de ficheiros: envio e transferência

Explore os ficheiros de um contentor, transfira-os ou arraste-os para o Finder (container copy), e largue lá dentro ficheiros ou pastas inteiras.

Execução rápida e Finder

Escolha uma imagem, partilhe uma pasta, mapeie portas, escolha um domínio e execute. Clique com o botão direito num ficheiro Compose no Finder e abra-o com o Gantry.

Etiquetas que contêm =

A CLI container rejeita valores de etiqueta com =. O Gantry codifica-os ao criar e descodifica-os ao ler, por isso um valor como a=b fica intacto.

Uma frota, dois runtimes

Os hosts apple/container ficam ao lado dos seus hosts Docker locais e SSH num único painel, com os mesmos minigráficos, o mesmo estado de saúde e as mesmas notificações de falhas.

O servidor MCP incluído dá aos agentes o mesmo alcance: contentores, máquinas, clusters e as ferramentas de sistema apple_* para serviços, builder, registos, propriedades, logs e kernels.

Perguntas frequentes

As respostas às suas perguntas

Tudo o que pode querer saber antes de instalar o Gantry.

Qual é a melhor GUI para o Apple container?

O Gantry é uma GUI nativa do macOS, gratuita e de código aberto, criada para a ferramenta container da Apple (apple/container). Cobre o ciclo de vida dos contentores, os logs, as estatísticas e um terminal exec, e ainda as partes da CLI a que outras GUI não chegam: clusters Kubernetes (container cluster), máquinas do container, o builder de imagens, as sessões em registos, os kernels, os logs dos serviços e as propriedades de sistema. Suporta a CLI 1.0 a 1.7.1 e só ativa cada funcionalidade quando a sua CLI a suporta. Consulte o guia do apple/container.

O que é o Apple container (apple/container)?

O apple/container é a ferramenta de código aberto da Apple para executar contentores Linux num Mac. Cada contentor é executado na sua própria máquina virtual leve, baseada na framework Virtualization da Apple. Requer um Mac com Apple silicon e é distribuído como uma ferramenta de linha de comandos chamada container, sem app de secretária. O Gantry acrescenta essa app de secretária.

O Gantry suporta o container cluster e o Kubernetes?

Sim. Num host apple/container, o Gantry cria e elimina clusters Kubernetes com container cluster (CLI 1.6.1 e 1.7; as CLI 1.5.0 a 1.6.0 usam container k8s). Pode escolher o nome, os workers, as CPU e a memória do plano de controlo e dos workers (1.7), a imagem dos nós, a CNI e se os nós utilizam as suas imagens locais (1.7). O Gantry mostra os nós, escreve o kubeconfig e abre o cluster no seu explorador Kubernetes. Consulte Kubernetes no apple/container.

É possível usar o docker compose com o Apple container?

Sim. O apple/container não tem um comando compose, por isso o Gantry faz a orquestração através da CLI container: compila os serviços com build:, cria a rede do projeto e os volumes com nome, e inicia cada serviço pela ordem de depends_on com as etiquetas padrão do Compose. Os nomes dos serviços são resolvidos através de aliases DNS de rede. Abra um docker-compose.yml a partir do Finder, do menu Ficheiro ou largando-o na janela.

Como abrir uma máquina do container no VS Code?

Inicie a máquina no Gantry e clique em Abrir no VS Code. O Gantry abre a máquina no VS Code por Remote-SSH, como no exemplo container-machine-vscode da Apple. A imagem da máquina tem de executar o sshd, e o VS Code com a extensão Remote-SSH tem de estar instalado.

Que versões do apple/container são suportadas pelo Gantry?

O Gantry requer a CLI container 1.0 ou posterior e recomenda a 1.7.1. Lê a versão instalada e mostra apenas as funcionalidades que essa versão suporta, por exemplo os tamanhos dos workers e o armazenamento de imagens partilhado (1.7), guardar como imagem (1.6) e Compactar disco (1.4). Se a CLI não estiver instalada ou for antiga, o Gantry propõe uma configuração guiada.

O Gantry consegue explorar um cluster Kubernetes?

Sim. A secção Kubernetes lista pods, Deployments, StatefulSets, DaemonSets, serviços, Ingress, ConfigMaps, segredos, nós e eventos de cada contexto do kubeconfig, e inclui logs dos pods, uma shell no pod, reencaminhamento de portas, escalar, reinício do rollout, eliminar e Aplicar YAML. O próprio Gantry comunica com a API do Kubernetes, por isso não precisa do kubectl. Consulte Executar Kubernetes num Mac.

O que é que “Explicar falha” envia para o Apple Intelligence?

Os logs recentes e os detalhes do contentor, sem os valores do ambiente e sem texto que pareça um segredo. Os pedidos pequenos são executados no modelo do dispositivo. Com a definição para logs longos ativada (macOS 27), os logs longos vão para o Private Cloud Compute. O painel mostra o que foi enviado. Um comando sugerido abre no Terminal, mas só é executado quando premir Return. Sem o Apple Intelligence, o Gantry oferece um prompt para copiar para outro assistente de IA.

Posso colar um comando docker run no Gantry?

Sim. Na folha Novo contentor, escolha Colar comando…. O Gantry lê docker run, docker create, podman run e container run, preenche o formulário e lista cada flag que não consegue usar, com o motivo. Consulte Criar um contentor a partir de um comando docker run.

O Gantry consegue gerir o builder, os registos e o kernel do apple/container?

Sim. A secção Sistema de um host apple/container inicia, para e elimina o builder de imagens com opções de CPU, memória e DNS; lista, adiciona e remove sessões em registos (a palavra-passe chega à CLI apenas por stdin); instala o kernel recomendado, um ficheiro de kernel ou um arquivo tar; transmite em direto os logs dos serviços; e edita as propriedades de sistema em config.toml.

O Gantry é uma alternativa ao Docker Desktop, OrbStack ou Podman Desktop?

Como GUI, sim. O Gantry é uma app nativa e gratuita do macOS para gerir contentores, imagens, volumes, redes, logs e estatísticas. É um cliente, não um motor: usa o daemon Docker que já tem em execução (Docker Desktop, OrbStack, Colima) ou a ferramenta container da Apple, e acrescenta uma vista multi-host, hosts SSH e um servidor MCP. Consulte a comparação.

O Gantry é gratuito?

Sim. O Gantry é gratuito e de código aberto, com licença MIT. Não tem subscrição, não exige conta e não tem limite de hosts nem de contentores.

O que é preciso para usar o Gantry?

macOS 26 ou posterior num Mac com Apple silicon ou Intel, e ainda um daemon Docker (Docker Desktop, OrbStack, Colima ou semelhante) ou a ferramenta container da Apple. O próprio apple/container requer Apple silicon, por isso num Mac Intel o Gantry gere apenas hosts Docker.

O Gantry funciona com o OrbStack, o Colima e o Docker Desktop?

Sim. O Gantry comunica diretamente com a API do Docker Engine através do socket Unix, por isso funciona com qualquer daemon que a exponha, incluindo o OrbStack, o Colima e o Docker Desktop.

O Gantry consegue gerir hosts Docker remotos?

Sim. O Gantry liga-se a daemons remotos por SSH, da mesma forma que docker -H ssh://, com bastiões ProxyJump, autenticação com várias chaves e religação automática. Não é preciso instalar nada no servidor, e os segredos ficam no porta-chaves do macOS.

O Gantry avisa quando um contentor falha?

Sim. O Gantry envia uma notificação nativa do macOS quando um contentor falha, fica sem memória ou falha a verificação de estado em qualquer host: local, SSH ou apple/container. Clique na notificação para ir para o contentor. As paragens e os reinícios feitos a partir do Gantry não são notificados, e pode desativar os avisos nas Definições.

O Gantry consegue descarregar imagens de registos privados?

Sim. Nos hosts Docker, o Gantry lê as credenciais do seu ~/.docker/config.json (o mesmo docker login que já executou), incluindo autenticação inline, credential helpers e o porta-chaves do macOS. Nos hosts apple/container, gere as sessões do container registry.

O Gantry consegue expor um contentor local à Internet?

Sim. Um clique numa porta publicada partilha-a através de um Cloudflare Tunnel. O Gantry instala o cloudflared se for preciso e depois inicia um túnel rápido (sem conta Cloudflare, com um URL temporário trycloudflare.com) ou um túnel com nome no seu próprio nome de host. O URL público aparece por baixo da porta, com controlos para abrir, copiar e parar.

O Gantry é uma app Electron?

Não. O Gantry é uma app nativa criada com SwiftUI e Swift 6. A interface está disponível em 28 idiomas: inglês, chinês simplificado e 26 idiomas europeus, por exemplo o sérvio em alfabeto cirílico e latino. Segue o idioma do sistema macOS.

Como instalar o Gantry?

Execute brew install --cask getgantry/tap/gantry, ou descarregue a versão mais recente do GitHub e arraste o Gantry.app para Aplicações.

Os agentes de IA podem controlar o Gantry?

Sim. O Gantry inclui um servidor MCP e App Intents do macOS, para que o Claude, os Atalhos, a Siri e os scripts tenham o mesmo alcance que a GUI em todos os hosts, incluindo os hosts SSH: contentores, imagens, volumes, redes, Compose, máquinas do apple/container, clusters Kubernetes, ferramentas de sistema apple_* (serviços, builder, registos, propriedades, logs, kernel) e partilha de portas. No macOS 26 e posterior, Explicar falha… também pergunta ao Apple Intelligence porque é que um contentor falhou. Adicione o servidor MCP com claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp.

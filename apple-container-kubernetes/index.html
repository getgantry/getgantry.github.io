Gantry/Kubernetes on apple/container

Kubernetes on Apple container

apple/container can run a Kubernetes cluster whose nodes are containers on your Mac. Gantry is a GUI for it: create a cluster, watch its nodes come up, run your local images in it, and browse its pods, logs and services, without long container cluster command lines.

In short. On an apple/container host, the Gantry Clusters section creates and deletes Kubernetes clusters with container cluster (CLI 1.6.1 and 1.7) or container k8s (CLI 1.5.0 to 1.6.0). On CLI 1.7.1 it sizes the workers apart from the control plane and turns on the shared image store. The Kubernetes section browses the cluster: pods, logs, shell, port forwards, scale and Apply YAML.

Requirements

  • A Mac with Apple silicon, macOS 26, and Gantry (brew install --cask getgantry/tap/gantry).
  • The container CLI 1.5.0 or later; 1.7.1 is recommended. Workers and the None CNI need 1.6.0 or later. Worker sizes and the shared image store need 1.7.0 or later. Use the signed installer package: the Homebrew build of 1.7.1 has no cluster services.
  • kubectl for the Kubernetes browser and the terminal. Gantry can install it with Homebrew.

Create a cluster

  1. Select your apple/container host and open Clusters in the sidebar.
  2. Start a new cluster and fill in the options below.
  3. Create it. The list shows the new cluster with streamed progress. Cancel stops the creation and deletes the nodes that were already made.
OptionCLI flagNotes
Name--nameAlso the kubeconfig context name
Workers--workersNumber of worker nodes. CLI 1.6.0+
Worker CPUs and memory--workers count=N,cpus=C,memory=MCLI 1.7+. Before 1.7, --cpus and --memory set every node
CPUs--cpusControl plane (CLI 1.7+), or every node (before 1.7)
Memory--memoryControl plane (CLI 1.7+), or every node (before 1.7), for example 4G
Use local images--shared-image-storeCLI 1.7+. Nodes run images from your local image store
Node image--node-imageEmpty keeps the CLI default
CNI--cniDefault (bundled kindnet), None (NONE, CLI 1.6.0+) or a custom manifest path

The same command on the CLI:

Shell
container cluster create --name dev --cpus 2 --memory 4G \
  --workers count=2,cpus=2,memory=4G --shared-image-store

Nodes and cluster details

The cluster list shows one row for each cluster. The detail view has an Overview (kubectl context, API server, Kubernetes version, image store, workers and their resources, node network), a Nodes table and Inspect for the raw node data. The toolbar has Browse Resources, and the More menu has Write Kubeconfig, Copy kubectl Context Command and Delete.

Cluster nodes are containers, but container cluster owns them. Gantry disables start, stop, restart, remove and rename for a node and tells you why, and Start All and Stop All skip nodes. On CLI 1.7 the CLI also hides nodes from container list. Clusters created with CLI 1.6 or earlier do not show in the 1.7 list; remove them with container cluster delete --name <name>.

Browse the cluster

Click Browse Resources on a running cluster, or open Kubernetes in the sidebar. The section needs no host, and it lists every kubeconfig context; the contexts of apple/container clusters come first. Pick a namespace or all namespaces, then a kind: pods, deployments, stateful sets, daemon sets, services, ingresses, config maps, secrets, nodes or events.

  • Pods: logs with follow, tail and the previous container; a shell in the pod; port forward to 127.0.0.1.
  • Workloads: scale deployments and stateful sets; restart a rollout.
  • Secrets: values are masked in the list and in the YAML until you click Reveal.
  • Apply YAML: paste a manifest or open a file; errors show in the sheet.

The browser runs kubectl. If Gantry cannot find it, the section shows brew install kubectl with a button that runs it. A native Kubernetes client that needs no kubectl is in development.

Connect kubectl

The CLI adds a context named after the cluster to ~/.kube/config when it creates the cluster. Use Copy kubectl Context Command in Gantry, or type it:

Shell
kubectl --context dev get nodes

To keep the cluster in its own file, use Write Kubeconfig. Gantry runs container cluster write-config; the default path is ~/.kube/<name>.kubeconfig.

Use local images in the cluster

On CLI 1.7, turn on Use local images when you create the cluster. It adds --shared-image-store, so the nodes can run any image that you build or pull with container, by name, with no registry. The setting is fixed at creation. After you rebuild a tag, use imagePullPolicy: Always or a new tag. Privileged pods can read every image in your local store, so keep this for local development.

Shell
container build -t myapp:dev .
kubectl --context dev create deployment myapp --image=myapp:dev

On CLI 1.5 and 1.6, right-click the image in Images and choose Load into Cluster. Gantry runs container cluster load-image, which copies the image into the containerd of each node. CLI 1.7 removed this command, so Gantry hides the action there.

Shell
container cluster load-image --name dev myapp:dev

When the cluster services do not answer

If a cluster command fails with cluster service unavailable, Gantry checks how the CLI is installed. A Homebrew build without the cluster plugins gets the message that the build lacks the cluster services and a Download Installer… link to the signed package. In other cases, Gantry offers Restart Services….

Choose a CNI

The default is the bundled kindnet manifest. Choose Custom manifest to install your own CNI, for example Calico or Cilium, from a file. Choose None to install a CNI yourself later; until then, the nodes stay NotReady.

Clusters from AI agents

The Gantry MCP server has list_clusters, create_cluster and delete_cluster, so an agent such as Claude Code can make a temporary cluster for a test and remove it after.

Add the Gantry MCP server
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Questions and answers

Does Apple container support Kubernetes?

Yes. The container CLI creates Kubernetes clusters whose nodes run as containers: container cluster in CLI 1.6.1 and 1.7, container k8s in CLI 1.5.0 to 1.6.0. Gantry gives this a GUI.

Does Gantry support container cluster?

Yes. Gantry lists, creates and deletes clusters on apple/container hosts, shows their nodes, writes the kubeconfig and opens the cluster in its Kubernetes browser. On CLI 1.7 it also sizes the workers and turns on the shared image store. It uses cluster or k8s to match your CLI version.

How do I use kubectl with an apple/container cluster?

When the CLI creates a cluster, it adds a kubeconfig context named after the cluster to ~/.kube/config. Run kubectl --context <name> get nodes. To keep a separate file, use Write Kubeconfig in Gantry; the default path is ~/.kube/<name>.kubeconfig.

How do I get a local image into the cluster without a registry?

On CLI 1.7, create the cluster with Use local images (--shared-image-store). Pods then run the images you build or pull with container, by name. On CLI 1.5 and 1.6, right-click the image in Images and choose Load into Cluster; Gantry runs container cluster load-image. CLI 1.7 removed load-image.

Can I create a multi-node cluster?

Yes. Set the number of workers in the create sheet; workers need CLI 1.6.0 or later. On CLI 1.7, you also set the CPUs and memory of the workers apart from the control plane.

Can I use my own CNI such as Calico or Cilium?

Yes. Choose Custom manifest and select the manifest file, or choose None and apply a CNI yourself after the cluster starts. Nodes stay NotReady until a CNI runs. None needs CLI 1.6.0 or later. The default CNI is the bundled kindnet manifest.

Why does Gantry say the cluster services are unavailable?

The container services did not answer a cluster command. If your CLI is a Homebrew build without the cluster services, Gantry says so and links to the signed installer on the apple/container releases page. Otherwise it offers Restart Services.

Do I need kubectl to use the cluster in Gantry?

For now, yes: the Gantry Kubernetes browser runs kubectl. If it is not installed, the browser shows the brew install kubectl command and can run it for you. A native Kubernetes client that removes this step is in development.

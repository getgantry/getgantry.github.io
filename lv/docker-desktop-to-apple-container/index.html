Gantry/No Docker Desktop

Pāreja no Docker Desktop uz Apple container

Apple rīks container palaiž tos pašus OCI attēlus kā Docker, tāpēc lielāko daļu darba var pārcelt, nomainot dažas komandas. Šis ceļvedis parāda Docker komandu atbilstību container komandām, pārceļ attēlus un sējumus un uzskaita trūkumus, kas jāzina pirms pārejas.

Īsumā. Instalējiet parakstīto container pakotni, komandās run, build, logs, exec un attēlu komandās aizstājiet docker ar container, nokopējiet nosauktos sējumus ar tar failu un atveriet savu docker-compose.yml lietotnē Gantry, jo CLI nav compose. Izmēģināšanas laikā Docker Desktop var palikt instalēts.

Kas mainās

  • Viena virtuālā mašīna katram konteineram. Docker Desktop palaiž visus konteinerus vienā Linux virtuālajā mašīnā. apple/container katram konteineram startē nelielu virtuālo mašīnu, tāpēc katrs konteiners jūsu Mac datorā saņem savu IP adresi.
  • Tie paši attēli un reģistri. Attēli ir OCI attēli; jūs tos lejupielādējat no Docker Hub, GHCR un privātiem reģistriem tāpat kā līdz šim.
  • Bez licences maksas. apple/container licence ir Apache 2.0. Docker Desktop prasa maksas plānu organizācijās ar 250 vai vairāk darbiniekiem vai 10 milj. USD vai lielākiem ieņēmumiem.
  • Tikai Apple silicon un macOS 26. Intel Mac datoros turpiniet izmantot Docker dzinēju.

Attēlu pārcelšana

Attēli no reģistra: lejupielādējiet tos vēlreiz ar container image pull. Lokālie attēli, kas ir tikai Docker: saglabājiet tos arhīvā un ielādējiet to. container image load nolasa OCI arhīvus, un jaunākās Docker versijas ar docker save raksta OCI izkārtojumu. Ja ielāde neizdodas, augšupielādējiet attēlu reģistrā un lejupielādējiet to.

Terminālis
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Nosaukto sējumu pārcelšana

Docker glabā sējumu datus savā virtuālajā mašīnā. Nokopējiet katru sējumu tar failā ar īslaicīgu konteineru un pēc tam izpakojiet to jaunā apple/container sējumā:

Terminālis
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Nosaukts sējums apple/container vidē ir retināts ext4 diska attēls, pēc noklusējuma ne lielāks par 512 GB. Citu izmēru iestatiet ar --opt size=20g. Jūsu Mac datora mapju bind montējumi darbojas tāpat kā Docker: -v ~/project:/app.

Compose faili

container CLI nav komandas compose. Tā vietā atveriet docker-compose.yml lietotnē Gantry (no Finder, ar Fails ▸ Atvērt Compose failu… vai ar vilkšanu un nomešanu). Gantry būvē build: pakalpojumus, izveido projekta tīklu un nosauktos sējumus un startē pakalpojumus depends_on secībā. Pakalpojumi sasniedz cits citu pēc pakalpojuma nosaukuma caur tīkla DNS aizstājvārdiem.

Tīkli un porti

  • -p 8080:80 publicē portu adresē localhost tāpat kā Docker.
  • Katram konteineram ir arī sava IP adrese. Izveidojiet lokālu DNS domēnu ar sudo container system dns create test un palaidiet konteinerus ar --dns-domain test: tie saņem tādus nosaukumus kā web.test.
  • container network create izveido lietotāja tīklus; konteineri vienā tīklā sasniedz cits citu.
  • Nav režīmu --network host, none vai container:.

Kas trūkst

  • Nav Docker Engine API. Rīki, kas sazinās ar /var/run/docker.sock, piemēram, Testcontainers, Docker SDK vai Dev Containers, neredz apple/container.
  • Nav restartēšanas politiku. --restart nav pieejams; konteiners pats no jauna nestartē.
  • CLI nav Compose. Compose failus palaiž Gantry: skatiet Compose faili.
  • Nav Docker Desktop paplašinājumu.
  • Tikai veseli CPU: --cpus 0.5 nedarbojas.
  • Kubernetes darbojas citādi: izmantojiet container cluster, skatiet Kubernetes palaišana Mac datorā.

Pārejas laikā paturiet abus

Gantry vienā sānjoslā pārvalda apple/container un jebkuru Docker dzinēju (Docker Desktop, OrbStack, Colima vai Docker caur SSH). Pārceliet pa vienam projektam un paturiet Docker rīkiem, kam vajadzīgs tā API. Kad Docker Desktop vairs nav vajadzīgs, varat to noņemt.

Saistītie ceļveži

  • Kubernetes palaišana Mac datorā ar Apple container: ceļvedis soli pa solim
  • Konteineru un sējumu glabāšana ārējā diskā Mac datorā
  • Konteinera izveide no docker run komandas Mac datorā (docker run uz container run)
  • Apple container GUI Mac datoram: pilns apple/container ceļvedis
  • Kubernetes ar Apple container: container cluster GUI un Kubernetes pārlūks

Jautājumi un atbildes

Vai Apple container var aizstāt Docker Desktop?

Konteineru palaišanai, būvēšanai un lejupielādei uz Apple silicon – jā. Tajā nav Docker Engine API, restartēšanas politiku, paplašinājumu un komandas compose. Gantry pievieno Compose failus un grafisko saskarni.

Vai Docker attēli darbojas ar Apple container?

Jā. apple/container izmanto standarta OCI attēlus un lejupielādē tos no tiem pašiem reģistriem. arm64 attēli darbojas natīvi; amd64 attēli darbojas caur Rosetta ar --arch amd64.

Vai docker compose darbojas ar Apple container?

No CLI – nē: nav komandas container compose. Gantry nolasa docker-compose.yml un palaiž pakalpojumus apple/container vidē jūsu vietā.

Vai Docker Desktop un Apple container var izmantot vienlaikus?

Jā. Tiem nav kopīgu attēlu un sējumu, bet tie var darboties līdzās. Gantry rāda abus vienā logā.

Vai Apple container ir bezmaksas komerciālai lietošanai?

Jā. apple/container ir atvērtā koda rīks ar Apache 2.0 licenci, un Gantry ir licencēta ar MIT licenci. Abi ir bezmaksas jebkura lieluma uzņēmumiem.

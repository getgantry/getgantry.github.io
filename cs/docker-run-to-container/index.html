Gantry/Z docker run

Kontejner z příkazu docker run

Většina souborů README uvádí řádek docker run. Gantry tento řádek přečte a vyplní formulář Nový kontejner, pro hostitele Docker nebo pro nástroj container od Applu. Tento průvodce ukazuje jak a také jak příkaz převést ručně.

Ve zkratce. V Gantry otevřete Nový kontejner, zvolte Vložit příkaz…, vložte řádek docker run a klikněte na Vyplnit formulář. Gantry vypíše každý příznak, který nemůže použít, i s důvodem. V CLI je většina příznaků stejná: nahraďte docker run za container run a odstraňte --restart.

Vložení příkazu v Gantry

  1. Vyberte hostitele: hostitele Docker nebo hostitele apple/container.
  2. Otevřete Kontejnery a klikněte na Nový kontejner.
  3. Klikněte na Vložit příkaz… a vložte řádek. Konce řádků s \, uvozovky, výzva $ i sudo nevadí.
  4. Projděte náhled: image, příznaky, které Gantry nemůže použít, poznámky a upozornění pro tohoto hostitele.
  5. Klikněte na Vyplnit formulář, zkontrolujte hodnoty a vytvořte kontejner.

Gantry čte docker run, docker container run, docker create, podman run a container run. Text za &&, ||, ; nebo | se ignoruje, s poznámkou.

Gantry zná asi 80 dalších příznaků Dockeru: správně přeskočí jejich hodnoty a vypíše je jako nepoužité, takže se nic neztratí bez poznámky.

Upozornění pro hostitele apple/container

Některé možnosti Dockeru v apple/container neexistují. Gantry na ně upozorní a vynechá je z požadavku na vytvoření:

  • zásady restartu (--restart);
  • zlomky CPU, například --cpus 0.5;
  • síťové režimy host, none a container:;
  • porty bez portu hostitele, například -p 80.

Na hostiteli Docker Gantry upozorní na možnosti apple/container: doménu DNS a možnosti jádra.

Ruční převod docker run na container run

V CLI zůstává většina příznaků stejná. Příklad s Redis:

Terminál
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

se změní na:

Terminál
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Nejdřív vytvořte pojmenovaný svazek příkazem container volume create. Odstraňte --restart a zaokrouhlete --cpus na celé číslo. --platform funguje jako v Dockeru.

Kopírování kontejneru jako příkazu

Funguje to i opačně. Klikněte na kontejner pravým tlačítkem nebo použijte nabídku Další a zvolte Kopírovat jako příkaz: Gantry vytvoří řádek docker run nebo container run. Vynechá výchozí hodnoty imagu, například jeho prostředí a příkaz, takže řádek zůstane krátký. Funguje to i u zastavených kontejnerů.

Uložení jako recept

V listu Nový kontejner otevřete Recepty a zvolte Uložit jako recept…. Příště vám Vyplnit z receptu dá stejný formulář na libovolném hostiteli. Recepty jsou v ~/Library/Application Support/Gantry/recipes.json, takže je můžete zálohovat nebo sdílet.

Omezení

  • Gantry zachová cestu --env-file, ale soubor nečte, a u -e KEY bez hodnoty nečte váš shell.
  • Připojení tmpfs a anonymní svazky z --mount se vypíšou jako nepodporované.
  • Dva porty pro stejný port kontejneru (-p 8080:80 -p 8081:80) formulář vyplní, ale formulář pak duplikát odmítne.

Otázky a odpovědi

Jak převést docker run na container run?

Nahraďte docker run za container run. -d, -p, -e, -v, --name, --rm, -it, -w a --entrypoint zůstávají stejné. Odstraňte --restart a používejte celá CPU. Nebo řádek vložte do Gantry a nechte ji vyplnit formulář.

Umí Gantry importovat příkaz docker run?

Ano. Vložit příkaz… v listu Nový kontejner přečte docker run, docker create, podman run a container run a vyplní formulář.

Co se stane s příznaky, které Gantry nepodporuje?

Vypíšou se v náhledu i s důvodem a zůstanou ve formuláři v sekci Z vloženého příkazu, takže je můžete zkontrolovat později.

Mohu běžící kontejner převést zpět na příkaz docker run?

Ano. Kopírovat jako příkaz v nabídce kontejneru vytvoří pro tento kontejner řádek docker run nebo container run.

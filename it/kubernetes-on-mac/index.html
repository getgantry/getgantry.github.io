Kubernetes su Mac con Apple container

Lo strumento container di Apple crea un cluster Kubernetes locale con un solo comando. Ogni nodo è una macchina virtuale leggera sul tuo Mac. Questa guida porta da un Mac vuoto a un deployment in esecuzione, prima nel terminale e poi in Gantry.

In breve. Installa il pacchetto firmato di container 1.7.1, esegui container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, crea un'immagine con container build ed eseguila nel cluster per nome. Gantry mostra lo stesso cluster in una finestra: nodi, pod, log, una shell e inoltri di porta.

Cosa ti serve

  • Un Mac con chip Apple e macOS 26 o successivo.
  • La CLI container 1.7.1 dal .pkg firmato nella pagina delle release di apple/container. La build Homebrew della 1.7.1 non include i servizi del cluster, quindi container cluster non riesce con cluster service unavailable.
  • Circa 6 GB di memoria libera per l'esempio qui sotto: tre nodi da 2 GB ciascuno.
  • kubectl, se vuoi usare il cluster dal terminale (brew install kubectl).

Avvia i servizi una volta, dopo aver installato il pacchetto:

Terminale
container system start

Crea il cluster

Questo comando crea un cluster chiamato dev con un nodo control plane e due worker. Ogni nodo ha 2 CPU e 2 GB di memoria:

Terminale
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M dimensiona un gruppo di worker. Ripetilo per gruppi di dimensioni diverse. Senza --workers, un solo nodo fa sia da control plane sia da worker.
  • --cpus e --memory dimensionano il control plane. Il valore predefinito è un quarto delle CPU e della memoria del tuo Mac, con un minimo di 2 CPU e 2 GB.
  • --shared-image-store permette ai nodi di usare le tue immagini locali (vedi sotto). Non puoi cambiarlo in seguito: elimina il cluster e crealo di nuovo.
  • --cni ./calico.yaml installa un tuo CNI al posto del kindnet incluso; --cni NONE non ne installa nessuno.

La CLI aggiunge a ~/.kube/config un contesto chiamato dev. Controlla i nodi:

Terminale
container cluster list --nodes
kubectl --context dev get nodes

Esegui un'immagine locale senza registro

Con --shared-image-store, i nodi possono eseguire qualsiasi immagine del tuo archivio immagini locale di container. Crea un'immagine e usala per nome:

Terminale
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Nota
Dopo aver ricreato lo stesso tag, esegui kubectl rollout restart con imagePullPolicy: Always, oppure usa un nuovo tag. Con IfNotPresent, un nodo tiene la copia che ha già. Qualunque cosa abbia i privilegi di root su un nodo può leggere ogni immagine del tuo archivio locale, comprese le immagini private, quindi usa l'archivio condiviso solo per lo sviluppo in locale.

Con le CLI 1.5 e 1.6 non c'è un archivio condiviso. Lì usa container cluster load-image, oppure Carica nel cluster in Gantry. La CLI 1.7 ha rimosso load-image.

Apri l'app nel browser

Inoltra una porta locale al deployment, poi apri http://localhost:8080:

Terminale
kubectl --context dev port-forward deployment/hello 8080:80

Esplora il cluster in Gantry

Gantry mostra lo stesso cluster senza comandi. Aggiungi il tuo host apple/container, apri Cluster e seleziona dev. La panoramica mostra la versione di Kubernetes, l'archivio immagini, i worker con le loro CPU e la loro memoria. Fai clic su Sfoglia risorse per aprire la sezione Kubernetes su quel contesto.

  • Pod, deployment, stateful set, daemon set, servizi, ingress, config map, secret, nodi ed eventi, per un namespace o per tutti.
  • Log dei pod con modalità segui e coda, una shell nel pod e inoltri di porta con un elenco da cui puoi interromperli.
  • Scalabilità, riavvio del rollout, eliminazione e Applica YAML da un manifest incollato o da un file.
  • I valori dei secret restano mascherati finché non fai clic su Mostra.

Il browser Kubernetes esegue kubectl. Se manca, Gantry mostra brew install kubectl e può eseguirlo per te. È in sviluppo un client nativo che non richiede kubectl.

Puoi anche creare il cluster in Gantry: Cluster ▸ Nuovo cluster ha selettori numerici per il control plane e i worker e un interruttore Usa immagini locali. Altre informazioni nella pagina Kubernetes su apple/container.

Arresta ed elimina il cluster

Terminale
container cluster delete --name dev

Se il nodo control plane si arresta, per esempio dopo container system stop, elimina il cluster e crealo di nuovo. Crea un cluster usa e getta con --rm per rimuoverne i nodi quando si arrestano.

Problemi comuni

  • cluster service unavailable: la CLI è la build Homebrew, oppure i servizi non sono in esecuzione. Installa il pacchetto firmato, oppure riavvia i servizi con container system stop e container system start. Gantry dà lo stesso consiglio in Cluster.
  • Un vecchio cluster non compare nell'elenco: la CLI 1.7 non elenca i cluster creati con la 1.6 o precedenti. Rimuovine uno con container cluster delete --name <name>.
  • I nodi restano NotReady: hai usato --cni NONE. Applica un manifest CNI.
  • Non riesci ad arrestare il container di un nodo: è voluto. container stop e delete rifiutano i nodi del cluster; usa container cluster delete.

Il confronto con Docker Desktop e OrbStack

Docker Desktop ha Kubernetes integrato con kubeadm (un nodo) o kind (più nodi), e OrbStack ha un cluster integrato a nodo singolo. container cluster esegue kubeadm su immagini kindest/node, ogni nodo nella propria VM, con cluster a più nodi e l'archivio immagini condiviso. Domande e risposte

Posso eseguire Kubernetes su un Mac senza Docker?

Sì. La CLI container di Apple crea da sé cluster Kubernetes con container cluster create. Ogni nodo gira come VM leggera, e non ti servono Docker, Docker Desktop, kind o minikube.

Quanti nodi può avere un container cluster?

Un control plane e tutti i worker per cui il tuo Mac ha CPU e memoria. Impostali con --workers; con la CLI 1.7 ogni gruppo di worker può avere CPU e memoria proprie.

Come uso nel cluster un'immagine creata in locale?

Crea il cluster con --shared-image-store (CLI 1.7), crea l'immagine con container build -t name:tag . e usa name:tag nella specifica del pod. Non serve un registro.

Quale versione di Kubernetes usa container cluster?

La CLI 1.7.1 usa per impostazione predefinita l'immagine dei nodi kindest/node:v1.35.5. Scegli un'altra versione con --node-image, per esempio docker.io/kindest/node:v1.34.11. Gantry mostra la versione nella panoramica del cluster.

Esiste una GUI per container cluster?

Sì. Gantry crea ed elimina cluster, mostra i nodi ed esplora pod, deployment, servizi, log e secret nella sua sezione Kubernetes. È gratuito e open source.

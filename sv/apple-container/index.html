Gantry/Guide till apple/container

Apple container på Mac: komplett guide och GUI

apple/container kör Linux-containrar på din Mac, var och en i en egen lätt virtuell maskin. Det levereras som kommandoradsverktyg. Gantry är ett inbyggt macOS-GUI för det. Den här guiden förklarar verktyget, hur du installerar det och vilken funktion i Gantry som täcker varje container-kommando.

Kort sagt. Gantry är en gratis macOS-app med öppen källkod (MIT) som hanterar Apples container-verktyg och Docker i ett fönster. Den stöder container-CLI 1.0 till 1.7.1 (rekommenderas) och visar bara de funktioner som din CLI-version stöder. Installera den med brew install --cask getgantry/tap/gantry.

Vad är apple/container?

apple/container är ett verktyg med öppen källkod från Apple, skrivet i Swift, som skapar och kör Linux-containrar på en Mac. Docker Desktop kör alla containrar i en gemensam Linux-VM; apple/container kör varje container i en egen lätt virtuell maskin, byggd på Apples Virtualization-ramverk. Det använder vanliga OCI-images och hämtar därför från och skickar till samma register som Docker.

  • Hårdvara: en Mac med Apple-chip.
  • macOS: Apple stöder det på macOS 26.
  • Gränssnitt: bara container-CLI:et. Det finns ingen skrivbordsapp och inget compose-kommando.
  • Nätverk: varje container får en egen IP-adress på din Mac, och lokala DNS-domäner ger containrar namn som web.test.

Varför använda ett GUI för apple/container?

CLI:et är komplett, men det dagliga arbetet kräver många kommandon: container list, logs, stats, exec och sedan system, builder, registry, machine och cluster för resten. Gantry samlar dem i ett fönster som uppdateras live, så att du ser statusen i stället för att fråga efter den. Appen lägger också till det som CLI:et saknar: Compose-filer, felnotiser, en översikt över flottan tillsammans med dina Docker-värdar och en MCP-server för AI-agenter.

Kom igång med apple/container i Gantry

  1. Installera Gantry: brew install --cask getgantry/tap/gantry och ta sedan bort karantänflaggan (se Installation).
  2. Installera container-CLI:et från den signerade .pkg-filen på versionssidan för apple/container. Om det saknas eller är äldre än 1.0 visar Gantry ett installationsark med stegen.
  3. Välj Lägg till värd… i Gantry och lägg till en Apple Container-värd. När du ansluter startas container-tjänsterna om de är stoppade.
  4. Om ingen standardkärna är installerad visar värdöversikten en banderoll. Klicka på den för att installera den rekommenderade kärnan.
Obs!
Använd det signerade installationspaketet, inte Homebrew-bygget. Homebrew-bygget saknar maskinbakänden och, i 1.7.1, klustertjänsterna, så container machine och container cluster kan inte köras.

Det här lägger Gantry till på apple/container

Kubernetes-kluster

Skapa Kubernetes-kluster med container cluster, ange storlek för dina workers, låt poddar använda dina lokala images, välj CNI och se varje nod. Bläddra sedan i klustret i Gantrys Kubernetes-utforskare. Se Kubernetes på apple/container och steg-för-steg-guiden Kör Kubernetes på en Mac.

Containermaskiner och VS Code

Maskiner är långlivade Linux-miljöer från container machine. Gantry skapar, startar, stoppar och raderar dem, anger standardmaskin, ändrar CPU:er och minne och öppnar ett skal. Med CLI 1.1 eller senare kan en maskin starta med nästlad virtualisering (Apple-chip M3 eller nyare) och en anpassad kärna. Öppna i VS Code ansluter till en maskin som körs via Remote-SSH; maskinens image måste köra sshd.

Docker Compose på apple/container

Öppna en docker-compose.yml från Finder (Öppna med ▸ Gantry eller Snabbåtgärder ▸ Compose Up i apple/container), från Arkiv ▸ Öppna Compose-fil… eller genom att släppa den på fönstret. Gantry bygger build:-tjänster, skapar projektets nätverk och namngivna volymer och startar varje tjänst i depends_on-ordning med de vanliga com.docker.compose.*-etiketterna. Med en standard-DNS-domän inställd når tjänsterna varandra via tjänstnamnet tack vare nätverksalias.

Nätverks-DNS-alias och lokala domäner

Gantry skickar nätverksalias till container som --network <name>,alias=…. Utan en standard-DNS-domän går bara fullständiga namn igenom, och ett underträdsalias (med inledande punkt, som .gateway) går bara igenom som sitt exakta alias. Med en standarddomän fungerar även korta namn. Gantry skapar och raderar lokala DNS-domäner, anger standarddomänen och ger nya containrar ett värdnamn av typen name.domain. Läs Lokala DNS-namn.

System: tjänster, byggare, register, kärna, loggar, egenskaper

Varje apple/container-värd har ett avsnitt System. Det fungerar även när värden inte är ansluten, så att du kan starta stoppade tjänster därifrån.

  • Status och version: klient- och serverversion, med en varning när de skiljer sig åt; starta, stoppa och starta om tjänsterna; fakta och sökvägar för värden.
  • Image-byggare: status, image, CPU:er, minne och IP-adress; start med alternativ för CPU, minne och DNS; stopp; radering. Ett kort talar om när byggarens image är inaktuell och skapar om den.
  • Registerinloggningar: lista, logga in och logga ut. Lösenordet går bara till CLI:et via stdin (--password-stdin), och Gantry sparar ingen kopia.
  • Kärna: installera den rekommenderade kärnan, en kärnfil eller ett tar-arkiv och följ förloppet live.
  • Tjänsteloggar: live eller en gång, för 5 minuter till 1 dygn, filtrerade på nivå, tjänst och text.
  • Systemegenskaper: ändringar sparas i ~/.config/container/config.toml, med en markering för väntande omstart och knappen Starta om tjänster. På CLI 1.7 har namnservrar, sökdomäner och alternativ i [container.dns] en listredigerare.

Commit, Trimma disk och filer

Spara som image använder container commit (CLI 1.6). Trimma disk använder container clean (CLI 1.4) och visas även som en rad i Frigör utrymme. Fliken Filer laddar ned filer och låter dig dra ut dem till Finder med container copy (containern måste vara startad), och laddar upp filer och mappar.

Etiketter som innehåller =

container create avvisar ett etikettvärde som innehåller =, även i CLI 1.6.1. Gantry kodar sådana värden när containern skapas och avkodar dem när den läses tillbaka, så de etiketter du anger är de etiketter du ser.

MCP-server och Genvägar

Den inbyggda servern gantry-mcp ger AI-agenter samma räckvidd på apple/container-värdar: containrar, images, volymer, nätverk, Compose, maskiner (list_machines, create_machine med flera), kluster (list_clusters, create_cluster, delete_cluster) och apple_*-systemverktyg för tjänster, byggare, register (inget inloggningsverktyg), egenskaper, loggar och installation av kärna. App Intents lägger till åtgärder för Genvägar och Siri. Läs AI-agenter & MCP.

Lägg till Gantrys MCP-server
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container bredvid Docker

Gantry hanterar apple/container-värdar, den lokala Docker-daemonen (Docker Desktop, OrbStack, Colima) och fjärrvärdar för Docker via SSH i ett sidofält och en översikt över flottan. Du behöver inte välja en enda körmiljö. En jämförelse funktion för funktion finns i Gantry jämfört med Docker Desktop, OrbStack och Podman Desktop. För att flytta över ditt arbete, läs Byt från Docker Desktop till Apple container.

Frågor och svar

Vilket är det bästa GUI:t för Apple container?

Gantry är ett gratis inbyggt macOS-GUI med öppen källkod, gjort för apple/container. Det översätter container-CLI:et till en skrivbordsapp: containrar, loggar, statistik och exec, plus Kubernetes-kluster, maskiner, image-byggaren, registerinloggningar, kärnor, tjänsteloggar och systemegenskaper. Tabellen på den här sidan listar varje kommando och funktionen i Gantry som använder det.

Finns det ett GUI för Apple container?

Apple levererar container bara som kommandoradsverktyg. Gantry är en separat app med öppen källkod som ger det ett GUI, bredvid dina Docker-värdar.

Kan jag använda docker compose med Apple container?

apple/container har inget compose-kommando. Gantry läser en docker-compose.yml, bygger build:-tjänster, skapar nätverket och namngivna volymer och startar tjänsterna i depends_on-ordning. Tjänstnamn slås upp via nätverks-DNS-alias.

Hur öppnar jag en containermaskin i VS Code?

Starta maskinen i Gantry och klicka på Öppna i VS Code. Gantry öppnar den via Remote-SSH, som i Apples exempel container-machine-vscode. Maskinens image måste köra sshd.

Fungerar Apple container på Intel-Mac?

Nej. apple/container kräver en Mac med Apple-chip. Gantry fungerar även på Intel-Mac, men där hanterar den bara Docker-värdar.

Vilken version av container-CLI:et ska jag installera?

Gantry kräver 1.0 eller senare och rekommenderar 1.7.1. Installera med det signerade installationspaketet från versionssidan för apple/container. Homebrew-bygget saknar maskinbakänden och, i 1.7.1, klustertjänsterna, så container machine och container cluster fungerar inte med det.

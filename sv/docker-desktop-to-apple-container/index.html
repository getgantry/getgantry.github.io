Gantry/Från Docker Desktop

Byt från Docker Desktop till Apple container

Apples container-verktyg kör samma OCI-images som Docker, så det mesta av ditt arbete flyttar över med några ändrade kommandon. Den här guiden visar vad Docker motsvarar i container, flyttar images och volymer och listar de luckor du bör känna till innan du byter.

Kort sagt. Installera det signerade container-paketet, byt docker mot container för run, build, logs, exec och images, kopiera namngivna volymer med en tar-fil och öppna din docker-compose.yml i Gantry, eftersom CLI:et inte har compose. Du kan ha kvar Docker Desktop medan du provar.

Det här ändras

  • En VM per container. Docker Desktop kör alla containrar i en Linux-VM. apple/container startar en liten VM för varje container, så varje container får en egen IP-adress på din Mac.
  • Samma images och register. Images är OCI-images; du hämtar från Docker Hub, GHCR och privata register som tidigare.
  • Ingen licensavgift. apple/container har licensen Apache 2.0. Docker Desktop kräver en betald plan i organisationer med 250 eller fler anställda eller en omsättning på 10 miljoner USD eller mer.
  • Bara Apple-chip och macOS 26. På Intel-Macar stannar du kvar vid en Docker-motor.

De flesta flaggor för run är desamma: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus och -m. Klistra in ett långt kommando i Gantry för att konvertera det: se Skapa en container från ett docker run-kommando.

    Ta med dina images

Images från ett register: hämta dem igen med container image pull. Lokala images som bara finns i Docker: spara dem i ett arkiv och läs in det. container image load läser OCI-arkiv, och nya Docker-versioner skriver en OCI-layout med docker save. Om inläsningen misslyckas skickar du imagen till ett register och hämtar den därifrån.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Flytta namngivna volymer

Docker lagrar volymdata i sin VM. Kopiera varje volym till en tar-fil med en kortlivad container och packa sedan upp den i en ny apple/container-volym:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

En namngiven volym i apple/container är en gles ext4-skivavbild, som standard högst 512 GB. Ange en annan storlek med --opt size=20g. Bindningsmonteringar av mappar på din Mac fungerar som i Docker: -v ~/project:/app.

    Compose-filer

container-CLI:et har inget compose-kommando. Öppna i stället docker-compose.yml i Gantry (Finder, Arkiv ▸ Öppna Compose-fil… eller dra och släpp). Gantry bygger build:-tjänsterna, skapar projektets nätverk och namngivna volymer och startar tjänsterna i depends_on-ordning. Tjänsterna når varandra via tjänstnamn genom nätverks-DNS-alias.

    Nätverk och portar
  • -p 8080:80 publicerar en port på localhost, som i Docker.
  • Varje container har också en egen IP-adress. Skapa en lokal DNS-domän med sudo container system dns create test och kör containrar med --dns-domain test: de får namn som web.test.
  • container network create skapar användarnätverk; containrar i samma nätverk når varandra.
  • Det finns inget läge --network host, none eller container:.
    Det här saknas
  • Inget Docker Engine-API. Verktyg som pratar med /var/run/docker.sock, till exempel Testcontainers, Dockers SDK:er eller Dev Containers, ser inte apple/container.
  • Inga omstartspolicyer. --restart finns inte; en container startar inte igen av sig själv.
  • Ingen Compose i CLI:et. Gantry kör Compose-filer: se Compose-filer.
  • Inga tillägg för Docker Desktop.
  • Bara hela CPU:er: --cpus 0.5 fungerar inte.
  • Kubernetes fungerar annorlunda: använd container cluster, se Kör Kubernetes på en Mac.
    Behåll båda medan du byter

Gantry hanterar apple/container och alla Docker-motorer (Docker Desktop, OrbStack, Colima eller Docker via SSH) i ett sidofält. Flytta ett projekt i taget och behåll Docker för de verktyg som behöver dess API. När du inte behöver det längre kan du ta bort Docker Desktop.

Frågor och svar

Kan Apple container ersätta Docker Desktop?

För att köra, bygga och hämta containrar på Apple-chip, ja. Det saknar Docker Engine-API, omstartspolicyer, tillägg och ett compose-kommando. Gantry lägger till Compose-filer och ett GUI.

Fungerar Docker-images med Apple container?

Ja. apple/container använder vanliga OCI-images och hämtar från samma register. arm64-images körs direkt; amd64-images körs via Rosetta med --arch amd64.

Fungerar docker compose med Apple container?

Inte från CLI:et: det finns inget container compose. Gantry läser docker-compose.yml och kör tjänsterna på apple/container åt dig.

Kan jag använda Docker Desktop och Apple container samtidigt?

Ja. De delar inte images eller volymer, men de kan köras sida vid sida. Gantry visar båda i ett fönster.

Är Apple container gratis för kommersiellt bruk?

Ja. apple/container har öppen källkod under Apache 2.0-licensen, och Gantry har MIT-licens. Båda är gratis för företag av alla storlekar.

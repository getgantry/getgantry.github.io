Gantry/Kubernetes apple/containeris

Kubernetes Apple containeris

apple/container saab käitada Kubernetese klastrit, mille sõlmed on konteinerid teie Macis. Gantry on selle GUI: looge klaster, jälgige sõlmede käivitumist, käitage selles oma kohalikke tõmmiseid ning sirvige selle podisid, logisid ja teenuseid, ilma pikkade container cluster käsuridadeta.

Lühidalt. apple/containeri hostis loob ja kustutab Gantry jaotis Klastrid Kubernetese klastreid käsuga container cluster (CLI 1.6.1 ja 1.7) või container k8s (CLI 1.5.0 kuni 1.6.0). CLI 1.7.1-s määrab see töösõlmede suuruse juhttasandist eraldi ja lülitab sisse jagatud tõmmisehoidla. Jaotis Kubernetes sirvib klastrit: podid, logid, shell, pordisuunamised, skaleerimine ja Rakenda YAML.

Nõuded

  • Apple'i kiibiga Mac, macOS 26 ja Gantry (brew install --cask getgantry/tap/gantry).
  • container CLI 1.5.0 või uuem; soovitatav on 1.7.1. Töösõlmed ja CNI Puudub vajavad versiooni 1.6.0 või uuemat. Töösõlmede suurused ja jagatud tõmmisehoidla vajavad versiooni 1.7.0 või uuemat. Kasutage allkirjastatud installipaketti: versiooni 1.7.1 Homebrew-versioonis pole klastriteenuseid.
  • kubectl Kubernetese brauseri ja terminali jaoks. Gantry saab selle Homebrew'ga installida.

Klastri loomine

  1. Valige oma apple/containeri host ja avage külgribal Klastrid.
  2. Alustage uut klastrit ja täitke allolevad valikud.
  3. Looge see. Loendis kuvatakse uus klaster koos edenemisega reaalajas. Tühista peatab loomise ja kustutab juba loodud sõlmed.

Sama käsk CLI-s:

Shell
container cluster create --name dev --cpus 2 --memory 4G \
  --workers count=2,cpus=2,memory=4G --shared-image-store

Sõlmed ja klastri üksikasjad

Klastrite loendis on iga klastri kohta üks rida. Üksikasjade vaates on Ülevaade (kubectl-i kontekst, API-server, Kubernetese versioon, tõmmisehoidla, töösõlmed ja nende ressursid, sõlmede võrk), tabel Sõlmed ja Uuri sõlmede toorandmete jaoks. Tööriistaribal on Sirvi ressursse ning menüüs Veel on Kirjuta kubeconfig, Kopeeri kubectl-i konteksti käsk ja Kustuta.

Klastri sõlmed on konteinerid, kuid neid haldab container cluster. Gantry keelab sõlme puhul käivitamise, peatamise, taaskäivitamise, eemaldamise ja ümbernimetamise ning ütleb põhjuse; Käivita kõik ja Peata kõik jätavad sõlmed vahele. CLI 1.7-s peidab CLI sõlmed ka käsu container list väljundist. CLI 1.6-ga või varasemaga loodud klastreid 1.7 loendis ei näidata; eemaldage need käsuga container cluster delete --name <name>.

Klastri sirvimine

Klõpsake töötaval klastril Sirvi ressursse või avage külgribal Kubernetes. Jaotis ei vaja hosti ja loetleb kõik kubeconfigi kontekstid; apple/containeri klastrite kontekstid on eespool. Valige nimeruum või kõik nimeruumid, seejärel liik: podid, Deploymentid, StatefulSetid, DaemonSetid, teenused, Ingressid, ConfigMapid, saladused, sõlmed või sündmused.

  • Podid: logid jälgimise, viimaste ridade ja eelmise konteineriga; shell podis; pordisuunamine aadressile 127.0.0.1.
  • Töökoormused: Deploymentide ja StatefulSetide skaleerimine; juurutuse taaskäivitamine.
  • Saladused: väärtused on loendis ja YAML-is varjatud, kuni klõpsate Näita.
  • Rakenda YAML: kleepige manifest või avage fail; vead kuvatakse lehel.

Brauser käivitab kubectl-i. Kui Gantry seda ei leia, näitab jaotis käsku brew install kubectl ja nuppu, mis selle käivitab. Arenduses on natiivne Kubernetese klient, mis ei vaja kubectl-i.

kubectl-i ühendamine

CLI lisab klastri loomisel faili ~/.kube/config klastri järgi nimetatud konteksti. Kasutage Gantrys käsku Kopeeri kubectl-i konteksti käsk või tippige see ise:

Shell
kubectl --context dev get nodes

Klastri hoidmiseks eraldi failis kasutage käsku Kirjuta kubeconfig. Gantry käivitab käsu container cluster write-config; vaiketee on ~/.kube/<name>.kubeconfig.

Kohalike tõmmiste kasutamine klastris

CLI 1.7-s lülitage klastri loomisel sisse Kasuta kohalikke tõmmiseid. See lisab lipu --shared-image-store, nii et sõlmed saavad nime järgi käitada mis tahes tõmmist, mille olete container-iga koostanud või tõmmanud, ilma registrita. Seda seadet saab määrata ainult loomisel. Kui koostate sildi uuesti, kasutage imagePullPolicy: Always või uut silti. Privilegeeritud podid saavad lugeda kõiki teie kohaliku hoidla tõmmiseid, seega kasutage seda ainult kohalikuks arenduseks.

Shell
container build -t myapp:dev .
kubectl --context dev create deployment myapp --image=myapp:dev

CLI 1.5-s ja 1.6-s paremklõpsake jaotises Tõmmised tõmmist ja valige Laadi klastrisse. Gantry käivitab käsu container cluster load-image, mis kopeerib tõmmise iga sõlme containerd'sse. CLI 1.7 eemaldas selle käsu, seega peidab Gantry seal selle toimingu.

Shell
container cluster load-image --name dev myapp:dev

Kui klastriteenused ei vasta

Kui klastri käsk nurjub veaga cluster service unavailable, kontrollib Gantry, kuidas CLI on installitud. Homebrew-versiooni puhul ilma klastri pistikprogrammideta kuvatakse teade, et selles versioonis pole klastriteenuseid, ja link Laadi alla installer… allkirjastatud paketile. Muudel juhtudel pakub Gantry nuppu Taaskäivita teenused….

CNI valimine

Vaikimisi kasutatakse kaasasolevat kindneti manifesti. Valige Kohandatud manifest, et installida failist oma CNI, näiteks Calico või Cilium. Valige Puudub, et installida CNI hiljem ise; seni jäävad sõlmed olekusse NotReady.

Klastrid AI-agentide abil

Gantry MCP-serveril on tööriistad list_clusters, create_cluster ja delete_cluster, nii et agent, näiteks Claude Code, saab luua testi jaoks ajutise klastri ja selle pärast eemaldada.

Gantry MCP-serveri lisamine
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Veel apple/containerist

Samm-sammulise juhise terminalist leiate juhendist Kubernetes Macis Apple containeriga. Lugege apple/containeri juhendit, et näha iga container käsku ja selle Gantry funktsiooni, või vaadake, kuidas Gantry võrdleb Docker Desktopi, OrbStacki ja Podman Desktopiga.

Küsimused ja vastused

Kas Apple container toetab Kubernetest?

Jah. container CLI loob Kubernetese klastreid, mille sõlmed töötavad konteineritena: container cluster CLI versioonides 1.6.1 ja 1.7, container k8s CLI versioonides 1.5.0 kuni 1.6.0. Gantry annab sellele GUI.

Kas Gantry toetab container clusterit?

Jah. Gantry loetleb, loob ja kustutab apple/containeri hostides klastreid, näitab nende sõlmi, kirjutab kubeconfigi ja avab klastri oma Kubernetese brauseris. CLI 1.7-s määrab see ka töösõlmede suuruse ja lülitab sisse jagatud tõmmisehoidla. See kasutab käsku cluster või k8s vastavalt teie CLI versioonile.

Kuidas kasutada kubectl-i apple/containeri klastriga?

Kui CLI loob klastri, lisab see faili ~/.kube/config klastri järgi nimetatud kubeconfigi konteksti. Käivitage kubectl --context <name> get nodes. Eraldi faili jaoks kasutage Gantrys käsku Kirjuta kubeconfig; vaiketee on ~/.kube/<name>.kubeconfig.

Kuidas saada kohalik tõmmis klastrisse ilma registrita?

CLI 1.7-s looge klaster valikuga Kasuta kohalikke tõmmiseid (--shared-image-store). Siis käitavad podid nime järgi tõmmiseid, mille olete container-iga koostanud või tõmmanud. CLI 1.5-s ja 1.6-s paremklõpsake jaotises Tõmmised tõmmist ja valige Laadi klastrisse; Gantry käivitab käsu container cluster load-image. CLI 1.7 eemaldas käsu load-image.

Kas saab luua mitme sõlmega klastri?

Jah. Määrake loomislehel töösõlmede arv; töösõlmed vajavad CLI versiooni 1.6.0 või uuemat. CLI 1.7-s määrate ka töösõlmede CPU-d ja mälu juhttasandist eraldi.

Kas saab kasutada oma CNI-d, nt Calicot või Ciliumit?

Jah. Valige Kohandatud manifest ja valige manifestifail või valige Puudub ja rakendage CNI ise pärast klastri käivitumist. Sõlmed jäävad olekusse NotReady, kuni mõni CNI töötab. Puudub vajab CLI versiooni 1.6.0 või uuemat. Vaikimisi CNI on kaasasolev kindneti manifest.

Miks ütleb Gantry, et klastriteenused pole saadaval?

container teenused ei vastanud klastri käsule. Kui teie CLI on Homebrew-versioon ilma klastriteenusteta, ütleb Gantry seda ja annab lingi allkirjastatud installerile apple/containeri väljalasete lehel. Muul juhul pakub see nuppu Taaskäivita teenused.

Kas klastri kasutamiseks Gantrys on vaja kubectl-i?

Praegu jah: Gantry Kubernetese brauser käivitab kubectl-i. Kui see pole installitud, näitab brauser käsku brew install kubectl ja saab selle teie eest käivitada. Arenduses on natiivne Kubernetese klient, mis selle sammu ära kaotab.

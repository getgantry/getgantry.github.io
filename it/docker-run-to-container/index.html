Gantry/Da docker run

Creare un container da un comando docker run

La maggior parte dei README riporta una riga docker run. Gantry legge quella riga e compila il modulo Nuovo container, per un host Docker o per lo strumento container di Apple. Questa guida mostra come, e come convertire il comando a mano.

In breve. In Gantry, apri Nuovo container, scegli Incolla comando…, incolla la riga docker run e fai clic su Compila modulo. Gantry elenca ogni flag che non può usare, con il motivo. Per la CLI, la maggior parte dei flag è la stessa: sostituisci docker run con container run e rimuovi --restart.

Incolla il comando in Gantry

  1. Seleziona un host: un host Docker o un host apple/container.
  2. Apri Container e fai clic su Nuovo container.
  3. Fai clic su Incolla comando… e incolla la riga. Le righe che terminano con \, le virgolette, un prompt $ e sudo vanno tutti bene.
  4. Leggi l'anteprima: l'immagine, i flag che Gantry non può usare, le note e gli avvisi per questo host.
  5. Fai clic su Compila modulo, controlla i valori e crea il container.

Gantry legge docker run, docker container run, docker create, podman run e container run. Il testo dopo &&, ||, ; o | viene ignorato, con una nota.

Gantry conosce circa 80 altri flag di Docker: ne salta correttamente i valori e li elenca come non usati, quindi nulla va perso senza una nota.

    Avvisi per gli host apple/container

Alcune opzioni di Docker non esistono su apple/container. Gantry le segnala e le esclude dalla richiesta di creazione:

  • criteri di riavvio (--restart);
  • frazioni di CPU come --cpus 0.5;
  • le modalità di rete host, none e container:;
  • porte senza porta dell'host, come -p 80.

Su un host Docker, Gantry segnala le opzioni di apple/container: il dominio DNS e le opzioni del kernel.

    Convertire a mano docker run in container run

Per la CLI, la maggior parte dei flag resta uguale. Un esempio con Redis:

Terminale
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

diventa:

Terminale
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Crea prima il volume con nome con container volume create. Rimuovi --restart e arrotonda --cpus a un numero intero. --platform funziona come in Docker.

    Copia un container come comando

Funziona anche al contrario. Fai clic destro su un container, o usa il menu Altro, e scegli Copia come comando: Gantry scrive una riga docker run o container run. Omette i valori predefiniti dell'immagine, come il suo ambiente e il suo comando, così la riga resta breve. Funziona anche con i container arrestati.

    Salvalo come ricetta

Nel pannello Nuovo container, apri Ricette e scegli Salva come ricetta…. La volta successiva, Compila da ricetta ti dà lo stesso modulo su qualsiasi host. Le ricette si trovano in ~/Library/Application Support/Gantry/recipes.json, quindi puoi farne un backup o condividerle.

    Limiti
  • Gantry conserva il percorso di --env-file ma non legge il file, e non legge la tua shell per -e KEY senza valore.
  • I montaggi tmpfs e i volumi anonimi di --mount sono elencati come non supportati.
  • Due porte per la stessa porta del container (-p 8080:80 -p 8081:80) compilano il modulo, ma poi il modulo rifiuta il duplicato.

Domande e risposte

Come converto docker run in container run?

Sostituisci docker run con container run. -d, -p, -e, -v, --name, --rm, -it, -w e --entrypoint restano uguali. Rimuovi --restart e usa CPU intere. Oppure incolla la riga in Gantry e lascia che compili il modulo.

Gantry può importare un comando docker run?

Sì. Incolla comando… nel pannello Nuovo container legge docker run, docker create, podman run e container run e compila il modulo.

Cosa succede ai flag che Gantry non supporta?

Sono elencati nell'anteprima con il motivo e restano nel modulo, nella sezione Dal comando incollato, così puoi controllarli in seguito.

Posso trasformare un container in esecuzione di nuovo in un comando docker run?

Sì. Copia come comando nel menu del container scrive una riga docker run o container run per quel container.

Gantry/Van Docker Desktop

Overstappen van Docker Desktop naar Apple container

Apples container-tool draait dezelfde OCI-images als Docker, dus het meeste werk verhuist mee met een paar gewijzigde commando's. Deze gids zet Docker naast container, verhuist images en volumes, en noemt de ontbrekende functies die je moet kennen voordat je overstapt.

Kort gezegd. Installeer het ondertekende container-pakket, vervang docker door container voor run, build, logs, exec en images, kopieer benoemde volumes via een tar-bestand en open je docker-compose.yml in Gantry, want de CLI heeft geen compose. Docker Desktop kan geïnstalleerd blijven terwijl je het uitprobeert.

Wat er verandert

  • Eén VM per container. Docker Desktop draait alle containers in één Linux-VM. apple/container start een kleine VM per container, dus elke container krijgt een eigen IP-adres op je Mac.
  • Dezelfde images en registry's. Images zijn OCI-images; je pullt zoals voorheen van Docker Hub, GHCR en privé-registry's.
  • Geen licentiekosten. apple/container valt onder Apache 2.0. Docker Desktop vereist een betaald abonnement in organisaties met 250 of meer medewerkers of $ 10 mln. of meer omzet.
  • Alleen Apple silicon en macOS 26. Op Intel-Macs blijf je bij een Docker-engine.

De meeste flags van run zijn hetzelfde: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus en -m. Plak een lang commando in Gantry om het om te zetten: zie Een container maken van een docker run-commando.

Je images meenemen

Images uit een registry: pull ze opnieuw met container image pull. Lokale images die alleen in Docker bestaan: sla ze op in een archief en laad dat. container image load leest OCI-archieven, en recente Docker-versies schrijven met docker save een OCI-layout. Mislukt het laden, push de image dan naar een registry en pull hem.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Benoemde volumes verhuizen

Docker bewaart volumegegevens in zijn VM. Kopieer elk volume met een kortlevende container naar een tar-bestand en pak het daarna uit in een nieuw apple/container-volume:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Een benoemd volume in apple/container is een sparse ext4-schijfkopie van standaard maximaal 512 GB. Stel een andere grootte in met --opt size=20g. Bind mounts van mappen op je Mac werken zoals in Docker: -v ~/project:/app.

Compose-bestanden

De container-CLI heeft geen compose-commando. Open de docker-compose.yml in plaats daarvan in Gantry (Finder, Archief ▸ Open Compose-bestand… of slepen). Gantry bouwt de build:-services, maakt het projectnetwerk en de benoemde volumes aan en start de services in de volgorde van depends_on. Services bereiken elkaar op servicenaam via netwerk-DNS-aliassen.

Netwerken en poorten

  • -p 8080:80 publiceert een poort op localhost, zoals in Docker.
  • Elke container heeft ook een eigen IP-adres. Maak een lokaal DNS-domein met sudo container system dns create test en draai containers met --dns-domain test: ze krijgen namen zoals web.test.
  • container network create maakt gebruikersnetwerken; containers op hetzelfde netwerk bereiken elkaar.
  • Er is geen modus --network host, none of container:.

Wat er ontbreekt

  • Geen Docker Engine-API. Tools die met /var/run/docker.sock praten, zoals Testcontainers, de Docker-SDK's of Dev Containers, zien apple/container niet.
  • Geen herstartbeleid. --restart is niet beschikbaar; een container start niet vanzelf opnieuw.
  • Geen Compose in de CLI. Gantry voert Compose-bestanden uit: zie Compose-bestanden.
  • Geen extensies van Docker Desktop.
  • Alleen hele CPU's: --cpus 0.5 werkt niet.
  • Kubernetes werkt anders: gebruik container cluster, zie Kubernetes draaien op een Mac.

Houd beide tijdens de overstap

Gantry beheert apple/container en elke Docker-engine (Docker Desktop, OrbStack, Colima of Docker via SSH) in één navigatiekolom. Verhuis één project tegelijk en houd Docker voor de tools die de API ervan nodig hebben. Heb je het niet meer nodig, dan kun je Docker Desktop verwijderen.

Vragen en antwoorden

Kan Apple container Docker Desktop vervangen?

Voor het draaien, bouwen en pullen van containers op Apple silicon: ja. Het heeft geen Docker Engine-API, geen herstartbeleid, geen extensies en geen compose-commando. Gantry voegt Compose-bestanden en een GUI toe.

Werken Docker-images met Apple container?

Ja. apple/container gebruikt standaard OCI-images en pullt uit dezelfde registry's. arm64-images draaien native; amd64-images draaien via Rosetta met --arch amd64.

Werkt docker compose met Apple container?

Niet vanuit de CLI: er is geen container compose. Gantry leest de docker-compose.yml en draait de services voor je op apple/container.

Kan ik Docker Desktop en Apple container tegelijk gebruiken?

Ja. Ze delen geen images of volumes, maar ze kunnen naast elkaar draaien. Gantry toont beide in één venster.

Is Apple container gratis voor commercieel gebruik?

Ja. apple/container is open source onder de Apache 2.0-licentie, en Gantry valt onder de MIT-licentie. Beide zijn gratis voor bedrijven van elke grootte.

Gantry/Disque externe

Stocker les conteneurs et les volumes sur un disque externe

Les images, les conteneurs et les volumes remplissent vite un petit disque interne. Avec l'outil container d'Apple, vous pouvez garder ces données sur un SSD externe : placez-y des dossiers isolés avec des montages liés, ou déplacez toute la racine des données. Ce guide montre les deux méthodes, et comment débrancher le disque sans dégâts.

En bref. Formatez le disque en APFS. Pour un seul projet, utilisez un montage lié vers un dossier : -v /Volumes/Fast/pg:/data. Pour tout déplacer, arrêtez les services, copiez ~/Library/Application Support/com.apple.container sur le disque avec cp -Rp, puis démarrez les services à chaque fois avec container system start --app-root /Volumes/Fast/container.

Où sont les données actuellement

apple/container garde toutes ses données dans un seul dossier, la racine de l'app (app root). Par défaut, c'est ~/Library/Application Support/com.apple.container, avec des dossiers pour les conteneurs, le contenu des images, les instantanés, les volumes, les noyaux et les réseaux. Vérifiez le chemin et l'espace occupé :

Terminal
container system status | grep appRoot
container system df

Choisir et formater le disque

  • Utilisez un SSD en USB-C ou Thunderbolt. Un disque dur à plateaux fonctionne, mais les conteneurs démarrent plus lentement.
  • Formatez-le en APFS (Mac OS étendu fonctionne aussi). N'utilisez pas exFAT, FAT ni NTFS : les volumes sont des images disque creuses, et ces systèmes de fichiers n'ont ni fichiers creux ni permissions Unix.
  • N'utilisez pas de disque réseau pour la racine de l'app.
  • Donnez au disque un nom court sans espaces, par exemple Fast. Le chemin est alors /Volumes/Fast.
    Option 1 : garder les données d'un projet sur le disque avec des montages liés

Un montage lié partage un dossier de votre Mac avec le conteneur, et ce dossier peut se trouver sur n'importe quel disque. C'est la façon simple de garder de grosses données, comme une base de données ou des fichiers de modèles, hors du disque interne :

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Le disque doit être connecté avant le démarrage du conteneur. Les images et le conteneur lui-même restent sur le disque interne.

    Option 2 : déplacer toutes les données d'apple/container sur le disque

Cette méthode déplace les images, les conteneurs, les instantanés et les volumes. Arrêtez d'abord les services, pour qu'aucun fichier ne change pendant la copie :

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Utilisez cp -Rp. Lors de notre test sous macOS 27 (d'APFS vers APFS en USB), cette commande a gardé les images des volumes creuses et conservé les attributs étendus. ditto a écrit chaque image creuse à sa taille complète, ce qui peut remplir le disque. Gardez l'ancien dossier tant que vous n'avez pas vérifié que vos conteneurs, images et volumes sont listés.

Attention
La CLI ne mémorise pas --app-root. Chaque container system start sans cette option réutilise le dossier interne. Utilisez l'option à chaque fois, par exemple dans un alias de shell, et vérifiez paths.appRoot dans container system status.

Gantry 0.27.0 démarre les services sans --app-root quand il se connecte à un hôte dont les services sont arrêtés. Démarrez d'abord les services depuis le terminal avec l'option ; Gantry utilise ensuite les services en cours d'exécution.

    Archiver des images sur le disque

Pour libérer de l'espace sans perdre une image, enregistrez-la sur le disque externe et supprimez-la. Rechargez-la quand vous en avez besoin :

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Débrancher le disque sans risque
  1. Arrêtez les conteneurs qui utilisent le disque : container stop <name>.
  2. Si la racine de l'app est sur le disque, arrêtez les services : container system stop.
  3. Éjectez le disque dans le Finder, puis débranchez-le.

Si le disque disparaît pendant que des conteneurs s'exécutent depuis celui-ci, ils échouent, et les écritures en cours peuvent être perdues. Après avoir reconnecté le disque, démarrez les services avec --app-root, puis démarrez les conteneurs.

    Les disques externes dans Gantry

Gantry exécute dès aujourd'hui des montages liés depuis n'importe quel disque : dans Nouveau conteneur, ajoutez un volume, choisissez un dossier sur le disque externe et un chemin dans le conteneur.

    Docker Desktop et OrbStack

Docker Desktop déplace son image disque dans Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack a ajouté un réglage d'emplacement des données dans la version 0.13.0. Voir le comparatif.

Questions et réponses

Peut-on stocker les images d'Apple container sur un disque externe ?

Oui. Démarrez les services avec container system start --app-root /Volumes/Disk/container. Toutes les images, tous les conteneurs, instantanés et volumes se trouvent alors dans ce dossier.

Quel système de fichiers utiliser sur le disque externe ?

APFS. Les volumes sont des images disque creuses et les conteneurs ont besoin des permissions Unix, que exFAT, FAT et NTFS n'ont pas.

Comment copier les données des conteneurs sans remplir le disque ?

Utilisez cp -Rp, qui a gardé les images creuses des volumes compactes lors de notre test. ditto a copié chaque image creuse à sa taille complète.

Que se passe-t-il si je débranche le disque pendant que des conteneurs tournent ?

Les conteneurs qui utilisent le disque échouent, et les données pas encore écrites peuvent être perdues. Avant d'éjecter le disque, arrêtez les conteneurs et, si la racine de l'app se trouve sur le disque, les services.

La CLI container mémorise-t-elle le nouvel emplacement ?

Non. Passez --app-root à chaque container system start. container system status affiche la racine utilisée sous paths.appRoot.

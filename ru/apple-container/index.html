Gantry/Руководство по apple/container

Apple container на Mac: полное руководство и GUI

apple/container запускает Linux-контейнеры на вашем Mac, каждый в своей лёгкой виртуальной машине. Это утилита командной строки, а Gantry — нативный GUI для неё на macOS. Здесь описано, что это за инструмент, как его настроить и какая функция Gantry отвечает за каждую команду container.

Коротко. Gantry — бесплатное приложение для macOS с открытым кодом (MIT), которое управляет инструментом container от Apple и Docker из одного окна. Оно поддерживает CLI container от 1.0 до 1.7.1 (рекомендуется) и показывает только те функции, которые поддерживает ваша версия CLI. Установка: brew install --cask getgantry/tap/gantry.

Что такое apple/container?

apple/container — инструмент Apple с открытым кодом, написанный на Swift, который создаёт и запускает Linux-контейнеры на Mac. Docker Desktop запускает все контейнеры в одной общей Linux-ВМ, а apple/container — каждый контейнер в своей лёгкой виртуальной машине на базе фреймворка Virtualization от Apple. Он использует стандартные образы OCI, поэтому скачивает их из тех же реестров, что и Docker, и отправляет в них же.

  • Оборудование: Mac с Apple silicon.
  • macOS: Apple поддерживает его на macOS 26.
  • Интерфейс: только CLI container. Приложения с графическим интерфейсом и команды compose нет.
  • Сеть: каждый контейнер получает собственный IP-адрес на вашем Mac, а локальные DNS-домены дают контейнерам имена вроде web.test.

Зачем GUI для apple/container?

CLI умеет всё, но в повседневной работе команд много: container list, logs, stats, exec, а для остального — system, builder, registry, machine и cluster. Gantry собирает их в одном окне с живыми обновлениями, так что вы видите состояние, а не опрашиваете его. Он также добавляет то, чего нет в CLI: файлы Compose, уведомления о сбоях, сводку по парку вместе с хостами Docker и MCP-сервер для ИИ-агентов.

Настройка apple/container с Gantry

  1. Установите Gantry: brew install --cask getgantry/tap/gantry, затем снимите флаг карантина (см. Установка).
  2. Установите CLI container из подписанного .pkg со страницы релизов apple/container. Если CLI нет или его версия ниже 1.0, Gantry покажет окно настройки с инструкциями.
  3. В Gantry выберите Добавить хост… и добавьте хост Apple Container. При подключении службы container запускаются, если они остановлены.
  4. Если ядро по умолчанию не установлено, в обзоре хоста появится баннер. Нажмите его, чтобы установить рекомендуемое ядро.
Внимание
Используйте подписанный установочный пакет, а не сборку Homebrew. В сборке Homebrew нет бэкенда машин, а в 1.7.1 — и служб кластера, поэтому container machine и container cluster не могут работать.

Что Gantry добавляет к apple/container

Кластеры Kubernetes

Создавайте кластеры Kubernetes командой container cluster, задавайте размер рабочих узлов, разрешайте подам использовать ваши локальные образы, выбирайте CNI и смотрите каждый узел. Затем просматривайте кластер в браузере Kubernetes в Gantry. См. Kubernetes на apple/container и пошаговое руководство Kubernetes на Mac.

Машины container и VS Code

Машины — долгоживущие Linux-окружения из container machine. Gantry создаёт, запускает, останавливает и удаляет их, задаёт машину по умолчанию, меняет CPU и память и открывает оболочку. В CLI 1.1 или новее машина может загружаться с вложенной виртуализацией (Apple silicon M3 или новее) и своим ядром. Открыть в VS Code подключается к работающей машине через Remote-SSH; в образе машины должен работать sshd.

Docker Compose на apple/container

Откройте docker-compose.yml из Finder (Открыть в программе ▸ Gantry или Быстрые действия ▸ Compose Up в apple/container), через Файл ▸ Открыть файл Compose… или перетащив его в окно. Gantry собирает сервисы с build:, создаёт сеть проекта и именованные тома и запускает каждый сервис в порядке depends_on со стандартными метками com.docker.compose.*. Если задан DNS-домен по умолчанию, сервисы находят друг друга по имени через сетевые алиасы.

Сетевые DNS-алиасы и локальные домены

Gantry передаёт сетевые алиасы в container как --network <name>,alias=…. Без DNS-домена по умолчанию работают только полные имена, а алиас поддерева (с точкой в начале, например .gateway) работает только как точный алиас. С доменом по умолчанию работают и короткие имена. Gantry создаёт и удаляет локальные DNS-домены, задаёт домен по умолчанию и даёт новым контейнерам имя хоста name.domain. См. Локальные DNS-имена.

Система: службы, сборщик, реестры, ядро, логи, свойства

У каждого хоста apple/container есть раздел Система. Он работает, даже когда хост отключён, так что остановленные службы можно запустить прямо оттуда.

  • Статус и версия: версии клиента и сервера с предупреждением, если они различаются; запуск, остановка и перезапуск служб; сведения о хосте и пути.
  • Сборщик образов: состояние, образ, CPU, память и IP; запуск с параметрами CPU, памяти и DNS; остановка; удаление. Карточка сообщает, что образ сборщика устарел, и пересоздаёт его.
  • Входы в реестры: просмотр, вход и выход. Пароль передаётся в CLI только через stdin (--password-stdin), и Gantry не хранит его копию.
  • Ядро: установка рекомендуемого ядра, файла ядра или tar-архива с отображением хода установки в реальном времени.
  • Логи служб: в реальном времени или разово, за период от 5 минут до 1 дня, с фильтром по уровню, службе и тексту.
  • Системные свойства: изменения записываются в ~/.config/container/config.toml, с отметкой об ожидающем перезапуске и кнопкой Перезапустить службы. В CLI 1.7 для DNS-серверов, доменов поиска и параметров [container.dns] есть редактор списков.

Сохранение в образ, сжатие диска и файлы

Сохранить в образ использует container commit (CLI 1.6). Сжать диск использует container clean (CLI 1.4) и также показывается строкой в панели «Освободить место». Вкладка «Файлы» сохраняет файлы на Mac и позволяет перетаскивать их в Finder с помощью container copy (контейнер должен быть запущен), а также загружает файлы и папки в контейнер.

Метки, содержащие =

container create отклоняет значение метки, содержащее =, в том числе в CLI 1.6.1. Gantry кодирует такие значения при создании контейнера и декодирует при чтении, поэтому вы видите ровно те метки, которые задали.

MCP-сервер и «Быстрые команды»

Встроенный сервер gantry-mcp даёт ИИ-агентам те же возможности на хостах apple/container: контейнеры, образы, тома, сети, Compose, машины (list_machines, create_machine и другие), кластеры (list_clusters, create_cluster, delete_cluster) и системные инструменты apple_* для служб, сборщика, реестров (без инструмента входа), свойств, логов и установки ядра. App Intents добавляют действия для «Быстрых команд» и Siri. См. ИИ-агенты и MCP.

Подключите MCP-сервер Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container рядом с Docker

Gantry управляет хостами apple/container, локальным демоном Docker (Docker Desktop, OrbStack, Colima) и удалёнными хостами Docker по SSH в одном боковом меню и на одной сводке парка. Выбирать одну среду выполнения не нужно. Сравнение инструментов по функциям — на странице Gantry, Docker Desktop, OrbStack и Podman Desktop. Чтобы перенести работу, прочитайте Переход с Docker Desktop на Apple container.

Вопросы и ответы

Какой GUI для Apple container лучший?

Gantry — бесплатный нативный GUI для macOS с открытым кодом, созданный для apple/container. Он переносит CLI container в приложение: контейнеры, логи, статистика и exec, а также кластеры Kubernetes, машины, сборщик образов, входы в реестры, ядра, логи служб и системные свойства. Таблица на этой странице показывает каждую команду и функцию Gantry, которая её использует.

Есть ли у Apple container графический интерфейс?

Apple поставляет container только как утилиту командной строки. Gantry — отдельное приложение с открытым кодом, которое даёт ему GUI рядом с вашими хостами Docker.

Можно ли использовать docker compose с Apple container?

В apple/container нет команды compose. Gantry читает docker-compose.yml, собирает сервисы с build:, создаёт сеть и именованные тома и запускает сервисы в порядке depends_on. Имена сервисов разрешаются через сетевые DNS-алиасы.

Как открыть машину container в VS Code?

Запустите машину в Gantry и нажмите Открыть в VS Code. Gantry откроет её через Remote-SSH, как в примере Apple container-machine-vscode. В образе машины должен работать sshd.

Работает ли Apple container на Mac с Intel?

Нет. apple/container нужен Mac с Apple silicon. Gantry работает и на Mac с Intel, но там управляет только хостами Docker.

Какую версию CLI container установить?

Gantry нужна версия 1.0 или новее, рекомендуется 1.7.1. Установите её подписанным установочным пакетом со страницы релизов apple/container. В сборке Homebrew нет бэкенда машин, а в 1.7.1 — и служб кластера, поэтому container machine и container cluster с ней не работают.

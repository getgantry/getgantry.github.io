apple/container

Gantry is a native GUI for Apple's container tool. Manage its services, image builder, registry logins, kernel, Kubernetes clusters, machines and local DNS without the terminal. For the full map of CLI commands to Gantry features, read the apple/container guide.

Setup

apple/container needs a Mac with Apple silicon. Install the container CLI 1.0+ (1.7.1 recommended) from Apple's official signed installer. The Homebrew build lacks the machine backend and, in 1.7.1, the cluster services. Gantry detects it automatically and, if it's missing or outdated, offers a guided setup. Then add an Apple Container host from Add Host….

Heads up
Use the official signed installer rather than the Homebrew bottle — the bottle omits the machine API server, so container machine cannot run.

Versions

Gantry reads the installed CLI version and turns on only the features that version supports, for example Trim Disk (1.4), Kubernetes clusters (1.5), Commit to Image (1.6) and cluster workers (1.6). The System section warns you when the client and server versions differ.

Background services

apple/container relies on background services that must be running for any container to work. Start, stop or restart them from the host's System section, the menu-bar strip or Settings → Apple.

The System section

Each apple/container host has a System section in the sidebar. It works when the host is disconnected.

  • Status and Version — client and server versions, service start/stop/restart, host facts, resources and paths.
  • Image Builder — state, image, CPUs, memory and IP. Start with CPU, memory and DNS options, stop, delete.
  • Registry Logins — list, log in, log out. The password goes to the CLI only on stdin; Gantry keeps no copy.
  • Kernel — install the recommended kernel, a kernel file or a tar archive. Without a default kernel, the host overview shows a banner with an install action.
  • Service Logs — live or one-shot logs over 5 minutes to 1 day, filtered by level, service and text.
  • System Properties — edits go to ~/.config/container/config.toml, with a pending-restart flag and a Restart Services button.

Kubernetes clusters

The Clusters section creates Kubernetes clusters with container cluster (CLI 1.6.1 and 1.7) or container k8s (CLI 1.5.0 to 1.6.0): workers, CPUs, memory, node image and CNI. On CLI 1.7 it sizes the workers apart from the control plane and can turn on the shared image store (Use local images). It shows the nodes, writes the kubeconfig and opens the cluster in the Kubernetes browser (Browse Resources). See Kubernetes on apple/container and Run Kubernetes on a Mac.

What's different from Docker

  • Every container gets its own routable IP on your Mac — no port publishing needed to reach it.
  • Containers can resolve by name through local DNS domains.
  • Machines are long-lived Linux VMs (comparable to OrbStack machines) — see Machines.
  • Compose files can be brought up directly on an apple host. Service names resolve through network DNS aliases.
  • Label values that contain = are encoded on create and decoded on read, because the CLI rejects them.

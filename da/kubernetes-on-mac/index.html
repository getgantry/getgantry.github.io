Gantry/Kubernetes på en Mac

Kør Kubernetes på en Mac med Apple container

Apples container-værktøj kan oprette en lokal Kubernetes-klynge med én kommando. Hver node er en let virtuel maskine på din Mac. Denne guide går fra en tom Mac til et kørende deployment, først i terminalen og derefter i Gantry.

Kort fortalt. Installer den signerede container 1.7.1-pakke, kør container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, byg et image med container build, og kør det i klyngen ved navn. Gantry viser den samme klynge i et vindue: noder, pods, logge, en shell og portvideresendelser.

Det skal du bruge

  • En Mac med Apple-chip og macOS 26 eller nyere.
  • container-CLI 1.7.1 fra den signerede .pkg på udgivelsessiden for apple/container. Homebrew-buildet af 1.7.1 indeholder ikke klyngetjenesterne, så container cluster fejler med cluster service unavailable.
  • Cirka 6 GB ledig hukommelse til eksemplet nedenfor: tre noder med 2 GB hver.
  • kubectl, hvis du vil bruge klyngen fra terminalen (brew install kubectl).

Start tjenesterne én gang, når du har installeret pakken:

Terminal
container system start

Opret klyngen

Denne kommando opretter en klynge ved navn dev med én kontrolplan-node og to arbejdsnoder. Hver node får 2 CPU'er og 2 GB hukommelse:

Terminal
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M angiver størrelsen på en gruppe arbejdsnoder. Gentag det for grupper af forskellig størrelse. Uden --workers er én node både kontrolplan og arbejdsnode.
  • --cpus og --memory angiver størrelsen på kontrolplanet. Standarden er en fjerdedel af din Macs CPU'er og hukommelse, mindst 2 CPU'er og 2 GB.
  • --shared-image-store lader noderne bruge dine lokale images (se nedenfor). Du kan ikke ændre det senere: slet klyngen, og opret den igen.
  • --cni ./calico.yaml installerer din egen CNI i stedet for den medfølgende kindnet; --cni NONE installerer ingen.

CLI'en tilføjer en kontekst ved navn dev til ~/.kube/config. Tjek noderne:

Terminal
container cluster list --nodes
kubectl --context dev get nodes

Kør et lokalt image uden registry

Med --shared-image-store kan noderne køre ethvert image i dit lokale container-image-lager. Byg et image, og brug det ved navn:

Terminal
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Bemærk
Når du har bygget det samme tag igen, så kør kubectl rollout restart med imagePullPolicy: Always, eller brug et nyt tag. Med IfNotPresent beholder en node den kopi, den allerede har. Alt, der har root på en node, kan læse alle images i dit lokale lager, også private images, så brug kun det delte lager til lokal udvikling.

På CLI 1.5 og 1.6 er der intet delt lager. Brug container cluster load-image der, eller Indlæs i klynge i Gantry. CLI 1.7 har fjernet load-image.

Åbn appen i en browser

Videresend en lokal port til deploymentet, og åbn derefter http://localhost:8080:

Terminal
kubectl --context dev port-forward deployment/hello 8080:80

Gennemse klyngen i Gantry

Gantry viser den samme klynge uden kommandoer. Tilføj din apple/container-vært, åbn Klynger, og vælg dev. Oversigten viser Kubernetes-versionen, image-lageret, arbejdsnoderne og deres CPU'er og hukommelse. Klik på Gennemse ressourcer for at åbne sektionen Kubernetes med den kontekst.

  • Pods, deployments, StatefulSets, DaemonSets, services, ingresses, ConfigMaps, secrets, noder og hændelser, for ét navnerum eller dem alle.
  • Podlogge med følg og tail, en shell i poden og portvideresendelser med en liste, hvor du kan stoppe dem.
  • Skalering, genstart af udrulning, sletning og Anvend YAML fra et indsat manifest eller en fil.
  • Værdier i secrets forbliver maskerede, indtil du klikker på Vis.

Kubernetes-browseren kører kubectl. Mangler det, viser Gantry brew install kubectl og kan køre kommandoen for dig. En native klient, der ikke kræver kubectl, er under udvikling.

Du kan også oprette klyngen i Gantry: Klynger ▸ Ny klynge har trinvælgere til kontrolplanet og arbejdsnoderne og en Brug lokale images-kontakt. Mere på siden Kubernetes på apple/container.

Stop og slet klyngen

Terminal
container cluster delete --name dev

Stopper kontrolplan-noden, for eksempel efter container system stop, så slet klyngen, og opret den igen. Opret en engangsklynge med --rm, så dens noder fjernes, når de stopper.

Almindelige problemer

  • cluster service unavailable: CLI'en er Homebrew-buildet, eller tjenesterne kører ikke. Installer den signerede pakke, eller genstart tjenesterne med container system stop og container system start. Gantry giver det samme råd under Klynger.
  • En gammel klynge mangler i listen: CLI 1.7 viser ikke klynger, der er oprettet med 1.6 eller ældre. Fjern en med container cluster delete --name <name>.
  • Noderne forbliver NotReady: du brugte --cni NONE. Anvend et CNI-manifest.
  • Du kan ikke stoppe en nodecontainer: det er med vilje. container stop og delete afviser klyngens noder; brug container cluster delete.

Sådan klarer det sig mod Docker Desktop og OrbStack

Docker Desktop har indbygget Kubernetes med kubeadm (én node) eller kind (flere noder), og OrbStack har en indbygget klynge med én node. container cluster kører kubeadm på kindest/node-images, hver node i sin egen VM, med klynger med flere noder og det delte image-lager. Se den fulde sammenligning.

Spørgsmål og svar

Kan jeg køre Kubernetes på en Mac uden Docker?

Ja. Apples container-CLI opretter selv Kubernetes-klynger med container cluster create. Hver node kører som en let VM, og du behøver ikke Docker, Docker Desktop, kind eller minikube.

Hvor mange noder kan en container cluster have?

Ét kontrolplan og så mange arbejdsnoder, som din Mac har CPU'er og hukommelse til. Angiv dem med --workers; på CLI 1.7 kan hver gruppe arbejdsnoder have egne CPU'er og egen hukommelse.

Hvordan bruger jeg et lokalt bygget image i klyngen?

Opret klyngen med --shared-image-store (CLI 1.7), byg imaget med container build -t name:tag ., og brug name:tag i pod-specifikationen. Der kræves intet registry.

Hvilken Kubernetes-version bruger container cluster?

CLI 1.7.1 bruger som standard node-imaget kindest/node:v1.35.5. Vælg en anden version med --node-image, for eksempel docker.io/kindest/node:v1.34.11. Gantry viser versionen i klyngeoversigten.

Findes der en GUI til container cluster?

Ja. Gantry opretter og sletter klynger, viser noderne og gennemser pods, deployments, services, logge og secrets i sin Kubernetes-sektion. Den er gratis og har åben kildekode.

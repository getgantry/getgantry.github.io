Gantry/Extern disk

Lagra containrar och volymer på en extern disk

Images, containrar och volymer fyller snabbt en liten intern disk. Med Apples container-verktyg kan du ha den datan på en extern SSD: lägg enskilda mappar där med bindningsmonteringar, eller flytta hela datakatalogen. Den här guiden visar båda, och hur du kopplar ur disken utan skador.

Kort sagt. Formatera disken som APFS. För ett projekt monterar du en mapp med en bindningsmontering: -v /Volumes/Fast/pg:/data. För allt stoppar du tjänsterna, kopierar ~/Library/Application Support/com.apple.container till disken med cp -Rp och startar tjänsterna med container system start --app-root /Volumes/Fast/container varje gång.

Var datan finns nu

apple/container lagrar all sin data i en mapp, appens rotkatalog. Som standard är det ~/Library/Application Support/com.apple.container, med mappar för containrar, image-innehåll, ögonblicksbilder, volymer, kärnor och nätverk. Kontrollera sökvägen och det använda utrymmet:

Terminal
container system status | grep appRoot
container system df

Välj och formatera disken

  • Använd en SSD via USB-C eller Thunderbolt. En snurrande hårddisk fungerar, men containrar startar långsammare.
  • Formatera den som APFS (Mac OS Extended fungerar också). Använd inte exFAT, FAT eller NTFS: volymer är glesa skivavbilder, och de filsystemen saknar glesa filer och Unix-behörigheter.
  • Använd inte en nätverksdisk för appens rotkatalog.
  • Ge disken ett kort namn utan mellanslag, till exempel Fast. Sökvägen blir då /Volumes/Fast.
    Alternativ 1: ha projektdata på disken med bindningsmonteringar

En bindningsmontering delar en mapp på din Mac med containern, och mappen kan ligga på vilken disk som helst. Det är det enkla sättet att hålla stora data, till exempel en databas eller modellfiler, borta från den interna disken:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Disken måste vara ansluten innan containern startar. Images och själva containern stannar på den interna disken.

    Alternativ 2: flytta all data i apple/container till disken

Det här flyttar images, containrar, ögonblicksbilder och volymer. Stoppa tjänsterna först, så att inga filer ändras under kopieringen:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Använd cp -Rp. I vårt test på macOS 27 (APFS till APFS via USB) förblev volymavbilderna glesa och de utökade attributen behölls. ditto skrev varje gles avbild i full storlek, vilket kan fylla disken. Behåll den gamla mappen tills du har kontrollerat att dina containrar, images och volymer listas.

Obs!
CLI:et kommer inte ihåg --app-root. Varje container system start utan flaggan använder den interna mappen igen. Använd flaggan varje gång, till exempel i ett skalalias, och kontrollera paths.appRoot i container system status.

Gantry 0.27.0 startar tjänsterna utan --app-root när den ansluter till en värd vars tjänster är stoppade. Starta tjänsterna från terminalen med flaggan först; Gantry använder då de tjänster som körs.

    Arkivera images på disken

För att frigöra utrymme utan att förlora en image sparar du den på den externa disken och raderar den. Läs in den igen när du behöver den:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Koppla ur disken på ett säkert sätt
  1. Stoppa de containrar som använder disken: container stop <name>.
  2. Om appens rotkatalog ligger på disken stoppar du tjänsterna: container system stop.
  3. Mata ut disken i Finder och koppla sedan ur den.

Om disken försvinner medan containrar körs från den misslyckas de, och pågående skrivningar kan gå förlorade. När du har anslutit disken igen startar du tjänsterna med --app-root och sedan containrarna.

    Externa diskar i Gantry

Gantry kör redan nu bindningsmonteringar från valfri disk: i Ny container lägger du till en volym och väljer en mapp på den externa disken och en sökväg i containern.

    Docker Desktop och OrbStack

Docker Desktop flyttar sin skivavbild under Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack lade till en inställning för dataplats i version 0.13.0. Se jämförelsen.

Frågor och svar

Kan jag lagra images för Apple container på en extern disk?

Ja. Starta tjänsterna med container system start --app-root /Volumes/Disk/container. Alla images, containrar, ögonblicksbilder och volymer ligger sedan i den mappen.

Vilket filsystem ska den externa disken ha?

APFS. Volymer är glesa skivavbilder och containrar behöver Unix-behörigheter, vilket exFAT, FAT och NTFS saknar.

Hur kopierar jag container-datan utan att fylla disken?

Använd cp -Rp, som höll de glesa volymavbilderna små i vårt test. ditto kopierade varje gles avbild i full storlek.

Vad händer om jag kopplar ur disken medan containrar körs?

De containrar som använder disken misslyckas, och data som ännu inte skrivits kan gå förlorad. Stoppa containrarna och, om appens rotkatalog ligger på disken, tjänsterna innan du matar ut den.

Kommer container-CLI:et ihåg den nya platsen?

Nej. Ange --app-root för varje container system start. container system status visar katalogen som används som paths.appRoot.

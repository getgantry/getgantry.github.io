Gantry/Disco externo

Guardar contenedores y volúmenes en un disco externo

Las imágenes, los contenedores y los volúmenes llenan rápido un disco interno pequeño. Con la herramienta container de Apple puedes guardar esos datos en un SSD externo: poner carpetas sueltas en él con montajes enlazados o mover toda la raíz de datos. Esta guía muestra las dos opciones y cómo desconectar el disco sin dañar nada.

En resumen. Formatea el disco en APFS. Para un proyecto, monta una carpeta: -v /Volumes/Fast/pg:/data. Para todo, detén los servicios, copia ~/Library/Application Support/com.apple.container al disco con cp -Rp e inicia los servicios cada vez con container system start --app-root /Volumes/Fast/container.

Dónde están ahora los datos

apple/container guarda todos sus datos en una carpeta, la raíz de la app (app root). De forma predeterminada es ~/Library/Application Support/com.apple.container, con carpetas para contenedores, contenido de imágenes, snapshots, volúmenes, kernels y redes. Comprueba la ruta y el espacio ocupado:

Terminal
container system status | grep appRoot
container system df

Elegir y formatear el disco

  • Usa un SSD por USB-C o Thunderbolt. Un disco mecánico funciona, pero los contenedores tardan más en arrancar.
  • Formatéalo en APFS (Mac OS Plus también funciona). No uses exFAT, FAT ni NTFS: los volúmenes son imágenes de disco dispersas, y esos sistemas de archivos no admiten archivos dispersos ni permisos Unix.
  • No uses un disco de red para la raíz de la app.
  • Ponle al disco un nombre corto sin espacios, por ejemplo Fast. La ruta será /Volumes/Fast.
    Opción 1: guardar los datos del proyecto en el disco con montajes enlazados

Un montaje enlazado comparte una carpeta de tu Mac con el contenedor, y la carpeta puede estar en cualquier disco. Es la forma sencilla de sacar del disco interno datos grandes, como una base de datos o archivos de modelos:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

El disco debe estar conectado antes de que arranque el contenedor. Las imágenes y el propio contenedor siguen en el disco interno.

    Opción 2: mover todos los datos de apple/container al disco

Así se mueven las imágenes, los contenedores, los snapshots y los volúmenes. Detén antes los servicios, para que ningún archivo cambie durante la copia:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Usa cp -Rp. En nuestra prueba en macOS 27 (de APFS a APFS por USB), mantuvo dispersas las imágenes de los volúmenes y conservó los atributos extendidos. ditto escribió cada imagen dispersa con su tamaño completo, lo que puede llenar el disco. Conserva la carpeta antigua hasta comprobar que tus contenedores, imágenes y volúmenes aparecen en las listas.

Atención
La CLI no recuerda --app-root. Cada container system start sin él vuelve a usar la carpeta interna. Usa el parámetro siempre, por ejemplo en un alias del shell, y comprueba paths.appRoot en container system status.

Gantry puede hacer este traslado por ti: consulta más abajo.

    Archivar imágenes en el disco

Para liberar espacio sin perder una imagen, guárdala en el disco externo y elimínala. Vuelve a cargarla cuando la necesites:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Desconectar el disco con seguridad
  1. Detén los contenedores que usan el disco: container stop <name>.
  2. Si la raíz de la app está en el disco, detén los servicios: container system stop.
  3. Expulsa el disco en el Finder y desconéctalo.

Si el disco desaparece mientras se ejecutan contenedores desde él, estos fallan, y las escrituras en curso pueden perderse. Cuando vuelvas a conectar el disco, inicia los servicios con --app-root y después los contenedores.

    Discos externos en Gantry

En un host apple/container, el panel Almacenamiento de la sección Sistema muestra dónde está la raíz de datos, en qué disco y cuánto espacio ocupan las imágenes, los contenedores, los snapshots, los volúmenes y los kernels. Mover a otro disco… detiene los servicios, copia los datos, los comprueba, cambia la raíz y vuelve a iniciar los servicios; solo elimina la copia antigua tras una confirmación aparte. Gantry recuerda la raíz para todos los inicios posteriores. Los volúmenes nuevos pueden estar en una carpeta de cualquier disco, y cuando ese disco no está conectado, Gantry te dice qué disco falta y no inicia los contenedores que lo necesitan.

    Docker Desktop y OrbStack

Docker Desktop mueve su imagen de disco en Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack añadió un ajuste de ubicación de datos en la versión 0.13.0. Consulta la comparativa.

Preguntas y respuestas

¿Puedo guardar las imágenes de Apple container en un disco externo?

Sí. Inicia los servicios con container system start --app-root /Volumes/Disk/container. Todas las imágenes, contenedores, snapshots y volúmenes estarán entonces en esa carpeta.

¿Qué sistema de archivos debe usar el disco externo?

APFS. Los volúmenes son imágenes de disco dispersas y los contenedores necesitan permisos Unix, que exFAT, FAT y NTFS no tienen.

¿Cómo copio los datos de container sin llenar el disco?

Usa cp -Rp, que en nuestra prueba mantuvo pequeñas las imágenes dispersas de los volúmenes. ditto copió cada imagen dispersa con su tamaño completo.

¿Qué pasa si desconecto el disco mientras se ejecutan contenedores?

Los contenedores que usan el disco fallan, y los datos que aún no se habían escrito pueden perderse. Antes de expulsarlo, detén los contenedores y, si la raíz de la app está en el disco, también los servicios.

¿La CLI container recuerda la nueva ubicación?

No. Pasa --app-root a cada container system start. container system status muestra la raíz en uso como paths.appRoot.

Z Docker Desktop na Apple container

Narzędzie container od Apple uruchamia te same obrazy OCI co Docker, więc większość pracy przeniesiesz po kilku zmianach w poleceniach. Ten przewodnik przekłada polecenia Dockera na container, przenosi obrazy i woluminy oraz wymienia braki, o których warto wiedzieć przed przejściem.

W skrócie. Zainstaluj podpisany pakiet container, zamień docker na container przy run, build, logs, exec i obrazach, skopiuj nazwane woluminy przez plik tar i otwórz swój docker-compose.yml w Gantry, bo CLI nie ma compose. Na czas prób możesz zostawić zainstalowany Docker Desktop.

Co się zmienia

  • Jedna maszyna wirtualna na kontener. Docker Desktop uruchamia wszystkie kontenery w jednej linuksowej maszynie wirtualnej. apple/container uruchamia małą maszynę wirtualną dla każdego kontenera, więc każdy dostaje własny adres IP na Twoim Macu.
  • Te same obrazy i rejestry. Obrazy są obrazami OCI; pobierasz je z Docker Hub, GHCR i prywatnych rejestrów tak jak dotąd.
  • Bez opłat licencyjnych. apple/container jest na licencji Apache 2.0. Docker Desktop wymaga płatnego planu w organizacjach z co najmniej 250 pracownikami lub co najmniej 10 mln USD przychodu.
  • Tylko Apple silicon i macOS 26. Na Macach z procesorem Intel zostań przy silniku Docker.

Większość flag run jest taka sama: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus i -m. Aby przekształcić długie polecenie, wklej je w Gantry: zobacz Kontener z polecenia docker run.

    Przeniesienie obrazów

Obrazy z rejestru: pobierz je ponownie poleceniem container image pull. Lokalne obrazy, które istnieją tylko w Dockerze: zapisz je do archiwum i wczytaj je. container image load odczytuje archiwa OCI, a nowsze wersje Dockera zapisują układ OCI poleceniem docker save. Jeśli wczytanie się nie uda, wypchnij obraz do rejestru i pobierz go.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Przeniesienie nazwanych woluminów

Docker trzyma dane woluminów wewnątrz swojej maszyny wirtualnej. Skopiuj każdy wolumin do pliku tar za pomocą krótko działającego kontenera, a potem rozpakuj go do nowego woluminu apple/container:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Nazwany wolumin w apple/container to rzadki (sparse) obraz dysku ext4, domyślnie maksymalnie 512 GB. Inny rozmiar ustawisz opcją --opt size=20g. Montowania katalogów z Twojego Maca działają jak w Dockerze: -v ~/project:/app.

    Pliki Compose

CLI container nie ma polecenia compose. Zamiast tego otwórz docker-compose.yml w Gantry (Finder, Plik ▸ Otwórz plik Compose… lub przeciągnij i upuść). Gantry buduje usługi z build:, tworzy sieć projektu i nazwane woluminy oraz uruchamia usługi w kolejności depends_on. Usługi łączą się ze sobą po nazwie usługi dzięki aliasom DNS sieci.

    Sieci i porty
  • -p 8080:80 publikuje port na localhost, tak jak w Dockerze.
  • Każdy kontener ma też własny adres IP. Utwórz lokalną domenę DNS poleceniem sudo container system dns create test i uruchamiaj kontenery z --dns-domain test: dostaną nazwy takie jak web.test.
  • container network create tworzy sieci użytkownika; kontenery w tej samej sieci widzą się nawzajem.
  • Nie ma trybu --network host, none ani container:.
    Czego brakuje
  • Brak Docker Engine API. Narzędzia, które łączą się z /var/run/docker.sock, takie jak Testcontainers, SDK Dockera czy Dev Containers, nie widzą apple/container.
  • Brak zasad ponownego uruchamiania. --restart jest niedostępne; kontener nie uruchamia się ponownie sam.
  • Brak Compose w CLI. Gantry uruchamia pliki Compose: zobacz Pliki Compose.
  • Brak rozszerzeń Docker Desktop.
  • Tylko całe procesory: --cpus 0.5 nie działa.
  • Kubernetes działa inaczej: użyj container cluster, zobacz Kubernetes na Macu.
    Oba naraz na czas przejścia

Gantry zarządza apple/container i dowolnym silnikiem Docker (Docker Desktop, OrbStack, Colima lub Docker przez SSH) na jednym pasku bocznym. Przenoś po jednym projekcie i zostaw Dockera dla narzędzi, które potrzebują jego API. Gdy nie będzie już potrzebny, możesz odinstalować Docker Desktop.

Pytania i odpowiedzi

Czy Apple container może zastąpić Docker Desktop?

Do uruchamiania, budowania i pobierania kontenerów na Apple silicon – tak. Nie ma Docker Engine API, zasad ponownego uruchamiania, rozszerzeń ani polecenia compose. Gantry dodaje obsługę plików Compose i GUI.

Czy obrazy Dockera działają z Apple container?

Tak. apple/container używa standardowych obrazów OCI i pobiera je z tych samych rejestrów. Obrazy arm64 działają natywnie; obrazy amd64 działają przez Rosetta z --arch amd64.

Czy docker compose działa z Apple container?

Nie z CLI: nie ma container compose. Gantry odczytuje docker-compose.yml i uruchamia usługi na apple/container za Ciebie.

Czy mogę używać Docker Desktop i Apple container jednocześnie?

Tak. Nie współdzielą obrazów ani woluminów, ale mogą działać obok siebie. Gantry pokazuje oba w jednym oknie.

Czy Apple container jest darmowy do użytku komercyjnego?

Tak. apple/container jest open source na licencji Apache 2.0, a Gantry na licencji MIT. Oba są darmowe dla firm każdej wielkości.

Gantry/Van docker run

Een container maken van een docker run-commando

De meeste README's geven een docker run-regel. Gantry leest die regel en vult het formulier Nieuwe container in, voor een Docker-host of voor Apples container-tool. Deze gids laat zien hoe, en hoe je het commando met de hand omzet.

Kort gezegd. Open in Gantry Nieuwe container, kies Plak commando…, plak de docker run-regel en klik op Vul formulier in. Gantry toont elke flag die het niet kan gebruiken, met de reden. Voor de CLI zijn de meeste flags hetzelfde: vervang docker run door container run en verwijder --restart.

Het commando plakken in Gantry

  1. Selecteer een host: een Docker-host of een apple/container-host.
  2. Open Containers en klik op Nieuwe container.
  3. Klik op Plak commando… en plak de regel. Regeleinden met \, aanhalingstekens, een $-prompt en sudo zijn geen probleem.
  4. Lees het voorbeeld: de image, de flags die Gantry niet kan gebruiken, opmerkingen en waarschuwingen voor deze host.
  5. Klik op Vul formulier in, controleer de waarden en maak de container.

Gantry leest docker run, docker container run, docker create, podman run en container run. Tekst na &&, ||, ; of | wordt genegeerd, met een opmerking.

Ongeveer 80 andere Docker-flags zijn bekend: Gantry slaat hun waarden correct over en toont ze als niet gebruikt, zodat er niets zonder opmerking verloren gaat.

Waarschuwingen voor apple/container-hosts

Sommige Docker-opties bestaan niet op apple/container. Gantry waarschuwt ervoor en laat ze weg uit het aanmaakverzoek:

  • herstartbeleid (--restart);
  • CPU-fracties zoals --cpus 0.5;
  • de netwerkmodi host, none en container:;
  • poorten zonder hostpoort, zoals -p 80.

Op een Docker-host waarschuwt Gantry voor de apple/container-opties: het DNS-domein en de kernelopties.

docker run met de hand omzetten naar container run

Voor de CLI blijven de meeste flags hetzelfde. Een voorbeeld met Redis:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

wordt:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Maak eerst het benoemde volume aan met container volume create. Verwijder --restart en rond --cpus af op een heel getal. --platform werkt zoals in Docker.

Een container kopiëren als commando

Het werkt ook andersom. Klik met de rechtermuisknop op een container, of gebruik het menu Meer, en kies Kopieer als commando: Gantry schrijft een docker run- of container run-regel. Het laat de standaardwaarden van de image weg, zoals de omgeving en het commando, zodat de regel kort blijft. Dit werkt ook voor gestopte containers.

Bewaren als recept

Open in het venster Nieuwe container Recepten en kies Bewaar als recept…. De volgende keer geeft Vul in vanuit recept hetzelfde formulier op elke host. Recepten staan in ~/Library/Application Support/Gantry/recipes.json, dus je kunt er een reservekopie van maken of ze delen.

Beperkingen

  • Gantry bewaart het pad van --env-file maar leest het bestand niet, en leest je shell niet uit voor -e KEY zonder waarde.
  • tmpfs-koppelingen en anonieme volumes uit --mount worden als niet ondersteund vermeld.
  • Twee poorten voor dezelfde containerpoort (-p 8080:80 -p 8081:80) vullen het formulier in, maar het formulier weigert dan het duplicaat.

Vragen en antwoorden

Hoe zet ik docker run om naar container run?

Vervang docker run door container run. -d, -p, -e, -v, --name, --rm, -it, -w en --entrypoint blijven hetzelfde. Verwijder --restart en gebruik hele CPU's. Of plak de regel in Gantry en laat het formulier invullen.

Kan Gantry een docker run-commando importeren?

Ja. Plak commando… in het venster Nieuwe container leest docker run, docker create, podman run en container run en vult het formulier in.

Wat gebeurt er met flags die Gantry niet ondersteunt?

Ze staan met de reden in het voorbeeld en blijven in het formulier in het gedeelte Uit het geplakte commando, zodat je ze later kunt controleren.

Kan ik een draaiende container weer omzetten naar een docker run-commando?

Ja. Kopieer als commando in het containermenu schrijft een docker run- of container run-regel voor die container.

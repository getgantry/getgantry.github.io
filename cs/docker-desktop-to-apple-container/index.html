Z Docker Desktop na Apple container

Nástroj container od Applu spouští stejné image OCI jako Docker, takže většinu práce přenesete s několika změnami v příkazech. Tento průvodce převádí Docker na container, přenáší image a svazky a uvádí mezery, o kterých byste měli vědět, než přejdete.

Ve zkratce. Nainstalujte podepsaný balíček container, u run, build, logs, exec a imagů nahraďte docker za container, pojmenované svazky zkopírujte přes soubor tar a docker-compose.yml otevřete v Gantry, protože CLI nemá compose. Během zkoušení můžete mít Docker Desktop dál nainstalovaný.

Co se mění

  • Jeden virtuální stroj na kontejner. Docker Desktop spouští všechny kontejnery v jednom linuxovém virtuálním stroji. apple/container spouští malý virtuální stroj pro každý kontejner, takže každý dostane na vašem Macu vlastní IP adresu.
  • Stejné image a registry. Image jsou image OCI; stahujete je z Docker Hub, GHCR a soukromých registrů jako dosud.
  • Žádný licenční poplatek. apple/container je pod licencí Apache 2.0. Docker Desktop vyžaduje placený plán v organizacích s 250 a více zaměstnanci nebo s obratem 10 mil. USD a více.
  • Jen Apple silicon a macOS 26. Na Macích s procesorem Intel zůstaňte u enginu Docker.

Většina příznaků run je stejná: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus a -m. Dlouhý příkaz převedete tak, že ho vložíte do Gantry: viz Kontejner z příkazu docker run.

    Přenos imagů

Image z registru: stáhněte je znovu příkazem container image pull. Místní image, které existují jen v Dockeru: uložte je do archivu a ten načtěte. container image load čte archivy OCI a novější verze Dockeru zapisují příkazem docker save layout OCI. Pokud načtení selže, odešlete image do registru a stáhněte ho.

Terminál
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Přesun pojmenovaných svazků

Docker drží data svazků uvnitř svého virtuálního stroje. Každý svazek zkopírujte do souboru tar pomocí krátce běžícího kontejneru a pak ho rozbalte do nového svazku apple/container:

Terminál
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Pojmenovaný svazek v apple/container je řídký (sparse) obraz disku ext4, ve výchozím stavu nejvýše 512 GB. Jinou velikost nastavíte pomocí --opt size=20g. Bind mounty složek z vašeho Macu fungují jako v Dockeru: -v ~/project:/app.

    Soubory Compose

CLI container nemá příkaz compose. Místo toho otevřete docker-compose.yml v Gantry (Finder, Soubor ▸ Otevřít soubor Compose… nebo přetažením). Gantry sestaví služby s build:, vytvoří síť projektu a pojmenované svazky a spustí služby v pořadí podle depends_on. Služby se navzájem najdou podle názvu služby díky aliasům DNS v síti.

    Sítě a porty
  • -p 8080:80 publikuje port na localhost, stejně jako v Dockeru.
  • Každý kontejner má také vlastní IP adresu. Vytvořte místní doménu DNS příkazem sudo container system dns create test a spouštějte kontejnery s --dns-domain test: dostanou názvy jako web.test.
  • container network create vytváří uživatelské sítě; kontejnery ve stejné síti na sebe vidí.
  • Režim --network host, none ani container: neexistuje.
    Co chybí
  • Žádné Docker Engine API. Nástroje, které komunikují s /var/run/docker.sock, například Testcontainers, Docker SDK nebo Dev Containers, apple/container nevidí.
  • Žádné zásady restartu. --restart není k dispozici; kontejner se sám znovu nespustí.
  • Žádný Compose v CLI. Soubory Compose spouští Gantry: viz Soubory Compose.
  • Žádná rozšíření Docker Desktop.
  • Jen celá CPU: --cpus 0.5 nefunguje.
  • Kubernetes funguje jinak: použijte container cluster, viz Kubernetes na Macu.
    Během přechodu mějte obojí

Gantry spravuje apple/container i libovolný engine Docker (Docker Desktop, OrbStack, Colima nebo Docker přes SSH) v jednom postranním panelu. Přenášejte jeden projekt po druhém a Docker si nechte pro nástroje, které potřebují jeho API. Až ho přestanete potřebovat, můžete Docker Desktop odinstalovat.

Otázky a odpovědi

Může Apple container nahradit Docker Desktop?

Pro spouštění, sestavování a stahování kontejnerů na Apple silicon ano. Nemá Docker Engine API, zásady restartu, rozšíření ani příkaz compose. Gantry přidává soubory Compose a GUI.

Fungují image Dockeru s Apple container?

Ano. apple/container používá standardní image OCI a stahuje ze stejných registrů. Image arm64 běží nativně; image amd64 běží přes Rosetta s --arch amd64.

Funguje docker compose s Apple container?

Z CLI ne: container compose neexistuje. Gantry přečte docker-compose.yml a spustí služby na apple/container za vás.

Mohu používat Docker Desktop a Apple container současně?

Ano. Nesdílejí image ani svazky, ale mohou běžet vedle sebe. Gantry ukazuje oba v jednom okně.

Je Apple container zdarma pro komerční použití?

Ano. apple/container je open source pod licencí Apache 2.0 a Gantry je pod licencí MIT. Obojí je zdarma pro firmy jakékoli velikosti.

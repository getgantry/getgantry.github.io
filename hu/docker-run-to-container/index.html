Gantry/docker run parancsból

Konténer létrehozása docker run parancsból

A legtöbb README egy docker run sort ad meg. A Gantry beolvassa ezt a sort, és kitölti az Új konténer űrlapot, akár Docker-gazdagéphez, akár az Apple container eszközéhez. Ez az útmutató megmutatja, hogyan, és azt is, hogyan alakíthatja át a parancsot kézzel.

Röviden. A Gantryben nyissa meg az Új konténer lapot, válassza a Parancs beillesztése… lehetőséget, illessze be a docker run sort, és kattintson az Űrlap kitöltése gombra. A Gantry indoklással felsorolja azokat a kapcsolókat, amelyeket nem tud használni. A CLI-ben a legtöbb kapcsoló ugyanaz: cserélje a docker run parancsot container run-ra, és törölje a --restart kapcsolót.

A parancs beillesztése a Gantrybe

  1. Jelöljön ki egy gazdagépet: Docker-gazdagépet vagy apple/container-gazdagépet.
  2. Nyissa meg a Konténerek nézetet, és kattintson az Új konténer gombra.
  3. Kattintson a Parancs beillesztése… gombra, és illessze be a sort. A \ sorvégek, az idézőjelek, a $ prompt és a sudo sem okoz gondot.
  4. Olvassa el az előnézetet: az image, a Gantry által nem használható kapcsolók, a megjegyzések és az erre a gazdagépre vonatkozó figyelmeztetések.
  5. Kattintson az Űrlap kitöltése gombra, ellenőrizze az értékeket, és hozza létre a konténert.

A Gantry beolvassa a docker run, a docker container run, a docker create, a podman run és a container run parancsot. Az &&, ||, ; vagy | utáni szöveget megjegyzéssel figyelmen kívül hagyja.

További mintegy 80 Docker-kapcsolót ismer a Gantry: helyesen átugorja az értékeiket, és nem használtként listázza őket, így semmi sem vész el megjegyzés nélkül.

Figyelmeztetések apple/container-gazdagépekhez

Néhány Docker-beállítás nem létezik az apple/containerben. A Gantry figyelmeztet rájuk, és kihagyja őket a létrehozási kérésből:

  • újraindítási szabályok (--restart);
  • CPU-törtek, például --cpus 0.5;
  • a host, none és container: hálózati módok;
  • gazdagépport nélküli portok, például -p 80.

Docker-gazdagépen a Gantry az apple/container-beállításokra figyelmeztet: a DNS-tartományra és a kernelbeállításokra.

A docker run átalakítása container run paranccsá kézzel

A CLI-ben a legtöbb kapcsoló ugyanaz marad. Egy Redis-példa:

Terminál
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

ebből lesz:

Terminál
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Először hozza létre a nevesített kötetet a container volume create paranccsal. Törölje a --restart kapcsolót, és kerekítse a --cpus értékét egész számra. A --platform ugyanúgy működik, mint a Dockerben.

Konténer másolása parancsként

Visszafelé is működik. Kattintson jobb gombbal egy konténerre, vagy használja a Továbbiak menüt, és válassza a Másolás parancsként parancsot: a Gantry egy docker run vagy container run sort ír. Kihagyja az image alapértékeit, például a környezetét és a parancsát, így a sor rövid marad. Leállított konténereknél is működik.

Mentés receptként

Az Új konténer lapon nyissa meg a Receptek menüt, és válassza a Mentés receptként… lehetőséget. Legközelebb a Kitöltés receptből bármely gazdagépen ugyanazt az űrlapot adja. A receptek a ~/Library/Application Support/Gantry/recipes.json fájlban vannak, így biztonsági másolatot készíthet róluk, vagy megoszthatja őket.

Korlátok

  • A Gantry megtartja a --env-file útvonalát, de nem olvassa be a fájlt, és érték nélküli -e KEY esetén nem olvassa ki a shellből az értéket.
  • A --mount tmpfs-csatolásai és névtelen kötetei nem támogatottként jelennek meg.
  • Ugyanarra a konténerportra mutató két port (-p 8080:80 -p 8081:80) kitölti az űrlapot, de az űrlap ezután elutasítja az ismétlődést.

Kérdések és válaszok

Hogyan alakítható át a docker run container run paranccsá?

Cserélje a docker run parancsot container run-ra. A -d, -p, -e, -v, --name, --rm, -it, -w és --entrypoint ugyanaz marad. Törölje a --restart kapcsolót, és egész CPU-kat használjon. Vagy illessze be a sort a Gantrybe, és az kitölti az űrlapot.

Importálhat a Gantry egy docker run parancsot?

Igen. Az Új konténer lapon a Parancs beillesztése… beolvassa a docker run, a docker create, a podman run és a container run parancsot, és kitölti az űrlapot.

Mi történik a Gantry által nem támogatott kapcsolókkal?

Az előnézet indoklással felsorolja őket, és az űrlapon A beillesztett parancsból szakaszban is megmaradnak, így később ellenőrizheti őket.

Visszaalakítható egy futó konténer docker run paranccsá?

Igen. A konténer menüjében a Másolás parancsként egy docker run vagy container run sort ír az adott konténerhez.

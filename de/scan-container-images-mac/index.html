Gantry/Images prüfen

Container-Images auf dem Mac auf Schwachstellen prüfen

Trivy und Grype sind kostenlose Open-Source-Scanner, die die Pakete in einem Image mit Datenbanken bekannter Schwachstellen abgleichen. Docker-Images lesen sie direkt. Apples container-Tool hat keinen Scan-Befehl und keinen Docker-Socket, deshalb sicherst du das Image zuerst. Diese Anleitung zeigt beide Wege, wie du die Befunde liest, wie du ein SBOM schreibst und wie du aus Gantry heraus scannst.

Kurz gesagt. Führe brew install trivy grype aus. Auf Docker führst du trivy image app:dev aus. Auf Apple container sicherst du das Image mit container image save --platform linux/arm64 -o app.tar app:dev, entpackst es mit tar -xf app.tar -C app-img und scannst den Ordner: trivy image --input app-img oder grype oci-dir:app-img. Die tar-Datei selbst lehnen beide Tools ab.

Scanner installieren

Installiere einen Scanner oder beide mit Homebrew. Jeder lädt beim ersten Scan seine Schwachstellendatenbank herunter, was etwa eine Minute dauert.

Terminal
brew install trivy grype

Wir haben die Befehle dieser Anleitung mit Trivy 0.76.2, Grype 0.121.3 und container 1.7.1 geprüft. Gantry braucht Trivy 0.50.0 oder Grype 0.74.0 oder neuer.

Ein Docker-Image scannen

Mit einer Docker-Engine (Docker Desktop, OrbStack oder Colima) lesen beide Tools ein lokales Image über den Docker-Socket anhand seines Namens:

Terminal
trivy image app:dev
grype app:dev

Ein Apple-container-Image scannen

Sichere das Image in ein OCI-Archiv und entpacke es in einen Ordner. Gib --platform an: Wenn der Image-Speicher nur einige Plattformen eines Images enthält, schlägt container image save ohne diese Option fehl.

Terminal
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Scanne dann den Ordner. Trivy liest ihn mit --input, Grype mit dem Präfix oci-dir::

Terminal
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Achtung
Übergib nicht die .tar-Datei. Das Archiv von container image save beginnt mit dem Eintrag ./: Trivy meldet „file manifest.json not found in tar“, und Grype lehnt es als „potential path traversal attack“ ab. Der entpackte Ordner funktioniert mit beiden.

Ergebnisse lesen

  • Schweregrad: Kritisch, Hoch, Mittel, Niedrig oder Unbekannt. Fang mit Kritisch und Hoch an. --severity HIGH,CRITICAL begrenzt die Ausgabe von Trivy.
  • Installierte und behobene Version: Gibt es eine behobene Version, aktualisiere das Basis-Image oder das Paket und baue neu. trivy --ignore-unfixed und grype --only-fixed blenden Befunde ohne Fix aus.
  • „won't fix“: Die Distribution hat entschieden, das Paket in diesem Release nicht zu beheben. Verwende ein neueres Basis-Image oder nimm das Risiko in Kauf.
  • Zwei Tools, zwei Datenbanken: Trivy und Grype melden oft unterschiedliche Zahlen. Keines liegt falsch; sie nutzen unterschiedliche Quellen.

SBOM exportieren

Eine Software-Stückliste (SBOM) listet jedes Paket im Image auf. Trivy schreibt CycloneDX und SPDX; Syft, das Begleittool von Grype, schreibt ebenfalls beide.

Terminal
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Build bei hohen Befunden scheitern lassen

Lass in einem Skript den Scanner den Exit-Code setzen. Grype beendet sich mit einem Code ungleich null, wenn ein Befund des angegebenen oder eines höheren Schweregrads existiert; bei Trivy verwendest du --exit-code 1 --severity HIGH,CRITICAL.

Terminal
grype oci-dir:python-img --fail-on high
echo $?

Aus Gantry scannen

Gantry 0.29.0 erledigt diese Schritte für dich. Wähle Auf Schwachstellen prüfen… im Image-Menü oder in der Symbolleiste der Image-Details.

  • Gantry findet Trivy oder Grype über GANTRY_TRIVY oder GANTRY_GRYPE, in PATH oder in /opt/homebrew/bin und /usr/local/bin. Sind beide installiert, ist Trivy der Standard. Ohne Scanner zeigt das Fenster die Homebrew-Befehle.
  • Auf apple/container sichert Gantry das Image mit --platform, entpackt es und scannt den Ordner. Auf lokalem Docker scannt es ein gesichertes Archiv. Bei Docker über SSH scannt es die Registry-Kopie des Tags.
  • Die Befunde sind nach Schweregrad gruppiert, mit Symbol und Wort, nicht nur mit einer Farbe. Jede Zeile hat die ID mit Link, das Paket, die installierte und die behobene Version. Ein Filter findet ein Paket oder eine ID.
  • SBOM exportieren schreibt CycloneDX (beide Tools) oder SPDX (Trivy).
  • Stoppen oder das Schließen des Fensters beendet den Scanner und entfernt die temporären Dateien.

Fragen und Antworten

Wie prüfe ich ein Apple-container-Image auf Schwachstellen?

Sichere es mit container image save --platform linux/arm64 -o app.tar app:dev, entpacke es mit tar -xf app.tar -C app-img und führe dann trivy image --input app-img oder grype oci-dir:app-img aus. Gantry erledigt diese Schritte mit Auf Schwachstellen prüfen….

Warum scheitern Trivy und Grype am Archiv von container image save?

Das Archiv beginnt mit dem Eintrag ./. Trivy findet darin weder manifest.json noch index.json, und Grype behandelt den Eintrag als Path Traversal. Entpacke das Archiv und scanne den Ordner.

Trivy oder Grype: Welches sollte ich verwenden?

Beide sind kostenlos und Open Source. Trivy findet zusätzlich Secrets und Fehlkonfigurationen und schreibt SPDX; Grype ist schlank und auf Pakete konzentriert. Sie nutzen unterschiedliche Datenbanken, daher findest du mit beiden mehr. Sind beide installiert, verwendet Gantry Trivy.

Installiert Gantry die Scanner?

Nein. Installiere sie mit brew install trivy grype. Gantry sucht in PATH, /opt/homebrew/bin und /usr/local/bin oder über GANTRY_TRIVY und GANTRY_GRYPE.

Brauche ich Docker Scout oder ein Docker-Konto, um Images zu prüfen?

Nein. Trivy und Grype funktionieren ohne Konto, mit Docker-Images und mit Apple-container-Images.

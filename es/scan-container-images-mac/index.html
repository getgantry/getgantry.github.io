Gantry/Analizar imágenes

Analizar imágenes de contenedores en busca de vulnerabilidades en un Mac

Trivy y Grype son analizadores gratuitos y de código abierto que comparan los paquetes de una imagen con bases de datos de vulnerabilidades conocidas. Leen las imágenes de Docker directamente. La herramienta container de Apple no tiene comando de análisis ni socket de Docker, así que primero guardas la imagen. Esta guía muestra las dos vías, cómo leer los hallazgos, cómo escribir un SBOM y cómo analizar desde Gantry.

En resumen. Ejecuta brew install trivy grype. En Docker, ejecuta trivy image app:dev. En Apple container, guarda la imagen con container image save --platform linux/arm64 -o app.tar app:dev, desempaquétala con tar -xf app.tar -C app-img y analiza la carpeta: trivy image --input app-img o grype oci-dir:app-img. Las dos herramientas rechazan el propio archivo tar.

Instalar un analizador

Instala uno de los analizadores o los dos con Homebrew. Cada uno descarga su base de datos de vulnerabilidades en el primer análisis, lo que tarda un minuto.

Terminal
brew install trivy grype

Hemos comprobado los comandos de esta guía con Trivy 0.76.2, Grype 0.121.3 y container 1.7.1. Gantry necesita Trivy 0.50.0 o Grype 0.74.0 o posterior.

Analizar una imagen de Docker

Con un motor Docker (Docker Desktop, OrbStack o Colima), las dos herramientas leen una imagen local por su nombre a través del socket de Docker:

Terminal
trivy image app:dev
grype app:dev

Analizar una imagen de Apple container

Guarda la imagen en un archivo OCI y desempaquétala en una carpeta. Pasa --platform: cuando el almacén de imágenes solo tiene algunas plataformas de una imagen, container image save falla sin él.

Terminal
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Después analiza la carpeta. Trivy la lee con --input, y Grype con el prefijo oci-dir::

Terminal
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Atención
No pases el archivo .tar. El archivo de container image save empieza con la entrada ./: Trivy informa “file manifest.json not found in tar” y Grype lo rechaza como “potential path traversal attack”. La carpeta desempaquetada funciona con las dos.

Leer los resultados

  • Gravedad: Crítica, Alta, Media, Baja o Desconocida. Empieza por Crítica y Alta. --severity HIGH,CRITICAL limita la salida de Trivy.
  • Versión instalada y versión corregida: si existe una versión corregida, actualiza la imagen base o el paquete y vuelve a compilar. trivy --ignore-unfixed y grype --only-fixed ocultan los hallazgos sin corrección.
  • “won't fix”: la distribución ha decidido no corregir el paquete en esta versión. Usa una imagen base más reciente o acepta el riesgo.
  • Dos herramientas, dos bases de datos: Trivy y Grype suelen dar recuentos distintos. Ninguna se equivoca; usan fuentes diferentes.

Exportar un SBOM

Una lista de materiales de software (SBOM) enumera todos los paquetes de la imagen. Trivy escribe CycloneDX y SPDX; Syft, la herramienta complementaria de Grype, también escribe los dos.

Terminal
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Hacer fallar una compilación ante hallazgos altos

En un script, deja que el analizador fije el código de salida. Grype sale con un código distinto de cero cuando hay un hallazgo de la gravedad indicada o superior; con Trivy, usa --exit-code 1 --severity HIGH,CRITICAL.

Terminal
grype oci-dir:python-img --fail-on high
echo $?

Analizar desde Gantry

Gantry 0.29.0 hace estos pasos por ti. Elige Analizar vulnerabilidades… en el menú de la imagen o en la barra de herramientas del detalle de la imagen.

  • Gantry busca Trivy o Grype en GANTRY_TRIVY o GANTRY_GRYPE, en PATH o en /opt/homebrew/bin y /usr/local/bin. Si están instalados los dos, usa Trivy por omisión. Sin analizador, la hoja muestra los comandos de Homebrew.
  • En apple/container, Gantry guarda la imagen con --platform, la desempaqueta y analiza la carpeta. En Docker local, analiza un archivo guardado. En Docker por SSH, analiza la copia del tag en el registro.
  • Los hallazgos se agrupan por gravedad, con un símbolo y una palabra, no solo con un color. Cada fila tiene el ID con un enlace, el paquete, la versión instalada y la versión corregida. Un filtro encuentra un paquete o un ID.
  • Exportar SBOM escribe CycloneDX (las dos herramientas) o SPDX (Trivy).
  • Detener o cerrar la hoja detiene el analizador y elimina los archivos temporales.

Preguntas y respuestas

¿Cómo analizo una imagen de Apple container en busca de vulnerabilidades?

Guárdala con container image save --platform linux/arm64 -o app.tar app:dev, desempaquétala con tar -xf app.tar -C app-img y después ejecuta trivy image --input app-img o grype oci-dir:app-img. Gantry hace estos pasos con Analizar vulnerabilidades….

¿Por qué fallan Trivy o Grype con el archivo de container image save?

El archivo empieza con la entrada ./. Trivy no encuentra en él manifest.json ni index.json, y Grype trata la entrada como un salto de directorio (path traversal). Desempaqueta el archivo y analiza la carpeta.

Trivy o Grype: ¿cuál debo usar?

Los dos son gratuitos y de código abierto. Trivy también encuentra secretos y configuraciones incorrectas y escribe SPDX; Grype es pequeño y se centra en los paquetes. Usan bases de datos distintas, así que ejecutar los dos encuentra más. Gantry usa Trivy cuando están instalados los dos.

¿Gantry instala los analizadores?

No. Instálalos con brew install trivy grype. Gantry busca en PATH, /opt/homebrew/bin y /usr/local/bin, o en GANTRY_TRIVY y GANTRY_GRYPE.

¿Necesito Docker Scout o una cuenta de Docker para analizar imágenes?

No. Trivy y Grype funcionan sin cuenta, con imágenes de Docker y con imágenes de Apple container.

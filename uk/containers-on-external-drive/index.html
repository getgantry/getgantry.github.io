Gantry/Зовнішній диск

Контейнери й томи на зовнішньому диску

Образи, контейнери й томи швидко заповнюють невеликий внутрішній диск. З інструментом container від Apple ці дані можна зберігати на зовнішньому SSD: окремі папки — через bind-монтування, або весь корінь даних повністю. Цей посібник показує обидва способи й пояснює, як від’єднати диск без пошкоджень.

Коротко. Відформатуйте диск в APFS. Для одного проєкту змонтуйте папку: -v /Volumes/Fast/pg:/data. Для всього одразу зупиніть служби, скопіюйте ~/Library/Application Support/com.apple.container на диск командою cp -Rp і щоразу запускайте служби командою container system start --app-root /Volumes/Fast/container.

Де дані зараз

apple/container зберігає всі дані в одній папці — корені програми (app root). Типово це ~/Library/Application Support/com.apple.container, з папками для контейнерів, вмісту образів, знімків, томів, ядер і мереж. Перевірте шлях і зайняте місце:

Термінал
container system status | grep appRoot
container system df

Вибір і форматування диска

  • Використовуйте SSD з USB-C або Thunderbolt. Жорсткий диск теж підійде, але контейнери запускатимуться повільніше.
  • Відформатуйте його в APFS (Mac OS Extended теж підійде). Не використовуйте exFAT, FAT чи NTFS: томи — це розріджені образи дисків, а в цих файлових системах немає розріджених файлів і прав доступу Unix.
  • Не використовуйте мережевий диск для кореня програми.
  • Дайте диску коротку назву без пробілів, наприклад Fast. Тоді шлях буде /Volumes/Fast.
    Спосіб 1: дані проєкту на диску через bind-монтування

Bind-монтування відкриває контейнеру папку вашого Mac, і ця папка може бути на будь-якому диску. Так найпростіше тримати великі дані, наприклад базу даних чи файли моделей, поза внутрішнім диском:

Термінал
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Диск має бути під’єднано до запуску контейнера. Образи й сам контейнер лишаються на внутрішньому диску.

    Спосіб 2: усі дані apple/container на диску

Так переносяться образи, контейнери, знімки й томи. Спочатку зупиніть служби, щоб під час копіювання жоден файл не змінювався:

Термінал
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Використовуйте cp -Rp. У нашій перевірці на macOS 27 (з APFS на APFS через USB) ця команда зберегла розрідженість образів томів і розширені атрибути. ditto записав кожен розріджений образ у повному розмірі, а це може заповнити диск. Не видаляйте стару папку, доки не переконаєтеся, що ваші контейнери, образи й томи видно в списках.

Увага
CLI не запам’ятовує --app-root. Кожен container system start без цього прапорця знову використовує внутрішню папку. Указуйте прапорець щоразу, наприклад в аліасі оболонки, і перевіряйте paths.appRoot у container system status.

Gantry 0.27.0 запускає служби без --app-root, коли під’єднується до хоста із зупиненими службами. Спочатку запустіть служби з цим прапорцем із термінала; тоді Gantry використовуватиме вже запущені служби.

    Архів образів на диску

Щоб звільнити місце й не втратити образ, збережіть його на зовнішній диск і вилучіть. Коли образ знадобиться, завантажте його знову:

Термінал
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Безпечне від’єднання диска
  1. Зупиніть контейнери, які використовують диск: container stop <name>.
  2. Якщо корінь програми на цьому диску, зупиніть служби: container system stop.
  3. Вийміть диск у Finder, потім від’єднайте його.

Якщо диск зникне, поки з нього працюють контейнери, вони зазнають збою, а незавершені записи можуть утратитися. Коли знову під’єднаєте диск, запустіть служби з --app-root, потім запустіть контейнери.

    Зовнішні диски в Gantry

Gantry вже зараз запускає bind-монтування з будь-якого диска: у Новий контейнер додайте том, виберіть папку на зовнішньому диску й шлях у контейнері.

    Docker Desktop і OrbStack

Docker Desktop переносить свій образ диска в Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack додав параметр розташування даних у версії 0.13.0. Див. порівняння.

Запитання й відповіді

Чи можна зберігати образи Apple container на зовнішньому диску?

Так. Запустіть служби командою container system start --app-root /Volumes/Disk/container. Тоді всі образи, контейнери, знімки й томи зберігатимуться в цій папці.

Яку файлову систему вибрати для зовнішнього диска?

APFS. Томи — це розріджені образи дисків, а контейнерам потрібні права доступу Unix, яких немає в exFAT, FAT і NTFS.

Як скопіювати дані контейнерів і не заповнити диск?

Використовуйте cp -Rp: у нашій перевірці ця команда зберегла розріджені образи томів малими. ditto скопіював кожен розріджений образ у повному розмірі.

Що станеться, якщо від’єднати диск під час роботи контейнерів?

Контейнери, які використовують диск, зазнають збою, а ще не записані дані можуть утратитися. Перед вийманням диска зупиніть контейнери та, якщо на диску корінь програми, служби.

Чи запам’ятовує CLI container нове розташування?

Ні. Передавайте --app-root під час кожного container system start. container system status показує поточний корінь як paths.appRoot.

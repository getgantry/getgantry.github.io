Gantry/Ekstern disk

Lagre containere og volumer på en ekstern disk

Images, containere og volumer fyller fort en liten intern disk. Med Apples verktøy container kan du ha disse dataene på en ekstern SSD: legg enkeltmapper der med bind-monteringer, eller flytt hele datarotmappen. Denne guiden viser begge deler, og hvordan du kobler fra disken uten skade.

Kort fortalt. Formater disken som APFS. For ett prosjekt bind-monterer du en mappe: -v /Volumes/Fast/pg:/data. For alt sammen stopper du tjenestene, kopierer ~/Library/Application Support/com.apple.container til disken med cp -Rp og starter tjenestene med container system start --app-root /Volumes/Fast/container hver gang.

Hvor dataene ligger nå

apple/container har alle dataene sine i én mappe, app-roten. Som standard er det ~/Library/Application Support/com.apple.container, med mapper for containere, image-innhold, øyeblikksbilder, volumer, kjerner og nettverk. Sjekk stien og plassen som er i bruk:

Terminal
container system status | grep appRoot
container system df

Velg og formater disken

  • Bruk en SSD på USB-C eller Thunderbolt. En harddisk med roterende plater fungerer, men containere starter tregere.
  • Formater den som APFS (Mac OS Extended fungerer også). Ikke bruk exFAT, FAT eller NTFS: volumer er glisne diskbilder, og disse filsystemene har verken glisne filer eller Unix-tillatelser.
  • Ikke bruk en nettverksdisk til app-roten.
  • Gi disken et kort navn uten mellomrom, for eksempel Fast. Stien blir da /Volumes/Fast.

Alternativ 1: ha prosjektdata på disken med bind-monteringer

En bind-montering deler en mappe på Macen med containeren, og mappen kan ligge på hvilken som helst disk. Dette er den enkle måten å holde store data, som en database eller modellfiler, unna den interne disken:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Disken må være tilkoblet før containeren starter. Images og selve containeren blir værende på den interne disken.

Alternativ 2: flytt alle apple/container-data til disken

Dette flytter images, containere, øyeblikksbilder og volumer. Stopp tjenestene først, så ingen filer endres under kopieringen:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Bruk cp -Rp. I testen vår på macOS 27 (APFS til APFS over USB) beholdt den volumbildene glisne og beholdt de utvidede attributtene. ditto skrev hvert glisne bilde i full størrelse, noe som kan fylle disken. Behold den gamle mappen til du har sjekket at containerne, imagene og volumene dine vises i listene.

Merk
CLI-en husker ikke --app-root. Hver container system start uten flagget bruker den interne mappen igjen. Bruk flagget hver gang, for eksempel i et skallalias, og sjekk paths.appRoot i container system status.

Gantry 0.27.0 starter tjenestene uten --app-root når den kobler til en vert der tjenestene er stoppet. Start tjenestene fra terminalen med flagget først; Gantry bruker da tjenestene som kjører. Støtte i Gantry for en flyttet datarotmappe er under utvikling.

Arkiver images på disken

Vil du frigjøre plass uten å miste et image, lagrer du det på den eksterne disken og sletter det. Last det inn igjen når du trenger det:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Koble fra disken trygt

  1. Stopp containerne som bruker disken: container stop <name>.
  2. Ligger app-roten på disken, stopper du tjenestene: container system stop.
  3. Løs ut disken i Finder, og koble den deretter fra.

Forsvinner disken mens containere kjører fra den, feiler de, og skriving som pågår, kan gå tapt. Når du har koblet til disken igjen, starter du tjenestene med --app-root og deretter containerne.

Eksterne disker i Gantry

Gantry kjører allerede bind-monteringer fra hvilken som helst disk: i Ny container legger du til et volum og velger en mappe på den eksterne disken og en sti i containeren. Støtte i Gantry for å flytte datarotmappen, volumer på en ekstern disk og en advarsel når disken ikke er tilkoblet, er under utvikling.

Docker Desktop og OrbStack

Docker Desktop flytter diskbildet sitt under Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack la til en innstilling for dataplassering i versjon 0.13.0. Se sammenligningen.

Spørsmål og svar

Kan jeg lagre images fra Apple container på en ekstern disk?

Ja. Start tjenestene med container system start --app-root /Volumes/Disk/container. Alle images, containere, øyeblikksbilder og volumer ligger da i den mappen.

Hvilket filsystem bør den eksterne disken ha?

APFS. Volumer er glisne diskbilder, og containere trenger Unix-tillatelser, noe exFAT, FAT og NTFS ikke har.

Hvordan kopierer jeg containerdataene uten å fylle disken?

Bruk cp -Rp, som holdt de glisne volumbildene små i testen vår. ditto kopierte hvert glisne bilde i full størrelse.

Hva skjer hvis jeg kobler fra disken mens containere kjører?

Containerne som bruker disken, feiler, og data som ennå ikke er skrevet, kan gå tapt. Stopp containerne og, hvis app-roten ligger på disken, tjenestene før du løser den ut.

Husker container-CLI-en den nye plasseringen?

Nei. Gi --app-root til hver container system start. container system status viser rotmappen som er i bruk, som paths.appRoot.

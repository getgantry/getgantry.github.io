Gantry/Von Docker Desktop

Von Docker Desktop zu Apple container wechseln

Apples container-Tool führt dieselben OCI-Images aus wie Docker, deshalb zieht der Großteil deiner Arbeit mit ein paar geänderten Befehlen um. Diese Anleitung ordnet Docker-Befehle container zu, zieht Images und Volumes um und listet die Lücken, die du vor dem Wechsel kennen solltest.

Kurz gesagt. Installiere das signierte container-Paket, ersetze docker durch container für run, build, logs, exec und images, kopiere benannte Volumes über eine tar-Datei und öffne deine docker-compose.yml in Gantry, denn die CLI hat kein compose. Docker Desktop kann installiert bleiben, während du es ausprobierst.

Was sich ändert

  • Eine VM pro Container. Docker Desktop führt alle Container in einer Linux-VM aus. apple/container startet für jeden Container eine kleine VM, daher bekommt jeder eine eigene IP-Adresse auf deinem Mac.
  • Dieselben Images und Registrys. Images sind OCI-Images; du pullst wie bisher von Docker Hub, GHCR und privaten Registrys.
  • Keine Lizenzgebühr. apple/container steht unter Apache 2.0. Docker Desktop braucht einen kostenpflichtigen Plan in Organisationen mit 250 oder mehr Beschäftigten oder 10 Mio. US-Dollar Umsatz oder mehr.
  • Nur Apple Silicon und macOS 26. Auf Intel-Macs bleibst du bei einer Docker-Engine.

Die meisten Flags von run sind gleich: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus und -m. Um einen langen Befehl umzuwandeln, setze ihn in Gantry ein: siehe Container aus einem docker run-Befehl erstellen.

    Deine Images mitnehmen

Images aus einer Registry: Pulle sie erneut mit container image pull. Lokale Images, die es nur in Docker gibt: Speichere sie in ein Archiv und lade es. container image load liest OCI-Archive, und aktuelle Docker-Versionen schreiben mit docker save ein OCI-Layout. Schlägt das Laden fehl, pushe das Image in eine Registry und pulle es.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Benannte Volumes umziehen

Docker speichert Volume-Daten in seiner VM. Kopiere jedes Volume mit einem kurzlebigen Container in eine tar-Datei und entpacke sie dann in ein neues apple/container-Volume:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Ein benanntes Volume ist in apple/container ein dünn belegtes ext4-Disk-Image, standardmäßig höchstens 512 GB groß. Eine andere Größe legst du mit --opt size=20g fest. Bind-Mounts von Ordnern auf deinem Mac funktionieren wie in Docker: -v ~/project:/app.

    Compose-Dateien

Die container-CLI hat keinen compose-Befehl. Öffne die docker-compose.yml stattdessen in Gantry (Finder, Ablage ▸ Compose-Datei öffnen… oder per Drag-and-drop). Gantry baut die build:-Dienste, erstellt das Projektnetzwerk und die benannten Volumes und startet die Dienste in der Reihenfolge von depends_on. Dienste erreichen sich über ihren Dienstnamen per Netzwerk-DNS-Aliasse.

    Netzwerke und Ports
  • -p 8080:80 veröffentlicht einen Port auf localhost, wie in Docker.
  • Jeder Container hat außerdem eine eigene IP-Adresse. Erstelle eine lokale DNS-Domain mit sudo container system dns create test und starte Container mit --dns-domain test: Sie bekommen Namen wie web.test.
  • container network create erstellt Benutzernetzwerke; Container im selben Netzwerk erreichen sich gegenseitig.
  • Es gibt keinen Modus --network host, none oder container:.
    Was fehlt
  • Keine Docker-Engine-API. Werkzeuge, die mit /var/run/docker.sock sprechen, etwa Testcontainers, die Docker-SDKs oder Dev Containers, sehen apple/container nicht.
  • Keine Neustartrichtlinien. --restart ist nicht verfügbar; ein Container startet nicht von selbst neu.
  • Kein Compose in der CLI. Gantry führt Compose-Dateien aus: siehe Compose-Dateien.
  • Keine Erweiterungen von Docker Desktop.
  • Nur ganze CPUs: --cpus 0.5 funktioniert nicht.
  • Kubernetes ist anders: Verwende container cluster, siehe Kubernetes auf dem Mac ausführen.
    Beides behalten, während du wechselst

Gantry verwaltet apple/container und jede Docker-Engine (Docker Desktop, OrbStack, Colima oder Docker über SSH) in einer Seitenleiste. Ziehe ein Projekt nach dem anderen um und behalte Docker für die Werkzeuge, die seine API brauchen. Wenn du es nicht mehr brauchst, kannst du Docker Desktop entfernen.

Fragen und Antworten

Kann Apple container Docker Desktop ersetzen?

Zum Ausführen, Bauen und Pullen von Containern auf Apple Silicon: ja. Es fehlen die Docker-Engine-API, Neustartrichtlinien, Erweiterungen und ein compose-Befehl. Gantry ergänzt Compose-Dateien und eine GUI.

Funktionieren Docker-Images mit Apple container?

Ja. apple/container verwendet Standard-OCI-Images und pullt aus denselben Registrys. arm64-Images laufen nativ; amd64-Images laufen mit --arch amd64 über Rosetta.

Funktioniert docker compose mit Apple container?

Nicht über die CLI: Es gibt kein container compose. Gantry liest die docker-compose.yml und führt die Dienste für dich auf apple/container aus.

Kann ich Docker Desktop und Apple container gleichzeitig verwenden?

Ja. Sie teilen keine Images oder Volumes, können aber nebeneinander laufen. Gantry zeigt beide in einem Fenster.

Ist Apple container für kommerzielle Nutzung kostenlos?

Ja. apple/container ist Open Source unter der Apache-2.0-Lizenz, und Gantry steht unter der MIT-Lizenz. Beide sind für Unternehmen jeder Größe kostenlos.

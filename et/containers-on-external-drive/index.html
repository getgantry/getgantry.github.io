Gantry/Väline ketas

Konteinerid ja köited välisel kettal

Tõmmised, konteinerid ja köited täidavad väikese sisemise ketta kiiresti. Apple'i container-tööriistaga saate neid andmeid hoida välisel SSD-l: pange üksikud kaustad sinna bind mount'idega või teisaldage kogu andmete juurkaust. See juhend näitab mõlemat ja seda, kuidas ketas kahjustusteta lahti ühendada.

Lühidalt. Vormindage ketas APFS-iks. Ühe projekti jaoks haakige kaust bind mount'ina: -v /Volumes/Fast/pg:/data. Kõige jaoks peatage teenused, kopeerige ~/Library/Application Support/com.apple.container käsuga cp -Rp kettale ja käivitage teenused iga kord käsuga container system start --app-root /Volumes/Fast/container.

Kus andmed praegu on

apple/container hoiab kõiki oma andmeid ühes kaustas, rakenduse juurkaustas (app root). Vaikimisi on see ~/Library/Application Support/com.apple.container, milles on kaustad konteinerite, tõmmiste sisu, hetktõmmiste, köidete, tuumade ja võrkude jaoks. Kontrollige teed ja kasutatud ruumi:

Terminal
container system status | grep appRoot
container system df

Ketta valimine ja vormindamine

  • Kasutage USB-C või Thunderbolti SSD-d. Pöörlev ketas töötab, kuid konteinerid käivituvad aeglasemalt.
  • Vormindage see APFS-iks (Mac OS Extended töötab samuti). Ärge kasutage exFAT-i, FAT-i ega NTFS-i: köited on hõredad kettatõmmised ning neil failisüsteemidel pole hõredaid faile ega Unixi õigusi.
  • Ärge kasutage rakenduse juurkausta jaoks võrguketast.
  • Andke kettale lühike nimi ilma tühikuteta, näiteks Fast. Siis on tee /Volumes/Fast.

Variant 1: hoidke projekti andmeid kettal bind mount'idega

Bind mount jagab teie Maci kausta konteineriga ja see kaust võib olla mis tahes kettal. Nii on lihtne hoida suuri andmeid, näiteks andmebaasi või mudelifaile, sisemiselt kettalt eemal:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Ketas peab olema ühendatud enne konteineri käivitumist. Tõmmised ja konteiner ise jäävad sisemisele kettale.

Variant 2: teisaldage kõik apple/containeri andmed kettale

See teisaldab tõmmised, konteinerid, hetktõmmised ja köited. Peatage kõigepealt teenused, et kopeerimise ajal ükski fail ei muutuks:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Kasutage käsku cp -Rp. Meie testis macOS 27-s (APFS-ilt APFS-ile USB kaudu) jättis see köidete tõmmised hõredaks ja säilitas laiendatud atribuudid. ditto kirjutas iga hõreda tõmmise täies suuruses, mis võib ketta täita. Hoidke vana kaust alles, kuni olete kontrollinud, et teie konteinerid, tõmmised ja köited on loendis.

Tähelepanu
CLI ei jäta lippu --app-root meelde. Iga container system start ilma selleta kasutab jälle sisemist kausta. Kasutage lippu iga kord, näiteks shelli aliases, ja kontrollige väärtust paths.appRoot käsu container system status väljundis.

Gantry 0.27.0 käivitab teenused ilma liputa --app-root, kui see ühendub hostiga, mille teenused on peatatud. Käivitage teenused kõigepealt terminalist koos lipuga; siis kasutab Gantry töötavaid teenuseid. Teisaldatud andmete juurkausta tugi Gantrys on arenduses.

Tõmmiste arhiveerimine kettale

Ruumi vabastamiseks tõmmist kaotamata salvestage see välisele kettale ja kustutage. Kui seda vajate, laadige see uuesti:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Ketta ohutu lahtiühendamine

  1. Peatage konteinerid, mis ketast kasutavad: container stop <name>.
  2. Kui rakenduse juurkaust on kettal, peatage teenused: container system stop.
  3. Väljutage ketas Finderis ja ühendage see seejärel lahti.

Kui ketas kaob ajal, mil sellelt töötavad konteinerid, siis need nurjuvad ja pooleli olevad kirjutused võivad kaduda. Kui olete ketta uuesti ühendanud, käivitage teenused lipuga --app-root ja seejärel konteinerid.

Välised kettad Gantrys

Gantry käitab bind mount'e mis tahes kettalt juba praegu: lisage lehel Uus konteiner köide, valige välisel kettal kaust ja konteineris tee. Gantry tugi andmete juurkausta teisaldamisele, köidetele välisel kettal ja hoiatusele, kui ketas pole ühendatud, on arenduses.

Docker Desktop ja OrbStack

Docker Desktop teisaldab oma kettatõmmise seadega Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack lisas andmete asukoha seade versioonis 0.13.0. Vaadake võrdlust.

Küsimused ja vastused

Kas Apple containeri tõmmiseid saab hoida välisel kettal?

Jah. Käivitage teenused käsuga container system start --app-root /Volumes/Disk/container. Siis asuvad kõik tõmmised, konteinerid, hetktõmmised ja köited selles kaustas.

Millist failisüsteemi peaks väline ketas kasutama?

APFS-i. Köited on hõredad kettatõmmised ja konteinerid vajavad Unixi õigusi, mida exFAT-il, FAT-il ja NTFS-il pole.

Kuidas kopeerida konteineri andmeid ketast täitmata?

Kasutage käsku cp -Rp, mis meie testis hoidis hõredad köidete tõmmised väikesena. ditto kopeeris iga hõreda tõmmise täies suuruses.

Mis juhtub, kui ühendan ketta lahti, kui konteinerid töötavad?

Ketast kasutavad konteinerid nurjuvad ja andmed, mida polnud veel kirjutatud, võivad kaduda. Enne ketta väljutamist peatage konteinerid ja, kui rakenduse juurkaust on kettal, ka teenused.

Kas container CLI jätab uue asukoha meelde?

Ei. Andke lipp --app-root igale käsule container system start. container system status näitab kasutusel olevat juurkausta väärtusena paths.appRoot.

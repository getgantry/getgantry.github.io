Gantry/Depuis docker run

Créer un conteneur à partir d'une commande docker run

La plupart des README donnent une ligne docker run. Gantry lit cette ligne et remplit le formulaire Nouveau conteneur, pour un hôte Docker ou pour l'outil container d'Apple. Ce guide montre comment faire, et comment convertir la commande à la main.

En bref. Dans Gantry, ouvrez Nouveau conteneur, choisissez Coller une commande…, collez la ligne docker run et cliquez sur Remplir le formulaire. Gantry liste chaque option qu'il ne peut pas utiliser, avec la raison. Pour la CLI, la plupart des options sont identiques : remplacez docker run par container run et retirez --restart.

Coller la commande dans Gantry

  1. Sélectionnez un hôte : un hôte Docker ou un hôte apple/container.
  2. Ouvrez Conteneurs et cliquez sur Nouveau conteneur.
  3. Cliquez sur Coller une commande… et collez la ligne. Les fins de ligne en \, les guillemets, une invite $ et sudo sont acceptés.
  4. Lisez l'aperçu : l'image, les options que Gantry ne peut pas utiliser, les remarques et les avertissements pour cet hôte.
  5. Cliquez sur Remplir le formulaire, vérifiez les valeurs et créez le conteneur.

Gantry lit docker run, docker container run, docker create, podman run et container run. Le texte qui suit &&, ||, ; ou | est ignoré, avec une remarque.

Environ 80 autres options de Docker sont reconnues : Gantry saute correctement leurs valeurs et les liste comme non utilisées, si bien que rien ne se perd sans remarque.

    Avertissements pour les hôtes apple/container

Certaines options de Docker n'existent pas sur apple/container. Gantry vous avertit et les retire de la requête de création :

  • les politiques de redémarrage (--restart) ;
  • les fractions de CPU comme --cpus 0.5 ;
  • les modes réseau host, none et container: ;
  • les ports sans port d'hôte, comme -p 80.

Sur un hôte Docker, Gantry avertit pour les options propres à apple/container : le domaine DNS et les options du noyau.

    Convertir docker run en container run à la main

Pour la CLI, la plupart des options restent identiques. Un exemple avec Redis :

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

devient :

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Créez d'abord le volume nommé avec container volume create. Retirez --restart et arrondissez --cpus à un nombre entier. --platform fonctionne comme dans Docker.

    Copier un conteneur comme commande

L'inverse fonctionne aussi. Faites un clic droit sur un conteneur, ou utilisez le menu Plus, et choisissez Copier comme commande : Gantry écrit une ligne docker run ou container run. Il omet les valeurs par défaut de l'image, comme son environnement et sa commande, pour que la ligne reste courte. Cela fonctionne aussi pour les conteneurs arrêtés.

    L'enregistrer comme modèle

Dans la feuille Nouveau conteneur, ouvrez Modèles et choisissez Enregistrer comme modèle…. La fois suivante, Remplir à partir d'un modèle redonne le même formulaire sur n'importe quel hôte. Les modèles sont dans ~/Library/Application Support/Gantry/recipes.json : vous pouvez les sauvegarder ou les partager.

    Limites
  • Gantry garde le chemin de --env-file mais ne lit pas le fichier, et ne lit pas votre shell pour -e KEY sans valeur.
  • Les montages tmpfs et les volumes anonymes de --mount sont listés comme non pris en charge.
  • Deux ports pour le même port de conteneur (-p 8080:80 -p 8081:80) remplissent le formulaire, mais celui-ci refuse ensuite le doublon.

Questions et réponses

Comment convertir docker run en container run ?

Remplacez docker run par container run. -d, -p, -e, -v, --name, --rm, -it, -w et --entrypoint restent identiques. Retirez --restart et utilisez des CPU entiers. Ou collez la ligne dans Gantry et laissez-le remplir le formulaire.

Gantry peut-il importer une commande docker run ?

Oui. Coller une commande… dans la feuille Nouveau conteneur lit docker run, docker create, podman run et container run et remplit le formulaire.

Que deviennent les options que Gantry ne prend pas en charge ?

Elles sont listées dans l'aperçu avec la raison, et restent dans le formulaire, dans la section Depuis la commande collée, pour que vous puissiez les vérifier plus tard.

Peut-on retransformer un conteneur en cours d'exécution en commande docker run ?

Oui. Copier comme commande dans le menu du conteneur écrit une ligne docker run ou container run pour ce conteneur.

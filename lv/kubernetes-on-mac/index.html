Gantry/Kubernetes Mac datorā

Kubernetes palaišana Mac datorā ar Apple container

Apple rīks container var izveidot lokālu Kubernetes klasteri ar vienu komandu. Katrs mezgls ir viegla virtuālā mašīna jūsu Mac datorā. Šis ceļvedis ved no tukša Mac datora līdz darbojošam Deployment – vispirms terminālī un pēc tam lietotnē Gantry.

Īsumā. Instalējiet parakstīto container 1.7.1 pakotni, izpildiet container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, uzbūvējiet attēlu ar container build un palaidiet to klasterī pēc nosaukuma. Gantry rāda to pašu klasteri logā: mezglus, podus, žurnālus, čaulu un portu pārsūtīšanu.

Kas jums vajadzīgs

  • Mac dators ar Apple silicon un macOS 26 vai jaunāku versiju.
  • container CLI 1.7.1 no parakstītās .pkg pakotnes apple/container laidienu lapā. 1.7.1 Homebrew versijā nav klastera pakalpojumu, tāpēc container cluster beidzas ar kļūdu cluster service unavailable.
  • Apmēram 6 GB brīvas atmiņas tālāk dotajam piemēram: trīs mezgli, katram 2 GB.
  • kubectl, ja vēlaties izmantot klasteri no termināļa (brew install kubectl).

Pēc pakotnes instalēšanas vienreiz startējiet pakalpojumus:

Terminālis
container system start

Klastera izveide

Šī komanda izveido klasteri dev ar vienu vadības plaknes mezglu un diviem darba mezgliem. Katrs mezgls saņem 2 CPU un 2 GB atmiņas:

Terminālis
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M nosaka darba mezglu grupas izmēru. Atkārtojiet to grupām ar dažādiem izmēriem. Bez --workers viens mezgls ir gan vadības plakne, gan darba mezgls.
  • --cpus un --memory nosaka vadības plaknes izmēru. Noklusējums ir ceturtdaļa no jūsu Mac datora CPU un atmiņas, vismaz 2 CPU un 2 GB.
  • --shared-image-store ļauj mezgliem izmantot jūsu lokālos attēlus (skatiet tālāk). Vēlāk to mainīt nevar: dzēsiet klasteri un izveidojiet to no jauna.
  • --cni ./calico.yaml komplektā iekļautā kindnet vietā instalē jūsu CNI; --cni NONE neinstalē nevienu.

CLI failā ~/.kube/config pievieno kontekstu dev. Pārbaudiet mezglus:

Terminālis
container cluster list --nodes
kubectl --context dev get nodes

Lokāla attēla palaišana bez reģistra

Ar --shared-image-store mezgli var palaist jebkuru attēlu no jūsu lokālās container attēlu krātuves. Uzbūvējiet attēlu un izmantojiet to pēc nosaukuma:

Terminālis
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Piezīme
Pēc tā paša taga atkārtotas būvēšanas izpildiet kubectl rollout restart ar imagePullPolicy: Always vai izmantojiet jaunu tagu. Ar IfNotPresent mezgls patur jau esošo kopiju. Viss, kam mezglā ir root tiesības, var nolasīt katru attēlu jūsu lokālajā krātuvē, arī privātos attēlus, tāpēc kopīgo krātuvi izmantojiet tikai lokālai izstrādei.

CLI 1.5 un 1.6 versijā kopīgās krātuves nav. Tur izmantojiet container cluster load-image vai lietotnē Gantry Ielādēt klasterī. CLI 1.7 versijā load-image ir noņemts.

Lietotnes atvēršana pārlūkprogrammā

Pārsūtiet lokālo portu uz Deployment un pēc tam atveriet http://localhost:8080:

Terminālis
kubectl --context dev port-forward deployment/hello 8080:80

Klastera pārlūkošana lietotnē Gantry

Gantry rāda to pašu klasteri bez komandām. Pievienojiet savu apple/container resursdatoru, atveriet Klasteri un atlasiet dev. Pārskatā redzama Kubernetes versija, attēlu krātuve, darba mezgli un to CPU un atmiņa. Noklikšķiniet uz Pārlūkot resursus, lai atvērtu sadaļu Kubernetes ar šo kontekstu.

  • Podi, Deployments, StatefulSets, DaemonSets, pakalpojumi, Ingresses, ConfigMaps, noslēpumi, mezgli un notikumi vienai nosaukumtelpai vai visām.
  • Podu žurnāli ar sekošanu un pēdējām rindām, čaula podā un portu pārsūtīšana ar sarakstu, kurā to var apturēt.
  • Mērogošana, izvēršanas restartēšana, dzēšana un Lietot YAML no ielīmēta manifesta vai faila.
  • Noslēpumu vērtības paliek paslēptas, līdz noklikšķināt uz „Atklāt”.

Kubernetes pārlūks izpilda kubectl. Ja tā nav, Gantry parāda brew install kubectl un var to izpildīt jūsu vietā. Tiek izstrādāts natīvs klients, kuram kubectl nav vajadzīgs.

Klasteri var izveidot arī lietotnē Gantry: Klasteri ▸ Jauns klasteris piedāvā skaitītājus vadības plaknei un darba mezgliem un slēdzi Izmantot lokālos attēlus. Vairāk lapā Kubernetes apple/container vidē.

Klastera apturēšana un dzēšana

Terminālis
container cluster delete --name dev

Ja vadības plaknes mezgls apstājas, piemēram, pēc container system stop, dzēsiet klasteri un izveidojiet to no jauna. Izveidojiet pagaidu klasteri ar --rm, lai tā mezgli tiktu noņemti, kad tie apstājas.

Biežākās problēmas

  • cluster service unavailable: CLI ir Homebrew versija, vai pakalpojumi nedarbojas. Instalējiet parakstīto pakotni vai restartējiet pakalpojumus ar container system stop un container system start. Gantry sadaļā „Klasteri” sniedz to pašu padomu.
  • Sarakstā nav veca klastera: CLI 1.7 nerāda klasterus, kas izveidoti ar 1.6 vai vecāku versiju. Noņemiet tādu ar container cluster delete --name <name>.
  • Mezgli paliek stāvoklī NotReady: jūs izmantojāt --cni NONE. Lietojiet CNI manifestu.
  • Mezgla konteineru nevar apturēt: tā ir paredzēts. container stop un delete atsakās apstrādāt klastera mezglus; izmantojiet container cluster delete.

Salīdzinājums ar Docker Desktop un OrbStack

Docker Desktop ir iebūvēts Kubernetes ar kubeadm (viens mezgls) vai kind (vairāki mezgli), un OrbStack ir iebūvēts klasteris ar vienu mezglu. container cluster palaiž kubeadm uz kindest/node attēliem, katru mezglu savā virtuālajā mašīnā, ar klasteriem no vairākiem mezgliem un kopīgu attēlu krātuvi. Skatiet pilno salīdzinājumu.

Saistītie ceļveži

  • Pāreja no Docker Desktop uz Apple container: komandas, Compose, sējumi un trūkumi
  • Konteineru un sējumu glabāšana ārējā diskā Mac datorā

Jautājumi un atbildes

Vai Mac datorā var palaist Kubernetes bez Docker?

Jā. Apple container CLI pats izveido Kubernetes klasterus ar container cluster create. Katrs mezgls darbojas kā viegla virtuālā mašīna, un jums nav vajadzīgs ne Docker, ne Docker Desktop, ne kind, ne minikube.

Cik mezglu var būt container cluster klasterim?

Viena vadības plakne un tik darba mezglu, cik pietiek jūsu Mac datora CPU un atmiņas. Iestatiet tos ar --workers; CLI 1.7 versijā katrai darba mezglu grupai var būt savs CPU un atmiņas apjoms.

Kā klasterī izmantot lokāli uzbūvētu attēlu?

Izveidojiet klasteri ar --shared-image-store (CLI 1.7), uzbūvējiet attēlu ar container build -t name:tag . un poda specifikācijā izmantojiet name:tag. Reģistrs nav vajadzīgs.

Kuru Kubernetes versiju izmanto container cluster?

CLI 1.7.1 pēc noklusējuma izmanto mezgla attēlu kindest/node:v1.35.5. Citu versiju izvēlieties ar --node-image, piemēram, docker.io/kindest/node:v1.34.11. Gantry rāda versiju klastera pārskatā.

Vai container cluster ir grafiskā saskarne?

Jā. Gantry izveido un dzēš klasterus, rāda mezglus un savā Kubernetes sadaļā pārlūko podus, Deployments, pakalpojumus, žurnālus un noslēpumus. Tā ir bezmaksas un atvērtā koda lietotne.

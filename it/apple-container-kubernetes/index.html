Gantry/Kubernetes su apple/container

Kubernetes su Apple container

apple/container può eseguire un cluster Kubernetes i cui nodi sono container sul tuo Mac. Gantry ne è la GUI: crea un cluster, guarda i nodi avviarsi, esegui le tue immagini locali ed esplora pod, log e servizi, senza lunghe righe di comando container cluster.

In breve. Su un host apple/container, la sezione Cluster di Gantry crea ed elimina cluster Kubernetes con container cluster (CLI 1.6.1 e 1.7) o container k8s (CLI dalla 1.5.0 alla 1.6.0). Con la CLI 1.7.1 dimensiona i worker separatamente dal control plane e attiva l'archivio immagini condiviso. La sezione Kubernetes esplora il cluster: pod, log, shell, inoltri di porta, scalabilità e Applica YAML.

Requisiti

  • Un Mac con chip Apple, macOS 26 e Gantry (brew install --cask getgantry/tap/gantry).
  • La CLI container 1.5.0 o successiva; si consiglia la 1.7.1. I worker e il CNI Nessuno richiedono la 1.6.0 o successiva. Le dimensioni dei worker e l'archivio immagini condiviso richiedono la 1.7.0 o successiva. Usa il pacchetto di installazione firmato: la build Homebrew della 1.7.1 non ha i servizi del cluster.
  • kubectl per il browser Kubernetes e il terminale. Gantry può installarlo con Homebrew.

Crea un cluster

  1. Seleziona il tuo host apple/container e apri Cluster nella barra laterale.
  2. Avvia la creazione di un nuovo cluster e compila le opzioni qui sotto.
  3. Crealo. L'elenco mostra il nuovo cluster con l'avanzamento in tempo reale. Annulla interrompe la creazione ed elimina i nodi già creati.
OpzioneFlag della CLINote
Nome--nameÈ anche il nome del contesto kubeconfig
Worker--workersNumero di nodi worker. CLI 1.6.0+
CPU e memoria dei worker--workers count=N,cpus=C,memory=MCLI 1.7+. Prima della 1.7, --cpus e --memory valgono per ogni nodo
CPU--cpusControl plane (CLI 1.7+) o ogni nodo (prima della 1.7)
Memoria--memoryControl plane (CLI 1.7+) o ogni nodo (prima della 1.7), per esempio 4G
Usa immagini locali--shared-image-storeCLI 1.7+. I nodi eseguono le immagini del tuo archivio immagini locale
Immagine dei nodi--node-imageSe vuoto, resta il valore predefinito della CLI
CNI--cniPredefinito (kindnet incluso), Nessuno (NONE, CLI 1.6.0+) o percorso di un manifest personalizzato

Lo stesso comando nella CLI:

Shell
container cluster create --name dev --cpus 2 --memory 4G \
  --workers count=2,cpus=2,memory=4G --shared-image-store

Nodi e dettagli del cluster

L'elenco dei cluster mostra una riga per ogni cluster. La vista di dettaglio ha una Panoramica (contesto kubectl, server API, versione di Kubernetes, archivio immagini, worker e relative risorse, rete dei nodi), una tabella Nodi e Ispeziona per i dati grezzi dei nodi. La barra degli strumenti ha Sfoglia risorse, e il menu Altro ha Scrivi kubeconfig, Copia comando contesto kubectl ed Elimina.

I nodi del cluster sono container, ma li gestisce container cluster. Gantry disattiva avvio, arresto, riavvio, rimozione e rinomina per un nodo e ti spiega perché, e Avvia tutti e Arresta tutti saltano i nodi. Con la CLI 1.7, la CLI nasconde anche i nodi da container list. I cluster creati con la CLI 1.6 o precedenti non compaiono nell'elenco della 1.7; rimuovili con container cluster delete --name <name>.

Esplora il cluster

Fai clic su Sfoglia risorse su un cluster in esecuzione, oppure apri Kubernetes nella barra laterale. La sezione non richiede un host ed elenca ogni contesto kubeconfig; i contesti dei cluster apple/container compaiono per primi. Scegli un namespace o tutti i namespace, poi un tipo: pod, deployment, stateful set, daemon set, servizi, ingress, config map, secret, nodi o eventi.

  • Pod: log con modalità segui, coda e container precedente; una shell nel pod; inoltro di porta verso 127.0.0.1.
  • Carichi di lavoro: scala deployment e stateful set; riavvia un rollout.
  • Secret: i valori sono mascherati nell'elenco e nello YAML finché non fai clic su Mostra.
  • Applica YAML: incolla un manifest o apri un file; gli errori compaiono nel pannello.

Il browser esegue kubectl. Se Gantry non lo trova, la sezione mostra brew install kubectl con un pulsante che lo esegue. È in sviluppo un client Kubernetes nativo che non richiede kubectl.

Collega kubectl

Quando crea il cluster, la CLI aggiunge a ~/.kube/config un contesto con il nome del cluster. Usa Copia comando contesto kubectl in Gantry, oppure digitalo:

Shell
kubectl --context dev get nodes

Per tenere il cluster in un file a parte, usa Scrivi kubeconfig. Gantry esegue container cluster write-config; il percorso predefinito è ~/.kube/<name>.kubeconfig.

Usa immagini locali nel cluster

Con la CLI 1.7, attiva Usa immagini locali quando crei il cluster. L'opzione aggiunge --shared-image-store, così i nodi possono eseguire per nome qualsiasi immagine che crei o scarichi con container, senza registro. L'impostazione è fissata alla creazione. Dopo aver ricreato un tag, usa imagePullPolicy: Always o un nuovo tag. I pod privilegiati possono leggere ogni immagine del tuo archivio locale, quindi usa questa opzione solo per lo sviluppo in locale.

Shell
container build -t myapp:dev .
kubectl --context dev create deployment myapp --image=myapp:dev

Con le CLI 1.5 e 1.6, fai clic destro sull'immagine in Immagini e scegli Carica nel cluster. Gantry esegue container cluster load-image, che copia l'immagine nel containerd di ogni nodo. La CLI 1.7 ha rimosso questo comando, quindi lì Gantry nasconde l'azione.

Shell
container cluster load-image --name dev myapp:dev

Quando i servizi del cluster non rispondono

Se un comando del cluster non riesce con cluster service unavailable, Gantry controlla come è installata la CLI. Con una build Homebrew senza i plug-in del cluster compare il messaggio che la build non ha i servizi del cluster e un link Scarica programma di installazione… al pacchetto firmato. Negli altri casi, Gantry propone Riavvia servizi….

Scegli un CNI

Il predefinito è il manifest kindnet incluso. Scegli Manifest personalizzato per installare un tuo CNI da file, per esempio Calico o Cilium. Scegli Nessuno per installare tu un CNI in seguito; fino ad allora, i nodi restano NotReady.

Cluster gestiti dagli agenti AI

Il server MCP di Gantry offre list_clusters, create_cluster e delete_cluster, così un agente come Claude Code può creare un cluster temporaneo per un test e rimuoverlo dopo.

Aggiungi il server MCP di Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Domande e risposte

Apple container supporta Kubernetes?

Sì. La CLI container crea cluster Kubernetes i cui nodi girano come container: container cluster nelle CLI 1.6.1 e 1.7, container k8s nelle CLI dalla 1.5.0 alla 1.6.0. Gantry aggiunge a tutto questo una GUI.

Gantry supporta container cluster?

Sì. Gantry elenca, crea ed elimina cluster sugli host apple/container, ne mostra i nodi, scrive il kubeconfig e apre il cluster nel suo browser Kubernetes. Con la CLI 1.7 dimensiona anche i worker e attiva l'archivio immagini condiviso. Usa cluster o k8s in base alla versione della tua CLI.

Come si usa kubectl con un cluster apple/container?

Quando la CLI crea un cluster, aggiunge a ~/.kube/config un contesto kubeconfig con il nome del cluster. Esegui kubectl --context <name> get nodes. Per tenere un file separato, usa Scrivi kubeconfig in Gantry; il percorso predefinito è ~/.kube/<name>.kubeconfig.

Come si carica un'immagine locale nel cluster senza registro?

Con la CLI 1.7, crea il cluster con Usa immagini locali (--shared-image-store). I pod eseguono poi per nome le immagini che crei o scarichi con container. Con le CLI 1.5 e 1.6, fai clic destro sull'immagine in Immagini e scegli Carica nel cluster; Gantry esegue container cluster load-image. La CLI 1.7 ha rimosso load-image.

Si può creare un cluster con più nodi?

Sì. Imposta il numero di worker nel pannello di creazione; i worker richiedono la CLI 1.6.0 o successiva. Con la CLI 1.7 imposti anche CPU e memoria dei worker separatamente dal control plane.

Posso usare un mio CNI, come Calico o Cilium?

Sì. Scegli Manifest personalizzato e seleziona il file del manifest, oppure scegli Nessuno e applica tu un CNI dopo l'avvio del cluster. I nodi restano NotReady finché non è attivo un CNI. Nessuno richiede la CLI 1.6.0 o successiva. Il CNI predefinito è il manifest kindnet incluso.

Perché Gantry dice che i servizi del cluster non sono disponibili?

I servizi di container non hanno risposto a un comando del cluster. Se la tua CLI è una build Homebrew senza i servizi del cluster, Gantry te lo dice e rimanda al programma di installazione firmato nella pagina delle release di apple/container. Altrimenti propone Riavvia servizi.

Serve kubectl per usare il cluster in Gantry?

Per ora sì: il browser Kubernetes di Gantry esegue kubectl. Se non è installato, il browser mostra il comando brew install kubectl e può eseguirlo per te. È in sviluppo un client Kubernetes nativo che elimina questo passaggio.

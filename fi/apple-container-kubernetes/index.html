Gantry/Kubernetes apple/containerilla

Kubernetes Apple containerilla

apple/container voi ajaa Kubernetes-klusteria, jonka solmut ovat kontteja Macillasi. Gantry on sille GUI: luo klusteri, seuraa solmujen käynnistymistä, aja paikallisia levykuviasi siinä ja selaa sen podeja, lokeja ja palveluja ilman pitkiä container cluster -komentorivejä.

Lyhyesti. apple/container-isännällä Gantryn Klusterit-osio luo ja poistaa Kubernetes-klustereita komennolla container cluster (CLI 1.6.1 ja 1.7) tai container k8s (CLI 1.5.0–1.6.0). CLI 1.7.1:ssä se mitoittaa työsolmut ohjaustasosta erikseen ja ottaa jaetun levykuvavaraston käyttöön. Kubernetes-osio selaa klusteria: podit, lokit, komentotulkki, porttien välitykset, skaalaus ja Käytä YAML.

Vaatimukset

  • Mac, jossa on Apple-siru, macOS 26 ja Gantry (brew install --cask getgantry/tap/gantry).
  • container-CLI 1.5.0 tai uudempi; suositus on 1.7.1. Työsolmut ja CNI-valinta Ei mitään vaativat version 1.6.0 tai uudemman. Työsolmujen koot ja jaettu levykuvavarasto vaativat version 1.7.0 tai uudemman. Käytä allekirjoitettua asennuspakettia: version 1.7.1 Homebrew-koonnissa ei ole klusteripalveluja.
  • kubectl Kubernetes-selainta ja päätettä varten. Gantry voi asentaa sen Homebrew'lla.

Klusterin luominen

  1. Valitse apple/container-isäntäsi ja avaa sivupalkista Klusterit.
  2. Aloita uusi klusteri ja täytä alla olevat valinnat.
  3. Luo se. Luettelossa näkyy uusi klusteri ja sen edistyminen reaaliajassa. Kumoa pysäyttää luonnin ja poistaa jo luodut solmut.
ValintaCLI-lippuHuomiot
Nimi--nameMyös kubeconfig-kontekstin nimi
Työsolmut--workersTyösolmujen määrä. CLI 1.6.0+
Työsolmujen CPU:t ja muisti--workers count=N,cpus=C,memory=MCLI 1.7+. Ennen versiota 1.7 --cpus ja --memory koskevat jokaista solmua
CPU:t--cpusOhjaustaso (CLI 1.7+) tai jokainen solmu (ennen versiota 1.7)
Muisti--memoryOhjaustaso (CLI 1.7+) tai jokainen solmu (ennen versiota 1.7), esimerkiksi 4G
Käytä paikallisia levykuvia--shared-image-storeCLI 1.7+. Solmut ajavat levykuvia paikallisesta levykuvavarastostasi
Solmun levykuva--node-imageTyhjä käyttää CLI:n oletusta
CNI--cniOletus (mukana tuleva kindnet), Ei mitään (NONE, CLI 1.6.0+) tai mukautetun manifestin polku

Sama komento CLI:ssä:

Komentotulkki
container cluster create --name dev --cpus 2 --memory 4G \
  --workers count=2,cpus=2,memory=4G --shared-image-store

Solmut ja klusterin tiedot

Klusteriluettelossa on yksi rivi kullekin klusterille. Tietonäkymässä on Yleiskatsaus (kubectl-konteksti, API-palvelin, Kubernetes-versio, levykuvavarasto, työsolmut ja niiden resurssit, solmuverkko), Solmut-taulukko ja Tarkastele solmujen raakadataa varten. Työkalupalkissa on Selaa resursseja, ja Lisää-valikossa ovat Kirjoita kubeconfig, Kopioi kubectl-kontekstikomento ja Poista.

Klusterin solmut ovat kontteja, mutta niitä hallitsee container cluster. Gantry poistaa solmulta käytöstä käynnistyksen, pysäytyksen, uudelleenkäynnistyksen, poiston ja uudelleennimeämisen ja kertoo syyn, ja Käynnistä kaikki ja Pysäytä kaikki ohittavat solmut. CLI 1.7:ssä CLI myös piilottaa solmut container list -luettelosta. CLI 1.6:lla tai vanhemmalla luodut klusterit eivät näy 1.7:n luettelossa; poista ne komennolla container cluster delete --name <name>.

Klusterin selaaminen

Napsauta käynnissä olevan klusterin kohdalla Selaa resursseja tai avaa sivupalkista Kubernetes. Osio ei tarvitse isäntää, ja se luettelee jokaisen kubeconfig-kontekstin; apple/container-klusterien kontekstit näkyvät ensimmäisinä. Valitse nimiavaruus tai kaikki nimiavaruudet ja sitten laji: podit, deploymentit, StatefulSetit, DaemonSetit, palvelut, ingressit, ConfigMapit, secretit, solmut tai tapahtumat.

  • Podit: lokit seurannalla, lopun näytöllä ja edellisen kontin lokeilla; komentotulkki podissa; porttien välitys osoitteeseen 127.0.0.1.
  • Työkuormat: deploymenttien ja StatefulSetien skaalaus; käyttöönoton uudelleenkäynnistys.
  • Secretit: arvot ovat peitettyinä luettelossa ja YAML:ssa, kunnes napsautat Näytä.
  • Käytä YAML: sijoita manifesti tai avaa tiedosto; virheet näkyvät ikkunassa.

Selain käyttää kubectl:ää. Jos Gantry ei löydä sitä, osio näyttää komennon brew install kubectl ja painikkeen, joka suorittaa sen.

kubectl:n yhdistäminen

CLI lisää klusteria luodessaan tiedostoon ~/.kube/config klusterin mukaan nimetyn kontekstin. Käytä Gantryssa toimintoa Kopioi kubectl-kontekstikomento tai kirjoita komento itse:

Komentotulkki
kubectl --context dev get nodes

Jos haluat pitää klusterin omassa tiedostossaan, käytä toimintoa Kirjoita kubeconfig. Gantry suorittaa komennon container cluster write-config; oletuspolku on ~/.kube/<name>.kubeconfig.

Paikalliset levykuvat klusterissa

Ota CLI 1.7:ssä käyttöön Käytä paikallisia levykuvia, kun luot klusterin. Se lisää valinnan --shared-image-store, joten solmut voivat ajaa nimellä mitä tahansa levykuvaa, jonka olet koostanut tai noutanut container-työkalulla, ilman rekisteriä. Asetus kiinnitetään luonnin yhteydessä. Kun koostat tagin uudelleen, käytä asetusta imagePullPolicy: Always tai uutta tagia. Etuoikeutetut podit voivat lukea jokaisen paikallisen varastosi levykuvan, joten käytä tätä vain paikallisessa kehityksessä.

Komentotulkki
container build -t myapp:dev .
kubectl --context dev create deployment myapp --image=myapp:dev

CLI 1.5:ssä ja 1.6:ssa napsauta levykuvaa Levykuvat-näkymässä hiiren oikealla ja valitse Siirrä klusteriin. Gantry suorittaa komennon container cluster load-image, joka kopioi levykuvan jokaisen solmun containerd:hen. CLI 1.7 poisti tämän komennon, joten Gantry piilottaa toiminnon siinä.

Komentotulkki
container cluster load-image --name dev myapp:dev

Kun klusteripalvelut eivät vastaa

Jos klusterikomento epäonnistuu virheellä cluster service unavailable, Gantry tarkistaa, miten CLI on asennettu. Homebrew-koonnille ilman klusterilaajennuksia se näyttää viestin, että koonnista puuttuvat klusteripalvelut, ja Lataa asentaja… -linkin allekirjoitettuun pakettiin. Muissa tapauksissa Gantry tarjoaa toimintoa Käynnistä palvelut uudelleen….

CNI:n valinta

Oletuksena on mukana tuleva kindnet-manifesti. Valitse Mukautettu manifesti, jos haluat asentaa oman CNI:n, esimerkiksi Calicon tai Ciliumin, tiedostosta. Valitse Ei mitään, jos asennat CNI:n itse myöhemmin; siihen asti solmut pysyvät NotReady-tilassa.

Kubernetes Macilla Apple containerin avulla

Applen container-työkalu luo paikallisen Kubernetes-klusterin yhdellä komennolla. Jokainen solmu on kevyt virtuaalikone Macillasi. Tämä opas vie tyhjästä Macista toimivaan deploymenttiin, ensin päätteessä ja sitten Gantryssa.

Mitä tarvitset

  • Mac, jossa on Apple-siru ja macOS 26 tai uudempi.
  • container-CLI 1.7.1 allekirjoitetusta .pkg-paketista apple/containerin julkaisusivulta. Version 1.7.1 Homebrew-koonnissa ei ole klusteripalveluja, joten container cluster epäonnistuu virheellä cluster service unavailable.
  • Noin 6 Gt vapaata muistia alla olevaa esimerkkiä varten: kolme solmua, kullakin 2 Gt.
  • kubectl, jos haluat käyttää klusteria päätteestä (brew install kubectl).

Käynnistä palvelut kerran paketin asennuksen jälkeen:

Pääte
container system start
    Luo klusteri

Tämä komento luo klusterin nimeltä dev, jossa on yksi ohjaustason solmu ja kaksi työsolmua. Jokainen solmu saa 2 CPU:ta ja 2 Gt muistia:

Pääte
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M mitoittaa työsolmujen ryhmän. Toista se, jos haluat erikokoisia ryhmiä. Ilman valintaa --workers yksi solmu on sekä ohjaustaso että työsolmu.
  • --cpus ja --memory mitoittavat ohjaustason. Oletus on neljännes Macisi CPU:ista ja muistista, vähintään 2 CPU:ta ja 2 Gt.
  • --shared-image-store antaa solmujen käyttää paikallisia levykuviasi (katso alta). Sitä ei voi muuttaa myöhemmin: poista klusteri ja luo se uudelleen.
  • --cni ./calico.yaml asentaa oman CNI:si mukana tulevan kindnetin sijaan; --cni NONE ei asenna mitään.

CLI lisää tiedostoon ~/.kube/config kontekstin nimeltä dev. Tarkista solmut:

Pääte
container cluster list --nodes
kubectl --context dev get nodes
    Aja paikallinen levykuva ilman rekisteriä

Valinnalla --shared-image-store solmut voivat ajaa mitä tahansa levykuvaa paikallisesta container-levykuvavarastostasi. Koosta levykuva ja käytä sitä nimellä:

Pääte
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Huomautus
Kun koostat saman tagin uudelleen, suorita kubectl rollout restart asetuksella imagePullPolicy: Always tai käytä uutta tagia. Asetuksella IfNotPresent solmu säilyttää kopion, joka sillä jo on. Mikä tahansa, jolla on root-oikeudet solmussa, voi lukea jokaisen paikallisen varastosi levykuvan, myös yksityiset levykuvat, joten käytä jaettua varastoa vain paikallisessa kehityksessä.

CLI 1.5:ssä ja 1.6:ssa jaettua varastoa ei ole. Käytä niissä komentoa container cluster load-image tai Gantryssa toimintoa Siirrä klusteriin. CLI 1.7 poisti komennon load-image.

    Avaa sovellus selaimessa

Välitä paikallinen portti deploymenttiin ja avaa sitten http://localhost:8080:

Pääte
kubectl --context dev port-forward deployment/hello 8080:80
    Pysäytä ja poista klusteri
Pääte
container cluster delete --name dev

Jos ohjaustason solmu pysähtyy, esimerkiksi komennon container system stop jälkeen, poista klusteri ja luo se uudelleen. Luo kertakäyttöinen klusteri valinnalla --rm, niin sen solmut poistetaan, kun ne pysähtyvät.

    Yleisiä ongelmia
  • cluster service unavailable: CLI on Homebrew-koonti, tai palvelut eivät ole käynnissä. Asenna allekirjoitettu paketti tai käynnistä palvelut uudelleen komennoilla container system stop ja container system start. Gantry antaa saman neuvon Klusterit-osiossa.
  • Vanha klusteri puuttuu luettelosta: CLI 1.7 ei luettele klustereita, jotka on luotu versiolla 1.6 tai vanhemmalla. Poista sellainen komennolla container cluster delete --name <name>.
  • Solmut pysyvät NotReady-tilassa: käytit valintaa --cni NONE. Ota CNI-manifesti käyttöön.
  • Solmukonttia ei voi pysäyttää: tämä on tarkoituksellista. container stop ja delete eivät käsittele klusterin solmuja; käytä komentoa container cluster delete.
    Vertailu Docker Desktopiin ja OrbStackiin

Docker Desktopissa on sisäänrakennettu Kubernetes kubeadmilla (yksi solmu) tai kindillä (useita solmuja), ja OrbStackissa on sisäänrakennettu yhden solmun klusteri. container cluster ajaa kubeadmia kindest/node-levykuvilla, jokainen solmu omassa virtuaalikoneessaan, ja tukee usean solmun klustereita ja jaettua levykuvavarastoa. Katso koko vertailu.

Klusterit AI-agenttien avulla

Gantryn MCP-palvelimessa on työkalut list_clusters, create_cluster ja delete_cluster, joten agentti, kuten Claude Code, voi luoda väliaikaisen klusterin testiä varten ja poistaa sen jälkeenpäin.

Lisää Gantryn MCP-palvelin
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Lisää apple/containerista

Vaiheittainen ohje päätteestä: Kubernetes Macilla Apple containerin avulla. apple/container-opas kertoo jokaisesta container-komennosta ja sitä vastaavasta Gantryn toiminnosta. Voit myös katsoa, miten Gantry vertautuu Docker Desktopiin, OrbStackiin ja Podman Desktopiin.

Kysymyksiä ja vastauksia

Tukeeko Apple container Kubernetesia?

Kyllä. container-CLI luo Kubernetes-klustereita, joiden solmut toimivat kontteina: container cluster CLI-versioissa 1.6.1 ja 1.7, container k8s CLI-versioissa 1.5.0–1.6.0. Gantry antaa tälle GUI:n.

Tukeeko Gantry container clusteria?

Kyllä. Gantry luettelee, luo ja poistaa klustereita apple/container-isännillä, näyttää niiden solmut, kirjoittaa kubeconfigin ja avaa klusterin Kubernetes-selaimessaan. CLI 1.7:ssä se myös mitoittaa työsolmut ja ottaa jaetun levykuvavaraston käyttöön. Se käyttää komentoa cluster tai k8s CLI-versiosi mukaan.

Miten kubectl:ää käytetään apple/container-klusterin kanssa?

Kun CLI luo klusterin, se lisää tiedostoon ~/.kube/config klusterin mukaan nimetyn kubeconfig-kontekstin. Suorita kubectl --context <name> get nodes. Jos haluat erillisen tiedoston, käytä Gantryssa toimintoa Kirjoita kubeconfig; oletuspolku on ~/.kube/<name>.kubeconfig.

Miten paikallisen levykuvan saa klusteriin ilman rekisteriä?

Luo CLI 1.7:ssä klusteri valinnalla Käytä paikallisia levykuvia (--shared-image-store). Podit ajavat silloin nimellä levykuvia, jotka olet koostanut tai noutanut container-työkalulla. CLI 1.5:ssä ja 1.6:ssa napsauta levykuvaa Levykuvat-näkymässä hiiren oikealla ja valitse Siirrä klusteriin; Gantry suorittaa komennon container cluster load-image. CLI 1.7 poisti komennon load-image.

Voiko luoda usean solmun klusterin?

Kyllä. Aseta työsolmujen määrä luontinäkymässä; työsolmut vaativat CLI:n version 1.6.0 tai uudemman. CLI 1.7:ssä asetat myös työsolmujen CPU:t ja muistin ohjaustasosta erikseen.

Voiko käyttää omaa CNI:tä, kuten Calicoa tai Ciliumia?

Kyllä. Valitse Mukautettu manifesti ja valitse manifestitiedosto, tai valitse Ei mitään ja ota CNI käyttöön itse klusterin käynnistyttyä. Solmut pysyvät NotReady-tilassa, kunnes jokin CNI on käynnissä. Ei mitään vaatii CLI:n version 1.6.0 tai uudemman. Oletus-CNI on mukana tuleva kindnet-manifesti.

Miksi Gantry sanoo, että klusteripalvelut eivät ole käytettävissä?

container-palvelut eivät vastanneet klusterikomentoon. Jos CLI:si on Homebrew-koonti ilman klusteripalveluja, Gantry kertoo sen ja linkittää allekirjoitettuun asentajaan apple/containerin julkaisusivulla. Muussa tapauksessa se tarjoaa toimintoa Käynnistä palvelut uudelleen.

Tarvitsenko kubectl:ää käyttääkseni klusteria Gantryssa?

Toistaiseksi kyllä: Gantryn Kubernetes-selain käyttää kubectl:ää. Jos sitä ei ole asennettu, selain näyttää komennon brew install kubectl ja voi suorittaa sen puolestasi.

Voiko Kubernetesia ajaa Macilla ilman Dockeria?

Kyllä. Applen container-CLI luo Kubernetes-klustereita itse komennolla container cluster create. Jokainen solmu toimii kevyenä virtuaalikoneena, etkä tarvitse Dockeria, Docker Desktopia, kindiä tai minikubea.

Montako solmua container clusterissa voi olla?

Yksi ohjaustaso ja niin monta työsolmua kuin Macisi CPU:t ja muisti riittävät. Aseta ne valinnalla --workers; CLI 1.7:ssä jokaisella työsolmuryhmällä voi olla omat CPU:t ja muisti.

Mitä Kubernetes-versiota container cluster käyttää?

CLI 1.7.1 käyttää oletuksena solmun levykuvaa kindest/node:v1.35.5. Valitse toinen versio valinnalla --node-image, esimerkiksi docker.io/kindest/node:v1.34.11. Gantry näyttää version klusterin yleiskatsauksessa.

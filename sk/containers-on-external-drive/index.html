Gantry/Externý disk

Kontajnery a zväzky na externom disku

Obrazy, kontajnery a zväzky rýchlo zaplnia malý interný disk. S nástrojom container od Apple môžete tieto dáta mať na externom SSD: jednotlivé priečinky tam umiestniť pomocou bind mountov, alebo presunúť celý koreňový priečinok dát. Tento návod ukazuje oboje a aj to, ako disk odpojiť bez poškodenia.

V skratke. Naformátujte disk ako APFS. Pre jeden projekt pripojte priečinok cez bind mount: -v /Volumes/Fast/pg:/data. Pre všetko zastavte služby, skopírujte ~/Library/Application Support/com.apple.container na disk príkazom cp -Rp a služby zakaždým spúšťajte príkazom container system start --app-root /Volumes/Fast/container.

Kde sú dáta teraz

apple/container drží všetky svoje dáta v jednom priečinku, koreňovom priečinku aplikácie (app root). Predvolene je to ~/Library/Application Support/com.apple.container, s priečinkami pre kontajnery, obsah obrazov, snímky, zväzky, jadrá a siete. Skontrolujte cestu a využité miesto:

Terminál
container system status | grep appRoot
container system df

Výber a formátovanie disku

  • Použite SSD cez USB-C alebo Thunderbolt. Platňový disk funguje tiež, ale kontajnery štartujú pomalšie.
  • Naformátujte ho ako APFS (funguje aj Mac OS Extended). Nepoužívajte exFAT, FAT ani NTFS: zväzky sú riedke obrazy disku a tieto systémy súborov nemajú riedke súbory ani unixové oprávnenia.
  • Ako koreňový priečinok aplikácie nepoužívajte sieťový disk.
  • Dajte disku krátky názov bez medzier, napríklad Fast. Cesta potom je /Volumes/Fast.
    Možnosť 1: dáta projektu na disku cez bind mounty

Bind mount zdieľa priečinok z vášho Macu s kontajnerom a ten priečinok môže byť na ľubovoľnom disku. Je to jednoduchý spôsob, ako mať veľké dáta, napríklad databázu alebo súbory modelov, mimo interného disku:

Terminál
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Disk musí byť pripojený skôr, než sa kontajner spustí. Obrazy a samotný kontajner zostávajú na internom disku.

    Možnosť 2: všetky dáta apple/container na disk

Týmto presuniete obrazy, kontajnery, snímky a zväzky. Najprv zastavte služby, aby sa počas kopírovania nezmenil žiadny súbor:

Terminál
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Použite cp -Rp. V našom teste v macOS 27 (z APFS na APFS cez USB) zachoval obrazy zväzkov riedke a zachoval rozšírené atribúty. ditto zapísal každý riedky obraz v plnej veľkosti, čo môže disk zaplniť. Starý priečinok si nechajte, kým neoveríte, že sa vaše kontajnery, obrazy a zväzky zobrazujú v zozname.

Pozor
CLI si --app-root nepamätá. Každé container system start bez neho znova použije interný priečinok. Príznak zadávajte zakaždým, napríklad v aliase shellu, a kontrolujte paths.appRoot v container system status.

Gantry tento presun dokáže urobiť za vás: pozrite si nižšie.

    Archivácia obrazov na disku

Ak chcete uvoľniť miesto bez straty obrazu, uložte ho na externý disk a vymažte ho. Keď ho budete potrebovať, znova ho načítajte:

Terminál
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Bezpečné odpojenie disku
  1. Zastavte kontajnery, ktoré disk používajú: container stop <name>.
  2. Ak je koreňový priečinok aplikácie na disku, zastavte služby: container system stop.
  3. Vysuňte disk vo Finderi a potom ho odpojte.

Ak disk zmizne, kým z neho bežia kontajnery, zlyhajú a rozpracované zápisy sa môžu stratiť. Po opätovnom pripojení disku spustite služby s --app-root a potom spustite kontajnery.

    Externé disky v Gantry

Na hostiteľovi apple/container ukazuje panel Úložisko v sekcii Systém, kde je koreňový priečinok dát, na ktorom disku a koľko miesta zaberajú obrazy, kontajnery, snímky, zväzky a jadrá. Presunúť na iný disk… zastaví služby, skopíruje dáta, overí ich, prepne koreňový priečinok a znova spustí služby; starú kópiu vymaže až po samostatnom potvrdení. Gantry si koreňový priečinok pamätá pre každé ďalšie spustenie. Nové zväzky môžu byť v priečinku na ľubovoľnom disku, a keď tento disk nie je pripojený, Gantry povie, ktorý disk chýba, a nespustí kontajnery, ktoré ho potrebujú.

    Docker Desktop a OrbStack

Docker Desktop presúva svoj obraz disku v Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack pridal nastavenie umiestnenia dát vo verzii 0.13.0. Pozrite si porovnanie.

Otázky a odpovede

Môžem mať obrazy Apple container na externom disku?

Áno. Spustite služby príkazom container system start --app-root /Volumes/Disk/container. Všetky obrazy, kontajnery, snímky a zväzky potom budú v tomto priečinku.

Aký systém súborov má mať externý disk?

APFS. Zväzky sú riedke obrazy disku a kontajnery potrebujú unixové oprávnenia, ktoré exFAT, FAT ani NTFS nemajú.

Ako skopírovať dáta kontajnerov, aby sa disk nezaplnil?

Použite cp -Rp, ktorý v našom teste zachoval riedke obrazy zväzkov malé. ditto skopíroval každý riedky obraz v plnej veľkosti.

Čo sa stane, keď disk odpojím, kým kontajnery bežia?

Kontajnery, ktoré disk používajú, zlyhajú a dáta, ktoré ešte neboli zapísané, sa môžu stratiť. Pred vysunutím zastavte kontajnery a, ak je na disku koreňový priečinok aplikácie, aj služby.

Pamätá si CLI container nové umiestnenie?

Nie. Zadávajte --app-root pri každom container system start. container system status ukazuje používaný koreňový priečinok ako paths.appRoot.

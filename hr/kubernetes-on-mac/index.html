Gantry/Kubernetes na Macu

Pokretanje Kubernetesa na Macu uz Apple container

Appleov alat container može jednom naredbom stvoriti lokalni Kubernetes klaster. Svaki čvor je lagani virtualni stroj na vašem Macu. Ovaj vodič vodi vas od praznog Maca do pokrenutog deploymenta, najprije u terminalu, a zatim u Gantryju.

Ukratko. Instalirajte potpisani paket container 1.7.1, pokrenite container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, izgradite sliku naredbom container build i pokrenite je u klasteru po nazivu. Gantry prikazuje isti klaster u prozoru: čvorove, podove, zapisnike, ljusku i prosljeđivanje portova.

Što vam treba

  • Mac s Apple siliconom i macOS 26 ili noviji.
  • CLI container 1.7.1 iz potpisanog paketa .pkg sa stranice izdanja apple/containera. Homebrew izgradnja verzije 1.7.1 ne uključuje servise klastera, pa container cluster javlja pogrešku cluster service unavailable.
  • Oko 6 GB slobodne memorije za primjer u nastavku: tri čvora po 2 GB.
  • kubectl, ako klaster želite koristiti iz terminala (brew install kubectl).

Nakon instalacije paketa jednom pokrenite servise:

Terminal
container system start

Stvaranje klastera

Ova naredba stvara klaster dev s jednim čvorom kontrolne ravnine i dva radna čvora. Svaki čvor dobiva 2 CPU-a i 2 GB memorije:

Terminal
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M određuje veličinu skupine radnih čvorova. Ponovite ga za skupine različitih veličina. Bez --workers jedan je čvor i kontrolna ravnina i radni čvor.
  • --cpus i --memory određuju veličinu kontrolne ravnine. Zadano je četvrtina CPU-ova i memorije vašeg Maca, najmanje 2 CPU-a i 2 GB.
  • --shared-image-store omogućuje čvorovima korištenje vaših lokalnih slika (vidi u nastavku). Kasnije to ne možete promijeniti: izbrišite klaster i stvorite ga ponovno.
  • --cni ./calico.yaml instalira vaš vlastiti CNI umjesto priloženog kindneta; --cni NONE ne instalira nijedan.

CLI dodaje kontekst dev u ~/.kube/config. Provjerite čvorove:

Terminal
container cluster list --nodes
kubectl --context dev get nodes

Pokretanje lokalne slike bez registra

Uz --shared-image-store čvorovi mogu pokrenuti bilo koju sliku iz vašeg lokalnog spremišta slika alata container. Izgradite sliku i upotrijebite je po nazivu:

Terminal
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Napomena
Nakon ponovne izgradnje iste oznake pokrenite kubectl rollout restart uz imagePullPolicy: Always ili upotrijebite novu oznaku. Uz IfNotPresent čvor zadržava kopiju koju već ima. Sve što na čvoru ima root ovlasti može čitati svaku sliku u vašem lokalnom spremištu, uključujući privatne slike, pa zajedničko spremište koristite samo za lokalni razvoj.

CLI 1.5 i 1.6 nemaju zajedničko spremište. Ondje upotrijebite container cluster load-image ili Učitaj u klaster u Gantryju. CLI 1.7 uklonio je load-image.

Otvaranje aplikacije u pregledniku

Proslijedite lokalni port na deployment, a zatim otvorite http://localhost:8080:

Terminal
kubectl --context dev port-forward deployment/hello 8080:80

Pregledavanje klastera u Gantryju

Gantry prikazuje isti klaster bez naredbi. Dodajte svoj apple/container host, otvorite Klasteri i odaberite dev. Pregled prikazuje verziju Kubernetesa, spremište slika, radne čvorove i njihove CPU-ove i memoriju. Kliknite Pregledaj resurse da biste otvorili odjeljak Kubernetes na tom kontekstu.

  • Podovi, deploymenti, StatefulSetovi, DaemonSetovi, servisi, Ingressi, ConfigMapovi, tajne, čvorovi i događaji, za jedan imenski prostor ili za sve.
  • Zapisnici poda s praćenjem i zadnjim recima, ljuska u podu i prosljeđivanje portova s popisom na kojem ga možete zaustaviti.
  • Skaliranje, ponovno pokretanje uvođenja, brisanje i Primijeni YAML iz zalijepljenog manifesta ili datoteke.
  • Vrijednosti tajni ostaju skrivene dok ne kliknete Otkrij.

Kubernetes preglednik pokreće kubectl. Ako nedostaje, Gantry prikazuje brew install kubectl i može tu naredbu pokrenuti umjesto vas. U razvoju je nativni klijent kojemu kubectl ne treba.

Klaster možete stvoriti i u Gantryju: Klasteri ▸ Novi klaster ima brojače za kontrolnu ravninu i radne čvorove te prekidač Koristi lokalne slike. Više na stranici Kubernetes na apple/containeru.

Zaustavljanje i brisanje klastera

Terminal
container cluster delete --name dev

Ako se čvor kontrolne ravnine zaustavi, npr. nakon container system stop, izbrišite klaster i stvorite ga ponovno. Za privremeni klaster upotrijebite --rm: njegovi se čvorovi uklanjaju kad se zaustave.

Česti problemi

  • cluster service unavailable: CLI je Homebrew izgradnja ili servisi nisu pokrenuti. Instalirajte potpisani paket ili ponovno pokrenite servise naredbama container system stop i container system start. Gantry daje isti savjet u odjeljku Klasteri.
  • Stari klaster nedostaje na popisu: CLI 1.7 ne prikazuje klastere stvorene verzijom 1.6 ili starijom. Uklonite takav klaster naredbom container cluster delete --name <name>.
  • Čvorovi ostaju u stanju NotReady: upotrijebili ste --cni NONE. Primijenite CNI manifest.
  • Kontejner čvora ne možete zaustaviti: to je namjerno. container stop i delete odbijaju čvorove klastera; upotrijebite container cluster delete.

Usporedba s Docker Desktopom i OrbStackom

Docker Desktop ima ugrađeni Kubernetes s kubeadmom (jedan čvor) ili kindom (više čvorova), a OrbStack ima ugrađeni klaster s jednim čvorom. container cluster pokreće kubeadm na slikama kindest/node, svaki čvor u vlastitom VM-u, s klasterima s više čvorova i zajedničkim spremištem slika. Pogledajte potpunu usporedbu.

Povezani vodiči

  • S Docker Desktopa na Apple container: naredbe, Compose, volumeni i nedostaci
  • Kontejneri i volumeni na vanjskom disku na Macu
  • Kontejner iz naredbe docker run na Macu (docker run u container run)
  • Apple container GUI za Mac: cjeloviti vodič za apple/container
  • Kubernetes na Apple containeru: GUI za container cluster i Kubernetes preglednik

Pitanja i odgovori

Mogu li pokrenuti Kubernetes na Macu bez Dockera?

Da. Appleov CLI container sam stvara Kubernetes klastere naredbom container cluster create. Svaki čvor radi kao lagani VM, a ne trebate Docker, Docker Desktop, kind ni minikube.

Koliko čvorova može imati container cluster?

Jednu kontrolnu ravninu i onoliko radnih čvorova koliko vaš Mac ima CPU-ova i memorije. Postavite ih s --workers; na CLI-ju 1.7 svaka skupina radnih čvorova može imati vlastite CPU-ove i memoriju.

Kako u klasteru koristiti lokalno izgrađenu sliku?

Stvorite klaster s --shared-image-store (CLI 1.7), izgradite sliku naredbom container build -t name:tag . i upotrijebite name:tag u specifikaciji poda. Registar nije potreban.

Koju verziju Kubernetesa koristi container cluster?

CLI 1.7.1 prema zadanim postavkama koristi sliku čvora kindest/node:v1.35.5. Drugu verziju odaberite s --node-image, npr. docker.io/kindest/node:v1.34.11. Gantry prikazuje verziju u pregledu klastera.

Postoji li GUI za container cluster?

Da. Gantry stvara i briše klastere, prikazuje čvorove i u svojem odjeljku Kubernetes pregledava podove, deploymente, servise, zapisnike i tajne. Besplatan je i otvorenog koda.

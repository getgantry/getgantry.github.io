Gantry/Fra Docker Desktop

Bytt fra Docker Desktop til Apple container

Apples verktøy container kjører de samme OCI-imagene som Docker, så det meste av arbeidet ditt kan flyttes over med noen få endrede kommandoer. Denne guiden viser hva Docker-kommandoene heter i container, flytter images og volumer, og lister opp manglene du bør kjenne til før du bytter.

Kort fortalt. Installer den signerte container-pakken, bytt ut docker med container for run, build, logs, exec og images, kopier navngitte volumer med en tar-fil, og åpne docker-compose.yml i Gantry, fordi CLI-en ikke har compose. Du kan beholde Docker Desktop installert mens du prøver.

Dette endres

  • Én VM per container. Docker Desktop kjører alle containere i én Linux-VM. apple/container starter en liten VM for hver container, så hver av dem får sin egen IP-adresse på Macen.
  • Samme images og registre. Images er OCI-images; du henter fra Docker Hub, GHCR og private registre som før.
  • Ingen lisensavgift. apple/container er Apache 2.0. Docker Desktop krever et betalt abonnement i organisasjoner med 250 eller flere ansatte eller minst 10 millioner dollar i omsetning.
  • Bare Apple-chip og macOS 26. På Intel-Macer bør du bli værende ved en Docker-motor.

De fleste flaggene til run er de samme: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus og -m. Vil du konvertere en lang kommando, limer du den inn i Gantry: se Opprett en container fra en docker run-kommando.

    Ta med imagene dine

Images fra et register: hent dem på nytt med container image pull. Lokale images som bare finnes i Docker: lagre dem i et arkiv og last det inn. container image load leser OCI-arkiver, og nyere Docker-versjoner skriver en OCI-layout med docker save. Feiler innlastingen, sender du imaget til et register og henter det derfra.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Flytt navngitte volumer

Docker lagrer volumdata inne i sin VM. Kopier hvert volum til en tar-fil med en kortlevd container, og pakk den deretter ut i et nytt apple/container-volum:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Et navngitt volum i apple/container er et glissent ext4-diskbilde, som standard på høyst 512 GB. Angi en annen størrelse med --opt size=20g. Bind-monteringer av mapper på Macen fungerer som i Docker: -v ~/project:/app.

    Compose-filer

container-CLI-en har ingen compose-kommando. Åpne docker-compose.yml i Gantry i stedet (Finder, Arkiv ▸ Åpne Compose-fil… eller dra og slipp). Gantry bygger build:-tjenestene, oppretter prosjektnettverket og de navngitte volumene, og starter tjenestene i depends_on-rekkefølge. Tjenestene når hverandre via tjenestenavnet gjennom DNS-aliaser i nettverket.

    Nettverk og porter
  • -p 8080:80 publiserer en port på localhost, som i Docker.
  • Hver container har også sin egen IP-adresse. Opprett et lokalt DNS-domene med sudo container system dns create test og kjør containere med --dns-domain test: de får navn som web.test.
  • container network create lager brukernettverk; containere i samme nettverk når hverandre.
  • Det finnes ingen --network host-, none- eller container:-modus.
    Dette mangler
  • Ingen Docker Engine API. Verktøy som snakker med /var/run/docker.sock, som Testcontainers, Docker-SDK-ene eller Dev Containers, ser ikke apple/container.
  • Ingen omstartsregler. --restart finnes ikke; en container starter ikke på nytt av seg selv.
  • Ingen Compose i CLI-en. Gantry kjører Compose-filer: se Compose-filer.
  • Ingen Docker Desktop-utvidelser.
  • Bare hele CPU-er: --cpus 0.5 fungerer ikke.
  • Kubernetes fungerer annerledes: bruk container cluster, se Kjør Kubernetes på en Mac.
    Behold begge mens du bytter

Gantry administrerer apple/container og alle Docker-motorer (Docker Desktop, OrbStack, Colima eller Docker over SSH) i ett sidepanel. Flytt ett prosjekt om gangen, og behold Docker for verktøyene som trenger API-et. Når du ikke lenger trenger det, kan du fjerne Docker Desktop.

Spørsmål og svar

Kan Apple container erstatte Docker Desktop?

For å kjøre, bygge og hente containere på Apple-chip, ja. Det har ikke Docker Engine API, omstartsregler, utvidelser eller en compose-kommando. Gantry legger til Compose-filer og et GUI.

Fungerer Docker-images med Apple container?

Ja. apple/container bruker standard OCI-images og henter fra de samme registrene. arm64-images kjører nativt; amd64-images kjører via Rosetta med --arch amd64.

Fungerer docker compose med Apple container?

Ikke fra CLI-en: det finnes ingen container compose. Gantry leser docker-compose.yml og kjører tjenestene på apple/container for deg.

Kan jeg bruke Docker Desktop og Apple container samtidig?

Ja. De deler ikke images eller volumer, men de kan kjøre side om side. Gantry viser begge i ett vindu.

Er Apple container gratis til kommersiell bruk?

Ja. apple/container har åpen kildekode under Apache 2.0-lisensen, og Gantry har MIT-lisens. Begge er gratis for bedrifter av alle størrelser.

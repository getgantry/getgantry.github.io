Gantry/Kubernetes en apple/container

Kubernetes en Apple container

apple/container puede ejecutar un clúster de Kubernetes cuyos nodos son contenedores en tu Mac. Gantry es una GUI para ello: crea un clúster, observa cómo arrancan sus nodos, conecta kubectl y carga tus imágenes locales, sin largas líneas de comando de container cluster.

En resumen. En un host apple/container, la sección Clústeres de Gantry crea y elimina clústeres de Kubernetes con container cluster (CLI 1.6.1) o container k8s (CLI 1.5.0 a 1.6.0). Admite varios workers, una CNI personalizada, una vista de nodos, kubeconfig y contexto de kubectl, y Cargar en el clúster para imágenes locales.

Requisitos

  • Un Mac con chip de Apple, macOS 26 y Gantry (brew install --cask getgantry/tap/gantry).
  • La CLI container 1.5.0 o posterior; se recomienda la 1.6.1. Los workers y la CNI Ninguno requieren la 1.6.0 o posterior.
  • kubectl, si quieres usar el clúster desde el terminal.

Crear un clúster

  1. Selecciona tu host apple/container y abre Clústeres en la barra lateral.
  2. Empieza un clúster nuevo y rellena las opciones de abajo.
  3. Créalo. La lista muestra el clúster nuevo con el progreso en directo. Cancelar detiene la creación y elimina los nodos ya creados.
OpciónParámetro de la CLINotas
Nombre--nameTambién es el nombre del contexto de kubeconfig
Workers--workersNúmero de nodos worker. CLI 1.6.0+
CPU--cpusPor nodo
Memoria--memoryPor nodo, por ejemplo 4G
Imagen de nodo--node-imageSi se deja vacía, se usa la predeterminada de la CLI
CNI--cniPredeterminado (kindnet incluido), Ninguno (NONE, CLI 1.6.0+) o la ruta de un manifiesto personalizado

El mismo comando en la CLI:

Shell
container cluster create --name dev --workers 2 --cpus 2 --memory 4G

Nodos y detalles del clúster

La lista de clústeres muestra cada clúster con sus nodos: rol, estado y dirección. La vista de detalle tiene un Resumen (contexto de kubectl, servidor de API, workers, red de nodos), una tabla de Nodos, Inspeccionar para los datos en bruto de los nodos, y las acciones Escribir kubeconfig, Copiar comando de contexto de kubectl y Eliminar.

Conectar kubectl

Al crear el clúster, la CLI añade a ~/.kube/config un contexto con el nombre del clúster. Usa Copiar comando de contexto de kubectl en Gantry, o escríbelo:

Shell
kubectl --context dev get nodes

Para tener el clúster en su propio archivo, usa Escribir kubeconfig. Gantry ejecuta container cluster write-config; la ruta predeterminada es ~/.kube/<name>.kubeconfig.

Cargar imágenes locales en el clúster

Compila o descarga una imagen en el host apple/container y luego haz clic derecho en ella en Imágenes y elige Cargar en el clúster. Gantry ejecuta container cluster load-image, que copia la imagen en el containerd de cada nodo. No necesitas un registro para el desarrollo local.

Shell
container cluster load-image --name dev myapp:dev

Elegir una CNI

La predeterminada es el manifiesto de kindnet incluido. Elige Manifiesto personalizado para instalar tu propia CNI desde un archivo, por ejemplo Calico o Cilium. Elige Ninguno para instalar tú una CNI más adelante; hasta entonces, los nodos siguen en NotReady.

Clústeres desde agentes de IA

El servidor MCP de Gantry tiene list_clusters, create_cluster y delete_cluster, así que un agente como Claude Code puede crear un clúster temporal para una prueba y eliminarlo después.

Añadir el servidor MCP de Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Preguntas y respuestas

¿Apple container es compatible con Kubernetes?

Sí. La CLI container crea clústeres de Kubernetes cuyos nodos se ejecutan como contenedores: container cluster en la CLI 1.6.1, container k8s en las CLI 1.5.0 a 1.6.0. Gantry le pone una GUI.

¿Gantry es compatible con container cluster?

Sí. Gantry lista, crea y elimina clústeres en hosts apple/container, muestra sus nodos, escribe el kubeconfig, copia el comando de contexto de kubectl y carga imágenes locales en un clúster. Usa cluster o k8s según tu versión de la CLI.

¿Cómo uso kubectl con un clúster de apple/container?

Cuando la CLI crea un clúster, añade a ~/.kube/config un contexto de kubeconfig con el nombre del clúster. Ejecuta kubectl --context <name> get nodes. Para tenerlo en un archivo aparte, usa Escribir kubeconfig en Gantry; la ruta predeterminada es ~/.kube/<name>.kubeconfig.

¿Cómo meto una imagen local en el clúster sin un registro?

En Gantry, haz clic derecho en la imagen en Imágenes y elige Cargar en el clúster. Gantry ejecuta container cluster load-image, que copia la imagen en el containerd de cada nodo.

¿Puedo crear un clúster con varios nodos?

Sí. Indica el número de workers en la hoja de creación. Los workers requieren la CLI 1.6.0 o posterior.

¿Puedo usar mi propia CNI, como Calico o Cilium?

Sí. Elige Manifiesto personalizado y selecciona el archivo del manifiesto, o elige Ninguno y aplica tú una CNI cuando el clúster haya arrancado. Los nodos siguen en NotReady hasta que hay una CNI en ejecución. Ninguno requiere la CLI 1.6.0 o posterior. La CNI predeterminada es el manifiesto de kindnet incluido.

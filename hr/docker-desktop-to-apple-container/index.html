Gantry/S Docker Desktopa

Prelazak s Docker Desktopa na Apple container

Appleov alat container pokreće iste OCI slike kao Docker, pa se većina vašeg rada prenosi uz nekoliko izmjena u naredbama. Ovaj vodič povezuje Docker s alatom container, prenosi slike i volumene i navodi nedostatke koje trebate znati prije prelaska.

Ukratko. Instalirajte potpisani paket container, zamijenite docker s container za run, build, logs, exec i images, kopirajte imenovane volumene putem tar datoteke i otvorite svoj docker-compose.yml u Gantryju, jer CLI nema compose. Dok isprobavate, Docker Desktop može ostati instaliran.

Što se mijenja

  • Jedan VM po kontejneru. Docker Desktop pokreće sve kontejnere u jednom Linux VM-u. apple/container za svaki kontejner pokreće mali VM, pa svaki dobiva vlastitu IP adresu na vašem Macu.
  • Iste slike i registri. Slike su OCI slike; povlačite ih s Docker Huba, GHCR-a i privatnih registara kao i prije.
  • Bez naknade za licencu. apple/container je pod licencom Apache 2.0. Docker Desktop zahtijeva plaćeni paket u organizacijama s 250 ili više zaposlenih ili 10 milijuna USD ili više prihoda.
  • Samo Apple silicon i macOS 26. Na Intel Macovima ostanite na Docker engineu.

Većina zastavica naredbe run je ista: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus i -m. Da biste pretvorili dugu naredbu, zalijepite je u Gantry: pogledajte Stvaranje kontejnera iz naredbe docker run.

    Prijenos slika

Slike iz registra: ponovno ih povucite naredbom container image pull. Lokalne slike koje postoje samo u Dockeru: spremite ih u arhivu i učitajte je. container image load čita OCI arhive, a novije verzije Dockera naredbom docker save zapisuju OCI layout. Ako učitavanje ne uspije, pošaljite sliku u registar i povucite je.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Premještanje imenovanih volumena

Docker drži podatke volumena unutar svojeg VM-a. Kopirajte svaki volumen u tar datoteku pomoću kratkotrajnog kontejnera, a zatim ga raspakirajte u novi apple/container volumen:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Imenovani volumen u apple/containeru je rijetka (sparse) ext4 slika diska, prema zadanim postavkama najviše 512 GB. Drugu veličinu postavite s --opt size=20g. Bind mountovi mapa na vašem Macu rade kao u Dockeru: -v ~/project:/app.

    Compose datoteke

CLI container nema naredbu compose. Umjesto toga otvorite docker-compose.yml u Gantryju (Finder, Datoteka ▸ Otvori Compose datoteku… ili povlačenjem i ispuštanjem). Gantry gradi servise s build:, stvara mrežu projekta i imenovane volumene te pokreće servise redoslijedom iz depends_on. Servisi se međusobno dosežu po nazivu servisa putem DNS aliasa mreže.

    Mreže i portovi
  • -p 8080:80 objavljuje port na localhost, kao u Dockeru.
  • Svaki kontejner ima i vlastitu IP adresu. Stvorite lokalnu DNS domenu naredbom sudo container system dns create test i pokrećite kontejnere s --dns-domain test: dobivaju nazive kao što je web.test.
  • container network create stvara korisničke mreže; kontejneri na istoj mreži dosežu jedan drugoga.
  • Nema načina --network host, none ni container:.
    Što nedostaje
  • Nema Docker Engine API-ja. Alati koji komuniciraju s /var/run/docker.sock, kao što su Testcontainers, Docker SDK-ovi ili Dev Containers, ne vide apple/container.
  • Nema pravila ponovnog pokretanja. --restart nije dostupan; kontejner se ne pokreće ponovno sam od sebe.
  • Nema Composea u CLI-ju. Gantry pokreće Compose datoteke: pogledajte Compose datoteke.
  • Nema proširenja za Docker Desktop.
  • Samo cijeli CPU-ovi: --cpus 0.5 ne radi.
  • Kubernetes radi drukčije: upotrijebite container cluster, pogledajte Pokretanje Kubernetesa na Macu.
    Zadržite oba tijekom prelaska

Gantry upravlja apple/containerom i bilo kojim Docker engineom (Docker Desktop, OrbStack, Colima ili Docker putem SSH-a) u jednoj bočnoj traci. Premještajte jedan po jedan projekt, a Docker zadržite za alate kojima treba njegov API. Kad vam više ne treba, Docker Desktop možete ukloniti.

Pitanja i odgovori

Može li Apple container zamijeniti Docker Desktop?

Za pokretanje, izgradnju i povlačenje kontejnera na Apple siliconu, da. Nema Docker Engine API, pravila ponovnog pokretanja, proširenja ni naredbu compose. Gantry dodaje Compose datoteke i GUI.

Rade li Docker slike s Apple containerom?

Da. apple/container koristi standardne OCI slike i povlači ih iz istih registara. arm64 slike rade nativno; amd64 slike rade putem Rosette uz --arch amd64.

Radi li docker compose s Apple containerom?

Ne iz CLI-ja: nema naredbe container compose. Gantry čita docker-compose.yml i umjesto vas pokreće servise na apple/containeru.

Mogu li istodobno koristiti Docker Desktop i Apple container?

Da. Ne dijele slike ni volumene, ali mogu raditi jedan uz drugoga. Gantry prikazuje oba u jednom prozoru.

Je li Apple container besplatan za komercijalnu upotrebu?

Da. apple/container je otvorenog koda pod licencom Apache 2.0, a Gantry je pod licencom MIT. Oba su besplatna za tvrtke bilo koje veličine.

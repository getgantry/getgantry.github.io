Gantry/Kubernetes en Mac

Ejecutar Kubernetes en un Mac con Apple container

La herramienta container de Apple puede crear un clúster local de Kubernetes con un solo comando. Cada nodo es una máquina virtual ligera en tu Mac. Esta guía va de un Mac vacío a un Deployment en ejecución, primero en el terminal y después en Gantry.

En resumen. Instala el paquete firmado de container 1.7.1, ejecuta container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, compila una imagen con container build y ejecútala en el clúster por su nombre. Gantry muestra el mismo clúster en una ventana: nodos, pods, logs, un shell y reenvíos de puertos.

Qué necesitas

  • Un Mac con chip de Apple y macOS 26 o posterior.
  • La CLI container 1.7.1 del .pkg firmado de la página de versiones de apple/container. La versión de Homebrew de la 1.7.1 no incluye los servicios de clúster, así que container cluster falla con cluster service unavailable.
  • Unos 6 GB de memoria libre para el ejemplo de abajo: tres nodos de 2 GB cada uno.
  • kubectl, si quieres usar el clúster desde el terminal (brew install kubectl).

Inicia los servicios una vez después de instalar el paquete:

Terminal
container system start

Crear el clúster

Este comando crea un clúster llamado dev con un nodo de plano de control y dos workers. Cada nodo recibe 2 CPU y 2 GB de memoria:

Terminal
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M define el tamaño de un grupo de workers. Repítelo para grupos de distinto tamaño. Sin --workers, un solo nodo hace de plano de control y de worker.
  • --cpus y --memory definen el tamaño del plano de control. El valor predeterminado es una cuarta parte de la CPU y la memoria de tu Mac, como mínimo 2 CPU y 2 GB.
  • --shared-image-store permite que los nodos usen tus imágenes locales (más abajo). No se puede cambiar después: elimina el clúster y vuelve a crearlo.
  • --cni ./calico.yaml instala tu propia CNI en lugar del kindnet incluido; --cni NONE no instala ninguna.

La CLI añade a ~/.kube/config un contexto llamado dev. Comprueba los nodos:

Terminal
container cluster list --nodes
kubectl --context dev get nodes

Ejecutar una imagen local sin registro

Con --shared-image-store, los nodos pueden ejecutar cualquier imagen de tu almacén de imágenes local de container. Compila una imagen y úsala por su nombre:

Terminal
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Nota
Después de recompilar el mismo tag, ejecuta kubectl rollout restart con imagePullPolicy: Always, o usa un tag nuevo. Con IfNotPresent, un nodo se queda con la copia que ya tiene. Cualquier proceso con root en un nodo puede leer todas las imágenes de tu almacén local, también las privadas, así que usa el almacén compartido solo para el desarrollo local.

En las CLI 1.5 y 1.6 no hay almacén compartido. Ahí, usa container cluster load-image o Cargar en el clúster en Gantry. La CLI 1.7 eliminó load-image.

Abrir la app en un navegador

Reenvía un puerto local al Deployment y abre http://localhost:8080:

Terminal
kubectl --context dev port-forward deployment/hello 8080:80

Explorar el clúster en Gantry

Gantry muestra el mismo clúster sin comandos. Añade tu host apple/container, abre Clústeres y selecciona dev. El resumen muestra la versión de Kubernetes, el almacén de imágenes, los workers y su CPU y memoria. Haz clic en Explorar recursos para abrir la sección Kubernetes en ese contexto.

  • Pods, Deployments, StatefulSets, DaemonSets, servicios, Ingress, ConfigMaps, secretos, nodos y eventos, de un espacio de nombres o de todos.
  • Logs de los pods con seguimiento y últimas líneas, un shell en el pod y reenvíos de puertos con una lista desde la que puedes detenerlos.
  • Escalado, reinicio del despliegue, eliminación y Aplicar YAML desde un manifiesto pegado o un archivo.
  • Los valores de los secretos siguen ocultos hasta que haces clic en Mostrar.

El navegador de Kubernetes ejecuta kubectl. Si falta, Gantry muestra brew install kubectl y puede ejecutarlo por ti. Está en desarrollo un cliente nativo que no necesita kubectl.

También puedes crear el clúster en Gantry: Clústeres ▸ Nuevo clúster tiene controles para el plano de control y los workers y un interruptor Usar imágenes locales. Más información en la página Kubernetes en apple/container.

Detener y eliminar el clúster

Terminal
container cluster delete --name dev

Si el nodo del plano de control se detiene, por ejemplo después de container system stop, elimina el clúster y vuelve a crearlo. Crea un clúster desechable con --rm para que sus nodos se eliminen cuando se detengan.

Problemas habituales

  • cluster service unavailable: la CLI es la versión de Homebrew o los servicios no están en ejecución. Instala el paquete firmado o reinicia los servicios con container system stop y container system start. Gantry muestra el mismo consejo en Clústeres.
  • Falta un clúster antiguo en la lista: la CLI 1.7 no lista los clústeres creados con la 1.6 o anterior. Elimina uno con container cluster delete --name <name>.
  • Los nodos siguen en NotReady: has usado --cni NONE. Aplica un manifiesto de CNI.
  • No puedes detener el contenedor de un nodo: es intencionado. container stop y delete rechazan los nodos de clúster; usa container cluster delete.

Comparación con Docker Desktop y OrbStack

Docker Desktop tiene Kubernetes integrado con kubeadm (un nodo) o kind (varios nodos), y OrbStack tiene integrado un clúster de un solo nodo. container cluster ejecuta kubeadm sobre imágenes kindest/node, cada nodo en su propia VM, con clústeres de varios nodos y el almacén de imágenes compartido. Preguntas y respuestas

¿Puedo ejecutar Kubernetes en un Mac sin Docker?

Sí. La CLI container de Apple crea por sí misma clústeres de Kubernetes con container cluster create. Cada nodo se ejecuta como una VM ligera, y no necesitas Docker, Docker Desktop, kind ni minikube.

¿Cuántos nodos puede tener un container cluster?

Un plano de control y tantos workers como permitan la CPU y la memoria de tu Mac. Defínelos con --workers; en la CLI 1.7, cada grupo de workers puede tener su propia CPU y memoria.

¿Cómo uso en el clúster una imagen compilada en local?

Crea el clúster con --shared-image-store (CLI 1.7), compila la imagen con container build -t name:tag . y usa name:tag en la especificación del pod. No hace falta ningún registro.

¿Qué versión de Kubernetes usa container cluster?

La CLI 1.7.1 usa de forma predeterminada la imagen de nodo kindest/node:v1.35.5. Elige otra versión con --node-image, por ejemplo docker.io/kindest/node:v1.34.11. Gantry muestra la versión en el resumen del clúster.

¿Hay una GUI para container cluster?

Sí. Gantry crea y elimina clústeres, muestra los nodos y explora pods, Deployments, servicios, logs y secretos en su sección Kubernetes. Es gratuita y de código abierto.

Gantry/Из docker run

Создание контейнера из команды docker run

В большинстве README есть строка docker run. Gantry читает эту строку и заполняет форму нового контейнера — для хоста Docker или для инструмента container от Apple. Это руководство показывает, как это работает и как преобразовать команду вручную.

Коротко. В Gantry откройте Новый контейнер, выберите Вставить команду…, вставьте строку docker run и нажмите Заполнить форму. Gantry перечисляет флаги, которые не может использовать, с причиной для каждого. Для CLI большинство флагов совпадают: замените docker run на container run и уберите --restart.

Вставка команды в Gantry

  1. Выберите хост: хост Docker или хост apple/container.
  2. Откройте Контейнеры и нажмите Новый контейнер.
  3. Нажмите Вставить команду… и вставьте строку. Переносы строк с \, кавычки, приглашение $ и sudo не мешают.
  4. Проверьте предпросмотр: образ, флаги, которые Gantry не может использовать, примечания и предупреждения для этого хоста.
  5. Нажмите Заполнить форму, проверьте значения и создайте контейнер.

Gantry понимает docker run, docker container run, docker create, podman run и container run. Текст после &&, ||, ; или | пропускается, и Gantry пишет об этом примечание.

Gantry знает ещё около 80 флагов Docker: он правильно пропускает их значения и показывает их как неиспользуемые, поэтому ничего не теряется без примечания.

    Предупреждения для хостов apple/container

Некоторых параметров Docker в apple/container нет. Gantry предупреждает о них и не включает их в запрос на создание:

  • политики перезапуска (--restart);
  • дробные CPU, например --cpus 0.5;
  • сетевые режимы host, none и container:;
  • порты без порта хоста, например -p 80.

На хосте Docker Gantry предупреждает о параметрах apple/container: DNS-домене и параметрах ядра.

    Как вручную перевести docker run в container run

Для CLI большинство флагов остаются прежними. Пример с Redis:

Терминал
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

превращается в:

Терминал
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Сначала создайте именованный том командой container volume create. Уберите --restart и округлите --cpus до целого числа. --platform работает так же, как в Docker.

    Копирование контейнера как команды

Работает и в обратную сторону. Нажмите на контейнер правой кнопкой или откройте меню «Ещё» и выберите Скопировать как команду: Gantry составит строку docker run или container run. Значения по умолчанию из образа, например его окружение и команду, он не включает, поэтому строка остаётся короткой. Это работает и для остановленных контейнеров.

    Сохранение как шаблона

В окне создания контейнера откройте Шаблоны и выберите Сохранить как шаблон…. В следующий раз Заполнить из шаблона даст ту же форму на любом хосте. Шаблоны хранятся в ~/Library/Application Support/Gantry/recipes.json, поэтому их можно сохранить в резервную копию или передать коллегам.

    Ограничения
  • Gantry сохраняет путь из --env-file, но не читает сам файл и не берёт значение из вашей оболочки для -e KEY без значения.
  • Монтирования tmpfs и анонимные тома из --mount показываются как неподдерживаемые.
  • Два порта для одного порта контейнера (-p 8080:80 -p 8081:80) попадают в форму, но форма затем отклоняет дубликат.

Вопросы и ответы

Как перевести docker run в container run?

Замените docker run на container run. -d, -p, -e, -v, --name, --rm, -it, -w и --entrypoint остаются прежними. Уберите --restart и используйте целые CPU. Или вставьте строку в Gantry, и он заполнит форму.

Может ли Gantry импортировать команду docker run?

Да. Вставить команду… в окне создания контейнера понимает docker run, docker create, podman run и container run и заполняет форму.

Что происходит с флагами, которые Gantry не поддерживает?

Они перечислены в предпросмотре с причиной и остаются в форме в разделе «Из вставленной команды», чтобы вы могли проверить их позже.

Можно ли превратить работающий контейнер обратно в команду docker run?

Да. Скопировать как команду в меню контейнера составляет строку docker run или container run для этого контейнера.

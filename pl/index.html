Aplikacja na Maca dla Apple container i Dockera

Gantry to darmowa aplikacja open source na Maca dla narzędzia container od Apple i dla Dockera, lokalnie i przez SSH. Uruchamiaj kontenery, klastry Kubernetes, maszyny i projekty Compose na apple/container z jednego okna, obok hostów Docker. Darmowa alternatywa dla Docker Desktop i OrbStack na Maca.

Pobierz na macOS
$ brew install --cask getgantry/tap/gantry

Gantry 0.29.0 · macOS 26+ · Apple silicon i Intel · licencja MIT · 28 języków · serwer MCP w zestawie

Kontenery

Twórz, uruchamiaj, otwieraj i zmieniaj kontenery na każdym hoście.

  • container run
  • docker exec -it
  • docker cp
  • docker port
Wklej docker run
Wklej polecenie docker run, podman run lub container run, a Gantry wypełni formularz Nowy kontener i wymieni flagi, których nie może użyć. Każdy kontener możesz skopiować z powrotem jako polecenie albo zapisać jako przepis. Jak to działa
Wbudowany terminal exec
Pełna emulacja terminala w każdym uruchomionym kontenerze, lokalnym lub zdalnym – z motywami kolorów (System, Solarized, Dracula, Nord).
Przeglądarka plików z przeciąganiem
Przeglądaj system plików kontenera, przenoś pliki do i z kontenera i upuszczaj całe foldery prosto z Findera – na hostach Docker i apple/container.
Otwieranie w przeglądarce i przekierowanie
Jedno kliknięcie otwiera opublikowany port. Porty SSH są automatycznie tunelowane na localhost – a jeśli port jest zajęty, Gantry wybiera wolny, który możesz zmienić.
Udostępnianie w internecie
Jedno kliknięcie udostępnia opublikowany port przez Cloudflare Tunnel. Gantry instaluje za Ciebie cloudflared, a potem daje szybki tunel (bez konta, adres URL *.trycloudflare.com) lub nazwany tunel w Twojej własnej domenie – w sam raz na podgląd wersji deweloperskiej, webhook albo dostęp agenta AI do kontenera na Twoim Macu.
Sekrety z pęku kluczy w środowisku
Przechowuj hasła i tokeny w pęku kluczy macOS (Ustawienia → Sekrety) i używaj ich jako zmiennych środowiskowych w oknach Nowy kontener i Szybkie uruchomienie. Formularz pokazuje keychain:NAME, nigdy wartość, a Gantry odczytuje wartość dopiero przy tworzeniu kontenera. Eksport Compose, przepisy i Kopiuj jako polecenie zapisują nazwę, nie wartość.
Wiele naraz
Zaznacz kilka kontenerów, obrazów, woluminów lub sieci i uruchom, zatrzymaj, uruchom ponownie lub usuń je w jednym kroku, z postępem i raportem dla każdego elementu.
Statystyki w czasie rzeczywistym
CPU, pamięć, sieć i dyskowe I/O na wykresach na żywo, z próbkowaniem co 1 s.
Kontenery na dysku zewnętrznym
Przenieś wszystkie dane apple/container na dysk zewnętrzny, trzymaj woluminy na wybranym dysku, a gdy ten dysk nie jest podłączony, zobaczysz jasne ostrzeżenie. Przeczytaj przewodnik

Obrazy i kompilacje

Pobieraj, buduj, skanuj i usuwaj obrazy.

  • docker build
  • docker pull
  • trivy image
  • docker system prune
Budowanie i pobieranie obrazów
Upuść Dockerfile na okno, aby zbudować obraz z logiem na żywo, albo pobierz obraz według referencji z postępem dla każdej warstwy. Taguj, czyść i przeglądaj historię warstw. Oznaczenie wskazuje obrazy zbudowane dla innej architektury CPU niż host.
Historia kompilacji
Każdy host ma sekcję Kompilacje: kompilacje z ich krokami, trafieniami w pamięć podręczną i logiem. Gantry zachowuje kompilacje, które sam uruchamia, z nazwami argumentów budowania, ale bez ich wartości. Na hostach Docker odczytuje też docker buildx history (buildx 0.23.0 lub nowszy). apple/container nie przechowuje historii kompilacji, więc tam widzisz kompilacje uruchomione przez Gantry.
Skanowanie obrazów za pomocą Trivy lub Grype
Wybierz Skanuj pod kątem luk… przy obrazie. Gantry uruchamia zainstalowane przez ciebie Trivy (0.50.0 lub nowsze) lub Grype (0.74.0 lub nowsze), na przykład z Homebrew, i grupuje wyniki od krytycznych do nieznanych. Eksportuj SBOM zapisuje CycloneDX lub, z Trivy, SPDX. Działa na apple/container, lokalnym Dockerze i Dockerze przez SSH, gdzie Gantry skanuje kopię otagowanego obrazu z rejestru.
Prywatne rejestry
Pobieranie korzysta z docker login, którego już używasz – Gantry odczytuje dane logowania z ~/.docker/config.json, pomocników i pęku kluczy, przy tworzeniu kontenera, w Szybkim uruchomieniu i w Compose.
Odzyskaj miejsce
Jeden panel pokazuje, co zajmuje miejsce – obrazy bez tagu, zatrzymane kontenery, nieużywane woluminy, pamięć podręczną budowania – wraz z rozmiarami, i czyści każdą kategorię osobno lub wszystkie naraz. Na apple/container uruchamia też Przytnij dysk.

Compose

Uruchom plik docker-compose.yml w Dockerze lub na apple/container albo utwórz go z działających kontenerów.

  • docker compose up -d
  • docker compose down
  • docker compose logs -f
Compose na każdym hoście
Kontenery są grupowane według projektu Compose. Uruchom plik Compose na dowolnym hoście – lokalnym Dockerze, SSH lub apple/container – z wbudowanym edytorem YAML; mechanizm uruchamiania dopasowuje się do silnika.
Eksport jako Compose
Wybierz Eksportuj jako Compose… przy jednym lub kilku kontenerach, aby otrzymać docker-compose.yml z portami, montowaniami, sieciami, polityką ponownego uruchamiania, testem stanu zdrowia, limitami i nie tylko. Wartości, które wyglądają na sekrety, stają się ${NAME}, chyba że je dołączysz. Na hostach apple/container Gantry ostrzega o flagach, których Compose nie potrafi wyrazić. Jak to działa

Kubernetes

Przeglądaj każdy kontekst kubeconfig albo utwórz klaster z apple/container.

  • kubectl get pods -A
  • kubectl logs -f
  • kubectl port-forward
  • container cluster
Przeglądarka Kubernetes
Przeglądaj pody, deploymenty, StatefulSety, DaemonSety, usługi, ingressy, ConfigMapy, sekrety, węzły i zdarzenia dowolnego kontekstu kubeconfig. Śledź logi podów, otwieraj powłokę, przekierowuj porty, skaluj, restartuj wdrożenia i stosuj YAML. Gantry sam łączy się z API Kubernetes, więc klaster utworzony poleceniem container cluster create można przeglądać bez instalowania czegokolwiek: bez kubectl.
Klastry Kubernetes
Utwórz klaster Kubernetes poleceniem container cluster: ustaw osobno rozmiar warstwy sterowania i węzłów roboczych, wybierz CNI i zobacz węzły, wersję Kubernetes i kontekst kubeconfig. Węzły klastra są chronione przed przypadkowym zatrzymaniem i usunięciem. Więcej

Hosty i flota

Ten Mac, hosty Docker przez SSH i apple/container na jednym pulpicie.

  • docker -H ssh://user@host
  • docker context use
  • docker stats
Jeden pulpit dla wszystkich hostów
Lokalny demon, flota SSH i apple/container na jednym ekranie – wykresy CPU i pamięci na żywo, podział kontenerów według stanu i problemy ze zdrowiem, które prowadzą prosto do winowajcy.
Zdalne hosty przez SSH
Tunelowanie dokładnie jak docker -H ssh:// przez dial-stdio – bastiony ProxyJump, uwierzytelnianie wieloma kluczami, automatyczne ponowne łączenie. Nic do instalowania na serwerze, sekrety w pęku kluczy. Import jednym kliknięciem z ~/.ssh/config i docker context ls.
Użycie zasobów dla wszystkich hostów
Jedna sortowalna tabela uruchomionych kontenerów na każdym podłączonym hoście: host, nazwa, obraz, CPU, pamięć, I/O sieci, I/O dysku i czas działania. Filtruj po nazwie, obrazie lub hoście albo pokaż jeden host. Kliknij dwukrotnie wiersz, aby otworzyć kontener. Tabela korzysta z próbek, które Gantry i tak zbiera co 5 sekund, więc nie otwiera nowych strumieni statystyk. Otwórz ją z paska bocznego, skrótem ⌘K lub przez gantry://open/usage.

Logi i awarie

Czytaj, przeszukuj i eksportuj logi. Znajdź przyczynę awarii kontenera.

  • docker logs -f
  • container logs
  • docker events
Logi na żywo
Śledzenie na żywo, wyszukiwanie ⌘F przez regex lub dosłowne, filtr poziomów (Error→Trace), kolory ANSI, bufor na 50 tys. wierszy – i scalone logi stacku dla całego projektu Compose.
Eksport logów
Eksportuj logi… (⇧⌘E) zapisuje widoczne wiersze, z filtrem poziomów, wyszukiwaniem i zakresem czasu, jako plik .log lub .txt. Kopiuj widoczne wiersze je kopiuje. Na hostach Docker możesz dodać znaczniki czasu i pokazać tylko ostatni okres, od 5 minut do jednego dnia.
Powiadomienia o awariach
Natywne powiadomienie, gdy kontener na dowolnym hoście ulegnie awarii, wyczerpie pamięć lub stanie się niezdrowy. Kliknij je, by przejść prosto do kontenera – zatrzymania wykonane przez Ciebie nie generują powiadomień.
Wyjaśnij awarię z Apple Intelligence
Wybierz Wyjaśnij awarię… przy kontenerze, który uległ awarii, lub przy nieudanej operacji. Gantry wysyła najnowsze logi i szczegóły, bez wartości zmiennych środowiskowych i tekstu przypominającego sekrety, do modelu na urządzeniu i pokazuje prawdopodobną przyczynę, dowody i kolejne kroki. Długie logi mogą trafić do Private Cloud Compute (macOS 27). Panel pokazuje dokładnie, co zostało wysłane.
Zrzuty ekranu w funkcji Wyjaśnij awarię
Upuść, wklej lub dodaj do 3 obrazków w funkcji Wyjaśnij awarię, na przykład zrzut ekranu strony z błędem. Obrazki zostają na tym Macu: czyta je tylko model na urządzeniu (macOS 27), nigdy Private Cloud Compute.

macOS

Pasek menu, powiadomienia, Spotlight, Skróty i klawiatura.

  • ⌘K
  • ⌥⌘P
  • ⇧⌘E
Część macOS
Powiadomienia z akcjami Uruchom ponownie, Pokaż logi i Kopiuj jako prompt. Spotlight znajduje kontenery, projekty Compose i hosty. Akcje Siri i Skrótów, widżet stanu floty, elementy sterujące w Centrum sterowania dla usług apple/container lub ulubionego kontenera oraz linki gantry:// dla skryptów.
Postęp na pasku menu
Panel na pasku menu pokazuje każde trwające pobieranie, budowanie i operację Compose z paskiem postępu, gotowymi warstwami lub usługami, bajtami, czasem i przyciskiem Anuluj. Ikona na pasku menu pokazuje, ile operacji trwa. Każdy projekt Compose ma Pobierz obrazy i Compose down; Compose down zachowuje woluminy i obrazy.
Paleta poleceń
Naciśnij ⌘K i pisz. Jedno wyszukiwanie obejmuje kontenery, projekty Compose, obrazy, woluminy, sieci, maszyny, klastry i hosty, z akcjami takimi jak Uruchom, Pokaż logi i Otwórz powłokę.
Touch ID przy nieodwracalnych czynnościach
Włącz tę opcję, a Gantry poprosi o Touch ID – lub hasło logowania – przed usunięciem kontenera lub hosta. Sekrety i tak są już w pęku kluczy.
Motywy terminala
Ubierz wbudowaną powłokę w System, Solarized Dark, Draculę lub Nord – pełna paleta pierwszego planu, tła i 16 kolorów ANSI, stosowana na żywo.

Natywne GUI na macOS dla Apple container

Narzędzie container od Apple uruchamia linuksowe kontenery jako lekkie maszyny wirtualne na Apple silicon, ale jest dostępne tylko jako narzędzie wiersza poleceń. Gantry to dla niego aplikacja desktopowa: tym, czym Docker Desktop jest dla Dockera, Gantry jest dla container. Obsługuje każde CLI container od 1.0 do zalecanego 1.7.1 i włącza każdą funkcję dopiero wtedy, gdy zainstalowane CLI ją obsługuje.

  • container system start
  • container machine
  • container builder start
  • container registry login
Kontenery, logi, statystyki i exec
Twórz, uruchamiaj, zatrzymuj, zabijaj i czyść; logi na żywo, statystyki, terminal exec, top i eksport do tar – w tym samym interfejsie co hosty Docker.
Klastry Kubernetes
Utwórz klaster Kubernetes poleceniem container cluster: ustaw osobno rozmiar warstwy sterowania i węzłów roboczych, wybierz CNI i zobacz węzły, wersję Kubernetes i kontekst kubeconfig. Węzły klastra są chronione przed przypadkowym zatrzymaniem i usunięciem. Więcej
Lokalne obrazy w klastrze
W CLI 1.7 włącz Używaj lokalnych obrazów (--shared-image-store), a pody uruchomią obrazy, które budujesz lub pobierasz, bez rejestru. W CLI 1.5 i 1.6 kliknij obraz prawym przyciskiem i wybierz Wczytaj do klastra.
Jasne wskazówki, gdy instalacja jest uszkodzona
Jeśli usługi klastra nie odpowiadają, Gantry mówi dlaczego. Wersja z Homebrew bez usług klastra dostaje link do podpisanego instalatora, a w każdym innym przypadku pojawia się przycisk Uruchom ponownie usługi.
Maszyny container w VS Code
Twórz, uruchamiaj i zatrzymuj linuksowe środowiska container machine, ustawiaj procesory i pamięć, otwieraj powłokę albo otwieraj maszynę w VS Code przez Remote-SSH.
Wirtualizacja zagnieżdżona i własne jądra
Uruchom maszynę z wirtualizacją zagnieżdżoną (M3 lub nowszy) albo z własnym jądrem. Uruchamiaj kontenery z własnego jądra z dodatkowymi argumentami rozruchu.
Compose dla Apple container
apple/container nie ma compose. Gantry uruchamia Twój docker-compose.yml: buduje, tworzy sieć i woluminy, a usługi uruchamia w kolejności depends_on. Nazwy usług są rozwiązywane przez aliasy DNS sieci.
Aliasy DNS sieci
Aliasy kontenerów, aliasy poddrzewa, takie jak .gateway, i krótkie nazwy, gdy ustawiona jest domyślna domena DNS. Każdy kontener dostaje routowalny adres IP i nazwę hosta name.domain.
Zarządzanie builderem obrazów
Zobacz stan buildera, obraz, procesory, pamięć i IP. Uruchom go z opcjami CPU, pamięci i DNS, zatrzymaj lub usuń. Gdy obraz buildera jest nieaktualny, Gantry proponuje jego ponowne utworzenie.
Logowania do rejestrów
Wyświetlaj, dodawaj i usuwaj logowania container registry. Hasło trafia do CLI wyłącznie przez stdin, a Gantry nie przechowuje jego kopii.
Instalacja jądra
Zainstaluj zalecane jądro, plik jądra lub archiwum tar i śledź postęp na żywo. Gantry ostrzega, gdy nie ma zainstalowanego domyślnego jądra.
Usługi i logi usług
Uruchamiaj, zatrzymuj i uruchamiaj ponownie usługi container, porównuj wersje klienta i serwera oraz śledź na żywo logi usług z filtrem poziomu, usługi i tekstu.
Edytor właściwości systemowych
Edytuj właściwości systemowe container w config.toml. Gantry oznacza zmiany, które wymagają restartu, i sam uruchamia ponownie usługi. W CLI 1.7 edytuje też domyślne ustawienia [container.dns]: serwery nazw, domeny wyszukiwania i opcje.
Zapis jako obraz i Przytnij dysk
Zapisz kontener jako obraz (container commit) i odzyskaj miejsce na dysku funkcją Przytnij dysk (container clean), dostępną także w panelu Odzyskaj miejsce.
Przeglądarka plików: wysyłanie i zapisywanie
Przeglądaj pliki kontenera, zapisuj je na Macu lub przeciągaj do Findera (container copy) i upuszczaj w kontenerze pliki albo całe foldery.
Szybkie uruchomienie i Finder
Wybierz obraz, udostępnij folder, zmapuj porty i wybierz domenę – i uruchom. Kliknij plik Compose prawym przyciskiem w Finderze i otwórz go w Gantry.
Etykiety ze znakiem =
CLI container odrzuca wartości etykiet ze znakiem =. Gantry koduje je przy tworzeniu i dekoduje przy odczycie, więc wartość taka jak a=b pozostaje nienaruszona.
Jedna flota, dwa środowiska
Hosty apple/container stoją obok lokalnego Dockera i hostów SSH na jednym pulpicie, z tymi samymi wykresami, stanem zdrowia i powiadomieniami o awariach.
Narzędzia MCP dla agentów
Wbudowany serwer MCP daje agentom te same możliwości: kontenery, maszyny, klastry i narzędzia systemowe apple_* dla usług, buildera, rejestrów, właściwości, logów i jąder.

  • Gantry kontra Docker Desktop, OrbStack i Podman Desktop
  • Z Docker Desktop
  • Dysk zewnętrzny
  • Z docker run

Agenci

Kopiuj jako prompt

Narzędzia MCP dla agentów
Wbudowany serwer MCP daje agentom te same możliwości: kontenery, maszyny, klastry i narzędzia systemowe apple_* dla usług, buildera, rejestrów, właściwości, logów i jąder.

Architektura

Gantry komunikuje się z Docker Engine API i z CLI container od Apple. Nie uruchamia własnej usługi.

100% natywny SwiftUI
Natywny SwiftUI, nie Electron. Aplikacja używa kontrolek, czcionki i okien macOS.
Swift 6
Nowoczesny kod, bezpieczny pod kątem współbieżności, na najnowszym zestawie narzędzi.
Bezpośrednio Engine API
Docker przez gniazdo Unix, bez potrzeby Docker CLI. apple/container przez własne CLI container.

Instalacja

Pobierz aplikację lub zainstaluj ją przez Homebrew. Konto nie jest potrzebne.

  • brew install --cask getgantry/tap/gantry
Pobierz na macOS
  1. InstalacjaUruchom cask Homebrew albo pobierz .zip z Wydań i przeciągnij Gantry.app do folderu Aplikacje.
  2. Pierwsze uruchomienieAplikacja nie jest jeszcze notaryzowana – kliknij prawym przyciskiem i wybierz Otwórz albo usuń kwarantannę poleceniem xattr -dr com.apple.quarantine /Applications/Gantry.app
  3. Dodaj hostLokalny Docker pojawi się sam. Dla Apple container dodaj host Apple Container; Gantry zaproponuje instalację CLI container. Agenci: claude mcp add gantry.

Pytania

Jakie GUI wybrać dla Apple container?

Gantry to darmowe natywne GUI open source na macOS, stworzone dla narzędzia container od Apple (apple/container). Obsługuje cykl życia kontenerów, logi, statystyki i terminal exec, a do tego części CLI, do których inne GUI nie sięgają: klastry Kubernetes (container cluster), maszyny container, builder obrazów, logowania do rejestrów, jądra, logi usług i właściwości systemowe. Obsługuje CLI od 1.0 do 1.7.1 i włącza każdą funkcję dopiero wtedy, gdy Twoje CLI ją obsługuje. Zobacz przewodnik po apple/container.

Czym jest Apple container (apple/container)?

apple/container to narzędzie open source od Apple do uruchamiania kontenerów linuksowych na Macu. Każdy kontener działa we własnej lekkiej maszynie wirtualnej, opartej na frameworku Virtualization od Apple. Wymaga Maca z Apple silicon i jest dostępne jako narzędzie wiersza poleceń container, bez aplikacji desktopowej. Gantry jest tą aplikacją.

Czy Gantry obsługuje container cluster i Kubernetes?

Tak. Na hoście apple/container Gantry tworzy i usuwa klastry Kubernetes poleceniem container cluster (CLI 1.6.1 i 1.7; CLI od 1.5.0 do 1.6.0 używa container k8s). Wybierasz nazwę, węzły robocze, procesory i pamięć warstwy sterowania oraz węzłów roboczych (1.7), obraz węzła, CNI i to, czy węzły używają Twoich lokalnych obrazów (1.7). Gantry pokazuje węzły, zapisuje kubeconfig i otwiera klaster w swojej przeglądarce Kubernetes. Zobacz Kubernetes na apple/container.

Czy można używać docker compose z Apple container?

Tak. apple/container nie ma polecenia compose, więc Gantry sam prowadzi orkiestrację przez CLI container: buduje usługi z build:, tworzy sieć projektu i nazwane woluminy, a następnie uruchamia usługi w kolejności depends_on ze standardowymi etykietami Compose. Nazwy usług są rozwiązywane przez aliasy DNS sieci. Otwórz plik docker-compose.yml z Findera, z menu Plik lub upuszczając go na okno.

Jak otworzyć maszynę container w VS Code?

Uruchom maszynę w Gantry i kliknij Otwórz w VS Code. Gantry otworzy maszynę w VS Code przez Remote-SSH, tak jak w przykładzie container-machine-vscode od Apple. Obraz maszyny musi uruchamiać sshd, a VS Code z rozszerzeniem Remote-SSH musi być zainstalowany.

Które wersje apple/container obsługuje Gantry?

Gantry wymaga CLI container 1.0 lub nowszego i zaleca 1.7.1. Odczytuje zainstalowaną wersję i pokazuje tylko funkcje, które ta wersja obsługuje, na przykład rozmiary węzłów roboczych i współdzielony magazyn obrazów (1.7), zapis jako obraz (1.6) i Przytnij dysk (1.4). Jeśli CLI brakuje lub jest za stare, Gantry poprowadzi Cię przez instalację.

Czy Gantry umie przeglądać klaster Kubernetes?

Tak. Sekcja Kubernetes wyświetla pody, deploymenty, StatefulSety, DaemonSety, usługi, ingressy, ConfigMapy, sekrety, węzły i zdarzenia dla każdego kontekstu kubeconfig. Ma logi podów, powłokę w podzie, przekierowania portów, skalowanie, restart wdrożenia, usuwanie i Zastosuj YAML. Gantry sam łączy się z API Kubernetes, więc kubectl nie jest potrzebny. Zobacz Kubernetes na Macu.

Co funkcja Wyjaśnij awarię wysyła do Apple Intelligence?

Najnowsze logi i szczegóły kontenera, bez wartości zmiennych środowiskowych i tekstu przypominającego sekrety. Małe zapytania obsługuje model na urządzeniu. Gdy włączysz ustawienie dla długich logów (macOS 27), długie logi trafiają do Private Cloud Compute. Panel pokazuje, co zostało wysłane. Sugerowane polecenie otwiera się w Terminalu, ale nie uruchamia się, dopóki nie naciśniesz Return. Bez Apple Intelligence Gantry proponuje prompt do skopiowania do innego asystenta AI.

Czy mogę wkleić polecenie docker run do Gantry?

Tak. W arkuszu Nowy kontener wybierz Wklej polecenie…. Gantry odczytuje docker run, docker create, podman run i container run, wypełnia formularz i wymienia każdą flagę, której nie może użyć, wraz z powodem. Zobacz Kontener z polecenia docker run.

Czy Gantry zarządza builderem, rejestrami i jądrem apple/container?

Tak. Sekcja System hosta apple/container uruchamia, zatrzymuje i usuwa builder obrazów z opcjami CPU, pamięci i DNS; wyświetla, dodaje i usuwa logowania do rejestrów (hasło trafia do CLI wyłącznie przez stdin); instaluje zalecane jądro, plik jądra lub archiwum tar; przesyła na żywo logi usług i edytuje właściwości systemowe w config.toml.

Czy Gantry to alternatywa dla Docker Desktop, OrbStack lub Podman Desktop?

Jako GUI – tak. Gantry to darmowa natywna aplikacja na macOS do zarządzania kontenerami, obrazami, woluminami, sieciami, logami i statystykami. To klient, a nie silnik: korzysta z demona Dockera, którego już używasz (Docker Desktop, OrbStack, Colima), lub z narzędzia container od Apple, i dodaje widok wielu hostów, hosty SSH oraz serwer MCP. Zobacz porównanie.

Czy Gantry jest darmowy?

Tak. Gantry jest darmowy i open source na licencji MIT. Bez subskrypcji, bez konta i bez limitu liczby hostów czy kontenerów.

Czego potrzebuję, żeby uruchomić Gantry?

macOS 26 lub nowszego na Apple silicon albo Intelu oraz demona Dockera (Docker Desktop, OrbStack, Colima lub podobnego) albo narzędzia container od Apple. Samo apple/container wymaga Apple silicon, więc na Macu z Intelem Gantry zarządza tylko hostami Docker.

Czy Gantry działa z OrbStack, Colima i Docker Desktop?

Tak. Gantry komunikuje się bezpośrednio z Docker Engine API przez gniazdo Unix, więc działa z każdym demonem, który je udostępnia, w tym z OrbStack, Colima i Docker Desktop.

Czy Gantry zarządza zdalnymi hostami Docker?

Tak. Gantry łączy się ze zdalnymi demonami przez SSH, tak samo jak docker -H ssh://, z obsługą bastionów ProxyJump, uwierzytelniania wieloma kluczami i automatycznego ponownego łączenia. Na serwerze nie trzeba niczego instalować, a sekrety są przechowywane w pęku kluczy macOS.

Czy Gantry powiadamia o awarii kontenera?

Tak. Gantry wysyła natywne powiadomienie macOS, gdy kontener na dowolnym hoście – lokalnym, SSH lub apple/container – ulegnie awarii, wyczerpie pamięć albo nie przejdzie testu stanu zdrowia. Kliknij je, aby przejść do kontenera. Zatrzymania i ponowne uruchomienia wykonane z Gantry nie generują powiadomień, a całą funkcję możesz wyłączyć w Ustawieniach.

Czy Gantry pobiera obrazy z prywatnych rejestrów?

Tak. Na hostach Docker Gantry odczytuje dane logowania z ~/.docker/config.json (zapisane przez docker login, którego już używasz), w tym wbudowane uwierzytelnianie, pomocników poświadczeń i pęk kluczy macOS. Na hostach apple/container zarządza logowaniami container registry.

Czy Gantry udostępni lokalny kontener w internecie?

Tak. Jedno kliknięcie opublikowanego portu udostępnia go przez Cloudflare Tunnel. Gantry w razie potrzeby instaluje cloudflared, a potem uruchamia szybki tunel (bez konta Cloudflare, z tymczasowym adresem URL trycloudflare.com) albo nazwany tunel z Twoją własną nazwą hosta. Publiczny adres URL pojawia się pod portem z przyciskami do otwarcia, skopiowania i zatrzymania.

Czy Gantry to aplikacja Electron?

Nie. Gantry to natywna aplikacja zbudowana w SwiftUI i Swift 6. Interfejs jest dostępny w 28 językach: angielskim, chińskim uproszczonym i 26 językach europejskich, na przykład serbskim w cyrylicy i alfabecie łacińskim. Dostosowuje się do języka systemu macOS.

Jak zainstalować Gantry?

Uruchom brew install --cask getgantry/tap/gantry albo pobierz najnowsze wydanie z GitHub i przeciągnij Gantry.app do folderu Aplikacje.

Czy agenci AI mogą sterować Gantry?

Tak. Gantry zawiera serwer MCP i App Intents macOS, więc Claude, Skróty, Siri i skrypty mają te same możliwości co GUI na każdym hoście, także na hostach SSH: kontenery, obrazy, woluminy, sieci, Compose, maszyny apple/container, klastry Kubernetes, narzędzia systemowe apple_* (usługi, builder, rejestry, właściwości, logi, jądro) i udostępnianie portów. Na macOS 26 i nowszym Wyjaśnij awarię… pyta też Apple Intelligence, dlaczego kontener uległ awarii. Dodaj serwer MCP poleceniem claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp.

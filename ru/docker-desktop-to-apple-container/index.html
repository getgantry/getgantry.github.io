Переход с Docker Desktop на Apple container

Инструмент container от Apple запускает те же образы OCI, что и Docker, поэтому большая часть работы переносится с небольшими изменениями команд. Это руководство сопоставляет Docker и container, переносит образы и тома и перечисляет ограничения, о которых стоит знать до перехода.

Коротко. Установите подписанный пакет container, замените docker на container для run, build, logs, exec и images, скопируйте именованные тома через tar-файл и откройте docker-compose.yml в Gantry, потому что в CLI нет compose. Пока вы пробуете, Docker Desktop можно не удалять.

Что меняется

  • Одна ВМ на контейнер. Docker Desktop запускает все контейнеры в одной ВМ Linux. apple/container запускает небольшую ВМ для каждого контейнера, поэтому у каждого свой IP-адрес на вашем Mac.
  • Те же образы и реестры. Образы — это образы OCI; вы скачиваете их с Docker Hub, GHCR и приватных реестров, как и раньше.
  • Без платы за лицензию. apple/container распространяется под Apache 2.0. Docker Desktop требует платного плана в организациях, где 250 или больше сотрудников или выручка $10 млн или больше.
  • Только Apple silicon и macOS 26. На Mac с Intel оставайтесь на движке Docker.

Большинство флагов run совпадают: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus и -m. Чтобы преобразовать длинную команду, вставьте её в Gantry: см. Создание контейнера из команды docker run.

    Перенос образов

Образы из реестра скачайте заново командой container image pull. Локальные образы, которые есть только в Docker, сохраните в архив и загрузите его. container image load читает архивы OCI, а новые версии Docker записывают в docker save макет OCI. Если загрузка не удалась, отправьте образ в реестр и скачайте его оттуда.

Терминал
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Перенос именованных томов

Docker хранит данные томов внутри своей ВМ. Скопируйте каждый том в tar-файл с помощью временного контейнера, затем распакуйте его в новый том apple/container:

Терминал
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Именованный том в apple/container — это разреженный образ диска ext4, по умолчанию не больше 512 ГБ. Другой размер задайте через --opt size=20g. Bind-монтирование папок вашего Mac работает так же, как в Docker: -v ~/project:/app.

    Файлы Compose

В CLI container нет команды compose. Вместо этого откройте docker-compose.yml в Gantry (из Finder, через Файл ▸ Открыть файл Compose… или перетаскиванием). Gantry собирает сервисы с build:, создаёт сеть проекта и именованные тома и запускает сервисы в порядке depends_on. Сервисы обращаются друг к другу по имени сервиса через сетевые DNS-алиасы.

    Сети и порты
  • -p 8080:80 публикует порт на localhost, как в Docker.
  • У каждого контейнера есть и собственный IP-адрес. Создайте локальный DNS-домен командой sudo container system dns create test и запускайте контейнеры с --dns-domain test: они получат имена вроде web.test.
  • container network create создаёт пользовательские сети; контейнеры в одной сети видят друг друга.
  • Режимов --network host, none и container: нет.
    Чего нет
  • Нет Docker Engine API. Инструменты, которые обращаются к /var/run/docker.sock, например Testcontainers, Docker SDK или Dev Containers, не видят apple/container.
  • Нет политик перезапуска. --restart недоступен; контейнер сам не запускается снова.
  • Нет Compose в CLI. Файлы Compose запускает Gantry: см. Файлы Compose.
  • Нет расширений Docker Desktop.
  • Только целые CPU: --cpus 0.5 не работает.
  • Kubernetes устроен иначе: используйте container cluster, см. Kubernetes на Mac.
    Оставьте оба на время перехода

Gantry управляет apple/container и любым движком Docker (Docker Desktop, OrbStack, Colima или Docker по SSH) в одном боковом меню. Переносите по одному проекту и оставьте Docker для инструментов, которым нужен его API. Когда Docker Desktop станет не нужен, его можно удалить.

Вопросы и ответы

Может ли Apple container заменить Docker Desktop?

Для запуска, сборки и скачивания контейнеров на Apple silicon — да. В нём нет Docker Engine API, политик перезапуска, расширений и команды compose. Gantry добавляет файлы Compose и GUI.

Работают ли образы Docker с Apple container?

Да. apple/container использует стандартные образы OCI и скачивает их из тех же реестров. Образы arm64 работают нативно, образы amd64 — через Rosetta с --arch amd64.

Работает ли docker compose с Apple container?

Не из CLI: команды container compose нет. Gantry читает docker-compose.yml и сам запускает сервисы на apple/container.

Можно ли одновременно использовать Docker Desktop и Apple container?

Да. У них нет общих образов и томов, но работать рядом они могут. Gantry показывает оба в одном окне.

Бесплатен ли Apple container для коммерческого использования?

Да. apple/container — открытый код под лицензией Apache 2.0, а Gantry распространяется под лицензией MIT. Оба бесплатны для компаний любого размера.

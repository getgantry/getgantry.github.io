Gantry/Attēlu skenēšana

Konteineru attēlu ievainojamību skenēšana Mac datorā

Trivy un Grype ir bezmaksas atvērtā koda skeneri, kas salīdzina attēla pakotnes ar zināmu ievainojamību datubāzēm. Docker attēlus tie lasa tieši. Apple rīkam container nav skenēšanas komandas un Docker soketa, tāpēc attēls vispirms jāsaglabā. Šajā ceļvedī parādīti abi veidi, kā lasīt atradumus, kā ierakstīt SBOM un kā skenēt no Gantry.

Īsumā. Palaidiet brew install trivy grype. Ar Docker palaidiet trivy image app:dev. Ar Apple container saglabājiet attēlu ar container image save --platform linux/arm64 -o app.tar app:dev, izpakojiet to ar tar -xf app.tar -C app-img un skenējiet mapi: trivy image --input app-img vai grype oci-dir:app-img. Pašu tar failu abi rīki nepieņem.

Skenera instalēšana

Instalējiet vienu skeneri vai abus ar Homebrew. Pirmajā skenēšanā katrs lejupielādē savu ievainojamību datubāzi, tas aizņem apmēram minūti.

Terminālis
brew install trivy grype

Šī ceļveža komandas pārbaudījām ar Trivy 0.76.2, Grype 0.121.3 un container 1.7.1. Gantry vajadzīgs Trivy 0.50.0 vai Grype 0.74.0 vai jaunāka versija.

Docker attēla skenēšana

Ar Docker dzinēju (Docker Desktop, OrbStack vai Colima) abi rīki lasa lokālu attēlu pēc nosaukuma caur Docker soketu:

Terminālis
trivy image app:dev
grype app:dev

Apple container attēla skenēšana

Saglabājiet attēlu OCI arhīvā un izpakojiet to mapē. Norādiet --platform: ja attēlu krātuvē ir tikai dažas attēla platformas, container image save bez tā neizdodas.

Terminālis
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Pēc tam skenējiet mapi. Trivy to lasa ar --input, Grype – ar prefiksu oci-dir::

Terminālis
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Uzmanību
Nenorādiet .tar failu. container image save arhīvs sākas ar ierakstu ./: Trivy ziņo „file manifest.json not found in tar”, un Grype to noraida kā „potential path traversal attack”. Izpakotā mape darbojas ar abiem.

Rezultātu lasīšana

  • Nopietnība: Critical, High, Medium, Low vai Unknown. Sāciet ar Critical un High. --severity HIGH,CRITICAL ierobežo Trivy izvadi.
  • Instalētā un labotā versija: ja labotā versija pastāv, atjauniniet bāzes attēlu vai pakotni un būvējiet vēlreiz. trivy --ignore-unfixed un grype --only-fixed paslēpj atradumus bez labojuma.
  • „won't fix”: distributīvs nolēma šajā laidienā pakotni nelabot. Izmantojiet jaunāku bāzes attēlu vai pieņemiet risku.
  • Divi rīki, divas datubāzes: Trivy un Grype bieži ziņo atšķirīgu skaitu. Neviens nekļūdās – tie izmanto dažādus avotus.

SBOM eksports

Programmatūras materiālu saraksts (SBOM) uzskaita visas attēla pakotnes. Trivy raksta CycloneDX un SPDX; Grype pavadonis Syft arī raksta abus.

Terminālis
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Būvējuma apturēšana nopietnu atradumu gadījumā

Skriptā ļaujiet izejas kodu noteikt skenerim. Grype beidz darbu ar nenulles kodu, ja ir norādītās vai augstākas nopietnības atradums; ar Trivy izmantojiet --exit-code 1 --severity HIGH,CRITICAL.

Terminālis
grype oci-dir:python-img --fail-on high
echo $?

Skenēšana no Gantry

Gantry 0.29.0 izpilda šos soļus jūsu vietā. Attēla izvēlnē vai attēla detaļu rīkjoslā izvēlieties Skenēt ievainojamības….

  • Gantry atrod Trivy vai Grype pēc GANTRY_TRIVY vai GANTRY_GRYPE, PATH vai mapēs /opt/homebrew/bin un /usr/local/bin. Ja instalēti abi, noklusējums ir Trivy. Ja skenera nav, logā redzamas Homebrew komandas.
  • apple/container resursdatorā Gantry saglabā attēlu ar --platform, izpako to un skenē mapi. Lokālajā Docker tā skenē saglabātu arhīvu. Docker caur SSH gadījumā tā skenē taga kopiju reģistrā.
  • Atradumi ir sagrupēti pēc nopietnības, ar simbolu un vārdu, ne tikai krāsu. Katrā rindā ir ID ar saiti, pakotne, instalētā versija un labotā versija. Filtrs atrod pakotni vai ID.
  • Eksportēt SBOM ieraksta CycloneDX (abi rīki) vai SPDX (Trivy).
  • Poga Apturēt vai loga aizvēršana aptur skeneri un noņem pagaidu failus.

Saistītie ceļveži

  • Pāreja no Docker Desktop uz Apple container: komandas, Compose, sējumi un trūkumi
  • Konteineru un sējumu glabāšana ārējā diskā Mac datorā
  • Konteinera izveide no docker run komandas Mac datorā (docker run uz container run)
  • Apple container GUI Mac datoram: pilns apple/container ceļvedis
  • Kubernetes ar Apple container: container cluster GUI un Kubernetes pārlūks
  • Gantry, Docker Desktop, OrbStack un Podman Desktop salīdzinājums Mac datorā (2026)

Jautājumi un atbildes

Kā skenēt Apple container attēlu, meklējot ievainojamības?

Saglabājiet to ar container image save --platform linux/arm64 -o app.tar app:dev, izpakojiet ar tar -xf app.tar -C app-img, pēc tam palaidiet trivy image --input app-img vai grype oci-dir:app-img. Gantry šos soļus izpilda ar Skenēt ievainojamības….

Kāpēc Trivy vai Grype neizdodas ar container image save arhīvu?

Arhīvs sākas ar ierakstu ./. Trivy tajā neatrod manifest.json vai index.json, un Grype uzskata šo ierakstu par ceļa šķērsošanu (path traversal). Izpakojiet arhīvu un skenējiet mapi.

Trivy vai Grype: kuru izmantot?

Abi ir bezmaksas un atvērtā koda. Trivy atrod arī noslēpumus un konfigurācijas kļūdas un raksta SPDX; Grype ir neliels un vērsts uz pakotnēm. Tie izmanto dažādas datubāzes, tāpēc abi kopā atrod vairāk. Ja instalēti abi, Gantry izmanto Trivy.

Vai Gantry instalē skenerus?

Nē. Instalējiet tos ar brew install trivy grype. Gantry meklē PATH, /opt/homebrew/bin un /usr/local/bin vai GANTRY_TRIVY un GANTRY_GRYPE.

Vai attēlu skenēšanai vajag Docker Scout vai Docker kontu?

Nē. Trivy un Grype darbojas bez konta – gan ar Docker attēliem, gan ar Apple container attēliem.

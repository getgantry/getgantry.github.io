Gantry/apple/container guide

Apple container on Mac: the complete guide and GUI

apple/container runs Linux containers on your Mac, each in its own lightweight virtual machine. It ships as a command-line tool. Gantry is a native macOS GUI for it. This guide explains the tool, how to set it up, and which Gantry feature covers each container command.

In short. Gantry is a free, open-source (MIT) macOS app that manages Apple's container tool and Docker from one window. It supports container CLI 1.0 to 1.7.1 (recommended) and shows only the features your CLI version supports. Install it with brew install --cask getgantry/tap/gantry.

What is apple/container?

apple/container is an open-source tool from Apple, written in Swift, that creates and runs Linux containers on a Mac. Docker Desktop runs all containers in one shared Linux VM; apple/container runs each container in its own lightweight virtual machine, built on Apple's Virtualization framework. It uses standard OCI images, so it pulls from and pushes to the same registries as Docker.

  • Hardware: a Mac with Apple silicon.
  • macOS: Apple supports it on macOS 26.
  • Interface: the container CLI only. There is no desktop app and no compose command.
  • Networking: each container gets its own IP address on your Mac, and local DNS domains give containers names such as web.test.

Why use a GUI for apple/container?

The CLI is complete, but daily work means many commands: container list, logs, stats, exec, then system, builder, registry, machine and cluster for the rest. Gantry puts them in one window with live updates, so you see the state instead of polling for it. It also adds what the CLI does not have: Compose files, failure notifications, a fleet view with your Docker hosts, and an MCP server for AI agents.

Set up apple/container with Gantry

  1. Install Gantry: brew install --cask getgantry/tap/gantry, then clear the quarantine flag (see Install).
  2. Install the container CLI from the signed .pkg on the apple/container releases page. If it is missing or older than 1.0, Gantry shows a setup sheet with the steps.
  3. In Gantry, choose Add Host… and add an Apple Container host. Connecting starts the container services if they are stopped.
  4. If no default kernel is installed, the host overview shows a banner. Click it to install the recommended kernel.
Heads up
Use the signed installer package, not the Homebrew build. The Homebrew build does not include the machine backend and, in 1.7.1, the cluster services, so container machine and container cluster cannot run.

What Gantry adds on apple/container

Kubernetes clusters

Create Kubernetes clusters with container cluster, size the workers, let pods use your local images, choose the CNI and see each node. Then browse the cluster in the Gantry Kubernetes browser. See Kubernetes on apple/container and the step-by-step guide Run Kubernetes on a Mac.

Container machines and VS Code

Machines are long-lived Linux environments from container machine. Gantry creates, starts, stops and deletes them, sets the default machine, edits CPUs and memory, and opens a shell. On CLI 1.1 or later, a machine can boot with nested virtualization (Apple silicon M3 or newer) and a custom kernel. Open in VS Code connects to a running machine over Remote-SSH; the machine image must run sshd.

Docker Compose on apple/container

Open a docker-compose.yml from Finder (Open With ▸ Gantry or Quick Actions ▸ Compose Up in apple/container), from File ▸ Open Compose File…, or by dropping it on the window. Gantry builds build: services, creates the project network and named volumes, and starts each service in depends_on order with the standard com.docker.compose.* labels. With a default DNS domain set, services reach each other by service name through network aliases.

Network DNS aliases and local domains

Gantry passes network aliases to container as --network <name>,alias=…. Without a default DNS domain, only fully qualified names pass, and a subtree alias (a leading dot, such as .gateway) passes only as its exact alias. With a default domain, short names work too. Gantry creates and deletes local DNS domains, sets the default domain, and gives new containers a name.domain hostname. See Local DNS names.

System: services, builder, registries, kernel, logs, properties

Each apple/container host has a System section. It works while the host is disconnected, so you can start stopped services from there.

  • Status and version: client and server versions, with a warning when they differ; start, stop and restart the services; host facts and paths.
  • Image Builder: state, image, CPUs, memory and IP; start with CPU, memory and DNS options; stop; delete. A card tells you when the builder image is outdated and recreates it.
  • Registry Logins: list, log in and log out. The password goes to the CLI on stdin (--password-stdin) only, and Gantry keeps no copy.
  • Kernel: install the recommended kernel, a kernel file or a tar archive, with streamed progress.
  • Service Logs: live or one-shot, over 5 minutes to 1 day, filtered by level, service and text.
  • System Properties: edits go to ~/.config/container/config.toml, with a pending-restart flag and a Restart Services button. On CLI 1.7, the [container.dns] name servers, search domains and options have a list editor.

Commit, Trim Disk and files

Commit to Image uses container commit (CLI 1.6). Trim Disk uses container clean (CLI 1.4) and also shows as a row in Reclaim Space. The Files tab downloads files and lets you drag them out to Finder with container copy (the container must be started), and uploads files and folders.

Labels that contain =

container create rejects a label value that contains =, also on CLI 1.6.1. Gantry encodes such values when it creates the container and decodes them when it reads it back, so the labels you set are the labels you see.

MCP server and Shortcuts

The bundled gantry-mcp server gives AI agents the same reach on apple/container hosts: containers, images, volumes, networks, Compose, machines (list_machines, create_machine and more), clusters (list_clusters, create_cluster, delete_cluster) and apple_* system tools for services, builder, registries (no login tool), properties, logs and kernel install. App Intents add Shortcuts and Siri actions. See AI agents & MCP.

Add the Gantry MCP server
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container next to Docker

Gantry manages apple/container hosts, the local Docker daemon (Docker Desktop, OrbStack, Colima) and remote Docker hosts over SSH in one sidebar and one fleet dashboard. You do not have to choose one runtime. For a feature-by-feature view of the tools, see Gantry vs Docker Desktop, OrbStack and Podman Desktop. To move your work over, read Move from Docker Desktop to Apple container.

Questions and answers

What is the best GUI for Apple container?

Gantry is a free, open-source native macOS GUI made for apple/container. It maps the container CLI to a desktop app: containers, logs, stats and exec, plus Kubernetes clusters, machines, the image builder, registry logins, kernels, service logs and system properties. The table on this page lists each command and the Gantry feature that uses it.

Does Apple container have a GUI?

Apple ships container as a command-line tool only. Gantry is a separate open-source app that gives it a GUI, next to your Docker hosts.

Can I use docker compose with Apple container?

apple/container has no compose command. Gantry reads a docker-compose.yml, builds build: services, creates the network and named volumes, and starts the services in depends_on order. Service names resolve through network DNS aliases.

How do I open a container machine in VS Code?

Start the machine in Gantry and click Open in VS Code. Gantry opens it over Remote-SSH, as in Apple's container-machine-vscode example. The machine image must run sshd.

Does Apple container work on Intel Macs?

No. apple/container needs a Mac with Apple silicon. Gantry runs on Intel Macs too, but there it manages Docker hosts only.

Which container CLI version should I install?

Gantry needs 1.0 or later and recommends 1.7.1. Install it with the signed installer package from the apple/container releases page. The Homebrew build does not include the machine backend or, in 1.7.1, the cluster services, so container machine and container cluster do not work with it.

Gantry/Išorinis diskas

Konteinerių ir tomų laikymas išoriniame diske

Atvaizdai, konteineriai ir tomai greitai užpildo nedidelį vidinį diską. Su Apple container įrankiu šiuos duomenis galite laikyti išoriniame SSD: atskirus aplankus perkelti per bind prijungimus arba perkelti visą duomenų šakninį katalogą. Šiame vadove aprašyti abu būdai ir kaip atjungti diską nieko nesugadinus.

Trumpai. Suformatuokite diską APFS sistema. Vienam projektui prijunkite aplanką per bind: -v /Volumes/Fast/pg:/data. Viskam: sustabdykite paslaugas, nukopijuokite ~/Library/Application Support/com.apple.container į diską su cp -Rp ir kaskart paleiskite paslaugas komanda container system start --app-root /Volumes/Fast/container.

Kur duomenys yra dabar

apple/container visus savo duomenis laiko viename aplanke – programos šakniniame kataloge (app root). Pagal numatytuosius nustatymus tai ~/Library/Application Support/com.apple.container su aplankais konteineriams, atvaizdų turiniui, momentinėms kopijoms, tomams, branduoliams ir tinklams. Patikrinkite kelią ir užimtą vietą:

Terminalas
container system status | grep appRoot
container system df

Disko pasirinkimas ir formatavimas

  • Naudokite SSD, prijungtą per USB-C arba Thunderbolt. Kietasis diskas su besisukančiomis plokštelėmis irgi tinka, bet konteineriai pasileidžia lėčiau.
  • Suformatuokite jį APFS sistema (tinka ir Mac OS Extended). Nenaudokite exFAT, FAT ar NTFS: tomai yra retieji disko atvaizdai, o šios failų sistemos nepalaiko retųjų failų ir Unix leidimų.
  • Programos šakniniam katalogui nenaudokite tinklo disko.
  • Duokite diskui trumpą pavadinimą be tarpų, pavyzdžiui, Fast. Tada kelias bus /Volumes/Fast.
    1 būdas: projekto duomenys diske per bind prijungimus

Bind prijungimas bendrina jūsų Mac aplanką su konteineriu, o aplankas gali būti bet kuriame diske. Tai paprastas būdas didelius duomenis, pavyzdžiui, duomenų bazę ar modelių failus, laikyti ne vidiniame diske:

Terminalas
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Diskas turi būti prijungtas prieš paleidžiant konteinerį. Atvaizdai ir pats konteineris lieka vidiniame diske.

    2 būdas: visų apple/container duomenų perkėlimas į diską

Taip perkeliami atvaizdai, konteineriai, momentinės kopijos ir tomai. Pirmiausia sustabdykite paslaugas, kad kopijuojant nepasikeistų nė vienas failas:

Terminalas
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Naudokite cp -Rp. Mūsų bandyme su macOS 27 (iš APFS į APFS per USB) ji išlaikė tomų atvaizdus retuosius ir išsaugojo išplėstinius atributus. ditto kiekvieną retąjį atvaizdą įrašė visu dydžiu, o tai gali užpildyti diską. Laikykite senąjį aplanką, kol patikrinsite, kad jūsų konteineriai, atvaizdai ir tomai rodomi sąrašuose.

Dėmesio
CLI neįsimena --app-root. Kiekviena container system start be šios vėliavėlės vėl naudoja vidinį aplanką. Naudokite vėliavėlę kiekvieną kartą, pavyzdžiui, apvalkalo slapyvardyje, ir tikrinkite paths.appRoot komandos container system status išvestyje.

Gantry 0.27.0, jungdamasi prie serverio, kurio paslaugos sustabdytos, paleidžia paslaugas be --app-root. Pirmiausia paleiskite paslaugas iš terminalo su šia vėliavėle; tada Gantry naudos jau veikiančias paslaugas.

    Atvaizdų archyvavimas diske

Norėdami atlaisvinti vietos neprarasdami atvaizdo, įrašykite jį į išorinį diską ir ištrinkite. Kai prireiks, įkelkite jį vėl:

Terminalas
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Saugus disko atjungimas
  1. Sustabdykite konteinerius, kurie naudoja diską: container stop <name>.
  2. Jei programos šakninis katalogas yra diske, sustabdykite paslaugas: container system stop.
  3. Išstumkite diską per Finder, tada jį atjunkite.

Jei diskas dingsta, kol iš jo veikia konteineriai, jie nulūžta, o vykdomi įrašymai gali būti prarasti. Vėl prijungę diską, paleiskite paslaugas su --app-root, tada paleiskite konteinerius.

    Išoriniai diskai Gantry programoje

Gantry jau dabar palaiko bind prijungimus iš bet kurio disko: lange Naujas konteineris pridėkite tomą, pasirinkite aplanką išoriniame diske ir kelią konteineryje.

    Docker Desktop ir OrbStack

Docker Desktop savo disko atvaizdą perkelia nustatyme Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack 0.13.0 versijoje pridėjo duomenų vietos nustatymą. Žr. palyginimą.

Susiję vadovai

  • Perėjimas nuo Docker Desktop prie Apple container: komandos, Compose, tomai ir trūkumai
  • Konteinerio kūrimas iš docker run komandos Mac kompiuteryje (docker run į container run)
  • Apple container GUI, skirta Mac: išsamus apple/container vadovas
  • Kubernetes su Apple container: container cluster GUI ir Kubernetes naršyklė
  • Gantry, Docker Desktop, OrbStack ir Podman Desktop palyginimas Mac kompiuteryje (2026)

Klausimai ir atsakymai

Ar galima laikyti Apple container atvaizdus išoriniame diske?

Taip. Paleiskite paslaugas komanda container system start --app-root /Volumes/Disk/container. Tada visi atvaizdai, konteineriai, momentinės kopijos ir tomai bus tame aplanke.

Kokią failų sistemą turi naudoti išorinis diskas?

APFS. Tomai yra retieji disko atvaizdai, o konteineriams reikia Unix leidimų, kurių exFAT, FAT ir NTFS neturi.

Kaip nukopijuoti konteinerių duomenis neužpildant disko?

Naudokite cp -Rp: mūsų bandyme ji išlaikė retuosius tomų atvaizdus mažus. ditto kiekvieną retąjį atvaizdą nukopijavo visu dydžiu.

Kas nutinka, jei atjungiu diską, kol veikia konteineriai?

Konteineriai, kurie naudoja diską, nulūžta, o dar neįrašyti duomenys gali būti prarasti. Prieš išstumdami diską sustabdykite konteinerius ir, jei programos šakninis katalogas yra diske, paslaugas.

Ar container CLI įsimena naują vietą?

Ne. Perduokite --app-root kiekvienai container system start komandai. container system status naudojamą šakninį katalogą rodo kaip paths.appRoot.

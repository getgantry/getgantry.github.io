Gantry/From docker run

Create a container from a docker run command

Most READMEs give a docker run line. Gantry reads that line and fills the New Container form, for a Docker host or for Apple's container tool. This guide shows how, and how to convert the command by hand.

In short. In Gantry, open New Container, choose Paste Command…, paste the docker run line and click Fill Form. Gantry lists each flag that it cannot use, with the reason. For the CLI, most flags are the same: replace docker run with container run and remove --restart.

Paste the command in Gantry

  1. Select a host: a Docker host or an apple/container host.
  2. Open Containers and click New Container.
  3. Click Paste Command… and paste the line. Line ends with \, quotes, a $ prompt and sudo are all fine.
  4. Read the preview: the image, the flags that Gantry cannot use, notes, and warnings for this host.
  5. Click Fill Form, check the values, and create the container.

Gantry reads docker run, docker container run, docker create, podman run and container run. Text after &&, ||, ; or | is ignored, with a note.

About 80 other Docker flags are known: Gantry skips their values correctly and lists them as not used, so nothing is lost without a note.

Warnings for apple/container hosts

Some Docker options do not exist on apple/container. Gantry warns about them and leaves them out of the create request:

  • restart policies (--restart);
  • CPU fractions such as --cpus 0.5;
  • the host, none and container: network modes;
  • ports without a host port, such as -p 80.

On a Docker host, Gantry warns about the apple/container options: the DNS domain and the kernel options.

Convert docker run to container run by hand

For the CLI, most flags stay the same. A Redis example:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

becomes:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Create the named volume first with container volume create. Remove --restart and round --cpus to a whole number. --platform works as in Docker.

Copy a container as a command

The other way works too. Right-click a container, or use the More menu, and choose Copy as Command: Gantry writes a docker run or container run line. It leaves out the defaults of the image, such as its environment and command, so the line stays short. This works for stopped containers as well.

Save it as a recipe

In the New Container sheet, open Recipes and choose Save as Recipe…. Next time, Fill from Recipe gives the same form on any host. Recipes are in ~/Library/Application Support/Gantry/recipes.json, so you can back them up or share them.

Limits

  • Gantry keeps the path of --env-file but does not read the file, and does not read your shell for -e KEY without a value.
  • tmpfs mounts and anonymous volumes from --mount are listed as not supported.
  • Two ports for the same container port (-p 8080:80 -p 8081:80) fill the form, but the form then refuses the duplicate.

Questions and answers

How do I convert docker run to container run?

Replace docker run with container run. -d, -p, -e, -v, --name, --rm, -it, -w and --entrypoint stay the same. Remove --restart and use whole CPUs. Or paste the line in Gantry and let it fill the form.

Can Gantry import a docker run command?

Yes. Paste Command… in the New Container sheet reads docker run, docker create, podman run and container run and fills the form.

What happens to flags that Gantry does not support?

They are listed in the preview with the reason, and they stay in the form in the section From the Pasted Command, so you can check them later.

Can I turn a running container back into a docker run command?

Yes. Copy as Command in the container menu writes a docker run or container run line for that container.

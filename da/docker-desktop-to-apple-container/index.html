Gantry/Fra Docker Desktop

Skift fra Docker Desktop til Apple container

Apples container-værktøj kører de samme OCI-images som Docker, så det meste af dit arbejde kan flyttes med få ændringer i kommandoerne. Denne guide oversætter Docker til container, flytter images og volumes og viser de mangler, du bør kende, før du skifter.

Kort fortalt. Installer den signerede container-pakke, erstat docker med container for run, build, logs, exec og images, kopiér navngivne volumes med en tar-fil, og åbn din docker-compose.yml i Gantry, for CLI'en har ingen compose. Du kan beholde Docker Desktop installeret, mens du prøver.

Hvad der ændrer sig

  • Én VM pr. container. Docker Desktop kører alle containere i én Linux-VM. apple/container starter en lille VM for hver container, så hver container får sin egen IP-adresse på din Mac.
  • Samme images og registries. Images er OCI-images; du henter fra Docker Hub, GHCR og private registries som før.
  • Ingen licensafgift. apple/container er Apache 2.0. Docker Desktop kræver et betalt abonnement i organisationer med 250 eller flere ansatte eller en omsætning på 10 mio. USD eller mere.
  • Kun Apple-chip og macOS 26. På Mac-computere med Intel skal du blive ved en Docker-motor.

De fleste flag til run er de samme: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus og -m. Vil du konvertere en lang kommando, så indsæt den i Gantry: se Opret en container ud fra en docker run-kommando.

Tag dine images med

Images fra et registry: hent dem igen med container image pull. Lokale images, der kun findes i Docker: gem dem i et arkiv, og indlæs det. container image load læser OCI-arkiver, og nyere Docker-versioner skriver et OCI-layout med docker save. Fejler indlæsningen, så send imaget til et registry, og hent det derfra.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Flyt navngivne volumes

Docker gemmer volumedata inde i sin VM. Kopiér hvert volume til en tar-fil med en kortlivet container, og pak den derefter ud i et nyt apple/container-volume:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Et navngivet volume i apple/container er et sparse ext4-diskimage, som standard højst 512 GB. Angiv en anden størrelse med --opt size=20g. Bind-mounts af mapper på din Mac virker som i Docker: -v ~/project:/app.

Compose-filer

container-CLI'en har ingen compose-kommando. Åbn i stedet docker-compose.yml i Gantry (Finder, Arkiv ▸ Åbn Compose-fil… eller træk og slip). Gantry bygger build:-tjenesterne, opretter projektets netværk og navngivne volumes og starter tjenesterne i rækkefølgen fra depends_on. Tjenesterne når hinanden ved tjenestenavn via netværkets DNS-aliasser.

Netværk og porte

  • -p 8080:80 publicerer en port på localhost som i Docker.
  • Hver container har også sin egen IP-adresse. Opret et lokalt DNS-domæne med sudo container system dns create test, og kør containere med --dns-domain test: de får navne som web.test.
  • container network create opretter brugernetværk; containere på samme netværk kan nå hinanden.
  • Der er ingen tilstand --network host, none eller container:.

Hvad der mangler

  • Ingen Docker Engine API. Værktøjer, der taler med /var/run/docker.sock, som Testcontainers, Docker-SDK'erne eller Dev Containers, kan ikke se apple/container.
  • Ingen genstartspolitikker. --restart findes ikke; en container starter ikke igen af sig selv.
  • Ingen Compose i CLI'en. Gantry kører Compose-filer: se Compose-filer.
  • Ingen udvidelser fra Docker Desktop.
  • Kun hele CPU'er: --cpus 0.5 virker ikke.
  • Kubernetes fungerer anderledes: brug container cluster, se Kør Kubernetes på en Mac.

Behold begge, mens du skifter

Gantry administrerer apple/container og enhver Docker-motor (Docker Desktop, OrbStack, Colima eller Docker over SSH) i én indholdsoversigt. Flyt ét projekt ad gangen, og behold Docker til de værktøjer, der kræver dets API. Når du ikke længere har brug for Docker Desktop, kan du fjerne det.

Spørgsmål og svar

Kan Apple container erstatte Docker Desktop?

Til at køre, bygge og hente containere på Apple-chip, ja. Det har ikke Docker Engine API, genstartspolitikker, udvidelser eller en compose-kommando. Gantry tilføjer Compose-filer og en GUI.

Virker Docker-images med Apple container?

Ja. apple/container bruger standard-OCI-images og henter fra de samme registries. arm64-images kører native; amd64-images kører via Rosetta med --arch amd64.

Virker docker compose med Apple container?

Ikke fra CLI'en: der findes ingen container compose. Gantry læser docker-compose.yml og kører tjenesterne på apple/container for dig.

Kan jeg bruge Docker Desktop og Apple container samtidig?

Ja. De deler ikke images eller volumes, men de kan køre side om side. Gantry viser begge i ét vindue.

Er Apple container gratis til kommerciel brug?

Ja. apple/container er åben kildekode under Apache 2.0-licensen, og Gantry har MIT-licens. Begge er gratis for virksomheder af enhver størrelse.

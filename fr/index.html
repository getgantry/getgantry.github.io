La GUI macOS native pour Apple container
et Docker — toute votre flotte sur un seul pont.

Gantry est une app Mac gratuite et open source pour l'outil container d'Apple et pour Docker, en local et via SSH. Pilotez conteneurs, clusters Kubernetes, machines et projets Compose sur apple/container depuis une seule fenêtre, à côté de vos hôtes Docker. Une alternative à Docker Desktop native pour Mac. Sans Electron. Sans abonnement. Sans limites.

Télécharger pour macOS
$ brew install --cask getgantry/tap/gantry

Terminal exec intégré

Émulation de terminal complète dans n'importe quel conteneur en cours d'exécution, local ou distant, avec des thèmes de couleurs (Système, Solarized, Dracula, Nord).

Hôtes distants via SSH

Des tunnels exactement comme docker -H ssh://, via dial-stdio : bastions ProxyJump, authentification multi-clés, reconnexion automatique. Rien à installer sur le serveur, secrets dans le trousseau. Import en un clic depuis ~/.ssh/config et docker context ls.

Navigateur de fichiers par glisser-déposer

Parcourez le système de fichiers d'un conteneur, faites entrer et sortir des fichiers, et déposez des dossiers entiers directement depuis le Finder, sur les hôtes Docker comme sur apple/container.

Ouvrir dans le navigateur & rediriger

Un clic ouvre un port publié. Les ports SSH sont redirigés automatiquement vers localhost ; si le port est pris, Gantry en choisit un libre, que vous pouvez modifier.

Partager sur Internet

Un clic expose un port publié via un Cloudflare Tunnel. Gantry installe cloudflared pour vous, puis fournit un tunnel rapide (sans compte, une URL *.trycloudflare.com) ou un tunnel nommé sur votre propre domaine : idéal pour un aperçu de dev, un webhook, ou pour qu'un agent IA atteigne un conteneur sur votre Mac.

Compose, partout

Les conteneurs sont regroupés par projet Compose. Lancez un fichier Compose sur n'importe quel hôte (Docker local, SSH ou apple/container) avec un éditeur YAML intégré ; l'exécution s'adapte à chaque moteur.

Registres privés, automatiquement

Les téléchargements d'images réutilisent le docker login que vous avez déjà fait : Gantry résout les identifiants depuis ~/.docker/config.json, les helpers et le trousseau, à la création, dans Exécution rapide comme dans Compose.

Construire & télécharger des images

Déposez un Dockerfile sur la fenêtre pour lancer un build avec journal en direct, ou téléchargez une image par référence avec la progression couche par couche. Taguez, purgez et consultez l'historique des couches. Un badge signale les images construites pour une architecture de processeur différente de celle de l'hôte.

Récupérer de l'espace

Un panneau montre ce qui occupe de l'espace (images orphelines, conteneurs arrêtés, volumes inutilisés, cache de build) avec les tailles, et purge chaque catégorie ou tout d'un coup. Sur apple/container, il lance aussi Compacter le disque.

Touch ID pour les actions destructrices

Activez l'option et Gantry demande Touch ID (ou votre mot de passe de session) avant de supprimer un conteneur ou un hôte. Les secrets sont déjà dans le trousseau.

Thèmes du terminal

Habillez le shell intégré en Système, Solarized Dark, Dracula ou Nord : palette complète de premier plan, d'arrière-plan et ANSI 16 couleurs, appliquée en direct.

GUI apple/container

La GUI macOS native pour Apple container

L'outil container d'Apple exécute des conteneurs Linux sous forme de VM légères sur puce Apple, mais il n'existe qu'en ligne de commande. Gantry en est l'app de bureau : Gantry est à container ce que Docker Desktop est à Docker. Il prend en charge toutes les CLI container, de la 1.0 jusqu'à la 1.6.1 recommandée, et n'active chaque fonctionnalité que si votre CLI installée la prend en charge.

Conteneurs, journaux, statistiques et exec

Créez, démarrez, arrêtez, forcez l'arrêt et purgez ; journaux en direct, statistiques, terminal exec, top et export tar, dans la même interface que vos hôtes Docker.

Clusters Kubernetes

Créez un cluster Kubernetes à plusieurs workers avec container cluster, choisissez le CNI (par défaut, aucun ou votre propre manifeste), surveillez les nœuds, écrivez le kubeconfig et copiez le contexte kubectl. En savoir plus

Charger des images locales dans un cluster

Faites un clic droit sur une image et choisissez Charger dans le cluster pour l'envoyer sur chaque nœud, sans passer par un registre.

Machines container dans VS Code

Créez, démarrez et arrêtez des environnements Linux container machine, réglez les CPU et la mémoire, ouvrez un shell ou ouvrez la machine dans VS Code via Remote-SSH.

Virtualisation imbriquée et noyaux personnalisés

Démarrez une machine avec la virtualisation imbriquée (M3 ou plus récent) ou avec votre propre noyau. Démarrez des conteneurs sur un noyau personnalisé avec des arguments de démarrage supplémentaires.

Compose pour Apple container

apple/container n'a pas de compose. Gantry exécute votre docker-compose.yml : il construit, crée le réseau et les volumes, puis démarre les services dans l'ordre de depends_on. Les noms de services sont résolus via des alias DNS réseau.

Alias DNS réseau

Alias de conteneur, alias de sous-arbre comme .gateway, et noms courts quand un domaine DNS par défaut est défini. Chaque conteneur reçoit une IP routable et un nom d'hôte name.domain.

Gérer le builder d'images

Consultez l'état du builder, son image, ses CPU, sa mémoire et son IP. Démarrez-le avec des options de CPU, de mémoire et de DNS, arrêtez-le ou supprimez-le.

Connexions aux registres

Listez, ajoutez et supprimez les connexions container registry. Le mot de passe n'est transmis à la CLI que via stdin, et Gantry n'en garde aucune copie.

Installation du noyau

Installez le noyau recommandé, un fichier de noyau ou une archive tar, avec la progression en direct. Gantry vous avertit quand aucun noyau par défaut n'est installé.

Services et journaux des services

Démarrez, arrêtez et redémarrez les services container, comparez les versions client et serveur, et suivez en direct les journaux des services, filtrés par niveau, service et texte.

Éditeur des propriétés système

Modifiez les propriétés système de container dans config.toml. Gantry signale les changements qui nécessitent un redémarrage et redémarre les services pour vous.

Enregistrer comme image et Compacter le disque

Enregistrez un conteneur comme image (container commit) et récupérez de l'espace disque avec Compacter le disque (container clean), aussi disponible dans le panneau Récupérer de l'espace.

Navigateur de fichiers : envoi et téléchargement

Parcourez les fichiers d'un conteneur, téléchargez-les ou faites-les glisser vers le Finder (container copy), et déposez-y des fichiers ou des dossiers entiers.

Exécution rapide et Finder

Choisissez une image, partagez un dossier, mappez des ports et choisissez un domaine, puis lancez. Faites un clic droit sur un fichier Compose dans le Finder et ouvrez-le avec Gantry.

Étiquettes contenant =

La CLI container rejette les valeurs d'étiquette contenant =. Gantry les encode à la création et les décode à la lecture : une valeur comme a=b reste intacte.

Une flotte, deux runtimes

Les hôtes apple/container côtoient vos hôtes Docker locaux et SSH dans un même tableau de bord, avec les mêmes sparklines, le même état de santé et les mêmes notifications de panne.

Outils MCP pour les agents

Le serveur MCP intégré donne aux agents la même portée : conteneurs, machines, clusters et outils système apple_* pour les services, le builder, les registres, les propriétés, les journaux et les noyaux.

FAQ

Vos questions, nos réponses

Tout ce qu'il faut savoir avant d'installer Gantry.

Quelle est la meilleure interface graphique pour Apple container ?

Gantry est une GUI macOS native, gratuite et open source, conçue pour l'outil container d'Apple (apple/container). Elle couvre le cycle de vie des conteneurs, les journaux, les statistiques et un terminal exec, ainsi que les parties de la CLI que les autres GUI n'atteignent pas : clusters Kubernetes (container cluster), machines container, builder d'images, connexions aux registres, noyaux, journaux des services et propriétés système. Elle prend en charge les CLI 1.0 à 1.6.1 et n'active chaque fonctionnalité que si votre CLI la prend en charge. Consultez le guide apple/container.

Qu'est-ce qu'Apple container (apple/container) ?

apple/container est l'outil open source d'Apple pour exécuter des conteneurs Linux sur un Mac. Chaque conteneur tourne dans sa propre machine virtuelle légère, basée sur le framework Virtualization d'Apple. Il nécessite un Mac à puce Apple et se présente comme un outil en ligne de commande nommé container, sans app de bureau. Gantry apporte cette app de bureau.

Gantry prend-il en charge container cluster et Kubernetes ?

Oui. Sur un hôte apple/container, Gantry crée et supprime des clusters Kubernetes avec container cluster (CLI 1.6.1 ; les CLI 1.5.0 à 1.6.0 utilisent container k8s). Vous choisissez le nom, le nombre de workers, les CPU, la mémoire, l'image des nœuds et le CNI (par défaut, aucun ou un manifeste personnalisé). Gantry affiche les nœuds, écrit le kubeconfig, copie la commande de contexte kubectl et charge les images locales dans le cluster. Voir Kubernetes sur apple/container.

Peut-on utiliser docker compose avec Apple container ?

Oui. apple/container n'a pas de commande compose : Gantry se charge donc de l'orchestration via la CLI container. Il construit les services build:, crée le réseau du projet et les volumes nommés, puis démarre chaque service dans l'ordre de depends_on avec les étiquettes Compose standard. Les noms de services sont résolus via des alias DNS réseau. Ouvrez un docker-compose.yml depuis le Finder, depuis le menu Fichier ou en le déposant sur la fenêtre.

Comment ouvrir une machine container dans VS Code ?

Démarrez la machine dans Gantry et cliquez sur Ouvrir dans VS Code. Gantry ouvre la machine dans VS Code via Remote-SSH, comme dans l'exemple container-machine-vscode d'Apple. L'image de la machine doit exécuter sshd, et VS Code doit être installé avec l'extension Remote-SSH.

Quelles versions d'apple/container Gantry prend-il en charge ?

Gantry nécessite la CLI container 1.0 ou ultérieure et recommande la 1.6.1. Il lit la version installée et n'affiche que les fonctionnalités qu'elle prend en charge, par exemple Enregistrer comme image (1.6), Compacter le disque (1.4) et les workers de cluster (1.6). Si la CLI est absente ou trop ancienne, Gantry propose une installation guidée.

Gantry peut-il gérer le builder, les registres et le noyau d'apple/container ?

Oui. La section Système d'un hôte apple/container démarre, arrête et supprime le builder d'images avec des options de CPU, de mémoire et de DNS ; liste, ajoute et supprime les connexions aux registres (le mot de passe n'est transmis à la CLI que via stdin) ; installe le noyau recommandé, un fichier de noyau ou une archive tar ; diffuse les journaux des services ; et modifie les propriétés système dans config.toml.

Gantry est-il une alternative à Docker Desktop, OrbStack ou Podman Desktop ?

Pour la GUI, oui. Gantry est une app macOS native et gratuite pour gérer conteneurs, images, volumes, réseaux, journaux et statistiques. C'est un client, pas un moteur : il utilise le daemon Docker que vous faites déjà tourner (Docker Desktop, OrbStack, Colima) ou l'outil container d'Apple, et ajoute une vue multi-hôtes, les hôtes SSH et un serveur MCP. Voir le comparatif.

Gantry est-il gratuit ?

Oui. Gantry est gratuit et open source, sous licence MIT. Pas d'abonnement, pas de compte, et aucune limite au nombre d'hôtes ou de conteneurs.

Quelle configuration faut-il pour utiliser Gantry ?

macOS 26 ou ultérieur sur puce Apple ou Intel, plus un daemon Docker (Docker Desktop, OrbStack, Colima ou équivalent) ou l'outil container d'Apple. apple/container nécessite lui-même une puce Apple : sur un Mac Intel, Gantry ne gère donc que des hôtes Docker.

Gantry fonctionne-t-il avec OrbStack, Colima et Docker Desktop ?

Oui. Gantry communique directement avec l'API Docker Engine via le socket Unix : il fonctionne donc avec tout daemon qui l'expose, dont OrbStack, Colima et Docker Desktop.

Gantry peut-il gérer des hôtes Docker distants ?

Oui. Gantry se connecte aux daemons distants via SSH, comme docker -H ssh://, avec bastions ProxyJump, authentification multi-clés et reconnexion automatique. Rien à installer sur le serveur, et les secrets restent dans le trousseau macOS.

Gantry me prévient-il quand un conteneur tombe en panne ?

Oui. Gantry envoie une notification macOS native quand un conteneur plante, manque de mémoire ou échoue à son contrôle d'état, sur n'importe quel hôte : local, SSH ou apple/container. Cliquez dessus pour accéder au conteneur. Les arrêts et redémarrages que vous lancez depuis Gantry ne déclenchent aucune notification, et vous pouvez désactiver la fonction dans les Réglages.

Gantry peut-il télécharger des images depuis un registre privé ?

Oui. Sur les hôtes Docker, Gantry lit les identifiants de votre ~/.docker/config.json (le même docker login que vous avez déjà fait), y compris l'authentification en ligne, les credential helpers et le trousseau macOS. Sur les hôtes apple/container, il gère les connexions container registry.

Gantry peut-il exposer un conteneur local sur Internet ?

Oui. Un clic sur un port publié le partage via un Cloudflare Tunnel. Gantry installe cloudflared si besoin, puis lance un tunnel rapide (sans compte Cloudflare, avec une URL temporaire trycloudflare.com) ou un tunnel nommé sur votre propre nom d'hôte. L'URL publique s'affiche sous le port, avec des commandes pour l'ouvrir, la copier et l'arrêter.

Gantry est-il une app Electron ?

Non. Gantry est une app native développée avec SwiftUI et Swift 6. L'interface est en anglais et en chinois simplifié et suit la langue du système macOS.

Comment installer Gantry ?

Exécutez brew install --cask getgantry/tap/gantry, ou téléchargez la dernière version sur GitHub et faites glisser Gantry.app dans le dossier Applications.

Les agents IA peuvent-ils piloter Gantry ?

Oui. Gantry intègre un serveur MCP et des App Intents macOS : Claude, Raccourcis, Siri et vos scripts ont la même portée que la GUI sur tous les hôtes, SSH compris : conteneurs, images, volumes, réseaux, Compose, machines apple/container, clusters Kubernetes, outils système apple_* (services, builder, registres, propriétés, journaux, noyau) et partage de ports. Ajoutez-le avec claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp.

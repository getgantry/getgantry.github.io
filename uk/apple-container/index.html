Gantry/Посібник з apple/container

Apple container на Mac: повний посібник і GUI

apple/container запускає Linux-контейнери на вашому Mac, кожен у власній легкій віртуальній машині. Це утиліта командного рядка, а Gantry — нативний GUI для неї на macOS. Тут описано, що це за інструмент, як його налаштувати й яка функція Gantry відповідає кожній команді container.

Коротко. Gantry — безплатна програма для macOS з відкритим кодом (MIT), яка керує інструментом container від Apple і Docker з одного вікна. Вона підтримує CLI container від 1.0 до 1.7.1 (рекомендовано) і показує лише ті функції, які підтримує ваша версія CLI. Інсталяція: brew install --cask getgantry/tap/gantry.

Що таке apple/container?

apple/container — інструмент Apple з відкритим кодом, написаний на Swift, який створює й запускає Linux-контейнери на Mac. Docker Desktop запускає всі контейнери в одній спільній Linux-ВМ, а apple/container — кожен контейнер у власній легкій віртуальній машині на основі фреймворку Virtualization від Apple. Він використовує стандартні образи OCI, тож отримує їх із тих самих реєстрів, що й Docker, і надсилає до них.

  • Обладнання: Mac з Apple silicon.
  • macOS: Apple підтримує його на macOS 26.
  • Інтерфейс: лише CLI container. Програми з графічним інтерфейсом і команди compose немає.
  • Мережа: кожен контейнер отримує власну IP-адресу на вашому Mac, а локальні DNS-домени дають контейнерам імена на кшталт web.test.

Навіщо GUI для apple/container?

CLI вміє все, але в щоденній роботі команд багато: container list, logs, stats, exec, а для решти — system, builder, registry, machine і cluster. Gantry збирає їх в одному вікні з живими оновленнями, тож ви бачите стан, а не опитуєте його. Він також додає те, чого немає в CLI: файли Compose, сповіщення про збої, панель парку разом із хостами Docker і сервер MCP для ШІ-агентів.

Налаштування apple/container з Gantry

  1. Інсталюйте Gantry: brew install --cask getgantry/tap/gantry, потім зніміть позначку карантину (див. Інсталяція).
  2. Інсталюйте CLI container з підписаного .pkg зі сторінки релізів apple/container. Якщо CLI немає або його версія нижча за 1.0, Gantry покаже вікно налаштування з інструкціями.
  3. У Gantry виберіть Додати хост… і додайте хост Apple Container. Під час під’єднання служби container запускаються, якщо їх зупинено.
  4. Якщо типове ядро не інстальовано, в огляді хоста з’явиться банер. Клацніть його, щоб інсталювати рекомендоване ядро.
Увага
Використовуйте підписаний інсталяційний пакет, а не збірку Homebrew. У збірці Homebrew немає бекенда машин, а в 1.7.1 — ще й служб кластера, тому container machine і container cluster не можуть працювати.

Що Gantry додає до apple/container

Кластери Kubernetes

Створюйте кластери Kubernetes командою container cluster, задавайте розмір робочих вузлів, дозволяйте подам використовувати ваші локальні образи, вибирайте CNI і переглядайте кожен вузол. Потім переглядайте кластер у браузері Kubernetes у Gantry. Див. Kubernetes на apple/container і покроковий посібник Kubernetes на Mac.

Машини container і VS Code

Машини — довготривалі Linux-середовища з container machine. Gantry створює, запускає, зупиняє й видаляє їх, задає типову машину, змінює CPU й пам’ять і відкриває оболонку. У CLI 1.1 або новішому машина може завантажуватися з вкладеною віртуалізацією (Apple silicon M3 або новіший) і власним ядром. Відкрити у VS Code під’єднується до запущеної машини через Remote-SSH; в образі машини має працювати sshd.

Docker Compose на apple/container

Відкрийте docker-compose.yml із Finder (Відкрити за допомогою ▸ Gantry або Швидкі дії ▸ Запустити Compose в apple/container), через Файл ▸ Відкрити файл Compose… або перетягнувши його у вікно. Gantry збирає служби з build:, створює мережу проєкту та іменовані томи й запускає кожну службу в порядку depends_on зі стандартними мітками com.docker.compose.*. Якщо задано типовий DNS-домен, служби знаходять одна одну за назвою через мережеві псевдоніми.

Мережеві DNS-псевдоніми та локальні домени

Gantry передає мережеві псевдоніми в container як --network <name>,alias=…. Без типового DNS-домену працюють лише повні імена, а псевдонім піддерева (із крапкою на початку, наприклад .gateway) працює лише як точний псевдонім. З типовим доменом працюють і короткі імена. Gantry створює й видаляє локальні DNS-домени, задає типовий домен і дає новим контейнерам ім’я хоста name.domain. Див. Локальні DNS-імена.

Система: служби, збирач, реєстри, ядро, журнали, властивості

Кожен хост apple/container має розділ Система. Він працює, навіть коли хост від’єднано, тож зупинені служби можна запустити просто звідти.

  • Статус і версія: версії клієнта й сервера з попередженням, якщо вони різняться; запуск, зупинка й перезапуск служб; відомості про хост і шляхи.
  • Збирач образів: стан, образ, CPU, пам’ять і IP; запуск із параметрами CPU, пам’яті й DNS; зупинка; видалення. Картка повідомляє, що образ збирача застарів, і створює його заново.
  • Входи в реєстри: перегляд, вхід і вихід. Пароль передається в CLI лише через stdin (--password-stdin), і Gantry не зберігає його копії.
  • Ядро: інсталяція рекомендованого ядра, файлу ядра або tar-архіву з відображенням перебігу в реальному часі.
  • Журнали служб: у реальному часі або одноразово, за період від 5 хвилин до 1 дня, з фільтром за рівнем, службою й текстом.
  • Системні властивості: зміни записуються в ~/.config/container/config.toml, з позначкою про очікуваний перезапуск і кнопкою Перезапустити служби. У CLI 1.7 для DNS-серверів, доменів пошуку й параметрів [container.dns] є редактор списків.

Збереження як образ, стиснення диска й файли

Зберегти як образ використовує container commit (CLI 1.6). Стиснути диск використовує container clean (CLI 1.4) і також показується рядком на панелі «Звільнити місце». Вкладка «Файли» завантажує файли й дає змогу перетягувати їх у Finder за допомогою container copy (контейнер має бути запущено), а також вивантажує файли й папки в контейнер.

Мітки, що містять =

container create відхиляє значення мітки, що містить =, зокрема в CLI 1.6.1. Gantry кодує такі значення під час створення контейнера й декодує під час читання, тож ви бачите саме ті мітки, які задали.

Сервер MCP і «Швидкі команди»

Вбудований сервер gantry-mcp дає ШІ-агентам ті самі можливості на хостах apple/container: контейнери, образи, томи, мережі, Compose, машини (list_machines, create_machine та інші), кластери (list_clusters, create_cluster, delete_cluster) і системні інструменти apple_* для служб, збирача, реєстрів (без інструмента входу), властивостей, журналів та інсталяції ядра. App Intents додають дії для «Швидких команд» і Siri. Див. ШІ-агенти та MCP.

Додайте сервер MCP Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container поруч із Docker

Gantry керує хостами apple/container, локальним демоном Docker (Docker Desktop, OrbStack, Colima) і віддаленими хостами Docker через SSH на одній боковій панелі й одній панелі парку. Вибирати одне середовище виконання не потрібно. Порівняння інструментів за функціями — на сторінці Gantry, Docker Desktop, OrbStack і Podman Desktop. Щоб перенести роботу, прочитайте Перехід із Docker Desktop на Apple container.

Запитання й відповіді

Який GUI для Apple container найкращий?

Gantry — безплатний нативний GUI для macOS з відкритим кодом, створений для apple/container. Він переносить CLI container у програму: контейнери, журнали, статистика й exec, а також кластери Kubernetes, машини, збирач образів, входи в реєстри, ядра, журнали служб і системні властивості. Таблиця на цій сторінці показує кожну команду та функцію Gantry, яка її використовує.

Чи має Apple container графічний інтерфейс?

Apple постачає container лише як утиліту командного рядка. Gantry — окрема програма з відкритим кодом, яка дає йому GUI поруч із вашими хостами Docker.

Чи можна використовувати docker compose з Apple container?

В apple/container немає команди compose. Gantry читає docker-compose.yml, збирає служби з build:, створює мережу та іменовані томи й запускає служби в порядку depends_on. Імена служб розв’язуються через мережеві DNS-псевдоніми.

Як відкрити машину container у VS Code?

Запустіть машину в Gantry і натисніть Відкрити у VS Code. Gantry відкриє її через Remote-SSH, як у прикладі Apple container-machine-vscode. В образі машини має працювати sshd.

Чи працює Apple container на Mac з Intel?

Ні. apple/container потрібен Mac з Apple silicon. Gantry працює й на Mac з Intel, але там керує лише хостами Docker.

Яку версію CLI container інсталювати?

Gantry потрібна версія 1.0 або новіша, рекомендовано 1.7.1. Інсталюйте її підписаним інсталяційним пакетом зі сторінки релізів apple/container. У збірці Homebrew немає бекенда машин, а в 1.7.1 — ще й служб кластера, тому container machine і container cluster з нею не працюють.

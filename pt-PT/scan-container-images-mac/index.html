Gantry/Analisar imagens

Analisar imagens de contentores à procura de vulnerabilidades num Mac

O Trivy e o Grype são scanners gratuitos e de código aberto que comparam os pacotes de uma imagem com bases de dados de vulnerabilidades conhecidas. Leem as imagens Docker diretamente. A ferramenta container da Apple não tem um comando de análise nem um socket Docker, por isso tem de guardar primeiro a imagem. Este guia mostra as duas formas, como ler os resultados, como escrever um SBOM e como analisar a partir do Gantry.

Em resumo. Execute brew install trivy grype. No Docker, execute trivy image app:dev. No Apple container, guarde a imagem com container image save --platform linux/arm64 -o app.tar app:dev, descompacte-a com tar -xf app.tar -C app-img e analise a pasta: trivy image --input app-img ou grype oci-dir:app-img. Ambas as ferramentas recusam o próprio ficheiro tar.

Instalar um scanner

Instale um scanner ou ambos com o Homebrew. Cada um descarrega a sua base de dados de vulnerabilidades na primeira análise, o que demora cerca de um minuto.

Terminal
brew install trivy grype

Verificámos os comandos deste guia com o Trivy 0.76.2, o Grype 0.121.3 e o container 1.7.1. O Gantry requer o Trivy 0.50.0 ou o Grype 0.74.0 ou posterior.

Analisar uma imagem Docker

Com um motor Docker (Docker Desktop, OrbStack ou Colima), ambas as ferramentas leem uma imagem local pelo nome através do socket Docker:

Terminal
trivy image app:dev
grype app:dev

Analisar uma imagem Apple container

Guarde a imagem num arquivo OCI e descompacte-o numa pasta. Indique --platform: quando o armazenamento de imagens tem apenas algumas plataformas de uma imagem, container image save falha sem essa opção.

Terminal
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Depois, analise a pasta. O Trivy lê-a com --input, o Grype com o prefixo oci-dir::

Terminal
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Atenção
Não indique o ficheiro .tar. O arquivo de container image save começa com a entrada ./: o Trivy indica “file manifest.json not found in tar” e o Grype rejeita-o como “potential path traversal attack”. A pasta descompactada funciona com ambos.

Ler os resultados

  • Gravidade: Crítica, Alta, Média, Baixa ou Desconhecida. Comece pelas críticas e altas. --severity HIGH,CRITICAL limita a saída do Trivy.
  • Versão instalada e versão corrigida: se existir uma versão corrigida, atualize a imagem base ou o pacote e compile de novo. trivy --ignore-unfixed e grype --only-fixed ocultam os resultados sem correção.
  • “won't fix”: a distribuição decidiu não corrigir o pacote nesta versão. Utilize uma imagem base mais recente ou aceite o risco.
  • Duas ferramentas, duas bases de dados: o Trivy e o Grype indicam muitas vezes contagens diferentes. Nenhum está errado; usam fontes diferentes.

Exportar um SBOM

Uma lista de materiais de software (SBOM) enumera todos os pacotes da imagem. O Trivy escreve CycloneDX e SPDX; o Syft, ferramenta irmã do Grype, também escreve ambos.

Terminal
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Fazer falhar uma compilação perante resultados graves

Num script, deixe o scanner definir o código de saída. O Grype sai com um código diferente de zero quando existe um resultado com a gravidade indicada ou superior; com o Trivy, use --exit-code 1 --severity HIGH,CRITICAL.

Terminal
grype oci-dir:python-img --fail-on high
echo $?

Analisar a partir do Gantry

O Gantry 0.29.0 faz estes passos por si. Escolha Analisar vulnerabilidades… no menu da imagem ou na barra de ferramentas do detalhe da imagem.

  • O Gantry encontra o Trivy ou o Grype em GANTRY_TRIVY ou GANTRY_GRYPE, no PATH, ou em /opt/homebrew/bin e /usr/local/bin. O Trivy é a predefinição quando ambos estão instalados. Sem scanner, a folha mostra os comandos do Homebrew.
  • No apple/container, o Gantry guarda a imagem com --platform, descompacta-a e analisa a pasta. No Docker local, analisa um arquivo guardado. No Docker por SSH, analisa a cópia da tag no registo.
  • Os resultados são agrupados por gravidade, com um símbolo e uma palavra, não apenas uma cor. Cada linha tem o ID com uma ligação, o pacote, a versão instalada e a versão corrigida. Um filtro encontra um pacote ou um ID.
  • Exportar SBOM escreve CycloneDX (ambas as ferramentas) ou SPDX (Trivy).
  • Parar ou fechar a folha para o scanner e remove os ficheiros temporários.

Perguntas e respostas

Como analiso uma imagem Apple container à procura de vulnerabilidades?

Guarde-a com container image save --platform linux/arm64 -o app.tar app:dev, descompacte-a com tar -xf app.tar -C app-img e execute trivy image --input app-img ou grype oci-dir:app-img. O Gantry faz estes passos com Analisar vulnerabilidades….

Porque é que o Trivy ou o Grype falham com o arquivo de container image save?

O arquivo começa com a entrada ./. O Trivy não encontra nele manifest.json nem index.json, e o Grype trata a entrada como um path traversal. Descompacte o arquivo e analise a pasta.

Trivy ou Grype: qual devo usar?

Ambos são gratuitos e de código aberto. O Trivy também encontra segredos e configurações incorretas e escreve SPDX; o Grype é pequeno e centrado nos pacotes. Usam bases de dados diferentes, por isso executar ambos encontra mais. O Gantry usa o Trivy quando ambos estão instalados.

O Gantry instala os scanners?

Não. Instale-os com brew install trivy grype. O Gantry procura no PATH, em /opt/homebrew/bin e /usr/local/bin, ou em GANTRY_TRIVY e GANTRY_GRYPE.

Preciso do Docker Scout ou de uma conta Docker para analisar imagens?

Não. O Trivy e o Grype funcionam sem conta, com imagens Docker e com imagens Apple container.

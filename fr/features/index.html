Conteneurs

Créez, exécutez, ouvrez et modifiez des conteneurs sur chaque hôte.

  • container run
  • docker exec -it
  • docker cp
  • docker port
Collez un docker run
Collez une commande docker run, podman run ou container run : Gantry remplit le formulaire Nouveau conteneur et liste les options qu'il ne peut pas utiliser. Copiez n'importe quel conteneur sous forme de commande, ou enregistrez-le comme modèle. Comment ça marche
Terminal exec intégré
Émulation de terminal complète dans n'importe quel conteneur en cours d'exécution, local ou distant, avec des thèmes de couleurs (Système, Solarized, Dracula, Nord).
Navigateur de fichiers par glisser-déposer
Parcourez le système de fichiers d'un conteneur, faites entrer et sortir des fichiers, et déposez des dossiers entiers directement depuis le Finder, sur les hôtes Docker comme sur apple/container.
Ouvrir dans le navigateur & rediriger
Un clic ouvre un port publié. Les ports SSH sont redirigés automatiquement vers localhost ; si le port est pris, Gantry en choisit un libre, que vous pouvez modifier.
Partager sur Internet
Un clic expose un port publié via un Cloudflare Tunnel. Gantry installe cloudflared pour vous, puis fournit un tunnel rapide (sans compte, une URL *.trycloudflare.com) ou un tunnel nommé sur votre propre domaine : idéal pour un aperçu de dev, un webhook, ou pour qu'un agent IA atteigne un conteneur sur votre Mac.
Les secrets du trousseau dans l'environnement
Gardez les mots de passe et les jetons dans le trousseau de macOS (Réglages → Secrets) et utilisez-les comme variables d'environnement dans « Nouveau conteneur » et « Exécution rapide ». Le formulaire affiche keychain:NAME, jamais la valeur, et Gantry ne lit la valeur qu'au moment de créer le conteneur. L'export Compose, les modèles et « Copier comme commande » écrivent le nom, pas la valeur.
Agir sur plusieurs éléments à la fois
Sélectionnez plusieurs conteneurs, images, volumes ou réseaux, puis démarrez-les, arrêtez-les, redémarrez-les ou supprimez-les en une seule étape, avec la progression et un rapport pour chaque élément.
Statistiques en temps réel
CPU, mémoire, réseau & E/S disque tracés en direct, échantillonnés toutes les secondes.
Des conteneurs sur un disque externe
Déplacez toutes les données d'apple/container sur un disque externe, gardez les volumes sur le disque de votre choix et recevez un avertissement clair quand ce disque n'est pas connecté. Lire le guide

Images et builds

Téléchargez, construisez, analysez et supprimez des images.

  • docker build
  • docker pull
  • trivy image
  • docker system prune
Construire & télécharger des images
Déposez un Dockerfile sur la fenêtre pour lancer un build avec journal en direct, ou téléchargez une image par référence avec la progression couche par couche. Taguez, purgez et consultez l'historique des couches. Un badge signale les images construites pour une architecture de processeur différente de celle de l'hôte.
Historique des builds
Chaque hôte a une section Builds : les builds avec leurs étapes, leurs accès au cache et leur journal. Gantry conserve les builds qu'il lance, avec les noms des arguments de build mais pas leurs valeurs. Sur les hôtes Docker, il lit aussi docker buildx history (buildx 0.23.0 ou ultérieur). apple/container ne conserve aucun historique des builds : vous y voyez donc les builds lancés par Gantry.
Analyser les images avec Trivy ou Grype
Choisissez Rechercher des vulnérabilités… sur une image. Gantry exécute le Trivy (0.50.0 ou ultérieur) ou le Grype (0.74.0 ou ultérieur) que vous avez installé, par exemple avec Homebrew, et regroupe les résultats de Critique à Inconnu. Exporter le SBOM écrit du CycloneDX, ou du SPDX avec Trivy. Cela fonctionne sur apple/container, Docker local et Docker via SSH ; dans ce dernier cas, Gantry analyse la copie d'une image taguée qui se trouve dans le registre.
Registres privés
Les téléchargements d'images réutilisent le docker login que vous avez déjà fait : Gantry résout les identifiants depuis ~/.docker/config.json, les helpers et le trousseau, à la création, dans Exécution rapide comme dans Compose.
Récupérer de l'espace
Un panneau montre ce qui occupe de l'espace (images orphelines, conteneurs arrêtés, volumes inutilisés, cache de build) avec les tailles, et purge chaque catégorie ou tout d'un coup. Sur apple/container, il lance aussi Compacter le disque.

Compose

Exécutez un docker-compose.yml sur Docker ou sur apple/container, et créez-en un à partir de conteneurs en cours d'exécution.

  • docker compose up -d
  • docker compose down
  • docker compose logs -f
Compose sur chaque hôte
Les conteneurs sont regroupés par projet Compose. Lancez un fichier Compose sur n'importe quel hôte (Docker local, SSH ou apple/container) avec un éditeur YAML intégré ; l'exécution s'adapte à chaque moteur.
Exporter en Compose
Choisissez Exporter en Compose… sur un ou plusieurs conteneurs pour obtenir un docker-compose.yml avec les ports, les montages, les réseaux, la politique de redémarrage, le contrôle d'intégrité, les limites et plus encore. Les valeurs qui ressemblent à des secrets deviennent ${NAME}, sauf si vous les incluez. Sur les hôtes apple/container, Gantry signale les options que Compose ne peut pas exprimer. Comment ça marche

Navigateur Kubernetes

Hôtes et flotte

Ce Mac, les hôtes Docker via SSH et apple/container sur un seul tableau de bord.

  • docker -H ssh://user@host
  • docker context use
  • docker stats
Un tableau de bord pour tous vos hôtes
Daemon local, flotte SSH et apple/container sur un seul écran : sparklines CPU/mémoire en direct, répartition des conteneurs par état, et problèmes de santé qui mènent droit au coupable.
Hôtes distants via SSH
Des tunnels exactement comme docker -H ssh://, via dial-stdio : bastions ProxyJump, authentification multi-clés, reconnexion automatique. Rien à installer sur le serveur, secrets dans le trousseau. Import en un clic depuis ~/.ssh/config et docker context ls.
Utilisation des ressources pour tous les hôtes
Un tableau triable des conteneurs en cours d'exécution sur chaque hôte connecté : hôte, nom, image, CPU, mémoire, E/S réseau, E/S disque et durée de fonctionnement. Filtrez par nom, image ou hôte, ou affichez un seul hôte. Double-cliquez sur une ligne pour ouvrir le conteneur. Le tableau utilise les mesures que Gantry prend déjà toutes les 5 secondes : il n'ouvre donc aucun nouveau flux de statistiques. Ouvrez-le depuis la barre latérale, avec ⌘K ou avec gantry://open/usage.

Journaux et échecs

Lisez, recherchez et exportez les journaux. Trouvez la cause quand un conteneur échoue.

  • docker logs -f
  • container logs
  • docker events
Journaux en direct
Suivi en temps réel, recherche ⌘F en regex ou en texte littéral, filtre par niveau (Error→Trace), couleurs ANSI, tampon de 50 000 lignes, et journaux du projet fusionnés pour tout un projet Compose.
Exporter les journaux
Exporter les journaux… (⇧⌘E) enregistre les lignes que vous voyez, avec le filtre de niveau, la recherche et la période, dans un fichier .log ou .txt. Copier les lignes visibles les copie. Sur les hôtes Docker, vous pouvez ajouter l'horodatage et n'afficher qu'une période allant des 5 dernières minutes au dernier jour.
Notifications en cas d'échec
Une notification native quand un conteneur plante, manque de mémoire ou devient défaillant, sur n'importe quel hôte. Cliquez dessus pour aller droit au conteneur ; les arrêts que vous déclenchez vous-même restent silencieux.
Expliquer l'échec avec Apple Intelligence
Choisissez Expliquer l'échec… sur un conteneur planté ou une opération qui a échoué. Gantry envoie au modèle de l'appareil les journaux récents et les détails, sans les valeurs d'environnement ni le texte qui ressemble à un secret, puis affiche la cause probable, les indices et les étapes suivantes. Les journaux longs peuvent partir vers Private Cloud Compute (macOS 27). Le panneau montre exactement ce qui a été envoyé.
Captures d'écran dans « Expliquer l'échec »
Déposez, collez ou ajoutez jusqu'à 3 images dans « Expliquer l'échec », par exemple une capture d'écran d'une page d'erreur. Les images restent sur ce Mac : seul le modèle sur l'appareil les lit (macOS 27), jamais Private Cloud Compute.

Intégré à macOS
Notifications avec Redémarrer, Afficher les journaux et Copier comme prompt. Spotlight trouve les conteneurs, les projets Compose et les hôtes. Actions Siri et Raccourcis, un widget d'état du parc, des commandes du Centre de contrôle pour les services apple/container ou un conteneur favori, et des liens gantry:// pour les scripts.
La progression dans la barre des menus
Le panneau de la barre des menus affiche chaque téléchargement, build et opération Compose en cours avec une barre de progression, les couches ou services terminés, les octets, la durée et un bouton Annuler. L'icône de la barre des menus indique le nombre d'opérations en cours. Chaque projet Compose dispose de Télécharger les images et de Compose Down ; Compose Down conserve les volumes et les images.
Palette de commandes
Appuyez sur ⌘K et tapez. Une seule recherche couvre les conteneurs, les projets Compose, les images, les volumes, les réseaux, les machines, les clusters et les hôtes, avec des actions comme Démarrer, Afficher les journaux et Ouvrir un shell.
Touch ID pour les actions destructrices
Activez l'option et Gantry demande Touch ID (ou votre mot de passe de session) avant de supprimer un conteneur ou un hôte. Les secrets sont déjà dans le trousseau.
Thèmes du terminal
Habillez le shell intégré en Système, Solarized Dark, Dracula ou Nord : palette complète de premier plan, d'arrière-plan et ANSI 16 couleurs, appliquée en direct.

La GUI macOS native pour Apple container

L'outil container d'Apple exécute des conteneurs Linux sous forme de VM légères sur puce Apple, mais il n'existe qu'en ligne de commande. Gantry en est l'app de bureau : Gantry est à container ce que Docker Desktop est à Docker. Il prend en charge toutes les CLI container de la 1.0 à la 1.7.1 recommandée, et n'active chaque fonctionnalité que si la CLI installée la prend en charge.

  • container system start
  • container machine
  • container builder start
  • container registry login
Conteneurs, journaux, statistiques et exec
Créez, démarrez, arrêtez, forcez l'arrêt et purgez ; journaux en direct, statistiques, terminal exec, top et export tar, dans la même interface que vos hôtes Docker.
Clusters Kubernetes
Créez un cluster Kubernetes avec container cluster : dimensionnez séparément le plan de contrôle et les workers, choisissez le CNI, et consultez les nœuds, la version de Kubernetes et le contexte kubeconfig. Les nœuds du cluster sont protégés contre un arrêt ou une suppression par erreur. En savoir plus
Images locales dans le cluster
Avec la CLI 1.7, activez Utiliser les images locales (--shared-image-store) : les pods exécutent les images que vous construisez ou téléchargez, sans registre. Avec les CLI 1.5 et 1.6, faites un clic droit sur une image et choisissez Charger dans le cluster.
Des indications claires quand l'installation est défectueuse
Si les services de cluster ne répondent pas, Gantry vous dit pourquoi. Un build Homebrew sans les services de cluster reçoit un lien vers le programme d'installation signé ; dans les autres cas, Gantry affiche un bouton Redémarrer les services.
Machines container dans VS Code
Créez, démarrez et arrêtez des environnements Linux container machine, réglez les CPU et la mémoire, ouvrez un shell ou ouvrez la machine dans VS Code via Remote-SSH.
Virtualisation imbriquée et noyaux personnalisés
Démarrez une machine avec la virtualisation imbriquée (M3 ou plus récent) ou avec votre propre noyau. Démarrez des conteneurs sur un noyau personnalisé avec des arguments de démarrage supplémentaires.
Compose pour Apple container
apple/container n'a pas de compose. Gantry exécute votre docker-compose.yml : il construit, crée le réseau et les volumes, puis démarre les services dans l'ordre de depends_on. Les noms de services sont résolus via des alias DNS réseau.
Alias DNS réseau
Alias de conteneur, alias de sous-arbre comme .gateway, et noms courts quand un domaine DNS par défaut est défini. Chaque conteneur reçoit une IP routable et un nom d'hôte name.domain.
Gérer le builder d'images
Consultez l'état, l'image, les CPU, la mémoire et l'IP du builder. Démarrez-le avec des options de CPU, de mémoire et de DNS, arrêtez-le ou supprimez-le. Quand l'image du builder est obsolète, Gantry propose de le recréer.
Connexions aux registres
Listez, ajoutez et supprimez les connexions container registry. Le mot de passe n'est transmis à la CLI que via stdin, et Gantry n'en garde aucune copie.
Installation du noyau
Installez le noyau recommandé, un fichier de noyau ou une archive tar, avec la progression en direct. Gantry vous avertit quand aucun noyau par défaut n'est installé.
Services et journaux des services
Démarrez, arrêtez et redémarrez les services container, comparez les versions client et serveur, et suivez en direct les journaux des services, filtrés par niveau, service et texte.
Éditeur des propriétés système
Modifiez les propriétés système de container dans config.toml. Gantry signale les modifications qui demandent un redémarrage et redémarre les services pour vous. Avec la CLI 1.7, il modifie aussi les valeurs par défaut de [container.dns] : serveurs de noms, domaines de recherche et options.
Enregistrer comme image et Compacter le disque
Enregistrez un conteneur comme image (container commit) et récupérez de l'espace disque avec Compacter le disque (container clean), aussi disponible dans le panneau Récupérer de l'espace.
Navigateur de fichiers : envoi et téléchargement
Parcourez les fichiers d'un conteneur, téléchargez-les ou faites-les glisser vers le Finder (container copy), et déposez-y des fichiers ou des dossiers entiers.
Exécution rapide et Finder
Choisissez une image, partagez un dossier, mappez des ports et choisissez un domaine, puis lancez. Faites un clic droit sur un fichier Compose dans le Finder et ouvrez-le avec Gantry.
Étiquettes contenant =
La CLI container rejette les valeurs d'étiquette contenant =. Gantry les encode à la création et les décode à la lecture : une valeur comme a=b reste intacte.
Une flotte, deux runtimes

Architecture

Gantry communique avec l'API Docker Engine et avec la CLI container d'Apple. L'app n'exécute aucun service propre.

100 % SwiftUI natif
SwiftUI natif, pas Electron. L'app utilise les commandes, la police et les fenêtres de macOS.
Swift 6
Code moderne et sûr en matière de concurrence, sur la dernière chaîne d'outils.
Accès direct à l'API Engine
Docker via le socket Unix, sans CLI Docker. apple/container via sa propre CLI container.
Mises à jour automatiques
Un appcast Sparkle signé EdDSA vous tient à jour sans vous déranger.

Questions

Quelle est la meilleure interface graphique pour Apple container ?

Gantry est une GUI macOS native, gratuite et open source, conçue pour l'outil container d'Apple (apple/container). Il couvre le cycle de vie des conteneurs, les journaux, les statistiques et un terminal exec, ainsi que les parties de la CLI que les autres GUI n'atteignent pas : clusters Kubernetes (container cluster), machines container, builder d'images, connexions aux registres, noyaux, journaux des services et propriétés système. Il prend en charge les CLI 1.0 à 1.7.1 et n'active chaque fonctionnalité que si votre CLI la prend en charge. Voir le guide apple/container.

Qu'est-ce qu'Apple container (apple/container) ?

apple/container est l'outil open source d'Apple pour exécuter des conteneurs Linux sur un Mac. Chaque conteneur tourne dans sa propre machine virtuelle légère, basée sur le framework Virtualization d'Apple. Il nécessite un Mac à puce Apple et se présente comme un outil en ligne de commande nommé container, sans app de bureau. Gantry apporte cette app de bureau.

Gantry prend-il en charge container cluster et Kubernetes ?

Oui. Sur un hôte apple/container, Gantry crée et supprime des clusters Kubernetes avec container cluster (CLI 1.6.1 et 1.7 ; les CLI 1.5.0 à 1.6.0 utilisent container k8s). Vous choisissez le nom, les workers, les CPU et la mémoire du plan de contrôle et des workers (1.7), l'image des nœuds, le CNI et l'utilisation de vos images locales par les nœuds (1.7). Gantry affiche les nœuds, écrit le kubeconfig et ouvre le cluster dans son navigateur Kubernetes. Voir Kubernetes sur apple/container.

Peut-on utiliser docker compose avec Apple container ?

Oui. apple/container n'a pas de commande compose : Gantry se charge donc de l'orchestration via la CLI container. Il construit les services build:, crée le réseau du projet et les volumes nommés, puis démarre chaque service dans l'ordre de depends_on avec les étiquettes Compose standard. Les noms de services sont résolus via des alias DNS réseau. Ouvrez un docker-compose.yml depuis le Finder, depuis le menu Fichier ou en le déposant sur la fenêtre.

Comment ouvrir une machine container dans VS Code ?

Démarrez la machine dans Gantry et cliquez sur Ouvrir dans VS Code. Gantry ouvre la machine dans VS Code via Remote-SSH, comme dans l'exemple container-machine-vscode d'Apple. L'image de la machine doit exécuter sshd, et VS Code doit être installé avec l'extension Remote-SSH.

Quelles versions d'apple/container Gantry prend-il en charge ?

Gantry nécessite la CLI container 1.0 ou ultérieure et recommande la 1.7.1. Il lit la version installée et n'affiche que les fonctionnalités prises en charge par cette version, par exemple la taille des workers et le stockage d'images partagé (1.7), l'enregistrement comme image (1.6) et « Compacter le disque » (1.4). Si la CLI est absente ou trop ancienne, Gantry propose une installation guidée.

Gantry peut-il parcourir un cluster Kubernetes ?

Oui. La section Kubernetes liste les pods, Deployments, StatefulSets, DaemonSets, services, Ingress, ConfigMaps, secrets, nœuds et événements de chaque contexte kubeconfig. Elle offre les journaux et un shell des pods, des redirections de port, la mise à l'échelle, le redémarrage d'un rollout, la suppression et l'application de YAML. Gantry communique lui-même avec l'API Kubernetes : vous n'avez pas besoin de kubectl. Voir Exécuter Kubernetes sur un Mac.

Qu'est-ce que « Expliquer l'échec » envoie à Apple Intelligence ?

Les journaux récents et les détails du conteneur, sans les valeurs d'environnement ni le texte qui ressemble à un secret. Les petites requêtes s'exécutent sur le modèle de l'appareil. Si le réglage des journaux longs est activé (macOS 27), les journaux longs partent vers Private Cloud Compute. Le panneau montre ce qui a été envoyé. Une commande suggérée s'ouvre dans Terminal mais ne s'exécute pas tant que vous n'appuyez pas sur Retour. Sans Apple Intelligence, Gantry propose un prompt à copier dans un autre assistant IA.

Puis-je coller une commande docker run dans Gantry ?

Oui. Dans la feuille Nouveau conteneur, choisissez Coller une commande…. Gantry lit docker run, docker create, podman run et container run, remplit le formulaire et liste chaque option qu'il ne peut pas utiliser, avec la raison. Voir Créer un conteneur à partir d'une commande docker run.

Gantry peut-il gérer le builder, les registres et le noyau d'apple/container ?

Oui. La section Système d'un hôte apple/container démarre, arrête et supprime le builder d'images avec des options de CPU, de mémoire et de DNS ; liste, ajoute et supprime les connexions aux registres (le mot de passe n'est transmis à la CLI que via stdin) ; installe le noyau recommandé, un fichier de noyau ou une archive tar ; diffuse les journaux des services ; et modifie les propriétés système dans config.toml.

Gantry est-il une alternative à Docker Desktop, OrbStack ou Podman Desktop ?

Pour la GUI, oui. Gantry est une app macOS native et gratuite pour gérer conteneurs, images, volumes, réseaux, journaux et statistiques. C'est un client, pas un moteur : il utilise le daemon Docker que vous faites déjà tourner (Docker Desktop, OrbStack, Colima) ou l'outil container d'Apple, et ajoute une vue multi-hôtes, les hôtes SSH et un serveur MCP. Voir le comparatif.

Gantry est-il gratuit ?

Oui. Gantry est gratuit et open source, sous licence MIT. Pas d'abonnement, pas de compte, et aucune limite au nombre d'hôtes ou de conteneurs.

Quelle configuration faut-il pour utiliser Gantry ?

macOS 26 ou ultérieur sur puce Apple ou Intel, plus un daemon Docker (Docker Desktop, OrbStack, Colima ou équivalent) ou l'outil container d'Apple. apple/container nécessite lui-même une puce Apple : sur un Mac Intel, Gantry ne gère donc que des hôtes Docker.

Gantry fonctionne-t-il avec OrbStack, Colima et Docker Desktop ?

Oui. Gantry communique directement avec l'API Docker Engine via le socket Unix : il fonctionne donc avec tout daemon qui l'expose, dont OrbStack, Colima et Docker Desktop.

Gantry peut-il gérer des hôtes Docker distants ?

Oui. Gantry se connecte aux daemons distants via SSH, comme docker -H ssh://, avec bastions ProxyJump, authentification multi-clés et reconnexion automatique. Rien à installer sur le serveur, et les secrets restent dans le trousseau macOS.

Gantry me prévient-il quand un conteneur tombe en panne ?

Oui. Gantry envoie une notification macOS native quand un conteneur plante, manque de mémoire ou échoue à son contrôle d'état, sur n'importe quel hôte : local, SSH ou apple/container. Cliquez dessus pour accéder au conteneur. Les arrêts et redémarrages que vous lancez depuis Gantry ne déclenchent aucune notification, et vous pouvez désactiver la fonction dans les Réglages.

Gantry peut-il télécharger des images depuis un registre privé ?

Oui. Sur les hôtes Docker, Gantry lit les identifiants de votre ~/.docker/config.json (le même docker login que vous avez déjà fait), y compris l'authentification en ligne, les credential helpers et le trousseau macOS. Sur les hôtes apple/container, il gère les connexions container registry.

Gantry peut-il exposer un conteneur local sur Internet ?

Oui. Un clic sur un port publié le partage via un Cloudflare Tunnel. Gantry installe cloudflared si besoin, puis lance un tunnel rapide (sans compte Cloudflare, avec une URL temporaire trycloudflare.com) ou un tunnel nommé sur votre propre nom d'hôte. L'URL publique s'affiche sous le port, avec des commandes pour l'ouvrir, la copier et l'arrêter.

Gantry est-il une app Electron ?

Non. Gantry est une app native développée avec SwiftUI et Swift 6. L'interface est disponible en 28 langues : anglais, chinois simplifié et 26 langues européennes, par exemple le serbe en alphabet cyrillique et latin. Elle suit la langue du système macOS.

Comment installer Gantry ?

Exécutez brew install --cask getgantry/tap/gantry, ou téléchargez la dernière version sur GitHub et faites glisser Gantry.app dans le dossier Applications.

Les agents IA peuvent-ils piloter Gantry ?

Oui. Gantry intègre un serveur MCP et des App Intents macOS : Claude, Raccourcis, Siri et les scripts ont la même portée que la GUI sur chaque hôte, hôtes SSH compris : conteneurs, images, volumes, réseaux, Compose, machines apple/container, clusters Kubernetes, outils système apple_* (services, builder, registres, propriétés, journaux, noyau) et partage de ports. Sous macOS 26 et ultérieur, Expliquer l'échec… demande aussi à Apple Intelligence pourquoi un conteneur a échoué. Ajoutez le serveur MCP avec claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp.

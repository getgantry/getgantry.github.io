Gantry/Ārējais disks

Konteineru un sējumu glabāšana ārējā diskā

Attēli, konteineri un sējumi ātri piepilda nelielu iekšējo disku. Ar Apple rīku container šos datus var glabāt ārējā SSD: atsevišķas mapes tur var novietot ar bind montējumiem vai pārvietot visu datu sakni. Šis ceļvedis parāda abus veidus un to, kā atvienot disku, to nesabojājot.

Īsumā. Formatējiet disku kā APFS. Vienam projektam izmantojiet mapes bind montējumu: -v /Volumes/Fast/pg:/data. Visiem datiem apturiet pakalpojumus, nokopējiet ~/Library/Application Support/com.apple.container uz disku ar cp -Rp un katru reizi startējiet pakalpojumus ar container system start --app-root /Volumes/Fast/container.

Kur dati ir tagad

apple/container glabā visus savus datus vienā mapē – lietotnes saknē (app root). Pēc noklusējuma tā ir ~/Library/Application Support/com.apple.container ar mapēm konteineriem, attēlu saturam, momentuzņēmumiem, sējumiem, kodoliem un tīkliem. Pārbaudiet ceļu un aizņemto vietu:

Terminālis
container system status | grep appRoot
container system df

Diska izvēle un formatēšana

  • Izmantojiet SSD ar USB-C vai Thunderbolt savienojumu. Arī cietais disks ar rotējošām plātnēm darbojas, bet konteineri startē lēnāk.
  • Formatējiet to kā APFS (der arī Mac OS Extended). Neizmantojiet exFAT, FAT vai NTFS: sējumi ir retināti diska attēli, bet šajās failu sistēmās nav retinātu failu un Unix atļauju.
  • Lietotnes saknei neizmantojiet tīkla disku.
  • Piešķiriet diskam īsu nosaukumu bez atstarpēm, piemēram, Fast. Tad ceļš ir /Volumes/Fast.

1. iespēja: projekta datu glabāšana diskā ar bind montējumiem

Bind montējums kopīgo jūsu Mac datora mapi ar konteineru, un šī mape var atrasties jebkurā diskā. Tas ir vienkāršs veids, kā lielus datus, piemēram, datubāzi vai modeļu failus, glabāt ārpus iekšējā diska:

Terminālis
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Diskam jābūt pievienotam, pirms konteiners startē. Attēli un pats konteiners paliek iekšējā diskā.

2. iespēja: visu apple/container datu pārvietošana uz disku

Tādējādi tiek pārvietoti attēli, konteineri, momentuzņēmumi un sējumi. Vispirms apturiet pakalpojumus, lai kopēšanas laikā neviens fails nemainītos:

Terminālis
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Izmantojiet cp -Rp. Mūsu pārbaudē macOS 27 (no APFS uz APFS caur USB) tas saglabāja sējumu attēlus retinātus un saglabāja paplašinātos atribūtus. ditto ierakstīja katru retināto attēlu pilnā izmērā, kas var piepildīt disku. Paturiet veco mapi, līdz esat pārbaudījis, ka jūsu konteineri, attēli un sējumi ir sarakstā.

Uzmanību
CLI neatceras --app-root. Katra container system start komanda bez tā atkal izmanto iekšējo mapi. Izmantojiet karodziņu katru reizi, piemēram, čaulas aizstājvārdā, un pārbaudiet paths.appRoot izvadē container system status.

Gantry 0.27.0 startē pakalpojumus bez --app-root, kad savienojas ar resursdatoru, kura pakalpojumi ir apturēti. Vispirms startējiet pakalpojumus no termināļa ar šo karodziņu; tad Gantry izmanto jau darbojošos pakalpojumus. Gantry atbalsts pārvietotai datu saknei tiek izstrādāts.

Attēlu arhivēšana diskā

Lai atbrīvotu vietu, nezaudējot attēlu, saglabājiet to ārējā diskā un dzēsiet. Kad tas vajadzīgs, ielādējiet to atkal:

Terminālis
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Droša diska atvienošana

  1. Apturiet konteinerus, kas izmanto disku: container stop <name>.
  2. Ja lietotnes sakne ir diskā, apturiet pakalpojumus: container system stop.
  3. Izstumiet disku lietotnē Finder un pēc tam atvienojiet to.

Ja disks pazūd, kamēr no tā darbojas konteineri, tie cieš kļūmi, un notiekošie ieraksti var tikt zaudēti. Pēc diska atkārtotas pievienošanas startējiet pakalpojumus ar --app-root un pēc tam startējiet konteinerus.

Ārējie diski lietotnē Gantry

Gantry jau tagad palaiž bind montējumus no jebkura diska: logā Jauns konteiners pievienojiet sējumu, izvēlieties mapi ārējā diskā un ceļu konteinerā. Gantry atbalsts datu saknes pārvietošanai, sējumiem ārējā diskā un brīdinājumam, ja disks nav pievienots, tiek izstrādāts.

Docker Desktop un OrbStack

Docker Desktop savu diska attēlu pārvieto ar Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack datu atrašanās vietas iestatījumu pievienoja versijā 0.13.0. Skatiet salīdzinājumu.

Jautājumi un atbildes

Vai Apple container attēlus var glabāt ārējā diskā?

Jā. Startējiet pakalpojumus ar container system start --app-root /Volumes/Disk/container. Tad visi attēli, konteineri, momentuzņēmumi un sējumi atrodas šajā mapē.

Kāda failu sistēma jāizmanto ārējam diskam?

APFS. Sējumi ir retināti diska attēli, un konteineriem vajadzīgas Unix atļaujas, kuru nav exFAT, FAT un NTFS.

Kā nokopēt konteineru datus, nepiepildot disku?

Izmantojiet cp -Rp, kas mūsu pārbaudē saglabāja retinātos sējumu attēlus mazus. ditto nokopēja katru retināto attēlu pilnā izmērā.

Kas notiek, ja atvienoju disku, kamēr darbojas konteineri?

Konteineri, kas izmanto disku, cieš kļūmi, un dati, kas vēl nebija ierakstīti, var tikt zaudēti. Pirms diska izstumšanas apturiet konteinerus un, ja lietotnes sakne ir diskā, arī pakalpojumus.

Vai container CLI atceras jauno atrašanās vietu?

Nē. Norādiet --app-root katrai container system start komandai. container system status rāda izmantoto sakni kā paths.appRoot.

Κοντέινερ και τόμοι σε εξωτερικό δίσκο

Οι εικόνες, τα κοντέινερ και οι τόμοι γεμίζουν γρήγορα έναν μικρό εσωτερικό δίσκο. Με το εργαλείο container της Apple μπορείτε να κρατάτε αυτά τα δεδομένα σε εξωτερικό SSD: βάλτε εκεί μεμονωμένους φακέλους με bind mount ή μετακινήστε ολόκληρο τον ριζικό φάκελο δεδομένων. Αυτός ο οδηγός δείχνει και τους δύο τρόπους, καθώς και πώς να αποσυνδέσετε τον δίσκο χωρίς ζημιά.

Με λίγα λόγια. Μορφοποιήστε τον δίσκο ως APFS. Για ένα έργο, κάντε bind mount ενός φακέλου: -v /Volumes/Fast/pg:/data. Για όλα, σταματήστε τις υπηρεσίες, αντιγράψτε το ~/Library/Application Support/com.apple.container στον δίσκο με cp -Rp και ξεκινάτε κάθε φορά τις υπηρεσίες με container system start --app-root /Volumes/Fast/container.

Πού βρίσκονται τώρα τα δεδομένα

Το apple/container κρατά όλα τα δεδομένα του σε έναν φάκελο, το app root. Από προεπιλογή είναι το ~/Library/Application Support/com.apple.container, με φακέλους για κοντέινερ, περιεχόμενο εικόνων, στιγμιότυπα, τόμους, πυρήνες και δίκτυα. Ελέγξτε τη διαδρομή και τον χώρο που χρησιμοποιείται:

Τερματικό
container system status | grep appRoot
container system df

Επιλογή και μορφοποίηση του δίσκου

  • Χρησιμοποιήστε SSD σε USB-C ή Thunderbolt. Ένας μηχανικός δίσκος λειτουργεί, αλλά τα κοντέινερ ξεκινούν πιο αργά.
  • Μορφοποιήστε τον ως APFS (λειτουργεί και το Mac OS Extended). Μη χρησιμοποιείτε exFAT, FAT ή NTFS: οι τόμοι είναι αραιές εικόνες δίσκου και αυτά τα συστήματα αρχείων δεν έχουν αραιά αρχεία ούτε δικαιώματα Unix.
  • Μη χρησιμοποιείτε δίσκο δικτύου για το app root.
  • Δώστε στον δίσκο ένα σύντομο όνομα χωρίς κενά, για παράδειγμα Fast. Η διαδρομή είναι τότε /Volumes/Fast.

Επιλογή 1: δεδομένα έργου στον δίσκο με bind mount

Ένα bind mount μοιράζεται έναν φάκελο του Mac σας με το κοντέινερ, και ο φάκελος μπορεί να βρίσκεται σε οποιονδήποτε δίσκο. Είναι ο εύκολος τρόπος να κρατήσετε μεγάλα δεδομένα, όπως μια βάση δεδομένων ή αρχεία μοντέλων, εκτός του εσωτερικού δίσκου:

Τερματικό
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Ο δίσκος πρέπει να είναι συνδεδεμένος πριν ξεκινήσει το κοντέινερ. Οι εικόνες και το ίδιο το κοντέινερ μένουν στον εσωτερικό δίσκο.

Επιλογή 2: μετακίνηση όλων των δεδομένων του apple/container στον δίσκο

Έτσι μετακινούνται εικόνες, κοντέινερ, στιγμιότυπα και τόμοι. Σταματήστε πρώτα τις υπηρεσίες, ώστε να μην αλλάξει κανένα αρχείο κατά την αντιγραφή:

Τερματικό
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Χρησιμοποιήστε cp -Rp. Στη δοκιμή μας σε macOS 27 (από APFS σε APFS μέσω USB), κράτησε αραιές τις εικόνες των τόμων και διατήρησε τα εκτεταμένα χαρακτηριστικά. Το ditto έγραψε κάθε αραιή εικόνα στο πλήρες μέγεθός της, κάτι που μπορεί να γεμίσει τον δίσκο. Κρατήστε τον παλιό φάκελο μέχρι να ελέγξετε ότι εμφανίζονται τα κοντέινερ, οι εικόνες και οι τόμοι σας.

Προσοχή
Το CLI δεν θυμάται το --app-root. Κάθε container system start χωρίς αυτό χρησιμοποιεί ξανά τον εσωτερικό φάκελο. Χρησιμοποιείτε τη σημαία κάθε φορά, για παράδειγμα σε ένα alias του shell, και ελέγχετε το paths.appRoot στο container system status.

Το Gantry 0.27.0 ξεκινά τις υπηρεσίες χωρίς --app-root όταν συνδέεται σε host με σταματημένες υπηρεσίες. Ξεκινήστε πρώτα τις υπηρεσίες από το τερματικό με τη σημαία· το Gantry χρησιμοποιεί τότε τις υπηρεσίες σε εκτέλεση. Η υποστήριξη του Gantry για μετακινημένο ριζικό φάκελο δεδομένων είναι υπό ανάπτυξη.

Αρχειοθέτηση εικόνων στον δίσκο

Για να ελευθερώσετε χώρο χωρίς να χάσετε μια εικόνα, αποθηκεύστε την στον εξωτερικό δίσκο και διαγράψτε την. Φορτώστε την ξανά όταν τη χρειαστείτε:

Τερματικό
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Ασφαλής αποσύνδεση του δίσκου

  1. Σταματήστε τα κοντέινερ που χρησιμοποιούν τον δίσκο: container stop <name>.
  2. Αν το app root βρίσκεται στον δίσκο, σταματήστε τις υπηρεσίες: container system stop.
  3. Εξαγάγετε τον δίσκο στο Finder και μετά αποσυνδέστε τον.

Αν ο δίσκος αποσυνδεθεί ενώ τρέχουν κοντέινερ από αυτόν, τα κοντέινερ αποτυγχάνουν και οι εγγραφές σε εξέλιξη μπορεί να χαθούν. Αφού συνδέσετε ξανά τον δίσκο, ξεκινήστε τις υπηρεσίες με --app-root και μετά τα κοντέινερ.

Εξωτερικοί δίσκοι στο Gantry

Το Gantry εκτελεί ήδη σήμερα bind mount από οποιονδήποτε δίσκο: στο Νέο κοντέινερ, προσθέστε έναν τόμο, επιλέξτε φάκελο στον εξωτερικό δίσκο και διαδρομή στο κοντέινερ. Η υποστήριξη του Gantry για μετακίνηση του ριζικού φακέλου δεδομένων, τόμους σε εξωτερικό δίσκο και προειδοποίηση όταν ο δίσκος δεν είναι συνδεδεμένος είναι υπό ανάπτυξη.

Docker Desktop και OrbStack

Το Docker Desktop μετακινεί την εικόνα δίσκου του στο Settings ▸ Resources ▸ Advanced ▸ Disk image location. Το OrbStack πρόσθεσε ρύθμιση θέσης δεδομένων στην έκδοση 0.13.0. Δείτε τη σύγκριση.

Ερωτήσεις και απαντήσεις

Μπορώ να αποθηκεύω τις εικόνες του Apple container σε εξωτερικό δίσκο;

Ναι. Ξεκινήστε τις υπηρεσίες με container system start --app-root /Volumes/Disk/container. Όλες οι εικόνες, τα κοντέινερ, τα στιγμιότυπα και οι τόμοι βρίσκονται τότε σε αυτόν τον φάκελο.

Ποιο σύστημα αρχείων πρέπει να έχει ο εξωτερικός δίσκος;

APFS. Οι τόμοι είναι αραιές εικόνες δίσκου και τα κοντέινερ χρειάζονται δικαιώματα Unix, που δεν έχουν τα exFAT, FAT και NTFS.

Πώς αντιγράφω τα δεδομένα των κοντέινερ χωρίς να γεμίσει ο δίσκος;

Χρησιμοποιήστε cp -Rp, που στη δοκιμή μας κράτησε μικρές τις αραιές εικόνες των τόμων. Το ditto αντέγραψε κάθε αραιή εικόνα στο πλήρες μέγεθός της.

Τι συμβαίνει αν αποσυνδέσω τον δίσκο ενώ τρέχουν κοντέινερ;

Τα κοντέινερ που χρησιμοποιούν τον δίσκο αποτυγχάνουν και δεδομένα που δεν είχαν ακόμη γραφτεί μπορεί να χαθούν. Πριν εξαγάγετε τον δίσκο, σταματήστε τα κοντέινερ και, αν το app root βρίσκεται στον δίσκο, τις υπηρεσίες.

Θυμάται το CLI container τη νέα θέση;

Όχι. Δίνετε το --app-root σε κάθε container system start. Το container system status δείχνει τον ριζικό φάκελο που χρησιμοποιείται ως paths.appRoot.

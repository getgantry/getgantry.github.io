Gantry/Внешний диск

Контейнеры и тома на внешнем диске

Образы, контейнеры и тома быстро заполняют небольшой внутренний диск. С инструментом container от Apple эти данные можно хранить на внешнем SSD: отдельные папки — через bind-монтирование, или весь корень данных целиком. Это руководство показывает оба способа и объясняет, как отключить диск без повреждений.

Коротко. Отформатируйте диск в APFS. Для одного проекта смонтируйте папку: -v /Volumes/Fast/pg:/data. Для всего сразу остановите службы, скопируйте ~/Library/Application Support/com.apple.container на диск командой cp -Rp и каждый раз запускайте службы командой container system start --app-root /Volumes/Fast/container.

Где данные сейчас

apple/container хранит все данные в одной папке — корне приложения (app root). По умолчанию это ~/Library/Application Support/com.apple.container, с папками для контейнеров, содержимого образов, снимков, томов, ядер и сетей. Проверьте путь и занятое место:

Терминал
container system status | grep appRoot
container system df

Выбор и форматирование диска

  • Используйте SSD с USB-C или Thunderbolt. Жёсткий диск тоже подойдёт, но контейнеры будут запускаться медленнее.
  • Отформатируйте его в APFS (Mac OS Extended тоже подойдёт). Не используйте exFAT, FAT или NTFS: тома — это разреженные образы дисков, а в этих файловых системах нет разреженных файлов и прав доступа Unix.
  • Не используйте сетевой диск для корня приложения.
  • Дайте диску короткое имя без пробелов, например Fast. Тогда путь будет /Volumes/Fast.
    Способ 1: данные проекта на диске через bind-монтирование

Bind-монтирование открывает контейнеру папку вашего Mac, и эта папка может быть на любом диске. Так проще всего держать большие данные, например базу данных или файлы моделей, вне внутреннего диска:

Терминал
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Диск должен быть подключён до запуска контейнера. Образы и сам контейнер остаются на внутреннем диске.

    Способ 2: все данные apple/container на диске

Так переносятся образы, контейнеры, снимки и тома. Сначала остановите службы, чтобы во время копирования ни один файл не менялся:

Терминал
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Используйте cp -Rp. В нашей проверке на macOS 27 (с APFS на APFS по USB) эта команда сохранила разреженность образов томов и расширенные атрибуты. ditto записал каждый разреженный образ в полном размере, а это может заполнить диск. Не удаляйте старую папку, пока не убедитесь, что ваши контейнеры, образы и тома видны в списках.

Внимание
CLI не запоминает --app-root. Каждый container system start без этого флага снова использует внутреннюю папку. Указывайте флаг каждый раз, например в алиасе оболочки, и проверяйте paths.appRoot в container system status.

Gantry может сделать этот перенос за вас: см. ниже.

    Архив образов на диске

Чтобы освободить место и не потерять образ, сохраните его на внешний диск и удалите. Когда образ понадобится, загрузите его снова:

Терминал
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Безопасное отключение диска
  1. Остановите контейнеры, которые используют диск: container stop <name>.
  2. Если корень приложения на этом диске, остановите службы: container system stop.
  3. Извлеките диск в Finder, затем отключите его.

Если диск пропадёт, пока с него работают контейнеры, они упадут, а незавершённые записи могут потеряться. Когда снова подключите диск, запустите службы с --app-root, затем запустите контейнеры.

    Внешние диски в Gantry

На хосте apple/container панель Хранилище в разделе «Система» показывает, где корень данных, на каком он диске и сколько места занимают образы, контейнеры, снимки, тома и ядра. Переместить на другой диск… останавливает службы, копирует данные, проверяет их, переключает корень и снова запускает службы; старую копию он удаляет только после отдельного подтверждения. Gantry запоминает корень для всех следующих запусков. Новые тома могут лежать в папке на любом диске, а если этот диск не подключён, Gantry сообщает, какого диска нет, и не запускает контейнеры, которым он нужен.

    Docker Desktop и OrbStack

Docker Desktop переносит свой образ диска в Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack добавил настройку расположения данных в версии 0.13.0. См. сравнение.

Вопросы и ответы

Можно ли хранить образы Apple container на внешнем диске?

Да. Запустите службы командой container system start --app-root /Volumes/Disk/container. Тогда все образы, контейнеры, снимки и тома будут храниться в этой папке.

Какую файловую систему выбрать для внешнего диска?

APFS. Тома — это разреженные образы дисков, а контейнерам нужны права доступа Unix, которых нет в exFAT, FAT и NTFS.

Как скопировать данные контейнеров и не заполнить диск?

Используйте cp -Rp: в нашей проверке эта команда сохранила разреженные образы томов маленькими. ditto скопировал каждый разреженный образ в полном размере.

Что будет, если отключить диск во время работы контейнеров?

Контейнеры, которые используют диск, упадут, а ещё не записанные данные могут потеряться. Перед извлечением диска остановите контейнеры и, если на диске корень приложения, службы.

Запоминает ли CLI container новое расположение?

Нет. Передавайте --app-root при каждом container system start. container system status показывает текущий корень как paths.appRoot.

Gantry/Külső meghajtó

Konténerek és kötetek tárolása külső meghajtón

Az image-ek, a konténerek és a kötetek gyorsan megtöltik a kis belső lemezt. Az Apple container eszközével ezeket az adatokat külső SSD-n is tarthatja: egyes mappákat bind mounttal tehet oda, vagy áthelyezheti a teljes adatgyökeret. Ez az útmutató mindkét módszert bemutatja, és azt is, hogyan választhatja le a lemezt adatvesztés nélkül.

Röviden. Formázza a lemezt APFS-re. Egy projekthez csatoljon bind mounttal egy mappát: -v /Volumes/Fast/pg:/data. Mindenhez állítsa le a szolgáltatásokat, másolja a ~/Library/Application Support/com.apple.container mappát a lemezre a cp -Rp paranccsal, és a szolgáltatásokat minden alkalommal a container system start --app-root /Volumes/Fast/container paranccsal indítsa.

Hol vannak most az adatok

Az apple/container minden adatát egyetlen mappában, az alkalmazásgyökérben (app root) tárolja. Ez alapértelmezés szerint a ~/Library/Application Support/com.apple.container, benne mappákkal a konténerek, az image-tartalom, a pillanatképek, a kötetek, a kernelek és a hálózatok számára. Ellenőrizze az útvonalat és a foglalt helyet:

Terminál
container system status | grep appRoot
container system df

A lemez kiválasztása és formázása

  • USB-C-s vagy Thunderbolt-os SSD-t használjon. Forgólemezes merevlemez is működik, de a konténerek lassabban indulnak.
  • Formázza APFS-re (a Mac OS kiterjesztett is működik). Ne használjon exFAT, FAT vagy NTFS fájlrendszert: a kötetek ritka (sparse) lemezképek, ezekben a fájlrendszerekben pedig nincsenek ritka fájlok és Unix-jogosultságok.
  • Az alkalmazásgyökérhez ne használjon hálózati lemezt.
  • Adjon a lemeznek rövid, szóköz nélküli nevet, például Fast. Az útvonal ekkor /Volumes/Fast.
    1. lehetőség: projektadatok a lemezen bind mountokkal

A bind mount a Mac egy mappáját osztja meg a konténerrel, és a mappa bármely lemezen lehet. Így tarthatja a legegyszerűbben a nagy adatokat, például egy adatbázist vagy modellfájlokat, a belső lemezen kívül:

Terminál
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

A lemeznek a konténer indulása előtt csatlakoztatva kell lennie. Az image-ek és maga a konténer a belső lemezen maradnak.

    2. lehetőség: az összes apple/container-adat áthelyezése a lemezre

Ez áthelyezi az image-eket, a konténereket, a pillanatképeket és a köteteket. Először állítsa le a szolgáltatásokat, hogy a másolás közben egyetlen fájl se változzon:

Terminál
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Használja a cp -Rp parancsot. A macOS 27-en végzett tesztünkben (APFS-ről APFS-re, USB-n) ritkák maradtak a kötetképek, és megmaradtak a kiterjesztett attribútumok. A ditto minden ritka képet teljes méretben írt ki, ami megtöltheti a lemezt. A régi mappát addig tartsa meg, amíg nem ellenőrizte, hogy a konténerek, az image-ek és a kötetek megjelennek a listákban.

Figyelem
A CLI nem jegyzi meg a --app-root kapcsolót. Minden container system start nélküle ismét a belső mappát használja. Mindig adja meg a kapcsolót, például egy shell-aliasban, és ellenőrizze a paths.appRoot értéket a container system status kimenetében.

A Gantry 0.27.0 --app-root nélkül indítja el a szolgáltatásokat, ha olyan gazdagéphez csatlakozik, amelynek a szolgáltatásai le vannak állítva. Először indítsa el a szolgáltatásokat a terminálból a kapcsolóval; a Gantry ezután a futó szolgáltatásokat használja.

    Image-ek archiválása a lemezre

Ha helyet szeretne felszabadítani úgy, hogy egy image se vesszen el, mentse a külső lemezre, és törölje. Ha szüksége van rá, töltse be újra:

Terminál
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    A lemez biztonságos leválasztása
  1. Állítsa le a lemezt használó konténereket: container stop <name>.
  2. Ha az alkalmazásgyökér a lemezen van, állítsa le a szolgáltatásokat: container system stop.
  3. Adja ki a lemezt a Finderben, majd húzza ki.

Ha a lemez eltűnik, miközben konténerek futnak róla, azok meghibásodnak, és a folyamatban lévő írások elveszhetnek. A lemez újracsatlakoztatása után indítsa el a szolgáltatásokat a --app-root kapcsolóval, majd indítsa el a konténereket.

    Külső meghajtók a Gantryben

A Gantry már most futtat bind mountokat bármely lemezről: az Új konténer lapon adjon hozzá egy kötetet, válasszon egy mappát a külső lemezen és egy útvonalat a konténerben.

    Docker Desktop és OrbStack

A Docker Desktop a lemezképét a Settings ▸ Resources ▸ Advanced ▸ Disk image location beállításban helyezi át. Az OrbStack a 0.13.0-s verzióban kapott adathely-beállítást. Lásd az összevetést.

Kérdések és válaszok

Tárolhatók az Apple container image-ei külső meghajtón?

Igen. Indítsa el a szolgáltatásokat a container system start --app-root /Volumes/Disk/container paranccsal. Ezután az összes image, konténer, pillanatkép és kötet ebben a mappában lesz.

Milyen fájlrendszert használjon a külső meghajtó?

APFS-t. A kötetek ritka (sparse) lemezképek, a konténereknek pedig Unix-jogosultságok kellenek, amelyek az exFAT, a FAT és az NTFS fájlrendszerben nincsenek meg.

Hogyan másolhatók a konténeradatok úgy, hogy ne teljen meg a lemez?

Használja a cp -Rp parancsot, amely a tesztünkben kicsinek tartotta a ritka kötetképeket. A ditto minden ritka képet teljes méretben másolt át.

Mi történik, ha kihúzom a meghajtót, miközben konténerek futnak?

A lemezt használó konténerek meghibásodnak, és a még ki nem írt adatok elveszhetnek. Mielőtt kiadja a lemezt, állítsa le a konténereket, és ha az alkalmazásgyökér a lemezen van, a szolgáltatásokat is.

Megjegyzi a container CLI az új helyet?

Nem. Minden container system start parancsnak adja meg a --app-root kapcsolót. A container system status a használt gyökeret paths.appRoot néven mutatja.

Gantry/Zunanji disk

Vsebniki in nosilci na zunanjem disku

Slike, vsebniki in nosilci hitro napolnijo majhen notranji disk. Z Applovim orodjem container lahko te podatke hranite na zunanjem SSD: posamezne mape tja postavite z veznimi priklopi ali pa premaknete celotno korensko mapo podatkov. Ta vodnik pokaže oboje in kako disk izklopite brez škode.

Na kratko. Disk formatirajte kot APFS. Za en projekt vezno priklopite mapo: -v /Volumes/Fast/pg:/data. Za vse podatke ustavite storitve, kopirajte ~/Library/Application Support/com.apple.container na disk s cp -Rp in storitve vsakič zaženite z container system start --app-root /Volumes/Fast/container.

Kje so podatki zdaj

apple/container vse svoje podatke hrani v eni mapi, korenski mapi aplikacije (app root). Privzeto je to ~/Library/Application Support/com.apple.container, z mapami za vsebnike, vsebino slik, posnetke, nosilce, jedra in omrežja. Preverite pot in porabljeni prostor:

Terminal
container system status | grep appRoot
container system df

Izbira in formatiranje diska

  • Uporabite SSD prek USB-C ali Thunderbolt. Vrteči se disk deluje, vendar se vsebniki zaganjajo počasneje.
  • Formatirajte ga kot APFS (deluje tudi Mac OS Extended). Ne uporabljajte exFAT, FAT ali NTFS: nosilci so redke slike diska, ti datotečni sistemi pa nimajo redkih datotek in dovoljenj Unix.
  • Za korensko mapo aplikacije ne uporabljajte omrežnega diska.
  • Disku dajte kratko ime brez presledkov, na primer Fast. Pot je potem /Volumes/Fast.
    Možnost 1: podatki projekta na disku z veznimi priklopi

Vezni priklop deli mapo iz vašega Maca z vsebnikom, mapa pa je lahko na katerem koli disku. Tako najlažje velike podatke, na primer bazo podatkov ali datoteke modelov, držite zunaj notranjega diska:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Disk mora biti priključen, preden se vsebnik zažene. Slike in sam vsebnik ostanejo na notranjem disku.

    Možnost 2: vsi podatki apple/container na disku

Tako premaknete slike, vsebnike, posnetke in nosilce. Najprej ustavite storitve, da se med kopiranjem ne spremeni nobena datoteka:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Uporabite cp -Rp. V našem preizkusu v macOS 27 (z APFS na APFS prek USB) je slike nosilcev ohranil redke in ohranil razširjene atribute. ditto je vsako redko sliko zapisal v polni velikosti, kar lahko napolni disk. Staro mapo obdržite, dokler ne preverite, da so vaši vsebniki, slike in nosilci na seznamu.

Pozor
CLI si --app-root ne zapomni. Vsak container system start brez te zastavice znova uporabi notranjo mapo. Zastavico uporabite vsakič, na primer v vzdevku lupine, in preverite paths.appRoot v container system status.

Gantry 0.27.0 zažene storitve brez --app-root, ko se poveže z gostiteljem, katerega storitve so ustavljene. Storitve najprej zaženite iz terminala z zastavico; Gantry nato uporabi storitve, ki že tečejo.

    Arhiviranje slik na disk

Če želite sprostiti prostor, ne da bi izgubili sliko, jo shranite na zunanji disk in izbrišite. Ko jo potrebujete, jo znova naložite:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Varen izklop diska
  1. Ustavite vsebnike, ki uporabljajo disk: container stop <name>.
  2. Če je korenska mapa aplikacije na disku, ustavite storitve: container system stop.
  3. Disk izvrzite v Finderju, nato ga izklopite.

Če disk izgine, medtem ko z njega tečejo vsebniki, ti odpovejo, zapisi v teku pa se lahko izgubijo. Ko disk znova priključite, zaženite storitve z --app-root, nato zaženite vsebnike.

    Zunanji diski v Gantryju

Gantry že zdaj zaganja vezne priklope s katerega koli diska: v oknu Nov vsebnik dodajte nosilec, izberite mapo na zunanjem disku in pot v vsebniku.

    Docker Desktop in OrbStack

Docker Desktop svojo sliko diska premakne v Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack je nastavitev za mesto podatkov dodal v različici 0.13.0. Glejte primerjavo.

Vprašanja in odgovori

Ali lahko slike Apple container hranim na zunanjem disku?

Da. Storitve zaženite z container system start --app-root /Volumes/Disk/container. Vse slike, vsebniki, posnetki in nosilci so nato v tej mapi.

Kateri datotečni sistem naj uporablja zunanji disk?

APFS. Nosilci so redke slike diska, vsebniki pa potrebujejo dovoljenja Unix, ki jih exFAT, FAT in NTFS nimajo.

Kako kopiram podatke vsebnikov, ne da bi napolnil disk?

Uporabite cp -Rp, ki je v našem preizkusu ohranil redke slike nosilcev majhne. ditto je vsako redko sliko kopiral v polni velikosti.

Kaj se zgodi, če disk izklopim, medtem ko vsebniki tečejo?

Vsebniki, ki uporabljajo disk, odpovejo, podatki, ki še niso bili zapisani, pa se lahko izgubijo. Preden disk izvržete, ustavite vsebnike in, če je korenska mapa aplikacije na disku, tudi storitve.

Ali si CLI container zapomni novo mesto?

Ne. --app-root podajte vsakemu container system start. container system status prikaže uporabljeno korensko mapo kot paths.appRoot.

Images & Compose

Images

  • Pull with optional registry authentication and per-layer progress.
  • Build from a Dockerfile — pick the context, tag, target stage, build args and cache option, and watch the log stream live. You can also drag a Dockerfile onto the window, or use Open With → Gantry.
  • Tag and remove images; prune dangling or all unused.
  • Inspect an image's layers/history and raw JSON, and see which containers use it.
  • A badge marks images (and their containers) built for a different CPU architecture than the host, for example amd64 on Apple silicon.
  • Scan for Vulnerabilities… in the image menu or toolbar runs Trivy (0.50.0 or later) or Grype (0.74.0 or later). Gantry finds them in PATH, /opt/homebrew/bin or /usr/local/bin (or GANTRY_TRIVY and GANTRY_GRYPE) and does not install them: brew install trivy or brew install grype. Findings are grouped from Critical to Unknown and link to their advisories. Export SBOM writes CycloneDX, or SPDX with Trivy. On apple/container and local Docker, Gantry saves the image to an archive and scans it; on SSH hosts it scans the registry copy of a tagged image. Results are not stored.
  • On apple/container hosts with CLI 1.5 or 1.6, Load into Cluster copies a local image into a Kubernetes cluster's nodes. CLI 1.7 replaces it with the shared image store of the cluster.

Build history

Each host has a Builds section after Images. It lists the builds that Gantry started (the Build Image sheet and Compose), with their state, duration, steps (Executed, Cached, Failed), cache use and log. Gantry keeps 100 builds per host and the last 512 KB of each log in ~/Library/Application Support/Gantry/build-history.json, with build-argument names but not their values. On Docker hosts it also reads docker buildx history (buildx 0.23.0 or later), shown with the source BuildKit. apple/container keeps no build history of its own, so an apple/container host shows only the builds that Gantry started. Clear History… removes only Gantry's records.

Compose

On apple/container hosts, open a docker-compose.yml from Docker → Open Compose File…, Finder's Open With, or by dropping it on the window. Choose the host, toggle recreate / no-cache, and bring the project up with a live, colorized log stream. When it's up, Gantry jumps to the host's Containers grouped by the Compose project.

The header of each Compose project in the container list has Pull Images and Compose Down. Compose Down removes the containers and keeps volumes and images. Pulls, builds and Compose runs show their progress in the menu bar. To go the other way, Export as Compose turns running containers into a compose file.

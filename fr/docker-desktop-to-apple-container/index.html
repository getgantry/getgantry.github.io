Gantry/Depuis Docker Desktop

Passer de Docker Desktop à Apple container

L'outil container d'Apple exécute les mêmes images OCI que Docker : l'essentiel de votre travail se transpose en changeant quelques commandes. Ce guide fait correspondre Docker et container, déplace les images et les volumes, et liste les limites à connaître avant de changer.

En bref. Installez le paquet signé de container, remplacez docker par container pour run, build, logs, exec et les images, copiez les volumes nommés avec un fichier tar et ouvrez votre docker-compose.yml dans Gantry, car la CLI n'a pas de compose. Vous pouvez garder Docker Desktop installé pendant l'essai.

Ce qui change

  • Une VM par conteneur. Docker Desktop exécute tous les conteneurs dans une seule VM Linux. apple/container démarre une petite VM pour chaque conteneur : chacun reçoit donc sa propre adresse IP sur votre Mac.
  • Mêmes images, mêmes registres. Les images sont des images OCI ; vous téléchargez depuis Docker Hub, GHCR et vos registres privés comme avant.
  • Aucune licence à payer. apple/container est sous licence Apache 2.0. Docker Desktop exige un abonnement payant dans les organisations de 250 employés ou plus ou de 10 millions de dollars de chiffre d'affaires ou plus.
  • Puce Apple et macOS 26 uniquement. Sur un Mac Intel, restez sur un moteur Docker.

La plupart des options de run sont identiques : -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus et -m. Pour convertir une longue commande, collez-la dans Gantry : voir Créer un conteneur à partir d'une commande docker run.

    Récupérer vos images

Images d'un registre : téléchargez-les à nouveau avec container image pull. Images locales qui n'existent que dans Docker : enregistrez-les dans une archive et chargez celle-ci. container image load lit les archives OCI, et les versions récentes de Docker écrivent une disposition OCI avec docker save. Si le chargement échoue, envoyez l'image vers un registre puis téléchargez-la.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Déplacer les volumes nommés

Docker conserve les données des volumes dans sa VM. Copiez chaque volume dans un fichier tar avec un conteneur éphémère, puis décompressez-le dans un nouveau volume apple/container :

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Un volume nommé d'apple/container est une image disque ext4 creuse, de 512 Go au plus par défaut. Choisissez une autre taille avec --opt size=20g. Les montages liés de dossiers de votre Mac fonctionnent comme dans Docker : -v ~/project:/app.

    Fichiers Compose

La CLI container n'a pas de commande compose. Ouvrez plutôt le docker-compose.yml dans Gantry (depuis le Finder, avec Fichier ▸ Ouvrir un fichier Compose… ou par glisser-déposer). Gantry construit les services build:, crée le réseau et les volumes nommés du projet, et démarre les services dans l'ordre de depends_on. Les services se joignent par leur nom de service grâce aux alias DNS du réseau.

    Réseaux et ports
  • -p 8080:80 publie un port sur localhost, comme dans Docker.
  • Chaque conteneur a aussi sa propre adresse IP. Créez un domaine DNS local avec sudo container system dns create test et exécutez les conteneurs avec --dns-domain test : ils reçoivent des noms comme web.test.
  • container network create crée des réseaux utilisateur ; les conteneurs d'un même réseau se joignent entre eux.
  • Il n'existe pas de mode --network host, none ni container:.
    Ce qui manque
  • Pas d'API Docker Engine. Les outils qui communiquent avec /var/run/docker.sock, comme Testcontainers, les SDK Docker ou Dev Containers, ne voient pas apple/container.
  • Pas de politique de redémarrage. --restart n'est pas disponible ; un conteneur ne redémarre pas de lui-même.
  • Pas de Compose dans la CLI. Gantry exécute les fichiers Compose : voir Fichiers Compose.
  • Pas d'extensions Docker Desktop.
  • CPU entiers uniquement : --cpus 0.5 ne fonctionne pas.
  • Kubernetes fonctionne autrement : utilisez container cluster, voir Exécuter Kubernetes sur un Mac.
    Garder les deux pendant la transition

Gantry gère apple/container et n'importe quel moteur Docker (Docker Desktop, OrbStack, Colima ou Docker via SSH) dans une seule barre latérale. Migrez un projet à la fois et gardez Docker pour les outils qui ont besoin de son API. Quand vous n'en avez plus besoin, vous pouvez désinstaller Docker Desktop.

Questions et réponses

Apple container peut-il remplacer Docker Desktop ?

Pour exécuter, construire et télécharger des conteneurs sur puce Apple, oui. Il n'a pas l'API Docker Engine, les politiques de redémarrage, les extensions ni de commande compose. Gantry ajoute les fichiers Compose et une GUI.

Les images Docker fonctionnent-elles avec Apple container ?

Oui. apple/container utilise des images OCI standard et télécharge depuis les mêmes registres. Les images arm64 s'exécutent nativement ; les images amd64 s'exécutent via Rosetta avec --arch amd64.

docker compose fonctionne-t-il avec Apple container ?

Pas depuis la CLI : il n'existe pas de container compose. Gantry lit le docker-compose.yml et exécute les services sur apple/container pour vous.

Peut-on utiliser Docker Desktop et Apple container en même temps ?

Oui. Ils ne partagent ni images ni volumes, mais ils peuvent fonctionner côte à côte. Gantry affiche les deux dans une seule fenêtre.

Apple container est-il gratuit pour un usage commercial ?

Oui. apple/container est open source sous licence Apache 2.0, et Gantry est sous licence MIT. Les deux sont gratuits pour les entreprises de toute taille.

Gantry/Från docker run

Skapa en container från ett docker run-kommando

De flesta README-filer har en docker run-rad. Gantry läser raden och fyller i formuläret Ny container, för en Docker-värd eller för Apples container-verktyg. Den här guiden visar hur, och hur du konverterar kommandot för hand.

Kort sagt. Öppna Ny container i Gantry, välj Klistra in kommando…, klistra in docker run-raden och klicka på Fyll i formulär. Gantry listar varje flagga som den inte kan använda, med orsaken. För CLI:et är de flesta flaggor desamma: byt docker run mot container run och ta bort --restart.

Klistra in kommandot i Gantry

  1. Välj en värd: en Docker-värd eller en apple/container-värd.
  2. Öppna Containrar och klicka på Ny container.
  3. Klicka på Klistra in kommando… och klistra in raden. Radslut med \, citattecken, en $-prompt och sudo går bra.
  4. Läs förhandsvisningen: imagen, de flaggor som Gantry inte kan använda, kommentarer och varningar för den här värden.
  5. Klicka på Fyll i formulär, kontrollera värdena och skapa containern.

Gantry läser docker run, docker container run, docker create, podman run och container run. Text efter &&, ||, ; eller | ignoreras, med en kommentar.

Varningar för apple/container-värdar

Vissa Docker-alternativ finns inte i apple/container. Gantry varnar för dem och utelämnar dem ur begäran om att skapa containern:

  • omstartspolicyer (--restart);
  • delar av CPU:er, till exempel --cpus 0.5;
  • nätverkslägena host, none och container:;
  • portar utan värdport, till exempel -p 80.

På en Docker-värd varnar Gantry för alternativen för apple/container: DNS-domänen och kärnalternativen.

Konvertera docker run till container run för hand

För CLI:et är de flesta flaggor desamma. Ett exempel med Redis:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

blir:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Skapa den namngivna volymen först med container volume create. Ta bort --restart och avrunda --cpus till ett heltal. --platform fungerar som i Docker.

Kopiera en container som kommando

Det fungerar även åt andra hållet. Högerklicka på en container, eller använd menyn Mer, och välj Kopiera som kommando: Gantry skriver en docker run- eller container run-rad. Den utelämnar imagens standardvärden, till exempel dess miljö och kommando, så att raden blir kort. Det fungerar även för stoppade containrar.

Spara som recept

Öppna Recept i arket Ny container och välj Spara som recept…. Nästa gång ger Fyll i från recept samma formulär på valfri värd. Recepten finns i ~/Library/Application Support/Gantry/recipes.json, så du kan säkerhetskopiera eller dela dem.

Begränsningar

  • Gantry behåller sökvägen för --env-file men läser inte filen, och läser inte ditt skal för -e KEY utan värde.
  • tmpfs-monteringar och anonyma volymer från --mount listas som inte stödda.
  • Två portar för samma containerport (-p 8080:80 -p 8081:80) fyller i formuläret, men formuläret avvisar sedan dubbletten.

Frågor och svar

Hur konverterar jag docker run till container run?

Byt docker run mot container run. -d, -p, -e, -v, --name, --rm, -it, -w och --entrypoint är desamma. Ta bort --restart och använd hela CPU:er. Eller klistra in raden i Gantry och låt den fylla i formuläret.

Kan Gantry importera ett docker run-kommando?

Ja. Klistra in kommando… i arket Ny container läser docker run, docker create, podman run och container run och fyller i formuläret.

Vad händer med flaggor som Gantry inte stöder?

De listas i förhandsvisningen med orsaken, och de finns kvar i formuläret i avsnittet Från det inklistrade kommandot, så att du kan kontrollera dem senare.

Kan jag göra om en container som körs till ett docker run-kommando?

Ja. Kopiera som kommando i containermenyn skriver en docker run- eller container run-rad för den containern.

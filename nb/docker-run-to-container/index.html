Gantry/Fra docker run

Opprett en container fra en docker run-kommando

De fleste README-filer gir en docker run-linje. Gantry leser den linjen og fyller ut skjemaet Ny container, for en Docker-vert eller for Apples verktøy container. Denne guiden viser hvordan, og hvordan du gjør om kommandoen for hånd.

Kort fortalt. I Gantry åpner du Ny container, velger Lim inn kommando…, limer inn docker run-linjen og klikker på Fyll ut skjema. Gantry lister opp hvert flagg den ikke kan bruke, med årsaken. For CLI-en er de fleste flaggene de samme: bytt ut docker run med container run og fjern --restart.

Lim inn kommandoen i Gantry

  1. Velg en vert: en Docker-vert eller en apple/container-vert.
  2. Åpne Containere og klikk på Ny container.
  3. Klikk på Lim inn kommando… og lim inn linjen. Linjeskift med \, anførselstegn, en $-ledetekst og sudo går helt fint.
  4. Les forhåndsvisningen: imaget, flaggene Gantry ikke kan bruke, merknader og advarsler for denne verten.
  5. Klikk på Fyll ut skjema, sjekk verdiene og opprett containeren.

Gantry leser docker run, docker container run, docker create, podman run og container run. Tekst etter &&, ||, ; eller | ignoreres, med en merknad.

Omtrent 80 andre Docker-flagg er kjent: Gantry hopper riktig over verdiene deres og lister dem opp som ikke brukt, så ingenting går tapt uten en merknad.

Advarsler for apple/container-verter

Noen Docker-alternativer finnes ikke i apple/container. Gantry advarer om dem og utelater dem fra opprettingsforespørselen:

  • omstartsregler (--restart);
  • brøkdeler av CPU-er, som --cpus 0.5;
  • nettverksmodusene host, none og container:;
  • porter uten vertsport, som -p 80.

På en Docker-vert advarer Gantry om alternativene for apple/container: DNS-domenet og kjernealternativene.

Gjør om docker run til container run for hånd

For CLI-en forblir de fleste flaggene de samme. Et eksempel med Redis:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

blir:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Opprett det navngitte volumet først med container volume create. Fjern --restart og rund av --cpus til et helt tall. --platform fungerer som i Docker.

Kopier en container som kommando

Det fungerer også den andre veien. Høyreklikk på en container, eller bruk Mer-menyen, og velg Kopier som kommando: Gantry skriver en docker run- eller container run-linje. Den utelater standardverdiene fra imaget, som miljøet og kommandoen, så linjen holder seg kort. Dette fungerer også for stoppede containere.

Lagre den som oppskrift

I arket Ny container åpner du Oppskrifter og velger Lagre som oppskrift…. Neste gang gir Fyll ut fra oppskrift det samme skjemaet på hvilken som helst vert. Oppskriftene ligger i ~/Library/Application Support/Gantry/recipes.json, så du kan sikkerhetskopiere eller dele dem.

Begrensninger

  • Gantry beholder stien fra --env-file, men leser ikke filen, og leser ikke skallet ditt for -e KEY uten verdi.
  • tmpfs-monteringer og anonyme volumer fra --mount listes opp som ikke støttet.
  • To porter for den samme containerporten (-p 8080:80 -p 8081:80) fyller ut skjemaet, men skjemaet avviser da duplikatet.

Spørsmål og svar

Hvordan gjør jeg om docker run til container run?

Bytt ut docker run med container run. -d, -p, -e, -v, --name, --rm, -it, -w og --entrypoint forblir de samme. Fjern --restart og bruk hele CPU-er. Eller lim inn linjen i Gantry og la appen fylle ut skjemaet.

Kan Gantry importere en docker run-kommando?

Ja. Lim inn kommando… i arket Ny container leser docker run, docker create, podman run og container run og fyller ut skjemaet.

Hva skjer med flagg som Gantry ikke støtter?

De listes opp i forhåndsvisningen med årsaken, og de blir værende i skjemaet i delen Fra den innlimte kommandoen, så du kan sjekke dem senere.

Kan jeg gjøre en container som kjører, om til en docker run-kommando igjen?

Ja. Kopier som kommando i containermenyen skriver en docker run- eller container run-linje for den containeren.

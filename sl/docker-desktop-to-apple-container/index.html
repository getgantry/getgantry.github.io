Gantry/Z Docker Desktop

Selitev z Docker Desktop na Apple container

Applovo orodje container zaganja enake slike OCI kot Docker, zato se večina vašega dela prenese z nekaj spremembami ukazov. Ta vodnik preslika Docker na container, prenese slike in nosilce ter našteje vrzeli, za katere morate vedeti pred prehodom.

Na kratko. Namestite podpisani paket container, pri run, build, logs, exec in images zamenjajte docker z container, poimenovane nosilce kopirajte z datoteko tar, svoj docker-compose.yml pa odprite v Gantryju, ker CLI nima ukaza compose. Med preizkušanjem lahko Docker Desktop ostane nameščen.

Kaj se spremeni

  • En navidezni stroj na vsebnik. Docker Desktop izvaja vse vsebnike v enem navideznem stroju Linux. apple/container za vsak vsebnik zažene majhen navidezni stroj, zato vsak dobi lasten naslov IP v vašem Macu.
  • Enake slike in registri. Slike so slike OCI; povlečete jih iz Docker Hub, GHCR in zasebnih registrov kot doslej.
  • Brez licenčnine. apple/container je pod licenco Apache 2.0. Docker Desktop zahteva plačljivo naročnino v organizacijah z 250 ali več zaposlenimi ali z 10 milijoni USD ali več prihodkov.
  • Samo Apple silicon in macOS 26. Na Macih z Intelom ostanite pri pogonu Docker.

Večina zastavic za run je enakih: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus in -m. Dolg ukaz pretvorite tako, da ga prilepite v Gantry: glejte Ustvarjanje vsebnika iz ukaza docker run.

    Prenos slik

Slike iz registra: znova jih povlecite z container image pull. Lokalne slike, ki obstajajo samo v Dockerju: shranite jih v arhiv in ga naložite. container image load bere arhive OCI, novejše različice Dockerja pa z docker save zapišejo postavitev OCI. Če nalaganje ne uspe, sliko potisnite v register in jo povlecite.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Selitev poimenovanih nosilcev

Docker hrani podatke nosilcev v svojem navideznem stroju. Vsak nosilec s kratkotrajnim vsebnikom kopirajte v datoteko tar, nato jo razpakirajte v nov nosilec apple/container:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Poimenovani nosilec v apple/container je redka slika diska ext4, privzeto velika največ 512 GB. Drugo velikost nastavite z --opt size=20g. Vezni priklopi map v vašem Macu delujejo kot v Dockerju: -v ~/project:/app.

    Datoteke Compose

CLI container nima ukaza compose. Namesto tega odprite docker-compose.yml v Gantryju (Finder, Datoteka ▸ Odpri datoteko Compose… ali povlecite in spustite). Gantry zgradi storitve build:, ustvari omrežje projekta in poimenovane nosilce ter zažene storitve v vrstnem redu iz depends_on. Storitve se med seboj dosežejo po imenu storitve prek omrežnih vzdevkov DNS.

    Omrežja in vrata
  • -p 8080:80 objavi vrata na localhost, kot v Dockerju.
  • Vsak vsebnik ima tudi lasten naslov IP. Ustvarite lokalno domeno DNS z sudo container system dns create test in zaganjajte vsebnike z --dns-domain test: dobijo imena, kot je web.test.
  • container network create ustvari uporabniška omrežja; vsebniki v istem omrežju se med seboj dosežejo.
  • Načinov --network host, none in container: ni.
    Kaj manjka
  • Ni API-ja Docker Engine. Orodja, ki komunicirajo z /var/run/docker.sock, na primer Testcontainers, kompleti SDK za Docker ali Dev Containers, apple/container ne vidijo.
  • Ni pravilnikov ponovnega zagona. --restart ni na voljo; vsebnik se sam ne zažene znova.
  • Ni Compose v CLI. Datoteke Compose zažene Gantry: glejte Datoteke Compose.
  • Ni razširitev Docker Desktop.
  • Samo celi CPU-ji: --cpus 0.5 ne deluje.
  • Kubernetes deluje drugače: uporabite container cluster, glejte Kubernetes v Macu.
    Med prehodom obdržite oboje

Gantry upravlja apple/container in kateri koli pogon Docker (Docker Desktop, OrbStack, Colima ali Docker prek SSH) v eni stranski vrstici. Selite en projekt naenkrat, Docker pa obdržite za orodja, ki potrebujejo njegov API. Ko ga ne potrebujete več, lahko Docker Desktop odstranite.

Vprašanja in odgovori

Ali lahko Apple container nadomesti Docker Desktop?

Za zaganjanje, gradnjo in vlečenje vsebnikov na Apple silicon da. Nima pa API-ja Docker Engine, pravilnikov ponovnega zagona, razširitev in ukaza compose. Gantry doda datoteke Compose in GUI.

Ali slike Docker delujejo z Apple container?

Da. apple/container uporablja standardne slike OCI in jih vleče iz istih registrov. Slike arm64 se izvajajo izvorno, slike amd64 pa prek Rosetta z --arch amd64.

Ali docker compose deluje z Apple container?

Iz CLI ne: ukaza container compose ni. Gantry prebere docker-compose.yml in namesto vas zažene storitve v apple/container.

Ali lahko Docker Desktop in Apple container uporabljam hkrati?

Da. Slik in nosilcev si ne delita, lahko pa se izvajata drug ob drugem. Gantry oba prikaže v enem oknu.

Ali je Apple container brezplačen za komercialno uporabo?

Da. apple/container je odprtokoden pod licenco Apache 2.0, Gantry pa pod licenco MIT. Oba sta brezplačna za podjetja vseh velikosti.

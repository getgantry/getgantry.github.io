Gantry/Kubernetes op apple/container

Kubernetes op Apple container

apple/container kan een Kubernetes-cluster draaien waarvan de nodes containers op je Mac zijn. Gantry is daar een GUI voor: maak een cluster, zie de nodes opkomen, verbind kubectl en laad je lokale images, zonder lange container cluster-opdrachtregels.

Kort gezegd. Op een apple/container-host maakt en verwijdert het onderdeel Clusters van Gantry Kubernetes-clusters met container cluster (CLI 1.6.1) of container k8s (CLI 1.5.0 tot en met 1.6.0). Het ondersteunt meerdere workers, een eigen CNI, een nodeoverzicht, kubeconfig en kubectl-context, en Laad in cluster voor lokale images.

Vereisten

  • Een Mac met Apple silicon, macOS 26 en Gantry (brew install --cask getgantry/tap/gantry).
  • De container-CLI 1.5.0 of nieuwer; 1.6.1 wordt aanbevolen. Workers en de CNI Geen vereisen 1.6.0 of nieuwer.
  • kubectl, als je het cluster vanuit de terminal wilt gebruiken.

Een cluster maken

  1. Selecteer je apple/container-host en open Clusters in de navigatiekolom.
  2. Start een nieuw cluster en vul de opties hieronder in.
  3. Maak het aan. De lijst toont het nieuwe cluster met gestreamde voortgang. Annuleer stopt het aanmaken en verwijdert de nodes die al gemaakt waren.
OptieCLI-flagOpmerkingen
Naam--nameOok de naam van de kubeconfig-context
Workers--workersAantal workernodes. CLI 1.6.0+
CPU's--cpusPer node
Geheugen--memoryPer node, bijvoorbeeld 4G
Node-image--node-imageLeeg laten voor de standaard van de CLI
CNI--cniStandaard (meegeleverde kindnet), Geen (NONE, CLI 1.6.0+) of een pad naar een aangepast manifest

Hetzelfde commando in de CLI:

Shell
container cluster create --name dev --workers 2 --cpus 2 --memory 4G

Nodes en clusterdetails

De clusterlijst toont elk cluster met zijn nodes: rol, status en adres. De detailweergave heeft een Overzicht (kubectl-context, API-server, workers, nodenetwerk), een tabel Nodes, Inspecteren voor de ruwe nodegegevens, en de acties Schrijf Kubeconfig, Kopieer kubectl-contextcommando en Verwijder.

kubectl verbinden

De CLI voegt bij het aanmaken van het cluster een context met de naam van het cluster toe aan ~/.kube/config. Gebruik Kopieer kubectl-contextcommando in Gantry, of typ het zelf:

Shell
kubectl --context dev get nodes

Wil je het cluster in een eigen bestand, gebruik dan Schrijf Kubeconfig. Gantry voert container cluster write-config uit; het standaardpad is ~/.kube/<name>.kubeconfig.

Lokale images in het cluster laden

Bouw of pull een image op de apple/container-host, klik er dan met de rechtermuisknop op in Images en kies Laad in cluster. Gantry voert container cluster load-image uit, dat de image naar de containerd van elke node kopieert. Voor lokale ontwikkeling heb je geen registry nodig.

Shell
container cluster load-image --name dev myapp:dev

Een CNI kiezen

De standaard is het meegeleverde kindnet-manifest. Kies Aangepast manifest om je eigen CNI, bijvoorbeeld Calico of Cilium, uit een bestand te installeren. Kies Geen om later zelf een CNI te installeren; tot die tijd blijven de nodes NotReady.

Clusters vanuit AI-agents

De Gantry MCP-server heeft list_clusters, create_cluster en delete_cluster, zodat een agent als Claude Code een tijdelijk cluster voor een test kan maken en het daarna weer kan verwijderen.

Voeg de Gantry MCP-server toe
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Meer over apple/container

Lees de apple/container-gids voor elk container-commando en de bijbehorende Gantry-functie, of bekijk hoe Gantry zich verhoudt tot Docker Desktop, OrbStack en Podman Desktop.

Vragen en antwoorden

Ondersteunt Apple container Kubernetes?

Ja. De container-CLI maakt Kubernetes-clusters waarvan de nodes als containers draaien: container cluster in CLI 1.6.1, container k8s in CLI 1.5.0 tot en met 1.6.0. Gantry voegt er een GUI aan toe.

Ondersteunt Gantry container cluster?

Ja. Gantry geeft een overzicht van clusters op apple/container-hosts, maakt en verwijdert ze, toont hun nodes, schrijft de kubeconfig, kopieert het kubectl-contextcommando en laadt lokale images in een cluster. Het gebruikt cluster of k8s, afhankelijk van je CLI-versie.

Hoe gebruik ik kubectl met een apple/container-cluster?

Wanneer de CLI een cluster maakt, voegt hij een kubeconfig-context met de naam van het cluster toe aan ~/.kube/config. Voer kubectl --context <name> get nodes uit. Wil je een apart bestand, gebruik dan Schrijf Kubeconfig in Gantry; het standaardpad is ~/.kube/<name>.kubeconfig.

Hoe krijg ik een lokale image in het cluster zonder registry?

Klik in Gantry onder Images met de rechtermuisknop op de image en kies Laad in cluster. Gantry voert container cluster load-image uit, dat de image naar de containerd van elke node kopieert.

Kan ik een cluster met meerdere nodes maken?

Ja. Stel het aantal workers in bij het aanmaken. Workers vereisen CLI 1.6.0 of nieuwer.

Kan ik mijn eigen CNI gebruiken, zoals Calico of Cilium?

Ja. Kies Aangepast manifest en selecteer het manifestbestand, of kies Geen en installeer zelf een CNI nadat het cluster is gestart. Nodes blijven NotReady tot er een CNI draait. Geen vereist CLI 1.6.0 of nieuwer. De standaard-CNI is het meegeleverde kindnet-manifest.

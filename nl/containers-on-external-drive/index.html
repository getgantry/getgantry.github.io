Gantry/Externe schijf

Containers en volumes op een externe schijf bewaren

Images, containers en volumes vullen een kleine interne schijf snel. Met Apples container-tool kun je die gegevens op een externe SSD bewaren: losse mappen via bind mounts, of de hele gegevensmap. Deze gids toont beide, en hoe je de schijf zonder schade loskoppelt.

Kort gezegd. Formatteer de schijf als APFS. Voor één project koppel je een map via een bind mount: -v /Volumes/Fast/pg:/data. Voor alles stop je de services, kopieer je ~/Library/Application Support/com.apple.container met cp -Rp naar de schijf en start je de services elke keer met container system start --app-root /Volumes/Fast/container.

Waar de gegevens nu staan

apple/container bewaart al zijn gegevens in één map, de app-root. Standaard is dat ~/Library/Application Support/com.apple.container, met mappen voor containers, image-inhoud, snapshots, volumes, kernels en netwerken. Controleer het pad en de gebruikte ruimte:

Terminal
container system status | grep appRoot
container system df

De schijf kiezen en formatteren

  • Gebruik een SSD via USB-C of Thunderbolt. Een harde schijf werkt ook, maar containers starten trager.
  • Formatteer hem als APFS (Mac OS Uitgebreid werkt ook). Gebruik geen exFAT, FAT of NTFS: volumes zijn sparse schijfkopieën, en die bestandssystemen hebben geen sparse bestanden en geen Unix-rechten.
  • Gebruik geen netwerkschijf voor de app-root.
  • Geef de schijf een korte naam zonder spaties, bijvoorbeeld Fast. Het pad is dan /Volumes/Fast.
    Optie 1: projectgegevens op de schijf bewaren met bind mounts

Een bind mount deelt een map van je Mac met de container, en die map kan op elke schijf staan. Zo houd je grote gegevens, zoals een database of modelbestanden, het makkelijkst van de interne schijf:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

De schijf moet aangesloten zijn voordat de container start. Images en de container zelf blijven op de interne schijf.

    Optie 2: alle apple/container-gegevens naar de schijf verplaatsen

Hiermee verplaats je images, containers, snapshots en volumes. Stop eerst de services, zodat er tijdens het kopiëren geen bestand verandert:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Gebruik cp -Rp. In onze test op macOS 27 (APFS naar APFS via USB) bleven de volume-images sparse en bleven de uitgebreide attributen behouden. ditto schreef elke sparse image op volle grootte, wat de schijf kan vullen. Bewaar de oude map tot je hebt gecontroleerd dat je containers, images en volumes in de lijst staan.

Let op
De CLI onthoudt --app-root niet. Elke container system start zonder deze flag gebruikt weer de interne map. Gebruik de flag elke keer, bijvoorbeeld in een shellalias, en controleer paths.appRoot in container system status.

Gantry 0.27.0 start de services zonder --app-root als het verbinding maakt met een host waarvan de services gestopt zijn. Start de services eerst vanuit de terminal met de flag; Gantry gebruikt dan de draaiende services.

    Images archiveren op de schijf

Om ruimte vrij te maken zonder een image kwijt te raken, sla je hem op de externe schijf op en verwijder je hem. Laad hem opnieuw wanneer je hem nodig hebt:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    De schijf veilig loskoppelen
  1. Stop de containers die de schijf gebruiken: container stop <name>.
  2. Staat de app-root op de schijf, stop dan de services: container system stop.
  3. Werp de schijf uit in de Finder en koppel hem daarna los.

Verdwijnt de schijf terwijl er containers vanaf draaien, dan mislukken die, en lopende schrijfacties kunnen verloren gaan. Start na het opnieuw aansluiten van de schijf de services met --app-root en daarna de containers.

    Externe schijven in Gantry

Gantry draait nu al bind mounts vanaf elke schijf: voeg in Nieuwe container een volume toe en kies een map op de externe schijf en een pad in de container.

    Docker Desktop en OrbStack

Docker Desktop verplaatst zijn schijfkopie via Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack heeft in versie 0.13.0 een instelling voor de gegevenslocatie toegevoegd. Zie de vergelijking.

Vragen en antwoorden

Kan ik images van Apple container op een externe schijf bewaren?

Ja. Start de services met container system start --app-root /Volumes/Disk/container. Alle images, containers, snapshots en volumes staan dan in die map.

Welk bestandssysteem moet de externe schijf hebben?

APFS. Volumes zijn sparse schijfkopieën en containers hebben Unix-rechten nodig, die exFAT, FAT en NTFS niet hebben.

Hoe kopieer ik de container-gegevens zonder de schijf te vullen?

Gebruik cp -Rp, dat de sparse volume-images in onze test klein hield. ditto kopieerde elke sparse image op volle grootte.

Wat gebeurt er als ik de schijf loskoppel terwijl er containers draaien?

De containers die de schijf gebruiken, mislukken, en gegevens die nog niet zijn geschreven, kunnen verloren gaan. Stop de containers en, als de app-root op de schijf staat, de services voordat je de schijf uitwerpt.

Onthoudt de container-CLI de nieuwe locatie?

Nee. Geef --app-root mee aan elke container system start. container system status toont de gebruikte map als paths.appRoot.

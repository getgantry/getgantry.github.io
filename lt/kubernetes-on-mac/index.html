Gantry/Kubernetes Mac kompiuteryje

Kubernetes paleidimas Mac kompiuteryje su Apple container

Apple container įrankis viena komanda gali sukurti vietinį Kubernetes klasterį. Kiekvienas mazgas yra lengva virtualioji mašina jūsų Mac kompiuteryje. Šis vadovas veda nuo tuščio Mac iki veikiančio diegimo – pirmiausia terminale, tada Gantry.

Trumpai. Įdiekite pasirašytą container 1.7.1 paketą, vykdykite container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, sukurkite atvaizdą su container build ir paleiskite jį klasteryje pagal pavadinimą. Gantry tą patį klasterį rodo lange: mazgus, podus, žurnalus, apvalkalą ir prievadų persiuntimą.

Ko reikia

  • Mac su Apple silicon ir macOS 26 arba naujesne.
  • container CLI 1.7.1 iš pasirašyto .pkg apple/container leidimų puslapyje. 1.7.1 Homebrew versijoje nėra klasterio paslaugų, todėl container cluster nepavyksta su klaida cluster service unavailable.
  • Toliau pateiktam pavyzdžiui – apie 6 GB laisvos atminties: trys mazgai po 2 GB.
  • kubectl, jei klasterį norite naudoti iš terminalo (brew install kubectl).

Įdiegę paketą, vieną kartą paleiskite paslaugas:

Terminalas
container system start

Klasterio kūrimas

Ši komanda sukuria klasterį dev su vienu valdymo plokštumos mazgu ir dviem darbiniais mazgais. Kiekvienas mazgas gauna 2 CPU ir 2 GB atminties:

Terminalas
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • --workers count=N,cpus=C,memory=M nustato darbinių mazgų grupės dydį. Kartokite parinktį skirtingo dydžio grupėms. Be --workers vienas mazgas yra ir valdymo plokštuma, ir darbinis mazgas.
  • --cpus ir --memory nustato valdymo plokštumos dydį. Numatytoji reikšmė – ketvirtadalis jūsų Mac CPU ir atminties, bet ne mažiau kaip 2 CPU ir 2 GB.
  • --shared-image-store leidžia mazgams naudoti jūsų vietinius atvaizdus (žr. toliau). Vėliau to pakeisti negalima: ištrinkite klasterį ir sukurkite jį iš naujo.
  • --cni ./calico.yaml vietoj įtraukto kindnet įdiegia jūsų CNI; --cni NONE neįdiegia jokio.

CLI į ~/.kube/config prideda kontekstą dev. Patikrinkite mazgus:

Terminalas
container cluster list --nodes
kubectl --context dev get nodes

Vietinio atvaizdo vykdymas be registro

Su --shared-image-store mazgai gali vykdyti bet kurį atvaizdą iš jūsų vietinės container atvaizdų saugyklos. Sukurkite atvaizdą ir naudokite jį pagal pavadinimą:

Terminalas
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Pastaba
Kai iš naujo sukuriate tą pačią žymę, vykdykite kubectl rollout restart su imagePullPolicy: Always arba naudokite naują žymę. Su IfNotPresent mazgas pasilieka jau turimą kopiją. Bet kas, turintis root teises mazge, gali skaityti kiekvieną atvaizdą jūsų vietinėje saugykloje, įskaitant privačius, todėl bendrą saugyklą naudokite tik vietiniam kūrimui.

CLI 1.5 ir 1.6 versijose bendros saugyklos nėra. Ten naudokite container cluster load-image arba Įkelti į klasterį Gantry programoje. CLI 1.7 komandą load-image pašalino.

Programos atidarymas naršyklėje

Persiųskite vietinį prievadą į diegimą, tada atidarykite http://localhost:8080:

Terminalas
kubectl --context dev port-forward deployment/hello 8080:80

Klasterio naršymas Gantry

Gantry rodo tą patį klasterį be komandų. Pridėkite savo apple/container serverį, atidarykite Klasteriai ir pasirinkite dev. Apžvalgoje rodoma Kubernetes versija, atvaizdų saugykla, darbiniai mazgai ir jų CPU bei atmintis. Spustelėkite Naršyti išteklius, kad atidarytumėte skyrių Kubernetes su tuo kontekstu.

  • Podai, Deployment, StatefulSet, DaemonSet, paslaugos, Ingress, ConfigMap, slaptieji duomenys, mazgai ir įvykiai – vienoje vardų srityje arba visose.
  • Podų žurnalai su sekimu ir paskutinėmis eilutėmis, apvalkalas pode ir prievadų persiuntimas su sąrašu, iš kurio jį galima sustabdyti.
  • Masto keitimas, diegimo paleidimas iš naujo, trynimas ir Taikyti YAML iš įklijuoto manifesto ar failo.
  • Slaptosios reikšmės lieka paslėptos, kol spustelėsite „Rodyti“.

Kubernetes naršyklė vykdo kubectl. Jei jo nėra, Gantry parodo brew install kubectl ir gali tai įvykdyti už jus. Kuriamas natyvus klientas, kuriam kubectl nereikės.

Klasterį galite sukurti ir Gantry: Klasteriai ▸ Naujas klasteris turi valdymo plokštumos ir darbinių mazgų reikšmių keitiklius bei jungiklį Naudoti vietinius atvaizdus. Daugiau – puslapyje Kubernetes su apple/container.

Klasterio sustabdymas ir ištrynimas

Terminalas
container cluster delete --name dev

Jei valdymo plokštumos mazgas sustoja, pavyzdžiui, po container system stop, ištrinkite klasterį ir sukurkite jį iš naujo. Laikiną klasterį kurkite su --rm, kad jo mazgai būtų pašalinti, kai sustoja.

Dažnos problemos

  • cluster service unavailable: CLI yra Homebrew versija arba paslaugos neveikia. Įdiekite pasirašytą paketą arba paleiskite paslaugas iš naujo komandomis container system stop ir container system start. Tą patį patarimą Gantry rodo skyriuje „Klasteriai“.
  • Senojo klasterio nėra sąraše: CLI 1.7 nerodo klasterių, sukurtų su 1.6 ar senesne versija. Pašalinkite tokį klasterį komanda container cluster delete --name <name>.
  • Mazgai lieka NotReady būsenos: naudojote --cni NONE. Pritaikykite CNI manifestą.
  • Negalite sustabdyti mazgo konteinerio: taip padaryta tyčia. container stop ir delete atsisako veikti su klasterio mazgais; naudokite container cluster delete.

Palyginimas su Docker Desktop ir OrbStack

Docker Desktop turi integruotą Kubernetes su kubeadm (vienas mazgas) arba kind (keli mazgai), o OrbStack – integruotą vieno mazgo klasterį. container cluster vykdo kubeadm su kindest/node atvaizdais, kiekvieną mazgą atskiroje virtualiojoje mašinoje, ir palaiko kelių mazgų klasterius bei bendrą atvaizdų saugyklą. Žr. išsamų palyginimą.

Susiję vadovai

  • Perėjimas nuo Docker Desktop prie Apple container: komandos, Compose, tomai ir trūkumai
  • Konteinerių ir tomų laikymas išoriniame diske Mac kompiuteryje
  • Konteinerio kūrimas iš docker run komandos Mac kompiuteryje (docker run į container run)
  • Apple container GUI, skirta Mac: išsamus apple/container vadovas
  • Kubernetes su Apple container: container cluster GUI ir Kubernetes naršyklė

Klausimai ir atsakymai

Ar galima paleisti Kubernetes Mac kompiuteryje be Docker?

Taip. Apple container CLI pati kuria Kubernetes klasterius komanda container cluster create. Kiekvienas mazgas veikia kaip lengva virtualioji mašina, o Docker, Docker Desktop, kind ar minikube nereikia.

Kiek mazgų gali turėti container cluster?

Vieną valdymo plokštumą ir tiek darbinių mazgų, kiek leidžia jūsų Mac CPU ir atmintis. Nustatykite juos su --workers; CLI 1.7 versijoje kiekviena darbinių mazgų grupė gali turėti savo CPU ir atmintį.

Kaip klasteryje naudoti vietoje sukurtą atvaizdą?

Sukurkite klasterį su --shared-image-store (CLI 1.7), sukurkite atvaizdą komanda container build -t name:tag . ir pod specifikacijoje naudokite name:tag. Registro nereikia.

Kurią Kubernetes versiją naudoja container cluster?

CLI 1.7.1 pagal numatytuosius nustatymus naudoja mazgo atvaizdą kindest/node:v1.35.5. Kitą versiją pasirinkite su --node-image, pavyzdžiui, docker.io/kindest/node:v1.34.11. Gantry versiją rodo klasterio apžvalgoje.

Ar yra container cluster GUI?

Taip. Gantry kuria ir trina klasterius, rodo mazgus, o skyriuje „Kubernetes“ leidžia naršyti podus, Deployment, paslaugas, žurnalus ir slaptuosius duomenis. Ji nemokama ir atvirojo kodo.

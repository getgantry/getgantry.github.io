Gantry/Disco externo

Guardar contentores e volumes num disco externo

Imagens, contentores e volumes enchem depressa um disco interno pequeno. Com a ferramenta container da Apple, pode guardar esses dados num SSD externo: colocar pastas individuais lá com montagens de associação ou mudar toda a raiz de dados. Este guia mostra as duas opções e como desligar o disco sem danos.

Em resumo. Formate o disco em APFS. Para um projeto, monte uma pasta: -v /Volumes/Fast/pg:/data. Para tudo, pare os serviços, copie ~/Library/Application Support/com.apple.container para o disco com cp -Rp e inicie sempre os serviços com container system start --app-root /Volumes/Fast/container.

Onde estão os dados agora

O apple/container guarda todos os dados numa pasta, a raiz da app. Por predefinição é ~/Library/Application Support/com.apple.container, com pastas para contentores, conteúdo das imagens, snapshots, volumes, kernels e redes. Verifique o caminho e o espaço ocupado:

Terminal
container system status | grep appRoot
container system df

Escolher e formatar o disco

  • Utilize um SSD com USB-C ou Thunderbolt. Um disco rígido mecânico funciona, mas os contentores arrancam mais devagar.
  • Formate-o em APFS (o Mac OS Expandido também funciona). Não utilize exFAT, FAT nem NTFS: os volumes são imagens de disco esparsas, e esses sistemas de ficheiros não têm ficheiros esparsos nem permissões Unix.
  • Não utilize um disco de rede para a raiz da app.
  • Dê ao disco um nome curto sem espaços, por exemplo Fast. O caminho fica então /Volumes/Fast.
    Opção 1: guardar os dados do projeto no disco com montagens de associação

Uma montagem de associação partilha uma pasta do Mac com o contentor, e a pasta pode estar em qualquer disco. É a forma mais simples de manter dados grandes, como uma base de dados ou ficheiros de modelos, fora do disco interno:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

O disco tem de estar ligado antes de o contentor arrancar. As imagens e o próprio contentor ficam no disco interno.

    Opção 2: mudar todos os dados do apple/container para o disco

Isto muda imagens, contentores, snapshots e volumes. Pare primeiro os serviços, para que nenhum ficheiro se altere durante a cópia:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Utilize cp -Rp. No nosso teste no macOS 27 (de APFS para APFS por USB), manteve as imagens dos volumes esparsas e manteve os atributos expandidos. O ditto escreveu cada imagem esparsa com o tamanho total, o que pode encher o disco. Mantenha a pasta antiga até confirmar que os seus contentores, imagens e volumes aparecem nas listas.

Atenção
A CLI não memoriza o --app-root. Cada container system start sem ele volta a usar a pasta interna. Utilize a flag sempre, por exemplo num alias da shell, e verifique paths.appRoot em container system status.

O Gantry 0.27.0 inicia os serviços sem --app-root quando se liga a um host com os serviços parados. Inicie primeiro os serviços no terminal com a flag; o Gantry utiliza depois os serviços em execução.

    Arquivar imagens no disco

Para libertar espaço sem perder uma imagem, guarde-a no disco externo e elimine-a. Volte a carregá-la quando precisar dela:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar
    Desligar o disco em segurança
  1. Pare os contentores que utilizam o disco: container stop <name>.
  2. Se a raiz da app estiver no disco, pare os serviços: container system stop.
  3. Ejete o disco no Finder e depois desligue-o.

Se o disco desaparecer enquanto há contentores a ser executados a partir dele, estes falham e as escritas em curso podem perder-se. Depois de voltar a ligar o disco, inicie os serviços com --app-root e, em seguida, os contentores.

    Discos externos no Gantry

O Gantry já executa montagens de associação a partir de qualquer disco: em Novo contentor, adicione um volume, escolha uma pasta no disco externo e um caminho no contentor.

    Docker Desktop e OrbStack

O Docker Desktop muda a sua imagem de disco em Settings ▸ Resources ▸ Advanced ▸ Disk image location. O OrbStack acrescentou uma definição de localização dos dados na versão 0.13.0. Consulte a comparação.

Perguntas e respostas

Posso guardar as imagens do Apple container num disco externo?

Sim. Inicie os serviços com container system start --app-root /Volumes/Disk/container. Todas as imagens, contentores, snapshots e volumes ficam então nessa pasta.

Que sistema de ficheiros deve usar o disco externo?

APFS. Os volumes são imagens de disco esparsas e os contentores precisam de permissões Unix, que o exFAT, o FAT e o NTFS não têm.

Como copiar os dados do container sem encher o disco?

Utilize cp -Rp, que no nosso teste manteve pequenas as imagens esparsas dos volumes. O ditto copiou cada imagem esparsa com o tamanho total.

O que acontece se desligar o disco com contentores em execução?

Os contentores que utilizam o disco falham e os dados ainda não escritos podem perder-se. Antes de ejetar o disco, pare os contentores e, se a raiz da app estiver no disco, os serviços.

A CLI container memoriza a nova localização?

Não. Passe --app-root a cada container system start. container system status mostra a raiz em uso como paths.appRoot.

Gantry/Kubernetes apple/container vidē

Kubernetes ar Apple container

apple/container var palaist Kubernetes klasteri, kura mezgli ir konteineri jūsu Mac datorā. Gantry tam ir grafiskā saskarne: izveidojiet klasteri, vērojiet, kā startē mezgli, pieslēdziet kubectl un ielādējiet lokālos attēlus bez garām container cluster komandrindām.

Īsumā. apple/container resursdatorā Gantry sadaļa Klasteri izveido un dzēš Kubernetes klasterus ar container cluster (CLI 1.6.1) vai container k8s (CLI no 1.5.0 līdz 1.6.0). Tā atbalsta vairākus darba mezglus, pielāgotu CNI, mezglu skatu, kubeconfig un kubectl kontekstu, kā arī Ielādēt klasterī lokālajiem attēliem.

Prasības

  • Mac dators ar Apple silicon, macOS 26 un Gantry (brew install --cask getgantry/tap/gantry).
  • container CLI 1.5.0 vai jaunāks; ieteicams 1.6.1. Darba mezgliem un CNI opcijai Nav nepieciešams 1.6.0 vai jaunāks.
  • kubectl, ja vēlaties izmantot klasteri no termināļa.

Klastera izveide

  1. Atlasiet savu apple/container resursdatoru un sānjoslā atveriet Klasteri.
  2. Sāciet jauna klastera izveidi un aizpildiet tālāk norādītās opcijas.
  3. Izveidojiet to. Sarakstā tiek rādīts jaunais klasteris un norise reāllaikā. Atcelt pārtrauc izveidi un dzēš jau izveidotos mezglus.
OpcijaCLI karodziņšPiezīmes
Nosaukums--nameArī kubeconfig konteksta nosaukums
Darba mezgli--workersDarba mezglu skaits. CLI 1.6.0+
CPU--cpusKatram mezglam
Atmiņa--memoryKatram mezglam, piemēram, 4G
Mezgla attēls--node-imageJa tukšs, tiek izmantots CLI noklusējums
CNI--cniNoklusējums (komplektā iekļautais kindnet), Nav (NONE, CLI 1.6.0+) vai ceļš uz pielāgotu manifestu

Tā pati komanda CLI:

Čaula
container cluster create --name dev --workers 2 --cpus 2 --memory 4G

Mezgli un klastera informācija

Klasteru sarakstā redzams katrs klasteris ar mezgliem: loma, stāvoklis un adrese. Detalizētajā skatā ir Pārskats (kubectl konteksts, API serveris, darba mezgli, mezglu tīkls), tabula Mezgli, Pārbaudīt neapstrādātiem mezglu datiem un darbības Ierakstīt kubeconfig, Kopēt kubectl konteksta komandu un Dzēst.

kubectl pieslēgšana

Izveidojot klasteri, CLI failā ~/.kube/config pievieno kontekstu ar klastera nosaukumu. Lietotnē Gantry izmantojiet Kopēt kubectl konteksta komandu vai ierakstiet to paši:

Čaula
kubectl --context dev get nodes

Lai glabātu klasteri atsevišķā failā, izmantojiet Ierakstīt kubeconfig. Gantry izpilda container cluster write-config; noklusējuma ceļš ir ~/.kube/<name>.kubeconfig.

Lokālo attēlu ielāde klasterī

Uzbūvējiet vai lejupielādējiet attēlu apple/container resursdatorā, pēc tam sadaļā Attēli ar peles labo pogu noklikšķiniet uz tā un izvēlieties Ielādēt klasterī. Gantry izpilda container cluster load-image, kas nokopē attēlu uz katra mezgla containerd. Lokālai izstrādei reģistrs nav vajadzīgs.

Čaula
container cluster load-image --name dev myapp:dev

CNI izvēle

Noklusējums ir komplektā iekļautais kindnet manifests. Izvēlieties Pielāgots manifests, lai instalētu savu CNI, piemēram, Calico vai Cilium, no faila. Izvēlieties Nav, lai vēlāk paši instalētu CNI; līdz tam mezgli paliek stāvoklī NotReady.

Klasteri no MI aģentiem

Gantry MCP serverim ir list_clusters, create_cluster un delete_cluster, tāpēc aģents, piemēram, Claude Code, var izveidot pagaidu klasteri testam un pēc tam to noņemt.

Pievienojiet Gantry MCP serveri
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Vairāk par apple/container

Lasiet apple/container ceļvedi par katru container komandu un tās Gantry iespēju vai skatiet, kā Gantry salīdzināma ar Docker Desktop, OrbStack un Podman Desktop.

Jautājumi un atbildes

Vai Apple container atbalsta Kubernetes?

Jā. container CLI izveido Kubernetes klasterus, kuru mezgli darbojas kā konteineri: container cluster CLI 1.6.1 versijā, container k8s CLI versijās no 1.5.0 līdz 1.6.0. Gantry tam piešķir grafisko saskarni.

Vai Gantry atbalsta container cluster?

Jā. Gantry rāda sarakstu, izveido un dzēš klasterus apple/container resursdatoros, rāda to mezglus, ieraksta kubeconfig, kopē kubectl konteksta komandu un ielādē lokālos attēlus klasterī. Atbilstoši jūsu CLI versijai tā izmanto cluster vai k8s.

Kā izmantot kubectl ar apple/container klasteri?

Kad CLI izveido klasteri, tas failā ~/.kube/config pievieno kubeconfig kontekstu ar klastera nosaukumu. Izpildiet kubectl --context <name> get nodes. Lai glabātu atsevišķu failu, lietotnē Gantry izmantojiet Ierakstīt kubeconfig; noklusējuma ceļš ir ~/.kube/<name>.kubeconfig.

Kā ielādēt lokālu attēlu klasterī bez reģistra?

Lietotnes Gantry sadaļā „Attēli” ar peles labo pogu noklikšķiniet uz attēla un izvēlieties Ielādēt klasterī. Gantry izpilda container cluster load-image, kas nokopē attēlu uz katra mezgla containerd.

Vai var izveidot klasteri ar vairākiem mezgliem?

Jā. Izveides logā norādiet darba mezglu skaitu. Darba mezgliem nepieciešams CLI 1.6.0 vai jaunāks.

Vai var izmantot savu CNI, piemēram, Calico vai Cilium?

Jā. Izvēlieties Pielāgots manifests un atlasiet manifesta failu vai izvēlieties Nav un pēc klastera startēšanas paši instalējiet CNI. Kamēr CNI nedarbojas, mezgli paliek stāvoklī NotReady. Opcijai Nav nepieciešams CLI 1.6.0 vai jaunāks. Noklusējuma CNI ir komplektā iekļautais kindnet manifests.

Gantry/Kubernetes σε Mac

Kubernetes σε Mac με το Apple container

Το εργαλείο container της Apple μπορεί να δημιουργήσει ένα τοπικό cluster Kubernetes με μία εντολή. Κάθε κόμβος είναι μια ελαφριά εικονική μηχανή στο Mac σας. Αυτός ο οδηγός ξεκινά από ένα άδειο Mac και φτάνει σε ένα deployment σε εκτέλεση, πρώτα στο τερματικό και μετά στο Gantry.

Με λίγα λόγια. Εγκαταστήστε το υπογεγραμμένο πακέτο container 1.7.1, εκτελέστε container cluster create --name dev --cpus 2 --memory 2g --workers count=2,cpus=2,memory=2g --shared-image-store, δομήστε μια εικόνα με container build και εκτελέστε την στο cluster με το όνομά της. Το Gantry εμφανίζει το ίδιο cluster σε ένα παράθυρο: κόμβους, pod, αρχεία καταγραφής, shell και προωθήσεις θυρών.

Τι χρειάζεστε

  • Ένα Mac με Apple silicon και macOS 26 ή νεότερο.
  • Το CLI container 1.7.1 από το υπογεγραμμένο .pkg στη σελίδα εκδόσεων του apple/container. Η έκδοση Homebrew της 1.7.1 δεν περιλαμβάνει τις υπηρεσίες cluster, οπότε το container cluster αποτυγχάνει με cluster service unavailable.
  • Περίπου 6 GB ελεύθερης μνήμης για το παρακάτω παράδειγμα: τρεις κόμβοι με 2 GB ο καθένας.
  • Το kubectl, αν θέλετε να χρησιμοποιείτε το cluster από το τερματικό (brew install kubectl).

Ξεκινήστε τις υπηρεσίες μία φορά μετά την εγκατάσταση του πακέτου:

Τερματικό
container system start

Δημιουργία του cluster

Αυτή η εντολή δημιουργεί ένα cluster με όνομα dev, με έναν κόμβο control plane και δύο worker. Κάθε κόμβος παίρνει 2 CPU και 2 GB μνήμης:

Τερματικό
container cluster create --name dev --cpus 2 --memory 2g \
  --workers count=2,cpus=2,memory=2g --shared-image-store
  • Το --workers count=N,cpus=C,memory=M ορίζει το μέγεθος μιας ομάδας worker. Επαναλάβετέ το για ομάδες διαφορετικού μεγέθους. Χωρίς --workers, ένας κόμβος είναι ταυτόχρονα control plane και worker.
  • Τα --cpus και --memory ορίζουν το μέγεθος του control plane. Η προεπιλογή είναι το ένα τέταρτο των CPU και της μνήμης του Mac σας, τουλάχιστον 2 CPU και 2 GB.
  • Το --shared-image-store επιτρέπει στους κόμβους να χρησιμοποιούν τις τοπικές σας εικόνες (δείτε παρακάτω). Δεν μπορείτε να το αλλάξετε αργότερα: διαγράψτε το cluster και δημιουργήστε το ξανά.
  • Το --cni ./calico.yaml εγκαθιστά δικό σας CNI αντί για το ενσωματωμένο kindnet· το --cni NONE δεν εγκαθιστά κανένα.

Το CLI προσθέτει ένα context με όνομα dev στο ~/.kube/config. Ελέγξτε τους κόμβους:

Τερματικό
container cluster list --nodes
kubectl --context dev get nodes

Εκτέλεση τοπικής εικόνας χωρίς μητρώο

Με το --shared-image-store, οι κόμβοι μπορούν να εκτελούν οποιαδήποτε εικόνα της τοπικής αποθήκης εικόνων του container. Δομήστε μια εικόνα και χρησιμοποιήστε την με το όνομά της:

Τερματικό
printf 'FROM nginx:alpine\n' > Dockerfile
container build -t hello:dev .
kubectl --context dev create deployment hello --image=hello:dev
kubectl --context dev get pods
Σημείωση
Αφού δομήσετε ξανά την ίδια ετικέτα, εκτελέστε kubectl rollout restart με imagePullPolicy: Always ή χρησιμοποιήστε νέα ετικέτα. Με IfNotPresent, ένας κόμβος κρατά το αντίγραφο που ήδη έχει. Οτιδήποτε έχει δικαιώματα root σε έναν κόμβο μπορεί να διαβάσει κάθε εικόνα της τοπικής σας αποθήκης, και τις ιδιωτικές, γι' αυτό χρησιμοποιήστε την κοινή αποθήκη μόνο για τοπική ανάπτυξη.

Στο CLI 1.5 και 1.6 δεν υπάρχει κοινή αποθήκη. Εκεί χρησιμοποιήστε το container cluster load-image ή τη Φόρτωση στο cluster στο Gantry. Το CLI 1.7 αφαίρεσε το load-image.

Άνοιγμα της εφαρμογής σε πρόγραμμα περιήγησης

Προωθήστε μια τοπική θύρα στο deployment και ανοίξτε το http://localhost:8080:

Τερματικό
kubectl --context dev port-forward deployment/hello 8080:80

Περιήγηση στο cluster με το Gantry

Το Gantry εμφανίζει το ίδιο cluster χωρίς εντολές. Προσθέστε τον host apple/container σας, ανοίξτε τα Cluster και επιλέξτε dev. Η επισκόπηση δείχνει την έκδοση του Kubernetes, την αποθήκη εικόνων, τα worker και τις CPU και τη μνήμη τους. Κάντε κλικ στην Περιήγηση στους πόρους για να ανοίξετε την ενότητα Kubernetes σε αυτό το context.

  • Pod, deployment, StatefulSet, DaemonSet, υπηρεσίες, Ingress, ConfigMap, μυστικά, κόμβοι και συμβάντα, για έναν χώρο ονομάτων ή για όλους.
  • Αρχεία καταγραφής pod με παρακολούθηση και tail, shell στο pod και προωθήσεις θυρών με λίστα από την οποία μπορείτε να τις σταματήσετε.
  • Κλιμάκωση, επανεκκίνηση rollout, διαγραφή και Εφαρμογή YAML από επικολλημένο manifest ή από αρχείο.
  • Οι τιμές των μυστικών μένουν κρυφές μέχρι να κάνετε κλικ στην «Εμφάνιση».

Ο περιηγητής Kubernetes εκτελεί το kubectl. Αν λείπει, το Gantry εμφανίζει το brew install kubectl και μπορεί να το εκτελέσει για εσάς. Ένας εγγενής πελάτης που δεν χρειάζεται kubectl είναι υπό ανάπτυξη.

Μπορείτε επίσης να δημιουργήσετε το cluster στο Gantry: το Cluster ▸ Νέο cluster έχει μετρητές για το control plane και τα worker και διακόπτη Χρήση τοπικών εικόνων. Περισσότερα στη σελίδα Kubernetes στο apple/container.

Διακοπή και διαγραφή του cluster

Τερματικό
container cluster delete --name dev

Αν ο κόμβος control plane σταματήσει, για παράδειγμα μετά από container system stop, διαγράψτε το cluster και δημιουργήστε το ξανά. Δημιουργήστε ένα προσωρινό cluster με --rm ώστε οι κόμβοι του να αφαιρούνται όταν σταματούν.

Συνηθισμένα προβλήματα

  • cluster service unavailable: το CLI είναι η έκδοση Homebrew ή οι υπηρεσίες δεν εκτελούνται. Εγκαταστήστε το υπογεγραμμένο πακέτο ή επανεκκινήστε τις υπηρεσίες με container system stop και container system start. Το Gantry δίνει την ίδια συμβουλή στα «Cluster».
  • Ένα παλιό cluster λείπει από τη λίστα: το CLI 1.7 δεν εμφανίζει cluster που δημιουργήθηκαν με 1.6 ή παλαιότερη. Αφαιρέστε το με container cluster delete --name <name>.
  • Οι κόμβοι μένουν NotReady: χρησιμοποιήσατε --cni NONE. Εφαρμόστε ένα manifest CNI.
  • Δεν μπορείτε να σταματήσετε ένα κοντέινερ κόμβου: αυτό γίνεται σκόπιμα. Τα container stop και delete αρνούνται τους κόμβους cluster· χρησιμοποιήστε container cluster delete.

Σύγκριση με το Docker Desktop και το OrbStack

Το Docker Desktop έχει ενσωματωμένο Kubernetes με kubeadm (ένας κόμβος) ή kind (πολλοί κόμβοι) και το OrbStack έχει ενσωματωμένο cluster ενός κόμβου. Το container cluster εκτελεί kubeadm σε εικόνες kindest/node, κάθε κόμβο στη δική του VM, με cluster πολλών κόμβων και κοινή αποθήκη εικόνων. Δείτε την πλήρη σύγκριση.

Σχετικοί οδηγοί

  • Από το Docker Desktop στο Apple container: εντολές, Compose, τόμοι και κενά
  • Κοντέινερ και τόμοι σε εξωτερικό δίσκο στο Mac
  • Κοντέινερ από εντολή docker run σε Mac (docker run σε container run)
  • GUI για Apple container σε Mac: ο πλήρης οδηγός apple/container
  • Kubernetes στο Apple container: GUI για container cluster και περιηγητής Kubernetes

Ερωτήσεις και απαντήσεις

Μπορώ να εκτελέσω Kubernetes σε Mac χωρίς Docker;

Ναι. Το CLI container της Apple δημιουργεί μόνο του cluster Kubernetes με container cluster create. Κάθε κόμβος τρέχει ως ελαφριά VM και δεν χρειάζεστε Docker, Docker Desktop, kind ή minikube.

Πόσους κόμβους μπορεί να έχει ένα container cluster;

Ένα control plane και όσα worker επιτρέπουν οι CPU και η μνήμη του Mac σας. Ορίστε τα με --workers· στο CLI 1.7 κάθε ομάδα worker μπορεί να έχει δικές της CPU και μνήμη.

Πώς χρησιμοποιώ στο cluster μια εικόνα που δόμησα τοπικά;

Δημιουργήστε το cluster με --shared-image-store (CLI 1.7), δομήστε την εικόνα με container build -t name:tag . και χρησιμοποιήστε το name:tag στην προδιαγραφή του pod. Δεν χρειάζεται μητρώο.

Ποια έκδοση Kubernetes χρησιμοποιεί το container cluster;

Το CLI 1.7.1 χρησιμοποιεί από προεπιλογή την εικόνα κόμβου kindest/node:v1.35.5. Επιλέξτε άλλη έκδοση με --node-image, για παράδειγμα docker.io/kindest/node:v1.34.11. Το Gantry δείχνει την έκδοση στην επισκόπηση του cluster.

Υπάρχει GUI για το container cluster;

Ναι. Το Gantry δημιουργεί και διαγράφει cluster, εμφανίζει τους κόμβους και περιηγείται σε pod, deployment, υπηρεσίες, αρχεία καταγραφής και μυστικά στην ενότητα Kubernetes. Είναι δωρεάν και ανοιχτού κώδικα.

Apple container sur Mac : le guide complet et la GUI

apple/container exécute des conteneurs Linux sur votre Mac, chacun dans sa propre machine virtuelle légère. Il se présente comme un outil en ligne de commande. Gantry en est une GUI macOS native. Ce guide présente l'outil, explique comment le configurer et indique quelle fonctionnalité de Gantry couvre chaque commande container.

En bref. Gantry est une app macOS gratuite et open source (MIT) qui gère l'outil container d'Apple et Docker depuis une seule fenêtre. Il prend en charge la CLI container 1.0 à 1.6.1 (recommandée) et n'affiche que les fonctionnalités prises en charge par votre version de la CLI. Installez-le avec brew install --cask getgantry/tap/gantry.

Qu'est-ce qu'apple/container ?

apple/container est un outil open source d'Apple, écrit en Swift, qui crée et exécute des conteneurs Linux sur un Mac. Docker Desktop exécute tous les conteneurs dans une seule VM Linux partagée ; apple/container exécute chaque conteneur dans sa propre machine virtuelle légère, basée sur le framework Virtualization d'Apple. Il utilise des images OCI standard : il télécharge depuis les mêmes registres que Docker et y envoie ses images.

  • Matériel : un Mac à puce Apple.
  • macOS : Apple le prend en charge sur macOS 26.
  • Interface : uniquement la CLI container. Il n'y a ni app de bureau ni commande compose.
  • Réseau : chaque conteneur reçoit sa propre adresse IP sur votre Mac, et des domaines DNS locaux donnent aux conteneurs des noms comme web.test.

Pourquoi une GUI pour apple/container ?

La CLI est complète, mais le travail quotidien demande beaucoup de commandes : container list, logs, stats, exec, puis system, builder, registry, machine et cluster pour le reste. Gantry les réunit dans une seule fenêtre avec des mises à jour en direct : vous voyez l'état au lieu de devoir l'interroger. Il ajoute aussi ce que la CLI n'a pas : fichiers Compose, notifications de panne, vue de flotte avec vos hôtes Docker et serveur MCP pour les agents IA.

Configurer apple/container avec Gantry

  1. Installez Gantry : brew install --cask getgantry/tap/gantry, puis retirez l'attribut de quarantaine (voir Installation).
  2. Installez la CLI container depuis le .pkg signé de la page des versions d'apple/container. Si elle est absente ou antérieure à 1.0, Gantry affiche une feuille de configuration avec les étapes.
  3. Dans Gantry, choisissez Ajouter un hôte… et ajoutez un hôte Apple Container. La connexion démarre les services container s'ils sont arrêtés.
  4. Si aucun noyau par défaut n'est installé, l'aperçu de l'hôte affiche une bannière. Cliquez dessus pour installer le noyau recommandé.
Attention
Utilisez le paquet d'installation signé, pas la version Homebrew. La version Homebrew n'inclut pas le backend des machines : container machine ne peut donc pas fonctionner.

Ce que Gantry ajoute à apple/container

Clusters Kubernetes

Créez des clusters Kubernetes à plusieurs workers avec container cluster, choisissez le CNI, consultez chaque nœud, écrivez le kubeconfig et chargez des images locales dans le cluster. Voir Kubernetes sur apple/container.

Machines container et VS Code

Les machines sont des environnements Linux durables créés avec container machine. Gantry les crée, les démarre, les arrête et les supprime, définit la machine par défaut, modifie les CPU et la mémoire, et ouvre un shell. Avec la CLI 1.1 ou ultérieure, une machine peut démarrer avec la virtualisation imbriquée (puce Apple M3 ou plus récente) et un noyau personnalisé. Ouvrir dans VS Code se connecte à une machine en cours d'exécution via Remote-SSH ; l'image de la machine doit exécuter sshd.

Docker Compose sur apple/container

Ouvrez un docker-compose.yml depuis le Finder (Ouvrir avec ▸ Gantry ou Actions rapides ▸ Compose Up dans apple/container), depuis Fichier ▸ Ouvrir un fichier Compose…, ou en le déposant sur la fenêtre. Gantry construit les services build:, crée le réseau du projet et les volumes nommés, puis démarre chaque service dans l'ordre de depends_on avec les étiquettes standard com.docker.compose.*. Avec un domaine DNS par défaut, les services se joignent par leur nom de service grâce aux alias réseau.

Alias DNS réseau et domaines locaux

Gantry transmet les alias réseau à container sous la forme --network <name>,alias=…. Sans domaine DNS par défaut, seuls les noms pleinement qualifiés passent, et un alias de sous-arbre (commençant par un point, comme .gateway) ne passe que sous sa forme exacte. Avec un domaine par défaut, les noms courts fonctionnent aussi. Gantry crée et supprime des domaines DNS locaux, définit le domaine par défaut et donne aux nouveaux conteneurs un nom d'hôte name.domain. Voir Noms DNS locaux.

Système : services, builder, registres, noyau, journaux, propriétés

Chaque hôte apple/container a une section Système. Elle fonctionne même quand l'hôte est déconnecté : vous pouvez donc y démarrer des services arrêtés.

  • État et version : versions client et serveur, avec un avertissement si elles diffèrent ; démarrer, arrêter et redémarrer les services ; infos et chemins de l'hôte.
  • Builder d'images : état, image, CPU, mémoire et IP ; démarrage avec options de CPU, de mémoire et de DNS ; arrêt ; suppression.
  • Connexions aux registres : lister, se connecter et se déconnecter. Le mot de passe n'est transmis à la CLI que via stdin (--password-stdin), et Gantry n'en garde aucune copie.
  • Noyau : installer le noyau recommandé, un fichier de noyau ou une archive tar, avec la progression en continu.
  • Journaux des services : en direct ou ponctuels, sur une période de 5 minutes à 1 jour, filtrés par niveau, service et texte.
  • Propriétés système : les modifications vont dans ~/.config/container/config.toml, avec un indicateur de redémarrage en attente et un bouton Redémarrer les services.

Enregistrer comme image, Compacter le disque et fichiers

Enregistrer comme image utilise container commit (CLI 1.6). Compacter le disque utilise container clean (CLI 1.4) et apparaît aussi comme une ligne dans Récupérer de l'espace. L'onglet Fichiers télécharge des fichiers et permet de les faire glisser vers le Finder avec container copy (le conteneur doit être démarré), et envoie des fichiers et des dossiers.

Étiquettes contenant =

container create rejette une valeur d'étiquette contenant =, y compris avec la CLI 1.6.1. Gantry encode ces valeurs à la création du conteneur et les décode à la lecture : les étiquettes que vous définissez sont bien celles que vous voyez.

Serveur MCP et Raccourcis

Le serveur gantry-mcp intégré donne aux agents IA la même portée sur les hôtes apple/container : conteneurs, images, volumes, réseaux, Compose, machines (list_machines, create_machine et d'autres), clusters (list_clusters, create_cluster, delete_cluster) et outils système apple_* pour les services, le builder, les registres (sans outil de connexion), les propriétés, les journaux et l'installation du noyau. Les App Intents ajoutent des actions Raccourcis et Siri. Voir Agents IA & MCP.

Ajouter le serveur MCP de Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container à côté de Docker

Gantry gère les hôtes apple/container, le daemon Docker local (Docker Desktop, OrbStack, Colima) et les hôtes Docker distants via SSH dans une seule barre latérale et un seul tableau de bord de flotte. Inutile de choisir un seul runtime. Pour une comparaison fonctionnalité par fonctionnalité, voir Gantry face à Docker Desktop, OrbStack et Podman Desktop.

Questions et réponses

Quelle est la meilleure interface graphique pour Apple container ?

Gantry est une GUI macOS native, gratuite et open source, conçue pour apple/container. Elle transpose la CLI container dans une app de bureau : conteneurs, journaux, statistiques et exec, plus les clusters Kubernetes, les machines, le builder d'images, les connexions aux registres, les noyaux, les journaux des services et les propriétés système. Le tableau de cette page liste chaque commande et la fonctionnalité Gantry qui l'utilise.

Apple container a-t-il une interface graphique ?

Apple fournit container uniquement sous forme d'outil en ligne de commande. Gantry est une app open source distincte qui lui donne une GUI, à côté de vos hôtes Docker.

Peut-on utiliser docker compose avec Apple container ?

apple/container n'a pas de commande compose. Gantry lit un docker-compose.yml, construit les services build:, crée le réseau et les volumes nommés, puis démarre les services dans l'ordre de depends_on. Les noms de services sont résolus via des alias DNS réseau.

Comment ouvrir une machine container dans VS Code ?

Démarrez la machine dans Gantry et cliquez sur Ouvrir dans VS Code. Gantry l'ouvre via Remote-SSH, comme dans l'exemple container-machine-vscode d'Apple. L'image de la machine doit exécuter sshd.

Apple container fonctionne-t-il sur un Mac Intel ?

Non. apple/container nécessite un Mac à puce Apple. Gantry fonctionne aussi sur les Mac Intel, mais il n'y gère que des hôtes Docker.

Quelle version de la CLI container installer ?

Gantry nécessite la 1.0 ou ultérieure et est testé avec la 1.6.1. Installez-la avec le paquet d'installation signé depuis la page des versions d'apple/container. La version Homebrew n'inclut pas le backend des machines : container machine n'y fonctionne donc pas.

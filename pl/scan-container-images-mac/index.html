Gantry/Skanowanie obrazów

Skanowanie obrazów kontenerów pod kątem luk na Macu

Trivy i Grype to darmowe skanery open source, które porównują pakiety w obrazie z bazami znanych luk. Obrazy Dockera odczytują bezpośrednio. Narzędzie container od Apple nie ma polecenia skanowania ani gniazda Dockera, więc najpierw zapisujesz obraz. Ten przewodnik pokazuje oba sposoby, jak czytać wyniki, jak zapisać SBOM i jak skanować z Gantry.

W skrócie. Uruchom brew install trivy grype. Na Dockerze uruchom trivy image app:dev. Na Apple container zapisz obraz poleceniem container image save --platform linux/arm64 -o app.tar app:dev, rozpakuj go poleceniem tar -xf app.tar -C app-img i przeskanuj folder: trivy image --input app-img lub grype oci-dir:app-img. Oba narzędzia odrzucają sam plik tar.

Instalacja skanera

Zainstaluj jeden skaner lub oba przez Homebrew. Każdy pobiera bazę luk przy pierwszym skanowaniu, co zajmuje około minuty.

Terminal
brew install trivy grype

Polecenia z tego przewodnika sprawdziliśmy z Trivy 0.76.2, Grype 0.121.3 i container 1.7.1. Gantry wymaga Trivy 0.50.0 lub Grype 0.74.0 albo nowszych.

Skanowanie obrazu Dockera

Z silnikiem Docker (Docker Desktop, OrbStack lub Colima) oba narzędzia odczytują lokalny obraz po nazwie przez gniazdo Dockera:

Terminal
trivy image app:dev
grype app:dev

Skanowanie obrazu Apple container

Zapisz obraz do archiwum OCI i rozpakuj go do folderu. Podaj --platform: gdy magazyn obrazów ma tylko niektóre platformy obrazu, container image save bez tej flagi kończy się błędem.

Terminal
container image pull python:3.11-slim
container image save --platform linux/arm64 -o python.tar python:3.11-slim
mkdir python-img && tar -xf python.tar -C python-img

Następnie przeskanuj folder. Trivy odczytuje go z --input, Grype z prefiksem oci-dir::

Terminal
trivy image --input python-img --severity HIGH,CRITICAL
grype oci-dir:python-img
Uwaga
Nie podawaj pliku .tar. Archiwum z container image save zaczyna się od wpisu ./: Trivy zgłasza „file manifest.json not found in tar”, a Grype odrzuca je jako „potential path traversal attack”. Rozpakowany folder działa z oboma.

Odczyt wyników

  • Ważność: Critical, High, Medium, Low lub Unknown. Zacznij od Critical i High. --severity HIGH,CRITICAL ogranicza wynik Trivy.
  • Wersja zainstalowana i z poprawką: jeśli istnieje wersja z poprawką, zaktualizuj obraz bazowy lub pakiet i zbuduj ponownie. trivy --ignore-unfixed i grype --only-fixed ukrywają wyniki bez poprawki.
  • „won't fix”: dystrybucja zdecydowała, że nie poprawi pakietu w tym wydaniu. Użyj nowszego obrazu bazowego albo zaakceptuj ryzyko.
  • Dwa narzędzia, dwie bazy: Trivy i Grype często zgłaszają różne liczby. Żadne się nie myli; korzystają z różnych źródeł.

Eksport SBOM

Wykaz składników oprogramowania (SBOM) zawiera każdy pakiet w obrazie. Trivy zapisuje CycloneDX i SPDX; Syft, narzędzie towarzyszące Grype, też zapisuje oba formaty.

Terminal
trivy image --input python-img --format cyclonedx -o sbom.cdx.json
trivy image --input python-img --format spdx-json -o sbom.spdx.json

Przerwanie kompilacji przy poważnych wynikach

W skrypcie pozwól skanerowi ustawić kod wyjścia. Grype kończy działanie z niezerowym kodem, gdy istnieje wynik o podanej lub wyższej ważności; z Trivy użyj --exit-code 1 --severity HIGH,CRITICAL.

Terminal
grype oci-dir:python-img --fail-on high
echo $?

Skanowanie z Gantry

Gantry 0.29.0 wykonuje te kroki za Ciebie. Wybierz Skanuj pod kątem luk… w menu obrazu lub na pasku narzędzi szczegółów obrazu.

  • Gantry znajduje Trivy lub Grype w GANTRY_TRIVY lub GANTRY_GRYPE, w PATH albo w /opt/homebrew/bin i /usr/local/bin. Gdy zainstalowane są oba, domyślny jest Trivy. Bez skanera arkusz pokazuje polecenia Homebrew.
  • Na apple/container Gantry zapisuje obraz z --platform, rozpakowuje go i skanuje folder. Na lokalnym Dockerze skanuje zapisane archiwum. W przypadku Dockera przez SSH skanuje kopię tagu z rejestru.
  • Wyniki są pogrupowane według ważności, z symbolem i słowem, nie tylko kolorem. Każdy wiersz zawiera identyfikator z linkiem, pakiet, zainstalowaną wersję i wersję z poprawką. Filtr znajduje pakiet lub identyfikator.
  • Eksportuj SBOM zapisuje CycloneDX (oba narzędzia) lub SPDX (Trivy).
  • Zatrzymaj lub zamknięcie arkusza zatrzymuje skaner i usuwa pliki tymczasowe.

Pytania i odpowiedzi

Jak przeskanować obraz Apple container pod kątem luk?

Zapisz go poleceniem container image save --platform linux/arm64 -o app.tar app:dev, rozpakuj poleceniem tar -xf app.tar -C app-img, a następnie uruchom trivy image --input app-img lub grype oci-dir:app-img. Gantry wykonuje te kroki poleceniem Skanuj pod kątem luk….

Dlaczego Trivy lub Grype nie radzi sobie z archiwum z container image save?

Archiwum zaczyna się od wpisu ./. Trivy nie znajduje w nim manifest.json ani index.json, a Grype traktuje ten wpis jako przechodzenie po ścieżce (path traversal). Rozpakuj archiwum i przeskanuj folder.

Trivy czy Grype: którego użyć?

Oba są darmowe i open source. Trivy znajduje też sekrety i błędy konfiguracji oraz zapisuje SPDX; Grype jest mały i skupia się na pakietach. Korzystają z różnych baz, więc uruchomienie obu znajduje więcej. Gantry używa Trivy, gdy zainstalowane są oba.

Czy Gantry instaluje skanery?

Nie. Zainstaluj je poleceniem brew install trivy grype. Gantry szuka ich w PATH, /opt/homebrew/bin i /usr/local/bin albo w GANTRY_TRIVY i GANTRY_GRYPE.

Czy do skanowania obrazów potrzebuję Docker Scout lub konta Docker?

Nie. Trivy i Grype działają bez konta, na obrazach Docker i na obrazach Apple container.

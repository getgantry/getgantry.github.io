Gantry/Fra docker run

Opret en container ud fra en docker run-kommando

De fleste README-filer angiver en docker run-linje. Gantry læser linjen og udfylder formularen Ny container, til en Docker-vært eller til Apples container-værktøj. Denne guide viser hvordan, og hvordan du konverterer kommandoen i hånden.

Kort fortalt. Åbn Ny container i Gantry, vælg Indsæt kommando…, indsæt docker run-linjen, og klik på Udfyld formular. Gantry viser hvert flag, den ikke kan bruge, med årsagen. I CLI'en er de fleste flag de samme: erstat docker run med container run, og fjern --restart.

Indsæt kommandoen i Gantry

  1. Vælg en vært: en Docker-vært eller en apple/container-vært.
  2. Åbn Containere, og klik på Ny container.
  3. Klik på Indsæt kommando…, og indsæt linjen. Linjeskift med \, anførselstegn, en $-prompt og sudo er alle i orden.
  4. Læs forhåndsvisningen: imaget, de flag, Gantry ikke kan bruge, bemærkninger og advarsler for denne vært.
  5. Klik på Udfyld formular, tjek værdierne, og opret containeren.

Gantry læser docker run, docker container run, docker create, podman run og container run. Tekst efter &&, ||, ; eller | ignoreres, med en bemærkning.

Omkring 80 andre Docker-flag er kendt: Gantry springer deres værdier korrekt over og viser dem som ikke brugt, så intet går tabt uden en bemærkning.

Advarsler for apple/container-værter

Nogle Docker-indstillinger findes ikke på apple/container. Gantry advarer om dem og udelader dem fra oprettelsen:

  • genstartspolitikker (--restart);
  • brøkdele af CPU'er som --cpus 0.5;
  • netværkstilstandene host, none og container:;
  • porte uden værtsport, som -p 80.

På en Docker-vært advarer Gantry om apple/container-indstillingerne: DNS-domænet og kerneindstillingerne.

Konvertér docker run til container run i hånden

I CLI'en forbliver de fleste flag de samme. Et eksempel med Redis:

Terminal
docker run -d --name cache --restart unless-stopped -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

bliver til:

Terminal
container volume create redisdata
container run -d --name cache -p 6379:6379 \
  -v redisdata:/data redis:7 redis-server --appendonly yes

Opret først det navngivne volume med container volume create. Fjern --restart, og rund --cpus af til et helt tal. --platform virker som i Docker.

Kopiér en container som kommando

Det virker også den anden vej. Højreklik på en container, eller brug menuen Mere, og vælg Kopiér som kommando: Gantry skriver en docker run- eller container run-linje. Den udelader imagets standardværdier, som dets miljø og kommando, så linjen forbliver kort. Det virker også for stoppede containere.

Gem den som opskrift

I arket Ny container åbner du Opskrifter og vælger Gem som opskrift…. Næste gang giver Udfyld fra opskrift den samme formular på enhver vært. Opskrifterne ligger i ~/Library/Application Support/Gantry/recipes.json, så du kan sikkerhedskopiere eller dele dem.

Begrænsninger

  • Gantry beholder stien fra --env-file, men læser ikke filen og læser ikke din shell for -e KEY uden værdi.
  • tmpfs-mounts og anonyme volumes fra --mount vises som ikke understøttet.
  • To porte til den samme containerport (-p 8080:80 -p 8081:80) udfylder formularen, men formularen afviser derefter dubletten.

Spørgsmål og svar

Hvordan konverterer jeg docker run til container run?

Erstat docker run med container run. -d, -p, -e, -v, --name, --rm, -it, -w og --entrypoint forbliver de samme. Fjern --restart, og brug hele CPU'er. Eller indsæt linjen i Gantry, og lad den udfylde formularen.

Kan Gantry importere en docker run-kommando?

Ja. Indsæt kommando… i arket Ny container læser docker run, docker create, podman run og container run og udfylder formularen.

Hvad sker der med flag, som Gantry ikke understøtter?

De vises i forhåndsvisningen med årsagen, og de bliver i formularen i sektionen Fra den indsatte kommando, så du kan tjekke dem senere.

Kan jeg gøre en kørende container til en docker run-kommando igen?

Ja. Kopiér som kommando i containermenuen skriver en docker run- eller container run-linje for den container.

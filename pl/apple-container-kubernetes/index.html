Gantry/Kubernetes na apple/container

Kubernetes na Apple container

apple/container potrafi uruchomić klaster Kubernetes, którego węzły są kontenerami na Twoim Macu. Gantry to dla niego GUI: utwórz klaster, obserwuj, jak startują węzły, podłącz kubectl i wczytaj lokalne obrazy – bez długich poleceń container cluster.

W skrócie. Na hoście apple/container sekcja Klastry w Gantry tworzy i usuwa klastry Kubernetes poleceniem container cluster (CLI 1.6.1) lub container k8s (CLI od 1.5.0 do 1.6.0). Obsługuje wiele węzłów roboczych, własny CNI, widok węzłów, kubeconfig i kontekst kubectl oraz Wczytaj do klastra dla lokalnych obrazów.

Wymagania

  • Mac z Apple silicon, macOS 26 i Gantry (brew install --cask getgantry/tap/gantry).
  • CLI container 1.5.0 lub nowsze; zalecane 1.6.1. Węzły robocze i CNI Brak wymagają 1.6.0 lub nowszego.
  • kubectl, jeśli chcesz korzystać z klastra w terminalu.

Tworzenie klastra

  1. Wybierz host apple/container i otwórz Klastry na pasku bocznym.
  2. Rozpocznij tworzenie nowego klastra i wypełnij opcje opisane poniżej.
  3. Utwórz klaster. Lista pokazuje nowy klaster z postępem na żywo. Anuluj przerywa tworzenie i usuwa już utworzone węzły.
OpcjaFlaga CLIUwagi
Nazwa--nameTakże nazwa kontekstu kubeconfig
Węzły robocze--workersLiczba węzłów roboczych. CLI 1.6.0+
Procesory--cpusNa węzeł
Pamięć--memoryNa węzeł, np. 4G
Obraz węzła--node-imagePuste pole zachowuje domyślny obraz CLI
CNI--cniDomyślny (wbudowany kindnet), Brak (NONE, CLI 1.6.0+) lub ścieżka do własnego manifestu

To samo polecenie w CLI:

Powłoka
container cluster create --name dev --workers 2 --cpus 2 --memory 4G

Węzły i szczegóły klastra

Lista klastrów pokazuje każdy klaster z jego węzłami: rolą, stanem i adresem. Widok szczegółów zawiera Przegląd (kontekst kubectl, serwer API, węzły robocze, sieć węzłów), tabelę Węzły, kartę Inspekcja z surowymi danymi węzłów oraz akcje Zapisz kubeconfig, Kopiuj polecenie kontekstu kubectl i Usuń.

Podłączenie kubectl

Tworząc klaster, CLI dodaje do ~/.kube/config kontekst o nazwie klastra. Użyj w Gantry Kopiuj polecenie kontekstu kubectl albo wpisz je ręcznie:

Powłoka
kubectl --context dev get nodes

Aby trzymać klaster w osobnym pliku, użyj Zapisz kubeconfig. Gantry uruchamia container cluster write-config; domyślna ścieżka to ~/.kube/<name>.kubeconfig.

Lokalne obrazy w klastrze

Zbuduj lub pobierz obraz na hoście apple/container, a następnie kliknij go prawym przyciskiem w sekcji Obrazy i wybierz Wczytaj do klastra. Gantry uruchamia container cluster load-image, które kopiuje obraz do containerd każdego węzła. Do lokalnej pracy nie potrzebujesz rejestru.

Powłoka
container cluster load-image --name dev myapp:dev

Wybór CNI

Domyślnie używany jest wbudowany manifest kindnet. Wybierz Własny manifest, aby zainstalować własny CNI z pliku, na przykład Calico lub Cilium. Wybierz Brak, aby zainstalować CNI samodzielnie później; do tego czasu węzły pozostają w stanie NotReady.

Klastry z poziomu agentów AI

Serwer MCP Gantry ma narzędzia list_clusters, create_cluster i delete_cluster, więc agent, taki jak Claude Code, może utworzyć tymczasowy klaster do testu i potem go usunąć.

Dodaj serwer MCP Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Pytania i odpowiedzi

Czy Apple container obsługuje Kubernetes?

Tak. CLI container tworzy klastry Kubernetes, których węzły działają jako kontenery: container cluster w CLI 1.6.1, container k8s w CLI od 1.5.0 do 1.6.0. Gantry dodaje do tego GUI.

Czy Gantry obsługuje container cluster?

Tak. Gantry wyświetla, tworzy i usuwa klastry na hostach apple/container, pokazuje ich węzły, zapisuje kubeconfig, kopiuje polecenie kontekstu kubectl i wczytuje lokalne obrazy do klastra. Używa cluster lub k8s zależnie od wersji CLI.

Jak używać kubectl z klastrem apple/container?

Gdy CLI tworzy klaster, dodaje do ~/.kube/config kontekst kubeconfig o nazwie klastra. Uruchom kubectl --context <name> get nodes. Aby trzymać klaster w osobnym pliku, użyj w Gantry Zapisz kubeconfig; domyślna ścieżka to ~/.kube/<name>.kubeconfig.

Jak wczytać lokalny obraz do klastra bez rejestru?

W Gantry kliknij obraz prawym przyciskiem w sekcji Obrazy i wybierz Wczytaj do klastra. Gantry uruchamia container cluster load-image, które kopiuje obraz do containerd każdego węzła.

Czy można utworzyć klaster z wieloma węzłami?

Tak. Ustaw liczbę węzłów roboczych w arkuszu tworzenia. Węzły robocze wymagają CLI 1.6.0 lub nowszego.

Czy mogę użyć własnego CNI, np. Calico lub Cilium?

Tak. Wybierz Własny manifest i wskaż plik manifestu albo wybierz Brak i zainstaluj CNI samodzielnie po uruchomieniu klastra. Węzły pozostają w stanie NotReady, dopóki CNI nie działa. Brak wymaga CLI 1.6.0 lub nowszego. Domyślny CNI to wbudowany manifest kindnet.

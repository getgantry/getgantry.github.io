Gantry/Nuo Docker Desktop

Perėjimas nuo Docker Desktop prie Apple container

Apple container įrankis vykdo tuos pačius OCI atvaizdus kaip Docker, todėl didžioji jūsų darbo dalis persikelia pakeitus kelias komandas. Šiame vadove pateikti Docker ir container atitikmenys, aprašytas atvaizdų ir tomų perkėlimas ir išvardyti trūkumai, apie kuriuos verta žinoti prieš pereinant.

Trumpai. Įdiekite pasirašytą container paketą, komandose run, build, logs, exec ir images pakeiskite docker į container, vardinius tomus nukopijuokite per tar failą, o docker-compose.yml atidarykite Gantry, nes CLI neturi compose. Kol bandote, Docker Desktop galite palikti įdiegtą.

Kas pasikeičia

  • Viena virtualioji mašina kiekvienam konteineriui. Docker Desktop visus konteinerius vykdo vienoje Linux virtualiojoje mašinoje. apple/container kiekvienam konteineriui paleidžia mažą virtualiąją mašiną, todėl kiekvienas gauna savo IP adresą jūsų Mac kompiuteryje.
  • Tie patys atvaizdai ir registrai. Atvaizdai yra OCI atvaizdai; juos, kaip ir anksčiau, atsisiunčiate iš Docker Hub, GHCR ir privačių registrų.
  • Jokio licencijos mokesčio. apple/container licencija – Apache 2.0. Docker Desktop reikia mokamo plano organizacijose, turinčiose 250 ar daugiau darbuotojų arba 10 mln. USD ar daugiau pajamų.
  • Tik Apple silicon ir macOS 26. Intel Mac kompiuteriuose likite su Docker varikliu.

Atvaizdų perkėlimas

Atvaizdus iš registro atsisiųskite iš naujo su container image pull. Vietinius atvaizdus, kurie yra tik Docker, įrašykite į archyvą ir jį įkelkite. container image load skaito OCI archyvus, o naujos Docker versijos su docker save įrašo OCI struktūrą. Jei įkelti nepavyksta, nusiųskite atvaizdą į registrą ir atsisiųskite jį.

Terminalas
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Vardinių tomų perkėlimas

Docker tomų duomenis laiko savo virtualiojoje mašinoje. Laikinu konteineriu nukopijuokite kiekvieną tomą į tar failą, tada išpakuokite jį į naują apple/container tomą:

Terminalas
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Vardinis tomas apple/container aplinkoje yra retasis ext4 disko atvaizdas, pagal numatytuosius nustatymus ne didesnis nei 512 GB. Kitą dydį nustatykite su --opt size=20g. Jūsų Mac aplankų bind prijungimai veikia kaip Docker: -v ~/project:/app.

Compose failai

container CLI neturi komandos compose. Vietoj to atidarykite docker-compose.yml Gantry programoje (per Finder, Failas ▸ Atidaryti Compose failą… arba nuvilkę failą). Gantry sukuria build: paslaugų atvaizdus, projekto tinklą ir vardinius tomus ir paleidžia paslaugas depends_on tvarka. Paslaugos pasiekia viena kitą pagal paslaugos vardą per tinklo DNS slapyvardžius.

Tinklai ir prievadai

  • -p 8080:80 paskelbia prievadą localhost adresu, kaip ir Docker.
  • Kiekvienas konteineris taip pat turi savo IP adresą. Sukurkite vietinį DNS domeną komanda sudo container system dns create test ir paleiskite konteinerius su --dns-domain test: jie gaus tokius vardus kaip web.test.
  • container network create kuria naudotojo tinklus; to paties tinklo konteineriai pasiekia vienas kitą.
  • Nėra režimų --network host, none ar container:.

Ko trūksta

  • Nėra Docker Engine API. Įrankiai, kurie jungiasi prie /var/run/docker.sock, pavyzdžiui, Testcontainers, Docker SDK ar Dev Containers, apple/container nemato.
  • Nėra paleidimo iš naujo politikų. --restart nepasiekiama; konteineris pats savaime iš naujo nepasileidžia.
  • CLI neturi Compose. Compose failus vykdo Gantry: žr. Compose failai.
  • Nėra Docker Desktop plėtinių.
  • Tik sveiki CPU: --cpus 0.5 neveikia.
  • Kubernetes veikia kitaip: naudokite container cluster, žr. Kubernetes paleidimas Mac kompiuteryje.

Pereinamuoju laikotarpiu naudokite abu

Gantry vienoje šoninėje juostoje valdo apple/container ir bet kurį Docker variklį (Docker Desktop, OrbStack, Colima arba Docker per SSH). Perkelkite po vieną projektą ir palikite Docker įrankiams, kuriems reikia jo API. Kai jo nebereikės, Docker Desktop galėsite pašalinti.

Susiję vadovai

  • Kubernetes Mac kompiuteryje su Apple container: vadovas žingsnis po žingsnio
  • Konteinerių ir tomų laikymas išoriniame diske Mac kompiuteryje
  • Konteinerio kūrimas iš docker run komandos Mac kompiuteryje (docker run į container run)
  • Apple container GUI, skirta Mac: išsamus apple/container vadovas
  • Kubernetes su Apple container: container cluster GUI ir Kubernetes naršyklė

Klausimai ir atsakymai

Ar Apple container gali pakeisti Docker Desktop?

Konteinerių vykdymui, kūrimui ir atsisiuntimui Apple silicon kompiuteriuose – taip. Jame nėra Docker Engine API, paleidimo iš naujo politikų, plėtinių ir komandos compose. Gantry prideda Compose failų palaikymą ir grafinę sąsają.

Ar Docker atvaizdai veikia su Apple container?

Taip. apple/container naudoja standartinius OCI atvaizdus ir atsisiunčia juos iš tų pačių registrų. arm64 atvaizdai veikia natyviai, amd64 atvaizdai – per Rosetta su --arch amd64.

Ar docker compose veikia su Apple container?

Iš CLI – ne: komandos container compose nėra. Gantry nuskaito docker-compose.yml ir paleidžia paslaugas apple/container aplinkoje už jus.

Ar galima naudoti Docker Desktop ir Apple container vienu metu?

Taip. Jie nesidalija atvaizdais ar tomais, bet gali veikti greta. Gantry abu rodo viename lange.

Ar Apple container nemokamas komerciniam naudojimui?

Taip. apple/container yra atvirojo kodo su Apache 2.0 licencija, o Gantry – su MIT licencija. Abu nemokami bet kokio dydžio įmonėms.

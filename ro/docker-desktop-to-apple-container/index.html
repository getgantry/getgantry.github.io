Gantry/De la Docker Desktop

Treceți de la Docker Desktop la Apple container

Instrumentul container de la Apple rulează aceleași imagini OCI ca Docker, așa că cea mai mare parte a muncii dvs. se mută cu câteva schimbări de comenzi. Acest ghid pune în corespondență Docker cu container, mută imaginile și volumele și listează lipsurile pe care trebuie să le cunoașteți înainte de trecere.

Pe scurt. Instalați pachetul semnat container, înlocuiți docker cu container pentru run, build, logs, exec și imagini, copiați volumele cu nume printr-un fișier tar și deschideți docker-compose.yml în Gantry, pentru că CLI-ul nu are compose. Puteți păstra Docker Desktop instalat cât timp încercați.

Ce se schimbă

  • O VM pentru fiecare container. Docker Desktop rulează toate containerele într-o singură VM Linux. apple/container pornește o VM mică pentru fiecare container, deci fiecare primește propria adresă IP pe Mac.
  • Aceleași imagini și registre. Imaginile sunt imagini OCI; descărcați din Docker Hub, GHCR și registre private ca înainte.
  • Fără taxă de licență. apple/container are licența Apache 2.0. Docker Desktop necesită un plan plătit în organizațiile cu 250 de angajați sau mai mulți ori cu venituri de 10 milioane USD sau mai mari.
  • Doar Apple silicon și macOS 26. Pe Mac-urile cu Intel, rămâneți la un motor Docker.

Majoritatea flagurilor pentru run sunt aceleași: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus și -m. Pentru a converti o comandă lungă, lipiți-o în Gantry: vedeți Creați un container dintr-o comandă docker run.

Aduceți imaginile

Imagini dintr-un registru: descărcați-le din nou cu container image pull. Imagini locale care există doar în Docker: salvați-le într-o arhivă și încărcați-o. container image load citește arhive OCI, iar versiunile recente de Docker scriu un layout OCI cu docker save. Dacă încărcarea eșuează, trimiteți imaginea într-un registru și descărcați-o de acolo.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine

Mutați volumele cu nume

Docker păstrează datele volumelor în VM-ul său. Copiați fiecare volum într-un fișier tar cu un container de scurtă durată, apoi despachetați-l într-un volum apple/container nou:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

Un volum cu nume în apple/container este o imagine de disc ext4 rară (sparse), implicit de cel mult 512 GB. Setați altă dimensiune cu --opt size=20g. Montările bind ale dosarelor de pe Mac funcționează ca în Docker: -v ~/project:/app.

Fișiere Compose

CLI-ul container nu are comanda compose. Deschideți în schimb docker-compose.yml în Gantry (din Finder, cu Fișier ▸ Deschide un fișier Compose… sau prin tragere și plasare). Gantry construiește serviciile build:, creează rețeaua proiectului și volumele cu nume și pornește serviciile în ordinea depends_on. Serviciile se găsesc între ele după numele serviciului, prin aliasuri DNS de rețea.

Rețele și porturi

  • -p 8080:80 publică un port pe localhost, ca în Docker.
  • Fiecare container are și propria adresă IP. Creați un domeniu DNS local cu sudo container system dns create test și rulați containerele cu --dns-domain test: primesc nume precum web.test.
  • container network create creează rețele de utilizator; containerele din aceeași rețea se pot accesa între ele.
  • Nu există modurile --network host, none sau container:.

Ce lipsește

  • Nu există Docker Engine API. Instrumentele care comunică cu /var/run/docker.sock, precum Testcontainers, SDK-urile Docker sau Dev Containers, nu văd apple/container.
  • Nu există politici de repornire. --restart nu este disponibil; un container nu repornește singur.
  • CLI-ul nu are Compose. Gantry rulează fișierele Compose: vedeți Fișiere Compose.
  • Nu există extensii Docker Desktop.
  • Doar CPU-uri întregi: --cpus 0.5 nu funcționează.
  • Kubernetes funcționează altfel: folosiți container cluster, vedeți Rulați Kubernetes pe Mac.

Păstrați-le pe amândouă în timpul trecerii

Gantry gestionează apple/container și orice motor Docker (Docker Desktop, OrbStack, Colima sau Docker prin SSH) într-o singură bară laterală. Mutați câte un proiect pe rând și păstrați Docker pentru instrumentele care au nevoie de API-ul său. Când nu mai aveți nevoie de el, puteți elimina Docker Desktop.

Ghiduri conexe

  • Kubernetes pe Mac cu Apple container: ghid pas cu pas
  • Containere și volume pe un disc extern pe Mac
  • Container dintr-o comandă docker run pe Mac (docker run în container run)
  • GUI Apple container pentru Mac: ghidul complet apple/container
  • Kubernetes pe Apple container: GUI pentru container cluster și browser Kubernetes

Întrebări și răspunsuri

Poate Apple container să înlocuiască Docker Desktop?

Pentru rularea, construirea și descărcarea containerelor pe Apple silicon, da. Nu are Docker Engine API, politici de repornire, extensii sau o comandă compose. Gantry adaugă fișierele Compose și un GUI.

Funcționează imaginile Docker cu Apple container?

Da. apple/container folosește imagini OCI standard și descarcă din aceleași registre. Imaginile arm64 rulează nativ; imaginile amd64 rulează prin Rosetta cu --arch amd64.

Funcționează docker compose cu Apple container?

Nu din CLI: nu există container compose. Gantry citește docker-compose.yml și rulează serviciile pe apple/container în locul dvs.

Pot folosi Docker Desktop și Apple container în același timp?

Da. Nu partajează imagini sau volume, dar pot rula unul lângă altul. Gantry le afișează pe amândouă într-o singură fereastră.

Este Apple container gratuit pentru uz comercial?

Da. apple/container este open source, sub licența Apache 2.0, iar Gantry are licența MIT. Ambele sunt gratuite pentru companii de orice dimensiune.

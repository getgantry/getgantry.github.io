Gantry/Externí disk

Kontejnery a svazky na externím disku

Image, kontejnery a svazky rychle zaplní malý interní disk. S nástrojem container od Applu můžete tato data mít na externím SSD: jednotlivé složky tam umístit pomocí bind mountů, nebo přesunout celou kořenovou složku dat. Tento průvodce ukazuje obojí a také to, jak disk odpojit bez poškození.

Ve zkratce. Naformátujte disk jako APFS. Pro jeden projekt připojte složku přes bind mount: -v /Volumes/Fast/pg:/data. Pro všechno zastavte služby, zkopírujte ~/Library/Application Support/com.apple.container na disk příkazem cp -Rp a služby pokaždé spouštějte příkazem container system start --app-root /Volumes/Fast/container.

Kde data jsou teď

apple/container drží všechna svá data v jedné složce, kořenové složce aplikace (app root). Ve výchozím stavu je to ~/Library/Application Support/com.apple.container, se složkami pro kontejnery, obsah imagů, snímky, svazky, jádra a sítě. Zkontrolujte cestu a využité místo:

Terminál
container system status | grep appRoot
container system df

Výběr a formátování disku

  • Použijte SSD přes USB-C nebo Thunderbolt. Plotnový disk funguje také, ale kontejnery startují pomaleji.
  • Naformátujte ho jako APFS (funguje i Mac OS Extended). Nepoužívejte exFAT, FAT ani NTFS: svazky jsou řídké obrazy disku a tyto systémy souborů nemají řídké soubory ani unixová oprávnění.
  • Jako kořenovou složku aplikace nepoužívejte síťový disk.
  • Dejte disku krátký název bez mezer, například Fast. Cesta pak je /Volumes/Fast.

Možnost 1: data projektu na disku přes bind mounty

Bind mount sdílí složku z vašeho Macu s kontejnerem a ta složka může být na libovolném disku. Je to snadný způsob, jak mít velká data, například databázi nebo soubory modelů, mimo interní disk:

Terminál
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

Disk musí být připojený dřív, než se kontejner spustí. Image a samotný kontejner zůstávají na interním disku.

Možnost 2: všechna data apple/container na disk

Tímto přesunete image, kontejnery, snímky a svazky. Nejdřív zastavte služby, aby se během kopírování žádný soubor nezměnil:

Terminál
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Použijte cp -Rp. V našem testu v macOS 27 (z APFS na APFS přes USB) zachoval obrazy svazků řídké a zachoval rozšířené atributy. ditto zapsal každý řídký obraz v plné velikosti, což může disk zaplnit. Starou složku si nechte, dokud neověříte, že se vaše kontejnery, image a svazky zobrazují v seznamu.

Pozor
CLI si --app-root nepamatuje. Každé container system start bez něj znovu použije interní složku. Příznak zadávejte pokaždé, například v aliasu shellu, a kontrolujte paths.appRoot v container system status.

Gantry 0.27.0 spouští služby bez --app-root, když se připojuje k hostiteli se zastavenými službami. Nejdřív spusťte služby s tímto příznakem z terminálu; Gantry pak použije běžící služby. Podpora přesunuté kořenové složky dat v Gantry je ve vývoji.

Archivace imagů na disku

Chcete-li uvolnit místo bez ztráty imagu, uložte ho na externí disk a smažte ho. Až ho budete potřebovat, znovu ho načtěte:

Terminál
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Bezpečné odpojení disku

  1. Zastavte kontejnery, které disk používají: container stop <name>.
  2. Pokud je kořenová složka aplikace na disku, zastavte služby: container system stop.
  3. Vysuňte disk ve Finderu a pak ho odpojte.

Pokud disk zmizí, zatímco z něj běží kontejnery, selžou a rozpracované zápisy se mohou ztratit. Po opětovném připojení disku spusťte služby s --app-root a pak spusťte kontejnery.

Externí disky v Gantry

Gantry už dnes spouští bind mounty z libovolného disku: v Nový kontejner přidejte svazek, vyberte složku na externím disku a cestu v kontejneru. Podpora přesunu kořenové složky dat, svazků na externím disku a upozornění, když disk není připojený, je v Gantry ve vývoji.

Docker Desktop a OrbStack

Docker Desktop přesouvá svůj obraz disku v Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack přidal nastavení umístění dat ve verzi 0.13.0. Viz srovnání.

Otázky a odpovědi

Mohu mít image Apple container na externím disku?

Ano. Spusťte služby příkazem container system start --app-root /Volumes/Disk/container. Všechny image, kontejnery, snímky a svazky pak budou v této složce.

Jaký systém souborů má mít externí disk?

APFS. Svazky jsou řídké obrazy disku a kontejnery potřebují unixová oprávnění, která exFAT, FAT ani NTFS nemají.

Jak zkopírovat data kontejnerů, aniž by se disk zaplnil?

Použijte cp -Rp, který v našem testu zachoval řídké obrazy svazků malé. ditto zkopíroval každý řídký obraz v plné velikosti.

Co se stane, když disk odpojím, zatímco kontejnery běží?

Kontejnery, které disk používají, selžou a data, která ještě nebyla zapsána, se mohou ztratit. Před vysunutím zastavte kontejnery a, pokud je na disku kořenová složka aplikace, i služby.

Pamatuje si CLI container nové umístění?

Ne. Zadávejte --app-root u každého container system start. container system status ukazuje používanou kořenovou složku jako paths.appRoot.

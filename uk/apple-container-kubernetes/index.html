Gantry/Kubernetes на apple/container

Kubernetes на Apple container

apple/container може запустити кластер Kubernetes, вузли якого — контейнери на вашому Mac. Gantry — GUI для цього: створіть кластер, стежте, як запускаються вузли, під’єднайте kubectl та імпортуйте локальні образи без довгих команд container cluster.

Коротко. На хості apple/container розділ Кластери в Gantry створює й видаляє кластери Kubernetes командою container cluster (CLI 1.6.1) або container k8s (CLI від 1.5.0 до 1.6.0). Він підтримує кілька робочих вузлів, власний CNI, перегляд вузлів, kubeconfig і контекст kubectl, а також Імпортувати в кластер для локальних образів.

Вимоги

  • Mac з Apple silicon, macOS 26 і Gantry (brew install --cask getgantry/tap/gantry).
  • CLI container версії 1.5.0 або новішої; рекомендовано 1.6.1. Для робочих вузлів і CNI Немає потрібна 1.6.0 або новіша.
  • kubectl, якщо ви хочете працювати з кластером із термінала.

Створення кластера

  1. Виберіть хост apple/container і відкрийте Кластери на боковій панелі.
  2. Почніть створення нового кластера й заповніть параметри нижче.
  3. Створіть його. Новий кластер з’явиться в списку, де в реальному часі видно перебіг створення. Скасувати зупиняє створення й видаляє вже створені вузли.
ПараметрПрапорець CLIПримітки
Назва--nameТакож назва контексту kubeconfig
Робочі вузли--workersКількість робочих вузлів. CLI 1.6.0+
CPU--cpusНа вузол
Пам’ять--memoryНа вузол, наприклад 4G
Образ вузла--node-imageПорожнє поле — типове значення CLI
CNI--cniТиповий (вбудований kindnet), «Немає» (NONE, CLI 1.6.0+) або шлях до власного маніфесту

Та сама команда в CLI:

Термінал
container cluster create --name dev --workers 2 --cpus 2 --memory 4G

Вузли й відомості про кластер

Список кластерів показує кожен кластер із його вузлами: роль, стан і адресу. Детальний вигляд містить Огляд (контекст kubectl, API-сервер, робочі вузли, мережа вузлів), таблицю Вузли, Перевірити з необробленими даними вузлів і дії Записати kubeconfig, Скопіювати команду контексту kubectl і Видалити.

Під’єднання kubectl

Під час створення кластера CLI додає в ~/.kube/config контекст із назвою кластера. Натисніть Скопіювати команду контексту kubectl у Gantry або введіть команду самі:

Термінал
kubectl --context dev get nodes

Щоб зберігати кластер в окремому файлі, натисніть Записати kubeconfig. Gantry виконає container cluster write-config; типовий шлях — ~/.kube/<name>.kubeconfig.

Імпорт локальних образів у кластер

Зберіть або отримайте образ на хості apple/container, потім клацніть його правою кнопкою в розділі Образи й виберіть Імпортувати в кластер. Gantry виконає container cluster load-image: команда копіює образ у containerd кожного вузла. Для локальної розробки реєстр не потрібен.

Термінал
container cluster load-image --name dev myapp:dev

Вибір CNI

Типово використовується вбудований маніфест kindnet. Виберіть Власний маніфест, щоб інсталювати власний CNI з файлу, наприклад Calico або Cilium. Виберіть Немає, щоб інсталювати CNI згодом самостійно; доти вузли лишаються в стані NotReady.

Керування кластерами через ШІ-агентів

Сервер MCP Gantry має list_clusters, create_cluster і delete_cluster, тож агент на кшталт Claude Code може створити тимчасовий кластер для тесту й потім вилучити його.

Додайте сервер MCP Gantry
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

Більше про apple/container

Прочитайте посібник з apple/container, де описано всі команди container та їхні функції в Gantry, або порівняйте Gantry з Docker Desktop, OrbStack і Podman Desktop.

Запитання й відповіді

Чи підтримує Apple container Kubernetes?

Так. CLI container створює кластери Kubernetes, вузли яких працюють як контейнери: container cluster у CLI 1.6.1, container k8s у CLI від 1.5.0 до 1.6.0. Gantry дає для цього GUI.

Чи підтримує Gantry container cluster?

Так. Gantry показує, створює й видаляє кластери на хостах apple/container, показує їхні вузли, записує kubeconfig, копіює команду контексту kubectl та імпортує локальні образи в кластер. Він використовує cluster або k8s залежно від версії CLI.

Як під’єднати kubectl до кластера apple/container?

Під час створення кластера CLI додає в ~/.kube/config контекст kubeconfig із назвою кластера. Виконайте kubectl --context <name> get nodes. Щоб мати окремий файл kubeconfig, натисніть Записати kubeconfig у Gantry; типовий шлях — ~/.kube/<name>.kubeconfig.

Як імпортувати локальний образ у кластер без реєстру?

У Gantry клацніть образ у розділі «Образи» правою кнопкою й виберіть Імпортувати в кластер. Gantry виконає container cluster load-image: команда копіює образ у containerd кожного вузла.

Чи можна створити кластер із кількох вузлів?

Так. Укажіть кількість робочих вузлів у вікні створення. Для робочих вузлів потрібен CLI 1.6.0 або новіший.

Чи можна використати власний CNI, наприклад Calico або Cilium?

Так. Виберіть Власний маніфест і вкажіть файл маніфесту або виберіть Немає й інсталюйте CNI самостійно після запуску кластера. Поки CNI не працює, вузли лишаються в стані NotReady. Для Немає потрібен CLI 1.6.0 або новіший. Типовий CNI — вбудований маніфест kindnet.

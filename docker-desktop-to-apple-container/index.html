Gantry/From Docker Desktop

Move from Docker Desktop to Apple container

Apple's container tool runs the same OCI images as Docker, so most of your work moves over with a few command changes. This guide maps Docker to container, moves images and volumes, and lists the gaps that you should know about before you switch.

In short. Install the signed container package, replace docker with container for run, build, logs, exec and images, copy named volumes with a tar file, and open your docker-compose.yml in Gantry, because the CLI has no compose. You can keep Docker Desktop installed while you try it.

What changes

  • One VM per container. Docker Desktop runs all containers in one Linux VM. apple/container starts a small VM for each container, so each one gets its own IP address on your Mac.
  • Same images and registries. Images are OCI images; you pull from Docker Hub, GHCR and private registries as before.
  • No license fee. apple/container is Apache 2.0. Docker Desktop needs a paid plan in organizations with 250 or more employees or $10M or more in revenue.
  • Apple silicon and macOS 26 only. On Intel Macs, stay with a Docker engine.

Most flags of run are the same: -d, -p, -e, -v, --name, --rm, -it, -w, --entrypoint, --cpus and -m. To convert a long command, paste it in Gantry: see Create a container from a docker run command.

    Bring your images

Images from a registry: pull them again with container image pull. Local images that exist only in Docker: save them to an archive and load it. container image load reads OCI archives, and recent Docker versions write an OCI layout with docker save. If the load fails, push the image to a registry and pull it.

Terminal
docker save -o app.tar app:dev
container image load -i app.tar
container image pull nginx:alpine
    Move named volumes

Docker keeps volume data inside its VM. Copy each volume to a tar file with a short-lived container, then unpack it into a new apple/container volume:

Terminal
docker run --rm -v data:/from -v "$PWD":/to alpine tar -C /from -cf /to/data.tar .
container volume create data
container run --rm -v data:/to -v "$PWD":/from alpine tar -C /to -xf /from/data.tar

A named volume in apple/container is a sparse ext4 disk image, 512 GB at most by default. Set another size with --opt size=20g. Bind mounts of folders on your Mac work as in Docker: -v ~/project:/app.

    Compose files

The container CLI has no compose command. Open the docker-compose.yml in Gantry instead (Finder, File ▸ Open Compose File… or drag and drop). Gantry builds the build: services, creates the project network and named volumes, and starts the services in depends_on order. Services reach each other by service name through network DNS aliases.

    Networks and ports
  • -p 8080:80 publishes a port on localhost, as in Docker.
  • Each container also has its own IP address. Create a local DNS domain with sudo container system dns create test and run containers with --dns-domain test: they get names such as web.test.
  • container network create makes user networks; containers on the same network reach each other.
  • There is no --network host, none or container: mode.
    What is missing
  • No Docker Engine API. Tools that talk to /var/run/docker.sock, such as Testcontainers, the Docker SDKs or Dev Containers, do not see apple/container.
  • No restart policies. --restart is not available; a container does not start again on its own.
  • No Compose in the CLI. Gantry runs Compose files: see Compose files.
  • No Docker Desktop extensions.
  • Whole CPUs only: --cpus 0.5 does not work.
  • Kubernetes is different: use container cluster, see Run Kubernetes on a Mac.
    Keep both while you switch

Gantry manages apple/container and any Docker engine (Docker Desktop, OrbStack, Colima, or Docker over SSH) in one sidebar. Move one project at a time, and keep Docker for the tools that need its API. When you no longer need it, you can remove Docker Desktop.

Questions and answers

Can Apple container replace Docker Desktop?

For running, building and pulling containers on Apple silicon, yes. It does not have the Docker Engine API, restart policies, extensions or a compose command. Gantry adds Compose files and a GUI.

Do Docker images work with Apple container?

Yes. apple/container uses standard OCI images and pulls from the same registries. arm64 images run natively; amd64 images run through Rosetta with --arch amd64.

Does docker compose work with Apple container?

Not from the CLI: there is no container compose. Gantry reads the docker-compose.yml and runs the services on apple/container for you.

Can I use Docker Desktop and Apple container at the same time?

Yes. They do not share images or volumes, but they can run side by side. Gantry shows both in one window.

Is Apple container free for commercial use?

Yes. apple/container is open source under the Apache 2.0 license, and Gantry is MIT licensed. Both are free for companies of any size.

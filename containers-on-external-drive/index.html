Gantry/External drive

Store containers and volumes on an external drive

Images, containers and volumes fill a small internal disk fast. With Apple's container tool you can keep that data on an external SSD: put single folders there with bind mounts, or move the whole data root. This guide shows both, and how to unplug the disk without damage.

In short. Format the disk as APFS. For one project, bind-mount a folder: -v /Volumes/Fast/pg:/data. For everything, stop the services, copy ~/Library/Application Support/com.apple.container to the disk with cp -Rp, and start the services with container system start --app-root /Volumes/Fast/container each time.

Where the data is now

apple/container keeps all its data in one folder, the app root. By default it is ~/Library/Application Support/com.apple.container, with folders for containers, image content, snapshots, volumes, kernels and networks. Check the path and the space in use:

Terminal
container system status | grep appRoot
container system df

Choose and format the disk

  • Use an SSD on USB-C or Thunderbolt. A spinning disk works, but containers start slower.
  • Format it as APFS (Mac OS Extended works too). Do not use exFAT, FAT or NTFS: volumes are sparse disk images, and those file systems have no sparse files and no Unix permissions.
  • Do not use a network disk for the app root.
  • Give the disk a short name without spaces, for example Fast. The path is then /Volumes/Fast.

Option 1: keep project data on the disk with bind mounts

A bind mount shares a folder of your Mac with the container, and the folder can be on any disk. This is the easy way to keep large data, such as a database or model files, off the internal disk:

Terminal
mkdir -p /Volumes/Fast/site
container run -d --name web -p 8080:80 \
  -v /Volumes/Fast/site:/usr/share/nginx/html:ro nginx:alpine

The disk must be connected before the container starts. Images and the container itself stay on the internal disk.

Option 2: move all apple/container data to the disk

This moves images, containers, snapshots and volumes. Stop the services first, so no file changes during the copy:

Terminal
container system stop
cp -Rp ~/Library/Application\ Support/com.apple.container /Volumes/Fast/container
container system start --app-root /Volumes/Fast/container
container system status | grep appRoot
container ls -a && container image ls && container volume ls

Use cp -Rp. In our test on macOS 27 (APFS to APFS over USB), it kept the volume images sparse and kept the extended attributes. ditto wrote each sparse image at its full size, which can fill the disk. Keep the old folder until you have checked that your containers, images and volumes are listed.

Heads up
The CLI does not remember --app-root. Each container system start without it uses the internal folder again. Use the flag every time, for example in a shell alias, and check paths.appRoot in container system status.

Gantry 0.27.0 starts the services without --app-root when it connects to a host whose services are stopped. Start the services from the terminal with the flag first; Gantry then uses the running services. Gantry support for a moved data root is in development.

Archive images on the disk

To free space without losing an image, save it to the external disk and delete it. Load it again when you need it:

Terminal
mkdir -p /Volumes/Fast/images
container image save -o /Volumes/Fast/images/myapp.tar myapp:dev
container image delete myapp:dev
container image load -i /Volumes/Fast/images/myapp.tar

Unplug the disk safely

  1. Stop the containers that use the disk: container stop <name>.
  2. If the app root is on the disk, stop the services: container system stop.
  3. Eject the disk in Finder, then unplug it.

If the disk goes away while containers run from it, they fail, and writes in progress can be lost. After you connect the disk again, start the services with --app-root, then start the containers.

External drives in Gantry

Gantry runs bind mounts from any disk today: in New Container, add a volume, choose a folder on the external disk and a path in the container. Gantry support for moving the data root, volumes on an external disk and a warning when the disk is not connected is in development.

Docker Desktop and OrbStack

Docker Desktop moves its disk image in Settings ▸ Resources ▸ Advanced ▸ Disk image location. OrbStack added a data location setting in version 0.13.0. See the comparison.

Questions and answers

Can I store Apple container images on an external drive?

Yes. Start the services with container system start --app-root /Volumes/Disk/container. All images, containers, snapshots and volumes then live in that folder.

Which file system should the external drive use?

APFS. Volumes are sparse disk images and containers need Unix permissions, which exFAT, FAT and NTFS do not have.

How do I copy the container data without filling the disk?

Use cp -Rp, which kept the sparse volume images small in our test. ditto copied each sparse image at its full size.

What happens if I unplug the drive while containers run?

The containers that use the disk fail, and data that was not yet written can be lost. Stop the containers and, if the app root is on the disk, the services before you eject it.

Does the container CLI remember the new location?

No. Pass --app-root to every container system start. container system status shows the root in use as paths.appRoot.

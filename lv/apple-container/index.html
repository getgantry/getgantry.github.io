Gantry/apple/container ceļvedis

Apple container Mac datorā: pilns ceļvedis un GUI

apple/container palaiž Linux konteinerus jūsu Mac datorā, katru savā vieglā virtuālajā mašīnā. Tas tiek piegādāts kā komandrindas rīks. Gantry ir tam paredzēta natīvā macOS grafiskā saskarne. Šajā ceļvedī paskaidrots, kas ir šis rīks, kā to iestatīt un kura Gantry iespēja atbilst katrai container komandai.

Īsumā. Gantry ir bezmaksas atvērtā koda (MIT) macOS lietotne, kas vienā logā pārvalda Apple rīku container un Docker. Tā atbalsta container CLI no 1.0 līdz 1.6.1 (ieteicamā) un rāda tikai tās iespējas, ko atbalsta jūsu CLI versija. Instalējiet to ar brew install --cask getgantry/tap/gantry.

Kas ir apple/container?

apple/container ir Apple atvērtā koda rīks, rakstīts Swift valodā, kas izveido un palaiž Linux konteinerus Mac datorā. Docker Desktop palaiž visus konteinerus vienā kopīgā Linux virtuālajā mašīnā, bet apple/container palaiž katru konteineru savā vieglā virtuālajā mašīnā, kas balstīta uz Apple Virtualization ietvaru. Tas izmanto standarta OCI attēlus, tāpēc lejupielādē no tiem pašiem reģistriem un augšupielādē tajos pašos reģistros, ko Docker.

  • Aparatūra: Mac dators ar Apple silicon.
  • macOS: Apple to atbalsta operētājsistēmā macOS 26.
  • Saskarne: tikai container CLI. Nav ne darbvirsmas lietotnes, ne komandas compose.
  • Tīkls: katrs konteiners jūsu Mac datorā saņem savu IP adresi, un lokālie DNS domēni piešķir konteineriem nosaukumus, piemēram, web.test.

Kāpēc apple/container izmantot grafisko saskarni?

CLI ir pilnīgs, taču ikdienas darbā vajag daudz komandu: container list, logs, stats, exec, bet pārējam – system, builder, registry, machine un cluster. Gantry apvieno tās vienā logā ar atjauninājumiem reāllaikā, tāpēc stāvokli redzat uzreiz, nevis to nepārtraukti pārbaudot. Tā pievieno arī to, kā CLI nav: Compose failus, paziņojumus par kļūmēm, parka skatu kopā ar Docker resursdatoriem un MCP serveri MI aģentiem.

apple/container iestatīšana ar Gantry

  1. Instalējiet Gantry: brew install --cask getgantry/tap/gantry, pēc tam noņemiet karantīnas atzīmi (skatiet Instalēšana).
  2. Instalējiet container CLI no parakstītās .pkg pakotnes apple/container laidienu lapā. Ja CLI nav vai tas ir vecāks par 1.0, Gantry parāda iestatīšanas logu ar soļiem.
  3. Lietotnē Gantry izvēlieties Pievienot resursdatoru… un pievienojiet Apple Container resursdatoru. Savienojoties container pakalpojumi tiek startēti, ja tie ir apturēti.
  4. Ja nav instalēts noklusējuma kodols, resursdatora pārskatā tiek rādīts paziņojums. Noklikšķiniet uz tā, lai instalētu ieteicamo kodolu.
Uzmanību
Izmantojiet parakstīto instalācijas pakotni, nevis Homebrew versiju. Homebrew versijā nav mašīnu aizmugursistēmas, tāpēc container machine nevar darboties.

Ko Gantry pievieno apple/container

Kubernetes klasteri

Izveidojiet Kubernetes klasterus ar vairākiem darba mezgliem, izmantojot container cluster, izvēlieties CNI, skatiet katru mezglu, ierakstiet kubeconfig un ielādējiet lokālos attēlus klasterī. Skatiet Kubernetes apple/container vidē.

Konteineru mašīnas un VS Code

Mašīnas ir ilgdzīvojošas Linux vides no container machine. Gantry tās izveido, startē, aptur un dzēš, iestata noklusējuma mašīnu, maina CPU un atmiņu un atver čaulu. Ar CLI 1.1 vai jaunāku mašīnu var sāknēt ar ligzdoto virtualizāciju (Apple silicon M3 vai jaunāks) un pielāgotu kodolu. Atvērt lietotnē VS Code savienojas ar darbojošos mašīnu caur Remote-SSH; mašīnas attēlā jādarbojas sshd.

Docker Compose apple/container vidē

Atveriet docker-compose.yml no Finder (Atvērt ar ▸ Gantry vai Ātrās darbības ▸ Compose Up apple/container vidē), no Fails ▸ Atvērt Compose failu… vai nometot to logā. Gantry būvē build: pakalpojumus, izveido projekta tīklu un nosauktos sējumus un startē katru pakalpojumu depends_on secībā ar standarta com.docker.compose.* etiķetēm. Ja iestatīts noklusējuma DNS domēns, pakalpojumi sasniedz cits citu pēc pakalpojuma nosaukuma, izmantojot tīkla aizstājvārdus.

Tīkla DNS aizstājvārdi un lokālie domēni

Gantry nodod tīkla aizstājvārdus rīkam container kā --network <name>,alias=…. Bez noklusējuma DNS domēna darbojas tikai pilnībā kvalificēti nosaukumi, un apakškoka aizstājvārds (ar punktu sākumā, piemēram, .gateway) darbojas tikai kā precīzs aizstājvārds. Ar noklusējuma domēnu darbojas arī īsie nosaukumi. Gantry izveido un dzēš lokālos DNS domēnus, iestata noklusējuma domēnu un piešķir jauniem konteineriem resursdatora nosaukumu name.domain. Skatiet Lokālie DNS nosaukumi.

Sistēma: pakalpojumi, būvētājs, reģistri, kodols, žurnāli, rekvizīti

Katram apple/container resursdatoram ir sadaļa Sistēma. Tā darbojas arī tad, kad resursdators ir atvienots, tāpēc no tās varat startēt apturētos pakalpojumus.

  • Stāvoklis un versija: klienta un servera versijas ar brīdinājumu, ja tās atšķiras; pakalpojumu startēšana, apturēšana un restartēšana; informācija par resursdatoru un ceļi.
  • Attēlu būvētājs: stāvoklis, attēls, CPU, atmiņa un IP; startēšana ar CPU, atmiņas un DNS opcijām; apturēšana; dzēšana.
  • Pieteikšanās reģistros: saraksts, pieteikšanās un izrakstīšanās. Parole tiek nodota CLI tikai caur stdin (--password-stdin), un Gantry tās kopiju neglabā.
  • Kodols: ieteicamā kodola, kodola faila vai tar arhīva instalēšana ar norisi reāllaikā.
  • Pakalpojumu žurnāli: reāllaikā vai vienreizēji, par periodu no 5 minūtēm līdz 1 dienai, filtrējot pēc līmeņa, pakalpojuma un teksta.
  • Sistēmas rekvizīti: izmaiņas tiek saglabātas failā ~/.config/container/config.toml, ar atzīmi par gaidāmu restartēšanu un pogu Restartēt pakalpojumus.

Saglabāšana kā attēlu, diska TRIM un faili

Saglabāt kā attēlu izmanto container commit (CLI 1.6). Veikt diska TRIM izmanto container clean (CLI 1.4) un tiek rādīts arī kā rinda panelī „Atgūt vietu”. Cilne „Faili” lejupielādē failus un ļauj tos izvilkt uz Finder ar container copy (konteineram jābūt startētam), kā arī augšupielādē failus un mapes.

Etiķetes, kas satur =

container create noraida etiķetes vērtību, kas satur =, arī CLI 1.6.1. Gantry šādas vērtības kodē, kad izveido konteineru, un atkodē, kad to nolasa, tāpēc jūs redzat tieši tās etiķetes, ko iestatījāt.

MCP serveris un Īsceļi

Komplektā iekļautais gantry-mcp serveris dod MI aģentiem tādas pašas iespējas apple/container resursdatoros: konteineri, attēli, sējumi, tīkli, Compose, mašīnas (list_machines, create_machine un citi), klasteri (list_clusters, create_cluster, delete_cluster) un apple_* sistēmas rīki pakalpojumiem, būvētājam, reģistriem (bez pieteikšanās rīka), rekvizītiem, žurnāliem un kodola instalēšanai. App Intents pievieno Īsceļu un Siri darbības. Skatiet MI aģenti un MCP.

Pievienojiet Gantry MCP serveri
claude mcp add gantry -- /Applications/Gantry.app/Contents/Resources/gantry-mcp

apple/container blakus Docker

Gantry pārvalda apple/container resursdatorus, lokālo Docker dēmonu (Docker Desktop, OrbStack, Colima) un attālos Docker resursdatorus caur SSH vienā sānjoslā un vienā parka informācijas panelī. Jums nav jāizvēlas viena izpildes vide. Rīku salīdzinājumu pa iespējām skatiet lapā Gantry salīdzinājumā ar Docker Desktop, OrbStack un Podman Desktop.

Jautājumi un atbildes

Kāda ir labākā Apple container grafiskā saskarne (GUI)?

Gantry ir bezmaksas atvērtā koda natīvā macOS grafiskā saskarne, kas radīta rīkam apple/container. Tā pārnes container CLI darbvirsmas lietotnē: konteineri, žurnāli, statistika un exec, kā arī Kubernetes klasteri, mašīnas, attēlu būvētājs, pieteikšanās reģistros, kodoli, pakalpojumu žurnāli un sistēmas rekvizīti. Šīs lapas tabulā norādīta katra komanda un Gantry iespēja, kas to izmanto.

Vai rīkam Apple container ir grafiskā saskarne?

Apple piegādā container tikai kā komandrindas rīku. Gantry ir atsevišķa atvērtā koda lietotne, kas tam piešķir grafisko saskarni blakus jūsu Docker resursdatoriem.

Vai ar Apple container var izmantot docker compose?

apple/container nav komandas compose. Gantry nolasa docker-compose.yml, būvē build: pakalpojumus, izveido tīklu un nosauktos sējumus un startē pakalpojumus depends_on secībā. Pakalpojumu nosaukumi tiek atrisināti ar tīkla DNS aizstājvārdiem.

Kā atvērt konteinera mašīnu lietotnē VS Code?

Startējiet mašīnu lietotnē Gantry un noklikšķiniet uz Atvērt lietotnē VS Code. Gantry to atver caur Remote-SSH, kā Apple piemērā container-machine-vscode. Mašīnas attēlā jādarbojas sshd.

Vai Apple container darbojas Intel Mac datoros?

Nē. apple/container nepieciešams Mac dators ar Apple silicon. Gantry darbojas arī Intel Mac datoros, bet tur pārvalda tikai Docker resursdatorus.

Kuru container CLI versiju instalēt?

Gantry nepieciešama 1.0 vai jaunāka versija, un tā ir pārbaudīta ar 1.6.1. Instalējiet to ar parakstīto instalācijas pakotni no apple/container laidienu lapas. Homebrew versijā nav mašīnu aizmugursistēmas, tāpēc container machine ar to nedarbojas.
